# 날씨별 음악 점수 산출식과 3시간 선곡 기획안

- 작성일: 2026-10-16
- 수정일: 2026-10-16
- 대상: PL과 음악 추천 담당 C, 공통 API 담당 B, 날씨 담당 A
- 상태: 초기 기획식과 오프라인 검산. 아래 수치 파라미터는 청취 검증 전 가설이며 기존 운영 계약을 교체하지 않습니다.
- 제안 점수 버전: `WEATHER_SCORE_PROPOSAL_20261016_V2`

날씨마다 **선호/확장 패턴별 음악 특성 0~100점 → 패턴별 가중합 → 같은 패턴의 핵심 검사와 75점 하한 → 정상 통과 패턴 중 최고점 → 전체 후보목록 → 사용자 조건 필터 → 3시간 조합**으로 처리합니다. 날씨는 맑음·구름낌·흐림·비·눈의 다섯 가지입니다. 같은 곡이 여러 날씨의 목록에 들어갈 수 있습니다.

이번 사용자 확인으로 **기획 기준의 초기식을 먼저 만들고, 날씨별 청취 평가가 쌓이면 회귀로 보정**합니다. V2의 필수 조건은 **모든 유효곡이 최소 한 날씨에서 75점과 핵심 성분 기준을 실제로 통과**하는 것입니다. 다른 날씨에서는 낮은 점수·핵심 부적합으로 탈락할 수 있습니다. 모든 곡에 적어도 한 날씨의 탈락을 강제하지는 않습니다.

V1에서는 유효 61,931곡 중 14,413곡이 모든 날씨에서 탈락했습니다. 특히 높은 energy·낮은 acousticness·낮은 valence 조합을 받는 영역이 부족했습니다. V2는 기존 선호 패턴을 유지하고 고정된 확장 패턴을 추가합니다. 미매칭 곡을 사후 최고점 날씨에 배정하거나 곡별 점수를 합격선으로 올리는 처리는 사용하지 않습니다. V1 기획서·정책·요약·분석 소스는 [V1 보관 안내](../../../analysis/weather_music_20261016/archive/v1/README.md)에 남겼습니다.

추가 확인으로 **지역은 하나로 고정하고 최신 유효 날씨 분류가 바뀌면 플레이리스트를 갱신**합니다. 미래 3시간 예보를 평균해 한 번에 여러 날씨를 합산하는 방식은 이번 새 기획에 사용하지 않습니다. PTY2/6 비·눈 혼합에는 비와 눈 모두에 합격한 곡을 사용합니다. 날씨 입력은 **실황 PTY와 유효한 예보 SKY를 조합하고 각 시각·출처를 따로 보존**하는 방식으로 사용자 확인을 받았습니다.

## 2. 컬럼 정의와 역할

### 날씨 점수에 직접 쓰는 네 컬럼

| 원본 컬럼 | 기호·입력 | 의미 | 적용 |
|---|---|---|---|
| `energy` | e, 원본 0~1 | 지각되는 강도·활동성 | 날씨별 활기 구간과의 거리 |
| `acousticness` | a, 원본 0~1 | 어쿠스틱 성향에 대한 지표 | 날씨별 질감 구간과의 거리. 0.8을 ‘어쿠스틱 악기 80%’로 해석하지 않음 |
| `valence` | v, 원본 0~1 | 음악이 전달하는 긍정적 정서 성향 | 밝기·정서 방향의 약한 가설. 실제 이용자의 행복도나 검수 mood가 아님 |
| `mode` | m, 0/1/NULL | 0 단조, 1 장조 | 최대 5점 보조. 단조=슬픔·장조=즐거움으로 확정하지 않음 |

특성의 의미는 [Spotify Audio Features 설명](https://developer.spotify.com/documentation/web-api/reference/get-audio-features)을 참고합니다. 이번 계산은 제공받은 CSV로 수행하며 Spotify API 신규 수집 가능성을 전제하지 않습니다.

원본 e/a/v의 소수를 그대로 사용합니다. 현행 서비스 저장값 `energy=floor(10e)`, `acousticness=floor(100a)`는 유지하고, 원본을 변환 정수로 덮어쓰지 않습니다. 정수값에서 원본 정밀도를 복원할 수 없습니다.

**valence는 현재 추천·표시 18개에 없는 새 점수 입력입니다.** 이번에는 원본과 연결한 분석 특성으로 사용합니다. 실제 채택 시 `raw_valence`와 원본 e/a의 불변 참조를 점수 특성 저장에 추가하는 계약이 필요합니다. 화면에 19번째 음악 항목을 즉시 추가하거나 기존 18개 규격에 이미 포함되어 있다고 취급하지 않습니다.

### 나머지 원본 컬럼

| 컬럼 | 역할과 처리 |
|---|---|
| `track_id` | 곡 단위 키·중복 제거·동점 기준. 날씨 점수 입력 아님 |
| `track_name`, `artists`, `album_name` | 표시·식별. 필수 문자열 누락은 후보 보류 |
| `duration_ms` | 양의 정수 ms. 3시간 조합에 사용하며 점수 가점 아님 |
| `track_genre` | 원본 복수 라벨을 보존하고 기존 18대분류에 매핑. 승인 연결과 사용자 선택 필터에 사용 |
| `tempo`, `time_signature` | 기존 speed 생성에 사용. 이번 W에 다시 가점으로 넣지 않음. tempo 0은 이번 분석에서 미확인으로 보류 |
| `instrumentalness` | 무보컬 옵션의 자동 판정 근거. 날씨 가점 아님 |
| `explicit` | 원본 보존·표시. 이번에 새로운 자동 제외 정책을 만들지 않음 |
| `danceability` | 리듬·움직임 관련 보조 분석. valence와 중복 가능성이 있어 초기 W에서는 제외 |
| `loudness` | energy와 강하게 겹치는 보조 분석값. 별도 W 가점 제외 |
| `speechiness` | 발화 성향 검수 참고. 이것만으로 보컬/무보컬 최종 판정하지 않음 |
| `liveness` | 라이브 현장성 관련 참고. 날씨 선호 근거가 없어 W 제외 |
| `popularity` | 인기도. 날씨 적합도·동점·가점에 사용하지 않음 |
| `key` | 조성 코드. 코드 숫자에 크기 순서 의미가 없으므로 기울기 입력 제외 |
| 이름 없는 인덱스 | 출처 행 확인만 수행. 곡 키·순위·학습 입력 제외 |

실제 고유곡의 Pearson r은 energy–acousticness **-0.732566**, energy–loudness **+0.758774**, danceability–valence **+0.492571**입니다. 특성끼리 겹친다는 근거이지 날씨 선호의 정답이 아닙니다. energy/acousticness도 상관되어 있으므로 두 가중치를 독립적인 인과효과로 해석하지 않습니다.

speed는 `time_signature=3`일 때만 tempo/1.5로 보정한 뒤 ROUND_HALF_UP 정수 반올림하여 `<80 slow`, `<110 medium`, `<150 fast`, 나머지 `fastest`입니다. 날씨별 원본 후보 점수와 요청별 speed 필터를 분리합니다.

무보컬 선택 시 확정 `instrumental_review_value`의 True/False가 우선이고, 미검수일 때만 `<.2 False / .2~.8미만 NULL / >=.8 True`를 사용합니다. 최종 True만 통과합니다. 무보컬 옵션 미선택에 이 조건을 전곡 공통 필터로 강제하지 않습니다.

## 3. 날씨별 선호 패턴과 확장 패턴

각 날씨에는 `PRIMARY` 선호 패턴과 `SUPPORT` 확장 패턴을 하나씩 둡니다. 선호 패턴은 V1의 구간·가중치·감쇠 폭을 그대로 사용하고 최대 100점입니다. 확장 패턴은 V1이 놓친 음악 특성 영역을 수용하며 최대 80점입니다. 원본 특성에 처음부터 적용하는 고정된 계산식이며, 미매칭 곡에만 나중에 붙이는 보정이 아닙니다.

구간·비중·감쇠 폭·80점 상한은 청취 검증 전 기획 가설입니다. ‘강한 에너지·낮은 밝기’를 구름낌의 활동적 패턴에, 조용한 전자음향을 흐림에 포함하는 것은 이번 정책의 선택이며 음악의 객관적 날씨 정답이라고 주장하지 않습니다.

### 두 패턴에 공통인 날씨별 비중

| 날씨 | energy | acousticness | valence | mode |
|---|---:|---:|---:|---:|
| 맑음 | 40% | 25% | 30% | 5% |
| 구름낌 | 30% | 35% | 30% | 5% |
| 흐림 | 25% | 40% | 30% | 5% |
| 비 | 30% | 40% | 25% | 5% |
| 눈 | 20% | 45% | 30% | 5% |

각 행의 합은 100%입니다. 이는 패턴 점수 예산 안의 상대 비중입니다. 실제 점수 예산은 선호 100점·확장 80점이므로 확장 패턴의 각 기여점수에는 .8을 곱합니다.

h는 목표 구간 경계에서 성분 점수가 100점에서 0점이 되는 거리입니다. 가중치는 감점 가능한 점수의 상대 크기, h는 떨어지는 속도입니다.

### 확장 패턴 SUPPORT

| 패턴 ID | 수용하는 특성 | energy e | acousticness a | valence v | 선호 mode | hE/hA/hV | 상한 c |

모든 구간 경계는 포함하며 서로 겹칠 수 있습니다. 일부 확장 패턴은 acousticness 전체 범위를 허용합니다. 이 패턴에서 A는 유효 원본 전체에서 100이므로 순위 변별에 기여하지 않는 상수 항입니다. 이를 어쿠스틱 정도의 실증 효과라고 해석하지 않습니다. 흐림/비의 확장 패턴에서는 acousticness가 질감 구분과 감점에 실제로 작용합니다.

확장 점수를 80점으로 제한해 전곡의 최고 점수가 일률적으로 95~100점이 되는 현상을 피합니다. 선호 패턴의 **함수와 80점 초과 우선 영역**은 보존되지만, 선호 75~80점 곡은 확장 패턴으로 점수가 달라질 수 있어 중하위 순위는 바뀔 수 있습니다. 많은 확장곡이 76/80점에 동점이 되는 한계도 패턴별 통계로 기록합니다.

## 4. 패턴별 컬럼 계산식과 날씨 점수

곡 i·날씨 w·패턴 p·특성 j에 대해 아래와 같이 계산합니다. 입력은 원본 0~1 소수입니다.

```text
d(x,L,U) = max(L-x, 0, x-U)
q_wpj(x) = min(1, d(x,L_wpj,U_wpj)/h_wpj)
F_wpj(x) = 100*(1-q_wpj(x))

E_iwp = F_wpE(e_i)
A_iwp = F_wpA(a_i)
V_iwp = F_wpV(v_i)
M_iwp = 100 if mode_i == preferred_mode_wp else 0

B_iwp = Σ_j [a_wj * F_iwpj] / 100
W_iwp = (c_wp/100) * B_iwp
```

a는 표의 40/25/30/5 같은 비중 숫자이며 합이 100입니다. c는 PRIMARY=100, SUPPORT=80입니다. 각 성분은 0~100, 패턴 W는 0~c입니다. mode 미확인은 M=0/NULL 보존, e/a/v 결측·범위 오류는 점수 NULL로 보류합니다. 결측에 따라 비중을 재분배하지 않습니다.

### 절편·기울기 표현

```text
q_M = 0 if mode가 선호값과 일치 else 1
b_wp = c_wp
γ_wpj = c_wp * a_wj / 100
W_iwp = b_wp - Σ_j γ_wpj*q_iwpj
```

선호 패턴은 b=100·γ=a, 확장 패턴은 b=80·γ=.8a입니다. 절편은 모든 성분이 목표에 맞을 때의 기준점수이며 전체 평균 곡의 점수가 아닙니다.

원본 x에 대한 패턴 기울기는 구간 아래에서 `+γ/h`, 위에서 `-γ/h`, 목표 구간 안과 이미 0점이 된 구간에서 0입니다. 예를 들어 맑음 PRIMARY energy는 원본 한 단위당 ±114.285714…점, CLEAR_SUPPORT energy는 ±213.333333…점입니다. 확장 패턴의 acousticness 구간이 0~1 전체이면 유효 입력 안의 기울기는 항상 0입니다.

각 패턴은 변환 특성 q에 대한 선형식이고, 원본에 대해서는 구간별 선형식입니다. 패턴의 최대값 선택까지 포함한 전체 날씨 함수는 하나의 전역 직선이나 단일 선형회귀가 아닙니다.

### 같은 패턴 안에서 합격을 검사

```text
core_ok(i,w,p) = E_iwp>=20 AND A_iwp>=20
pass(i,w,p) = core_ok(i,w,p) AND W_iwp>=75
weather_pass(i,w) = OR_p pass(i,w,p)

CorePatterns(i,w) = {p : core_ok(i,w,p)}
CorePatterns가 있으면:
  selected_pattern = argmax_p∈CorePatterns W_iwp
  동점은 pattern_id 코드 포인트 오름차순
  W_iw = W_iw,selected_pattern
  weather_pass = W_iw>=75
CorePatterns가 없으면:
  후보 제외
  raw_max_score와 그 패턴은 진단용으로만 보존
```

합격 날씨의 대표점수·E/A/V/M·상한·패턴 ID는 정상 합격한 **동일 패턴 하나**에서 가져옵니다. 가장 높은 원점수 패턴이 핵심 조건에 실패해도 다른 패턴이 정상 통과할 수 있습니다. 성분마다 다른 패턴의 최대 E·A를 섞거나, 핵심 탈락 패턴의 높은 W를 후보 정렬점수로 쓰지 않습니다.

정상 패턴이 여러 개이면 최고점을 사용합니다. 다른 날씨 점수를 빼거나 합계 100/softmax 정규화를 하지 않으므로 각 날씨의 계산은 독립입니다. 공통 특성 때문에 결과 점수끼리 통계적 상관이 생길 수 있습니다.

75점·20점 경계는 포함합니다. 경계 판정 전에 반올림하지 않으며 원본 소수의 정확한 유리수 또는 동등한 정확 연산을 사용합니다. 표시에만 ROUND_HALF_UP 소수 두 자리를 적용합니다. CSV의 근삿값과 판정 근거인 정확한 값을 구분합니다.

## 5. 전곡 최소 한 날씨 합격의 보장과 부적합 유지

### 전체 유효 특성 영역을 덮는 이유

유효 원본 영역은 `0<=e,a,v<=1`입니다. 다음 경우 분기로 모든 점을 다섯 확장 패턴 중 최소 하나에 연결할 수 있습니다.

```text
e>=.5 AND v>=.5                         → CLEAR_SUPPORT 목표 영역
e>=.5 AND v<=.5                         → CLOUDY_SUPPORT 목표 영역
e<=.5 AND v>=.5                         → SNOW_SUPPORT 목표 영역
e<=.5 AND v<=.5 AND a<=.5                → OVERCAST_SUPPORT 목표 영역
e<=.5 AND v<=.5 AND a>=.5                → RAIN_SUPPORT 목표 영역
```

이는 사후 배정 코드가 아니라 **고정한 목표 상자들의 합집합이 단위 정육면체 전체라는 증명**입니다. 어떤 곡이 어느 상자 안에 있으면 그 패턴의 E/A/V는 모두 100입니다. mode가 불일치하거나 미확인이어도 비중은 5%뿐이므로:

```text
W_support >= .8*(100-5) = 76 >= 75
E_support = A_support = 100 >= 20
```

따라서 모든 유효 e/a/v는 최소 하나의 날씨에서 **원래 75점·핵심 20점 조건을 실제로 통과**합니다. 입력마다 가장 높은 날씨에 강제로 넣거나, 낮은 점수를 75로 올리거나, 실패 후 하한을 자동으로 낮추는 규칙이 없습니다. 0/.5/1 경계 조합과 mode0/1/미확인 검사는 증명의 구현 대조이며, 그 유한 표본만으로 전체 도메인을 증명했다고 하지 않습니다.

### 보장 범위

현재 전곡 재검증 대상은 기존과 동일한 기본 유효집합 B, **61,931개 고유 track_id**입니다. 이름·길이·장르 연결·유효 특성·speed 근거를 검증하지 못한 원본 곡까지 정상 적격으로 승격하지 않습니다. 위 도메인 증명은 같은 유효 입력을 가진 새 곡에도 점수상 합격을 보장하지만 READY·검수·이용자 필터·현재 날씨에서의 후보량까지 보장하지는 않습니다.

```text
assert union(Pool_CLEAR, Pool_CLOUDY, Pool_OVERCAST, Pool_RAIN, Pool_SNOW) == B
assert unmatched_ids == []
assert 모든 후보는 같은 패턴의 W>=75 AND E>=20 AND A>=20
```

선택 장르·무보컬·speed·제외 조건을 적용한 특정 날씨의 후보 부족은 여전히 가능합니다. 이를 해결하려고 해당 조건을 자동 해제하지 않습니다.

### 다른 날씨에서의 탈락

확장 패턴의 좁은 h=.15와 패턴별 핵심 조건을 유지합니다. 예를 들어 강하고 밝은 곡은 맑음에서 통과할 수 있지만 조용한 비/눈 패턴의 energy에서 탈락할 수 있습니다. 어두운 고에너지 곡은 구름낌의 확장 패턴에 통과해도 밝은 맑음에서는 75점에 못 미칠 수 있습니다.

전곡 최소 한 날씨 합격을 위해 타 날씨 점수를 차감하거나 모든 곡의 최소 한 날씨 탈락을 강제하지 않습니다. 다른 날씨 부적합이 실제로 남는지 전곡 분포와 고정 앵커를 별도로 검증합니다. 날씨별 계산상 합격은 새 기획 기준의 충족이며 청취 품질·만족도 보장은 아닙니다.

## 6. 날씨별 전체 후보목록과 3시간 선곡

### 전체 후보목록

날씨별 전체 목록은 다음 집합이며 200곡으로 자르지 않습니다.

```text
Pool_w = {고유곡 i: 구조/카탈로그 조건 통과 AND weather_pass(i,w)}
순서 = W_iw 내림차순, 정확 동점이면 track_id 오름차순
```

운영 Pool에는 READY 카탈로그·승인/활성 장르·유효한 speed 등 서비스 자격을 함께 적용합니다. 이번 CSV 검산의 Pool은 이 중 확인할 수 있는 구조·특성·장르 매핑만 검사한 **분석 후보**입니다.

공통 풀에는 보컬 포함 여부·선택 장르·선택 테마를 고정하지 않습니다. 사용자 요청이 오면 해당 풀에서 최종 instrumental·선택 장르·고정 allowed_speed·제외 곡 등 조건을 적용합니다. 같은 사이클의 허용 집합은 날씨 풀 갱신으로 확대하지 않습니다.

현행 취향 연결은 다음처럼 유지할 수 있습니다.

```text
P_i = 활성 취향 그룹의 100/0 일치 점수 평균
S_i = .75*W_iw + .25*P_i     # 활성 그룹이 있을 때
S_i = W_iw                  # 모두 미선택일 때
```

W 하한과 핵심 조건을 **먼저** 통과한 곡에만 S를 계산합니다. 취향 가점으로 날씨 탈락곡을 다시 넣지 않습니다. 장르/speed는 기존 필수 필터, 테마는 기존 승인 mood 일치 가점이며 추가 문서의 테마 필수·장르 80% 규칙을 자동 도입하지 않습니다.

### 3시간 조합

곡 선택변수 `z_i∈{0,1}`, 길이 `t_i=duration_ms_i`로 정의합니다.

```text
D = Σ(t_i*z_i)
10,560,000 <= D <= 11,040,000     # 176~184분
target = 10,800,000              # 180분
Q = Σ(t_i*S_i*z_i) / D
```

현행 순서에 맞춰 **정확 180분 → 180분 초과에서 가까운 시간 → 180분 미만에서 가까운 시간**을 우선하고, 같은 시간에서는 Q를 최대화합니다. 남은 동점은 곡 ID로 결정합니다. 곡 수를 최대화하거나 단순히 상위곡을 누적하다가 180분에서 자르지 않습니다. 최종 기본 순서는 S 내림차순·ID 오름차순입니다.

상위 200곡은 탐색 시작 창일 뿐입니다. 실패하면 400→800→…→전체 적격 후보로 확장합니다. 제한 창 실패·시간 초과·최적성 미입증은 `SEARCH_INCOMPLETE`로 구분하고, 전체에서 불가능함을 확인한 경우에만 `CANDIDATE_SHORTAGE`로 판단합니다. 후보가 부족하다고 75점·핵심 조건·사용자 필터를 자동으로 풀거나 176분 미만으로 단축하지 않습니다.

정확 시간 조합을 찾은 것과 같은 시간의 최대 Q를 입증한 것은 다릅니다. 이번 예시는 정확 180분의 구성 가능성을 검산하며 품질 최적성을 입증하지 못하면 `NOT_PROVEN`으로 표시합니다. 기존 운영 성공 계약을 만족했다고 보고하지 않습니다.

이번 단일 날씨 예시는 생성 시점의 유효 날씨 분류로 3시간 목록을 구성한 것입니다. 이후 날씨 분류가 바뀌면 다음 절차로 새 버전을 만듭니다. 이는 기존 계약의 ‘180분 예보 전체를 미리 덮고 시간 가중평균’과 다른 새 정책이며, 실제 채택 때 날씨 유효성·작업·스냅샷 계약도 함께 바꿔야 합니다.

### 기존 날씨 수집과 정제 계약에 연결

[날씨01 수집](../../handoff/weather/01_날씨_수집과_지역매핑.md)·[02 항목과 정제](../../handoff/weather/02_날씨_데이터규격과_정제.md)·[03 저장](../../handoff/weather/03_날씨_저장구조.md)·[04 호출](../../handoff/weather/04_API호출과_RDB적재시험.md)·[05 분류](../../handoff/weather/05_날씨분류와_계절기준.md) 다섯 문서를 대조했습니다. 수집 규격은 있으며 실제 해당 파이프라인이 이 저장소에서 실행·운영된다는 의미는 아닙니다.

| 입력 묶음 | 수집 기획 | 이번 음악식에서의 역할 |
|---|---|---|
| 실황 | 10분 간격. PTY·REH·RN1·T1H·UUU·VEC·VVV·WSD | 유효 PTY로 강수 형태 결정. **SKY는 없음** |
| 초단기예보 | 1시간 간격, 미래 6시간×11항목. 위 8개+SKY·LGT·POP | 강수 없는 경우 유효 예보 SKY로 맑음/구름낌/흐림 결정. 예보임과 대상 시각 보존 |
| SNO | 3시간 발표 기준, 가까운 9개 대상시각의 신적설 | 안내 보완. 이번 W의 직접 가중치 없음 |
| KIM tcld | 3시간 간격 대상의 예측 구름량, 원본0~1→% | 별도 보완값. 기본 SKY 대체·혼합·관측값 승격 없음 |

사용자 조회는 **지역코드→nx·ny→이미 저장된 ES의 observation/forecast 묶음**을 이용합니다. 화면 요청마다 기상청을 호출하지 않습니다. 내부 수집/정제/보관은 Kafka→Spark→MongoDB/ES이며 추천기는 날씨 사실을 다시 추정하지 않습니다.

분류 어댑터는 다음 순서입니다.

| 유효 실황 PTY | SKY 필요 | 점수/후보 연결 |
|---|---|---|
| 1·5 | 아니오 | 비 RAIN |
| 3·7 | 아니오 | 눈 SNOW |
| 2·6 | 아니오 | 비·눈 교집합 어댑터 |
| 0 | 예 | 예보 SKY1→맑음, SKY3→구름낌, SKY4→흐림 |
| 결측·오류 | 임의 대체 안 함 | 판정 보류·갱신 실패 안내 |

실황 허용 PTY는 0/1/2/3/5/6/7이고 초단기 허용은 0~7이므로, 실황 출처에 PTY4가 오면 소나기로 받아들이지 않고 코드 오류로 처리합니다. 예보 원본 PTY4의 소나기/RAIN 연결은 보존하되 이번 현재 분류에서 관측 PTY로 승격하지 않습니다. SKY0/2도 오류입니다. PTY0만 보고 맑음으로 정하지 않습니다. POP가 높아도 실제 비로 바꾸지 않고, RN1=0이어도 유효 PTY의 비 형태는 유지합니다.

각 측정값의 `raw/value/unit/status`와 위치 `region_code/nx/ny`, 실황의 `issued_at/target_at/received_at`, SKY 예보의 **별도** `issued_at/target_at/received_at`, 출처·정제 버전·원문 해시 참조를 함께 보존합니다. 정제 시각은 KST +09:00, 서비스 API는 공통 계약에 따라 UTC Z로 변환할 수 있으나 세 시각과 두 출처를 하나로 합치지 않습니다.

예보 SKY는 관측 구름량이 아닙니다. 화면/스냅샷에 예보 대상 시각을 표시하고, 현재 시점에 적용 가능한 유효 예보로 확인된 것만 사용합니다. 기존 인계에는 대상시각은 있으나 음악 조회에 적용할 정확한 SKY 유효구간/TTL 선택식은 충분히 고정되어 있지 않습니다. **A의 조회 계약에서 적용 대상시각과 유효 시작/종료를 제공하도록 연결하고, 그 정보가 없으면 지나간 예보를 임의 연장하거나 다른 대상시각을 현재 관측으로 바꾸지 않습니다.** 실황은 정상이나 PTY0/SKY 부재이면 강수 없음만 확인할 수 있으므로 맑음/구름낌/흐림 판정은 보류합니다.

날씨 데이터의 기온(T1H)·습도·풍속·강수량을 이번 점수에 다시 수치 가점으로 넣지 않습니다. 이 값은 분류/안내에 사용하고, 음악 점수는 결정된 프로필을 입력으로 독립 산출합니다. `TMP/PCP` 같은 다른 API 명칭을 현재 수집 컬럼이라고 섞어 쓰지 않습니다.

### 한 지역의 실시간 날씨 변경

1. 고정한 지역의 최신 유효 실황 PTY와, 필요할 때 적용 가능한 예보 SKY로 분류를 결정하고 각 시각·출처 버전을 고정합니다. 과거값·누락을 맑음으로 바꾸지 않습니다.
2. 이전 분류와 같으면 날씨 갱신만으로 목록을 다시 만들지 않습니다. 맑음→비처럼 분류가 바뀌면 새 날씨 풀에서 새 3시간 목록을 생성합니다. 지역 자체를 바꾸면 새로운 조건의 요청으로 처리합니다.
3. 사용자가 선택한 장르·무보컬·빠르기·제외 조건과 같은 사이클의 allowed_genre/allowed_speed는 보존합니다. 새 날씨가 필수 조건을 풀어주는 근거가 되지 않습니다.
4. 생성 중 날씨가 또 바뀌면 작업에 고정한 날씨 버전과 최신 버전을 비교해 늦은 응답이 새 목록을 덮어쓰지 않도록 합니다. 성공한 새 결과는 새 revision으로 발행하고 과거 결과·곡 평가를 덮어쓰거나 복사하지 않습니다.
5. 후보 부족·날씨 오류이면 기존 결과를 보존하고 갱신 실패/날씨 정보 지연을 안내합니다. 기존 결과를 새 날씨에 적합한 새 결과로 표시하지 않습니다.

‘실시간’은 A의 유효 날씨 데이터 갱신을 수신/조회했을 때 반응한다는 뜻입니다. 실황 수집은 10분, 초단기 수집은 1시간이므로 실제 관측·발표 지연과 조회 주기보다 먼저 감지한다고 약속하지 않습니다. ES 발행·브라우저 반복 조회 주기·알림 방식은 별도 인계에서 정하며 초 단위 임의 값을 만들지 않습니다.

재생 UX의 초기 제안은 **목록은 갱신하되 현재 곡을 끝까지 유지하고 다음 곡부터 새 3시간 대기열로 전환**하는 것입니다. 새 3시간은 다음 곡 시작부터의 목록 길이이며 현재 곡의 잔여시간은 별도입니다. 이 재생 전환 방식은 아직 사용자 확정 전 제안이고, 외부 플레이어의 현재 상태·재생 가능 여부 검증도 필요합니다.

### PTY2/6 비·눈 혼합

```text
Pool_RAIN_SNOW = Pool_RAIN ∩ Pool_SNOW
weather_pass_mixed = weather_pass_RAIN AND weather_pass_SNOW
W_mixed_for_sort = min(W_RAIN, W_SNOW)   # 교집합 안의 정렬용 초기 제안
```

교집합 사용은 사용자 결정입니다. 두 점수 중 낮은 쪽으로 정렬하는 것은 약한 쪽의 적합도를 우선하는 초기 제안이며, 여섯 번째 날씨 모델을 학습하는 것이 아닙니다. 두 기본 날씨의 점수와 통과 사유를 모두 보존합니다. PTY2/6 원현상도 보존하고 PTY1/3의 특별 speed 제한을 자동 확대하지 않습니다.

CSV의 길이 합계와 YouTube에서 매칭한 영상의 길이는 다를 수 있습니다. 영상 버전·인트로·광고·버퍼링을 포함한 실제 경과 3시간은 이 식으로 보장하지 않습니다. 이번 산출물은 음악 추천 계산이며 계정 연결·스트리밍 구현을 포함하지 않습니다.

## 7. 청취 평가와 패턴별 회귀 보정

### 날씨별 정답과 패턴 근거

곡별 날씨 적합도 `y_iw∈[0,100]`를 별도로 수집합니다. 다섯 y의 합을 100으로 제한하지 않습니다. 현재 공개 좋아요/싫어요·선곡표 별점은 곡별 날씨 적합도 정답이 아니므로 자동 재사용하지 않습니다. 초기 W를 y로 넣는 것은 규칙 재현일 뿐 청취 검증이 아닙니다.

평가 기록은 `track_id`, 날씨, 원본/특성 버전, 평가자 익명 식별자, 점수·평가 시각·안내 버전을 보존합니다. 선호/확장 중 어떤 특성 패턴에 맞는지도 PL 검수 근거로 기록합니다. 초기식의 높은 점수뿐 아니라 경계·낮은 점수·다른 날씨 탈락·확장으로 새로 수용한 곡을 포함해 평가합니다. 평가하지 않은 항목은 NULL이며 0이 아닙니다.

날씨별 정답 한 개를 두 패턴에 그대로 복제해 독립 회귀하면 부적합한 패턴까지 같은 정답을 학습할 수 있습니다. 초기에는 **SUPPORT를 고정하고 검수한 PRIMARY부터 보정**하는 순서를 제안합니다. 패턴 적합성 라벨이 확보된 뒤 패턴별 학습을 검토합니다. 실제 운영 판정은 학습식뿐 아니라 core·패턴 선택까지 포함해 평가해야 합니다.

### 상관계수와 기울기

단순회귀 `y=α+βx`에서는 다음과 같습니다.

```text
β = Cov(x,y)/Var(x) = r_xy*s_y/s_x
α = mean(y)-β*mean(x)
```

x와 y를 모두 표준화한 단순회귀에서만 기울기가 r과 같습니다. 다중회귀 계수에 개별 r을 그대로 넣지 않습니다. 음악 특성끼리의 r은 날씨 y와의 상관도 아니므로 weather 기울기로 전용하지 않습니다. [NIST 선형 최소제곱 회귀](https://www.itl.nist.gov/div898/handbook/pmd/section1/pmd141.htm), [최소제곱 계수 추정](https://www.itl.nist.gov/div898/handbook/pmd/section4/pmd431.htm).

### 패턴별 식과 전체 판정

```text
패턴 예측: y_hat_iwp = b_wp - Σ_j γ_wpj*q_iwpj
초기 b_wp = c_wp
초기 γ_wpj = c_wp*a_wj/100

패턴별 계수 학습의 예:
minimize Σ_i[ y_iwp - (b_wp-Σ_jγ_wpj*q_iwpj) ]²
         + λ*Σ_j(γ_wpj-γ_initial_wpj)²

공통 제약: 0<=b_wp<=c_wp, γ_wpj>=0, Σ_jγ_wpj<=b_wp
SUPPORT 커버 유지 제약: b_wp-γ_mode_wp>=75
```

패턴 라벨을 확보하지 않은 상태에서 `y_iwp`가 존재한다고 취급하지 않습니다. 위 학습식은 패턴별 학습 대상과 정답을 확정한 뒤 적용하는 설계입니다. 입력 변환은 고정된 q이고, 개별 회귀는 q에 대한 선형식입니다. core 검사와 최고 패턴 선택을 포함한 날씨 전체 함수는 한 개의 단순 선형회귀가 아닙니다.

`b<=c`는 SUPPORT 상한 80을 보존하며, `γ>=0,Σγ<=b`는 q∈[0,1]에서 예측을 0~c로 유지합니다. SUPPORT 목표 영역 안에서는 q_E=q_A=q_V=0이므로 `b-γ_mode>=75`가 mode 최악값까지 합격을 보장합니다. 목표 구간을 바꾸면 이 제약만으로 전체 도메인 커버를 보장할 수 없으므로 상자 합집합의 증명과 전곡 검사를 다시 수행해야 합니다.

전곡 커버는 제품 정책의 제약입니다. 어떤 확장곡의 청취 정답이 75보다 낮게 나와도 정책 때문에 자동으로 높게 ‘검증’된 것은 아닙니다. 이 경우 수용 날씨·패턴을 청취 근거로 다시 설계하거나 전곡 합격 요구와의 충돌을 명시적으로 조율해야 합니다. 평가 점수를 규칙에 맞게 수정하지 않습니다.

학습 전에 패턴별 q 분산·mode 분포·설계행렬 rank·공선성을 점검합니다. A가 0~1 전체 목표인 SUPPORT에서는 q_A가 항상 0이라 해당 계수는 그 영역의 데이터만으로 추정할 수 없습니다. 안정화 항은 수치 해를 도울 뿐 각 계수의 실증 식별을 보장하지 않습니다.

### 누수 방지와 수용 검증

곡 ID·가능하면 아티스트 묶음 단위로 학습/검증/최종 테스트를 분리합니다. 패턴 증설·L/U/h·상한 c·λ·하한·게이트는 학습/검증에서만 선택하고 최종 테스트는 선택이 끝난 뒤 평가하도록 보존합니다. 같은 곡의 장르 반복행이나 패턴 반복행이 자료 분할을 넘나들면 안 됩니다.

동일 곡·날씨 반복 평가의 원본은 보존합니다. 대표 y의 평균/중앙값·표본 가중치는 파일럿에서 정하고 평가가 많은 곡을 반복 수만큼 과대가중하지 않습니다. 특정 표본 수만 넘으면 검증 완료라고 정하지 않습니다.

날씨/패턴별 MAE·RMSE·순위 상관·75점 통과곡 청취 적합 비율·부적합 오통과·장르/무보컬별 편차를 봅니다. 동시에 `union(Pool_w)==B`, 고정 부적합 앵커, 패턴별 대표 수·76/80/100점 동점 비율을 재검증합니다. 데이터 커버율 100%와 청취 적합률을 같은 지표로 부르지 않습니다.

학습 후 γ를 무조건 합 100으로 재정규화하면 예측이 바뀌므로 하지 않습니다. 설명용 비중 `γ_j/Σγ`는 분모가 양수일 때만 보고하며 통계적 중요도와 동일시하지 않습니다. 새 정책은 새 사이클에 적용하고 과거 결과·평가·스냅샷을 다시 계산하지 않습니다.

| 4개 | 3,136 | 3,609 |
| 5개 | 320 | 374 |

V2에서 다섯 날씨를 모두 통과한 곡은 **374/61,931=약 0.60%**입니다. 나머지 **61,557곡(99.40%)은 한 곳 이상에서 탈락**하므로 다른 날씨에서 부적합할 수 있다는 조건도 유지됩니다. 전곡을 반드시 한 곳 이상에서 탈락시키지는 않습니다. 이 비율은 이번 규칙의 분리 정도이며 실제 청취 정확도가 아닙니다.

흐림–비의 후보 Jaccard는 약 0.630, 맑음–비는 약 0.0137입니다. 전곡 점수의 Pearson r은 각각 약 +0.936, -0.699입니다. 이 상관 계산에는 탈락곡의 core 통과 패턴 점수 또는 core 통과 패턴이 전혀 없을 때의 진단용 raw 최고점도 포함합니다. 유사한 날씨의 겹침을 금지하거나 통계적 상관을 0으로 강제하지 않습니다. 각 날씨 수식이 다른 날씨 점수를 참조하지 않는다는 독립 계산과 구분합니다.

### 가정 입력으로 확인한 부적합 패턴

다음은 실제 곡이 아닌 계산 검증용 입력입니다. 표는 대표 W이며, `통과`는 동일 패턴의 E/A 핵심과 W 하한을 모두 통과했다는 뜻입니다. 탈락 점수는 core 통과 패턴 중 최고점이며, 그런 패턴이 없으면 진단용 raw 최고점입니다.

| 원본 e/a/v/m 가정 | 맑음 | 구름낌 | 흐림 | 비 | 눈 |
|---|---:|---:|---:|---:|---:|
| 0.8/0.1/0.8/1 | 100 통과 | 52 탈락 | 32 탈락 | 0 탈락 | 64 탈락 |
| 0.9/0.05/0.1/0 | 53.57 탈락 | 80 통과 | 60 탈락 | 30 탈락 | 36 탈락 |
| 0.2/0.1/0.2/0 | 30.71 탈락 | 61.88 탈락 | 80 통과 | 60 탈락 | 52 탈락 |
| 0/0.95/0/0 | 20 탈락 | 56 탈락 | 72.5 탈락 | 80 통과 | 61 탈락 |
| 0.1/0.9/0.9/1 | 48 탈락 | 36.88 탈락 | 60.83 탈락 | 70 탈락 | 90 통과 |

중간 경계(.5/.5/.5)는 여러 날씨에서 합격할 수 있고, 높은 에너지·낮은 밝기는 구름낌만, 낮은 에너지·전자음향·낮은 밝기는 흐림만 통과하는 검증 입력도 존재합니다. 연속 입력 전체를 덮으면서 다른 날씨의 낮은 점수와 핵심 탈락을 유지합니다. 구름낌 PRIMARY의 A는 유효 범위에서 37.5 이상이고 SUPPORT의 A는 항상 100이므로, 그 날씨에서 A>=20 단독 게이트는 여전히 변별력이 없습니다. 에너지·밝기·전체 점수로 구분합니다.

대표 패턴 선택 오류도 따로 검사했습니다. 구름낌 입력 `e=.843,a=.5,v=.53,m=0`은 PRIMARY W=75.7이지만 E=19라 탈락합니다. SUPPORT는 W=75.2이고 핵심 조건을 통과하므로 이를 선택해 정상 합격합니다. raw 최고점 하나만 고르고 core를 검사하거나 서로 다른 패턴의 E/A를 조립하지 않습니다. 같은 입력에서 v=.65로 바꾸면 SUPPORT는 56점입니다. PRIMARY 75.7/E19 대신 core 통과 SUPPORT 56점을 진단 대표로 보존하되, 75점 미달로 후보에서 제외하는 반례도 통과했습니다.

### 수치·파일 검증

원본 소수 문자열의 Fraction으로 10개 패턴의 전곡 점수를 계산했습니다. float64 단독 판정과 비교하면 현재 75점의 날씨 합집합 판정은 구름낌 7곡·눈 8곡에서 달라질 수 있었습니다. PRIMARY만 비교한 구름낌의 차이는 V1과 같은 11곡이나, V2에서는 일부가 SUPPORT로도 통과해 최종 합집합 차이가 7곡입니다. 반올림으로 해결하지 않고 정확 비교로 검산했습니다. 70/75/80 경계의 패턴별·합집합 차이는 `summary.json`에 별도 보존합니다.

다섯 SUPPORT 영역의 닫힌 구간 분할과 내부 최저점 76점으로 전체 도메인 커버를 증명했습니다. 별도로 e/a/v의 0·.5·1과 mode 0/1/NULL의 81개 경계 입력, 고정 분리 사례, 위 대표 패턴 선택 반례, 연속값 누락 시 점수 NULL/보류를 검사했습니다. 81개 샘플만으로 연속 도메인을 증명했다고 표시하지 않습니다.

저장한 전체 후보 5개·비/눈 교집합 1개·180분 예시 5개, 총 **11개 CSV를 다시 읽어** ID 중복·정확 점수 정렬·하한·같은 패턴의 핵심/성분·출처/버전과 예시의 후보 포함·speed·정확 ms를 확인했습니다. 원본 114,000행 전체와 고유 89,741곡은 품질 분모로 따로 유지하며, 유효 분석 61,931곡의 커버와 혼동하지 않습니다.

`score_formula_version=WEATHER_SCORE_PROPOSAL_20261016_V2`, `model_version=NULL`, `model_fit_status=INITIAL_PLANNING_NOT_FITTED`로 기록합니다. 새 회귀계수를 추정하거나 청취 적합성을 검증했다고 표시하지 않습니다.

## 9. 저장과 담당 연결

기획 파라미터 `policy_version`, 날씨 코드, L/U/h·가중치·b·하한·게이트, 원본 해시와 특성 스키마, 카탈로그 버전을 고정합니다. 곡별 각 패턴의 E/A/V/M/W·core/합격 여부와 최종 selected_pattern_id·상한·통과/탈락 사유를 당시 값으로 보존하고 `model_version=NULL`이면 학습 모델을 사용하지 않았다는 의미로 기록합니다.

운영 연결은 C가 음악 원본 특성과 점수·후보·정수 시간 조합을 구현하고, PL이 구간 가설·부적합 사례·청취 평가를 검수합니다. A는 실제 PTY/SKY와 예보 유효성을 제공하고, B는 공통 작업·결과·불변 피드백 API 연결, INF는 환경·발행·복구를 담당합니다. 실제 담당자 이름과 일정은 별도입니다.

이번 파일은 별도 신규 기획안입니다. 기존 첫 네 제품 문서·공통 계약·음악 통합 계약·JSON 계약/고정 예시·DB/화면/태스크를 이번에 교체하지 않았습니다. 실제 채택 시 추가 valence 입력, W 하한·핵심 게이트·날씨별 가중치·원본 정밀도·목록 버전을 해당 문서와 함께 연결해야 합니다.

## 10. 남은 결정과 적용 제한

1. **날씨 연결:** PTY2/6은 비·눈 합격곡의 교집합으로 확정했습니다. 구름낌은 기존 PTY0/SKY3 구름많음의 표시명입니다. 맑음=PTY0/SKY1, 흐림=PTY0/SKY4, 비=PTY1/4/5, 눈=PTY3/7의 점수 연결은 기존 근거를 따릅니다. 원현상은 보존하며 점수 연결이 PTY1/3의 특별 speed 제한 확대를 뜻하지는 않습니다.
2. **날씨 갱신의 실제 연결:** 한 지역에서 실황 PTY+유효 예보 SKY의 분류 변화마다 새 목록 버전을 만드는 방향은 확정했습니다. A의 SKY 대상시각/유효구간·데이터 조회 주기·실제 감지 지연·작업 경쟁 방지·현재 곡 유지/다음 곡 전환의 재생 UX는 후속 구현·수용 대상입니다. 예보 평균을 사용하는 기존 계약과의 교체 영향은 실제 반영 단계에 함께 정리합니다.
3. **초기 수치 수용:** 75점·핵심 20점·목표 구간·비중·h와 SUPPORT 상한 80점은 초기 가설입니다. 실제 READY 자료에 대한 장르/빠르기/무보컬 조합별 수용과 청취 결과로 확정합니다. 곡 수가 부족하다는 이유만으로 자동 완화하지 않습니다.
4. **기존 문서 잔존 충돌:** 구현 설계도의 S3 기준 원본 표현·일부 18개 목록 누락, 태스크의 옛 미검수 연주곡 금지 표현은 최신 음악 통합 계약과 다릅니다. 이번 안은 음악 RDB 기준·정확한 18개·검수 우선/AUTO True 허용을 따르며 관련 기존 파일은 수정하지 않았습니다.

원본/문서 전문 검토, 링크·계산·분포·길이 검산과 실제 서버/DB/청취·플랫폼 재생 검증은 서로 다른 근거입니다. 이번 범위는 앞의 문서·오프라인 계산까지입니다.
