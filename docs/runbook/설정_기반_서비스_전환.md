# 설정 기반 서비스 전환

- 작성일/수정일: 2026-10-16
- 담당: Codex, 서비스 통합 설정. `feature/integration` 작업 트리.
- 범위: 코드 편집 없이 접속 설정·기존 초기화/작업자 경로를 실행하는 진입점입니다. DB/클러스터 설치나 운영 배포 완료를 뜻하지 않습니다.

## 설정 파일

실제 비밀값은 Git에 넣지 않습니다. 프로세스 환경이 파일보다 우선하며 공통·날씨 파일은 예시에 있는 이름만 읽습니다. 빈 값은 기본값을 지우지 않고 셸 실행·변수 치환을 하지 않습니다.

| 파일 | 설정할 내용 |
|---|---|
| `backend/.env` | 공통 [예시](../../backend/.env.example). `C_LOCAL_DEMO=0`, `INTEGRATION_ENABLED=1`, PG 접속/TLS·Django 키/호스트/CSRF·양의 TTL/업로드/탐색 한도·원본 절대 경로/S3·ES·날씨 매핑 DSN·피드백 Kafka·광고 내부 비밀·Gemini |
| `pipeline/weather/.env` | 날씨 [예시](../../pipeline/weather/.env.example). KMA/Kafka/PG 매핑/ES·Spark master/실행기/체크포인트/상태 경로. API의 ES/인덱스/매핑 대상과 일치해야 합니다. |
| `ad-server/backend/.env` | 광고 [예시](../../ad-server/backend/.env.example). Mongo replica set URI/DB·`ADS_IS_TEST=0`·공통 HTTPS URL/같은 내부 비밀·delivery 서명·공개 정책·필요한 광고 호스트 PG/TLS |
| `frontend/.env.local` | 프론트 [예시](../../frontend/.env.example). `VITE_C_DEMO=0`·공통/광고 프록시 목적지. 설정 변경 후 프론트를 재시작합니다. |
| `config/environments/runtime.env` | 실행 [예시](../../config/environments/runtime.env.example). 공통/광고/날씨 Python 및 Node 경로와 바인딩. 공통/광고 Django 버전은 다른 가상환경으로 유지합니다. |

이미 준비된 DB/토픽·설치된 호환 Python 의존성과 Spark 실행기가 전제입니다. 서버 설치·권한·TLS 인증서·라우팅·reverse proxy는 INF 인계 항목입니다. 원격 MongoDB는 writable replica set primary와 트랜잭션을 지원해야 합니다. standalone을 허용하지 않습니다.

## 실행 순서

저장소 루트에서 프로젝트 Python으로 아래 스크립트를 실행합니다. Windows는 `.venv/Scripts/python.exe`, Linux는 `.venv/bin/python`입니다. 설정에 비밀값을 넣고 명령행에 DSN/키를 붙이지 않습니다.

```text
python scripts/runtime.py plan
python scripts/runtime.py prepare
python scripts/runtime.py check
```

`plan`은 실행 목록만 출력합니다. `prepare` 기본 동작은 쓰기 없는 계획입니다. `check`는 비밀값 없는 설정 일치 검사와 서비스 자체 설정 검사를 수행하며 외부 접속을 하지 않습니다. 준비 상태 성공을 표시하려면 다음 실제 읽기 검증이 필요합니다.

```text
python scripts/runtime.py prepare --apply --music
python scripts/runtime.py check --connect
python scripts/runtime.py up
```

- `prepare --apply`는 공통 migration/피드백 토픽, 빈 날씨 지역 테이블과 공식 매핑/날씨 토픽/ES 인덱스, 광고 컬렉션/인덱스를 준비합니다. 기존 날씨 매핑·광고 validator·호환 ES 인덱스를 보존하고 구조 충돌을 자동 덮어쓰기로 해결하지 않습니다. 토픽이 없으면 `*_TOPIC_PARTITIONS`/`*_REPLICATION_FACTOR`를 명시해야 하며 기존 토픽을 삭제/축소하지 않습니다.
- 여러 저장소에 걸친 초기화는 하나의 원자 트랜잭션이 아닙니다. 실패 전에 일부 단계가 적용될 수 있고 자동 삭제/되돌리기를 하지 않습니다. 설정/충돌을 확인한 뒤 재실행하면 이미 준비된 구조는 재사용합니다. 광고 호스트의 기존 Django 세션/관리 점검용 `POSTGRES_*`도 공통 PG 대상에 맞춰 설정하며 광고 업무/로그는 MongoDB에 유지합니다.
- 최초 관리자도 설정으로 발급하려면 `BOOTSTRAP_ADMIN_USERNAME/PASSWORD/PERMISSIONS`를 지정합니다. 권한은 `manage_ads,manage_music,view_feedback` 중 명시한 값만 부여하고 기존 계정의 비밀번호·권한은 변경하지 않습니다. 읽기 점검에서 각 관리 기능을 맡을 활성 관리자 권한을 확인합니다.
- `--music`은 설정한 `MUSIC_SOURCE_PATH/SCHEMA/SHA256/CATALOG_VERSION`으로 재개 가능한 CSV 등록을 실행합니다. 원본은 로컬/S3 해시 보관 후 적재하고 미검수는 draft입니다. 승인된 해당 원본의 곡만 카탈로그를 발행합니다. 이미 같은 원본/버전이 발행됐으면 보존하며 버전 충돌은 중단합니다.
- 음악 미검수면 `REVIEW_REQUIRED`, 활성 운영 카탈로그가 없으면 `NOT_READY`입니다. 기존 SQLite의 시험 카탈로그·계정·피드백을 자동 운영 데이터로 승격/복사하지 않습니다. 기존 승인 데이터를 이전하려면 그 원본·승인 근거를 준비해야 합니다.
- `check --connect`는 PG 접속/migration·운영 카탈로그·지역 매핑·ES 스키마·피드백 토픽·S3 versioning과 광고 Mongo 스키마를 읽습니다. 연결 실패/누락은 종료 코드1이고 연결하지 않은 상태를 READY로 표시하지 않습니다. 이 점검은 공유 인증의 실제 로그인/광고 노출·클릭, 모든 버전 호환/성능을 증명하지 않습니다.
- `up`은 위 실제 준비 점검이 통과해야 서비스들을 시작합니다. 음악 검수만 대기하면 `ADMIN_READY_MUSIC_PENDING`으로 관리자 UI/작업자를 시작해 검수·발행을 진행할 수 있고 공개 추천은 준비 전까지 차단합니다. DB/스키마/권한/다른 연결 오류는 이 예외로 우회하지 않습니다. 최초 준비를 함께 하려면 `up --apply --music`입니다. 하위 프로세스 종료/실패 시 나머지도 정리하고 실패로 종료합니다. `run --role common-worker`처럼 한 역할만 실행할 수도 있습니다.
- 점검 성공은 `STORAGE_READY`이며 저장 구조 준비 상태입니다. 실제 날씨 최초 수집/유효 예보가 아직 없으면 ON은 정상적으로 차단하고 OFF는 독립 실행합니다. 수집이 완료되기 전 시험 날씨로 운영 성공을 만들지 않습니다.
- 기본 역할은 common-api/common-worker/feedback-relay/feedback-consumer/weather-collector/weather-spark/ads-api/ads-workers/frontend입니다. 피드백은 Python consumer를 사용하며 같은 집계에 Spark 소비자를 중복 실행하지 않습니다.
- 이 실행기는 팀 통합 개발용 Django runserver/Vite를 사용합니다. 운영 ASGI 서버/TLS/정적 파일 배포·서비스 supervision은 별도 운영 명령으로 연결해야 합니다. 프론트 빌드 결과의 VITE 설정은 빌드 때 고정되므로 대상 변경 후 재빌드해야 합니다.

## 남은 실제 검증

이번 보완에서는 사용자 지시대로 실제 인프라에 접속/스키마 적용하지 않았습니다. 실제 관리 계정 발급, 음악 승인 자료, 날씨 최초 수집과 ES 값/만료, S3 쓰기/복원 권한, Kafka ACK/소비/재시작, 공통↔광고 로그인/측정, PG 다중 작업자 경쟁은 설정 제공 후 수행해야 합니다. 비밀번호·세션·과거 데이터는 임의로 생성/이전하지 않습니다.

코드와 시험 근거는 [서비스 통합 변경 라우팅](../development/서비스_통합_구현_변경_라우팅.md)의 후속 설정 전환 기록을 따릅니다.
