4차 항목은 후속 범위 구분을 위해 기재한다.

## 1. 배경과 문제

- 카페, 음식점 등 음악이 필요한 매장의 운영자를 핵심 사용자로 한다.

- 지역 날씨와 사용자의 취향을 반영한 약 3시간의 선곡표를 제공해, 직접 곡을 찾고 목록을 구성·조정하는 부담을 줄이고자 한다.

## 2. 이해관계자 및 업무 기대 결과

## 3. 업무 목표·측정 방법

| 업무 목표 | 확인 방법 | 목표값·판정 기준 |
|---|---|---|
| 선곡 준비·조정 부담 감소 | 같은 과제에서 기존 방식과 서비스 이용 시간을 비교하고, 조정 부담을 질문한다. | 시간 절감과 부담 감소의 목표 수준은 사용자 조사 후 합의한다. |
| 날씨·취향에 맞는 추천 제공 | 선곡표 별점과 별도의 날씨·매장 분위기 적합성 평가를 확인한다. | 별점·적합성 목표와 평가 대상·규모·기간은 평가 전에 합의한다. |
| 광고 운영·성과 확인 기반 확보 | 유효 노출·클릭의 집계 정확성을 검증하고 운영 지표를 확인한다. | 검증 사례의 예상 집계와 실제 집계가 일치해야 한다. 운영 성과 목표는 별도 합의한다. |

목표값이 정해지기 전에는 측정 결과를 기록하되, 사업 목표를 달성했다고 판단하지 않는다.

- 외부 재생목록 생성

## 6. 업무 규칙

- 기본 추천은 비로그인으로 이용하며 지역만 필수로 한다.
- 사용자 결과는 본인만 조정하고, 관리 업무는 권한이 있는 관리자만 수행한다.
- 기본 추천은 날씨·취향을 반영한 규칙 방식으로 제공한다.
- 선곡표의 총길이는 180분을 목표로 하며, 176~184분을 허용한다. 필수 조건은 임의로 완화하지 않는다.
- 명시적인 재설정 요청에만 Gemini를 사용하며, 같은 조건과 제외 곡을 유지한다. 조건 변경은 새 기본 추천으로 처리하고, 실패하면 기존 상태를 보존한다. 검증된 결과만 승인한다.
- 곡별 좋아요·싫어요와 선곡표 별점은 선택적으로 입력·변경·취소한다. 평가는 자동 추천이나 곡 제외로 연결하지 않는다.
- 3차 광고는 카페 대상으로 제공하며, 유효한 노출·클릭을 음악 피드백과 분리해 집계한다. 지표·예상 사용량은 실제 결제와 구분한다.

## 7. 업무 제약

- 음악 원본과 규격 확보만으로 추천에 사용할 데이터가 준비된 것은 아니다. 실제 적격곡과 검수·발행 결과를 확인해야 한다.
- 추천은 유효한 지역·날씨와 적격 음악 자료에 의존한다. 누락·만료·정책 미정 상태를 정상 데이터로 간주하지 않는다.
- 외부 API의 접근·호출 한도와 비용, 운영 환경·보관 정책은 실제 연결 전에 확인한다.
- 팀원의 참여 시간, 일정과 비용 한도 안에서 진행하며 미정인 운영 수치를 임의로 확정하지 않는다.

## 9. 완료·인수 기준

1. 비로그인으로 지역·날씨 확인부터 추천·곡 제외·재설정·평가·승인까지 이용할 수 있다.
2. 선곡표가 합의한 날씨·취향·제외 곡·시간 기준을 충족하고, 재설정 실패 시 기존 결과가 보존된다.
3. 권한이 있는 관리자만 음악 등록·검수·피드백 조회를 수행하며, 다른 사용자의 결과에 대한 무단 접근이 차단된다.
4. 광고 관리·배너 제공·유효 노출 및 클릭 집계가 정상 동작한다.
5. 합의한 성능·이용 환경·보관·복구 기준을 실제 시험으로 확인한다.
6. 검증 결과·운영 절차·미해결 사항을 기록하고 다음 담당자에게 인계할 수 있다.
7. 업무 목표의 실제 평가 결과와 미해결 사항을 확인한 뒤, 최종 승인자가 인수 여부를 결정한다.
