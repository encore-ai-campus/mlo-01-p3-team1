## 4. HTTP 연결 목록

- 공통: `GET /api/auth/me`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/regions?q=&region_id=`, `GET /api/weather?region_id=`.
- 내부 광고 검증: `POST /api/internal/ads-context` + `Authorization: Bearer …`, body `action=admin|guest`, guest의 `bootstrap` boolean. 외부 reverse proxy에 공개할 경로가 아닙니다.
- 음악: `POST /api/admin/music/imports` multipart `file/source_schema_version/source_sha256`; `GET /api/admin/music/reviews`; `POST /api/admin/music/{track_id}/reviews`; `GET /api/admin/music/readiness`; `POST /api/admin/music/catalogs` body `version/source_ref/source_sha256`.
- 피드백: 기존 본인 playlist feedback/reaction/rating, 관리자 `GET /api/admin/feedback/exclusions`, `/{event_id}`, `/api/admin/feedback/metrics`.
- 날씨 갱신: `POST /api/playlists/{id}/weather-refresh`, body `exclusion_revision`, 멱등 키 필수. 수락 시 job_id 202, 변화 없음은 기존 playlist_id 200. 기존 추천/제외/승인 URL은 유지합니다.
- 광고: Vite의 광고 경로만 별도 광고 호스트로 전달합니다. 개발 프록시 설정은 운영 reverse proxy의 설치 완료를 뜻하지 않습니다.

오류는 기존 공통 code/message/details/request_id 계약을 사용합니다. 인증/권한 401/403, 다른 소유 404, revision/멱등/이미 발행 버전 충돌 409, 입력 422, 미설정/저장소 연결 실패 503으로 차단합니다. 원본 파일은 불변 보관을 먼저 수행하므로 DB 등록 실패 후 미참조 파일이 남을 수 있으며 자동 삭제하지 않습니다.

## 5. 설정과 실행 인계

실제 값은 [환경 안내](../../config/environments/README.md)와 각 `.env.example`의 이름으로 비공개 전달합니다. `.env`를 셸 코드로 실행하지 않습니다. 기상청 키만 [키 로더 라우팅](./날씨_환경설정_변경_라우팅.md)의 파일 fallback을 사용합니다.

1. 공통 가상환경은 backend/requirements.lock, 광고는 기존 uv.lock 기반 별도 환경을 사용합니다. 공통에 argon2-cffi/kafka-python/boto3를 추가했습니다. SQLite는 명시 C_LOCAL_DEMO에서만 사용하며 시험은 C_LOCAL_DATABASE로 격리합니다.
2. 통합 운영은 C_LOCAL_DEMO=0, INTEGRATION_ENABLED=1, DJANGO_SECRET_KEY/허용 호스트/CSRF origin, PostgreSQL PG* 및 TLS/CA를 설정합니다. GUEST_TTL_SECONDS/ADMIN_SESSION_SECONDS/CSV_UPLOAD_MAX_BYTES는 확정값을 입력해야 하며 0/미설정이면 해당 작업을 차단합니다. 보관/만료 정책을 임의 확정하지 않았습니다.
3. 검토 후 `python backend/manage.py migrate`로 common 0001~0005(guest·이벤트/outbox·평가·검수/source/projection·곡 원본 연결·불변 snapshot·S3 보관 manifest)를 적용합니다. 이 작업에서는 시험 DB에만 적용했습니다. 최초 관리자 발급은 BOOTSTRAP_ADMIN_PASSWORD를 비공개 환경으로 전달하고 bootstrap_admin의 `--permissions`를 명시합니다. 재발급은 같은 비공개 환경 항목의 새 비밀번호와 `bootstrap_admin <username> --reset-password`로 실행하며 기존 세션을 회수합니다. 이 명령을 실제 계정에 실행하지 않았습니다.
4. 날씨는 WEATHER_MAPPING_DSN 또는 PG*로 매핑 DB, ES_URL/WEATHER_INDEX 및 필요한 ES_USERNAME/ES_PASSWORD/ES_CA_CERT를 설정합니다. 인증값은 HTTPS에서만 전달하며 기본 TLS 검증을 유지합니다. `prepare_es`의 출력은 검토용 매핑이고 `--apply`만 생성 요청을 수행합니다. 기존 인덱스를 자동 변경하지 않습니다.

Spark 옵션은 보안 키만 허용하고 호스트 검증 해제를 거부하며 JAAS 등을 로그에서 가립니다. 실제 connector/클러스터 TLS 연결은 별도 검증해야 합니다.

9. 음악 원본은 MUSIC_RAW_DIRECTORY와 MUSIC_S3_BUCKET/REGION/PREFIX를 설정합니다. versioning이 이미 활성화된 버킷과 제한된 GetBucketVersioning/PutObject/GetObject(version 포함) 권한을 INF가 제공합니다. SDK는 실행 환경의 IAM 자격증명 체인을 사용하며 코드에 키를 넣지 않습니다. SHA-256 객체 키에 `IfNoneMatch='*'`를 적용하고 기존 객체는 해시 메타데이터·크기·version을 확인합니다. 초기화는 `prepare --apply --music` 또는 `up --apply --music`을 실제 운영자가 명시 실행할 때만 수행합니다. 이번 검증은 dry-run만 실행했습니다. API 입력/응답·업무 정책·피드백 envelope는 변경하지 않습니다. BOOTSTRAP 설정은 최초 계정만 만들며 기존 계정 비밀번호/권한을 자동 재설정하지 않습니다.

`up`은 실제 저장 구조 점검 후 역할을 시작합니다. 음악 검수만 대기하면 ADMIN_READY_MUSIC_PENDING으로 관리 화면을 열어 검수·발행할 수 있지만 공개 추천 준비 완료를 주장하지 않습니다. 연결 오류는 이 예외로 통과시키지 않습니다. 정상 구조 점검도 STORAGE_READY이며 실제 날씨 최초 수집·공유 인증·측정·성능의 종단 검증과 다릅니다.
