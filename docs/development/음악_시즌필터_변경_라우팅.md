## 후속: 명시한 YouTube 재생용 선택 카탈로그

사용자가 한국에서 차단된 곡 1개를 같은 날씨·장르 곡으로 교체하는 것을 승인한 뒤, 통합 담당이 확정한 전체 재생 목록만 기존 대시보드의 로컬 프리뷰로 적재하도록 선택 옵션을 추가했습니다. 곡 교체/최종47개 ID·실제 한국 가용성·매핑 파일·사용자 대시보드/큐 재검증은 통합 담당이 결정·기록합니다. 이 작업자는 그 목록을 임의로 다시 고르거나 운영 카탈로그에 적용하지 않습니다.

추가 코드 경로는 같은 `seed_csv_preview.py`의 `load_playback_selection`과 `Command.handle`입니다. `--playback-selection`은 LOCAL_DEMO=1에서만 동작하고 `--youtube-mappings`가 필수입니다. JSON의 키는 아래 네 개이며 스키마·현재 원본 SHA·비어 있지 않은 selection_version·양수 개수의 고유 문자열 track_ids를 검사합니다.

```json
{
  "schema_version": "YOUTUBE_PLAYBACK_SELECTION_V1",
  "source_dataset_sha256": "b202fa49909b2d5cef71a04b1d21243cfeb36414535f2ca9272aa646721177bd",
  "track_ids": ["명시적으로 확정한 원본 track_id 목록"],
  "selection_version": "명시 선택 버전"
}
```

위 ID는 형식 예시이며 실제 곡 ID가 아닙니다. 명령은 양수 N개 목록을 검증하는 일반형이고 실제 이번 파일은 통합 담당의47곡입니다. 모든 ID가 정제된 GENERAL 원본에 존재하고 선택 전곡의 영상 매핑이 VERIFIED일 때만 입력 순서로 rows를 좁혀 새 test Catalog를 만듭니다. CANDIDATE/BLOCKED_EMBED·누락 매핑·중복/모르는 ID·비일반곡·잘못된 출처는 Catalog 쓰기 전에 실패합니다. 지정하지 않은 기존 전체 일반 프리뷰 동작은 유지합니다.

불변 Catalog 버전에 `-selection-<선택파일SHA앞12>`를 붙이고 source_ref는 `local-preview:youtube-playback-selection:<원본CSV파일명>`입니다. 각 당시 곡에는 `playback_selection_position`, `playback_selection_version`, `playback_selection_sha256`을 저장합니다. JSON 순서와 적재 rows 순서는 보존하지만 기존 worker의 점수/ID 정렬을 변경하지 않으므로 실제 대시보드 결과 순서를 최종 큐 순서로 다시 확인해야 합니다. Spotify play_url·기존 전체/과거 Catalog·is_test/preview_only와 운영 미검수 구분은 유지합니다.

실행은 기존 seed 명령에 `--youtube-mappings <최종 검증 파일> --playback-selection <최종 선택 파일>`을 함께 추가합니다. 새 migration/API/service/프런트/DB 변경은 없습니다. 검증은 명시 순서/이전 Catalog 보존, 잘못된 스키마/SHA/비일반곡·누락/중복/빈 선택 차단, 전곡 VERIFIED 요구와 BLOCKED_EMBED 보존, LOCAL_DEMO·영상 입력 필수 등 새4건을 추가했습니다. 루트 `.venv`에서 `C_LOCAL_DEMO=1`로 `backend.music backend.recommendation.tests` 전체61건(occasion11건)이 메모리 시험 DB에서 통과했습니다. 실제 선택 파일/seed/DB·브라우저 실행은 통합 담당의 별도 근거를 확인합니다.
