## 기준과 확인한 수령 문서

제품 기준은 [사용자 흐름](../product/카페_음악_서비스_기능_및_사용자_흐름_정리.md), [구현 설계도](../product/카페_음악_서비스_구현_설계도.md), [후보 산출 가이드](../product/카페_음악_추천_서비스_3차_컬럼_기반_추천_로직_가이드.md), [구현 태스크](../product/카페_음악_추천_서비스_3차_구현_태스크.md)의 별도 작업자·소유/멱등·lease·부모 보존과 ON/OFF/176~184분 계약입니다. 사용자 결정은 여러 사용자의 추천 요청을 여러 워커/서버로 배분하는 방식입니다. 한 요청의 계산을 Spark로 분할하거나 점수·후보·날씨 정책을 바꾸지 않습니다.

수령 원문은 기준 커밋의 다음 파일을 확인하고 보존했습니다.

- `docs/handoff/infra/local infra guide.md`: PC3대/VM9대·Kafka/Spark/ES3대씩과 관리 접속 구조.
- `docs/handoff/infra/AWS 인프라 구축 계획.md`: Control t3.large 2대/각8GiB, PG t3.small 1대, 전체14대 계획.

실제 통합 코드는 Django/DRF이며 `backend.cafe.asgi:application`을 사용합니다. 이 차이는 새 실행 인계에 기록하고 수령 원문의 FastAPI 표기를 수정하지 않았습니다. 현재 코드의 ASGI 서버를 Uvicorn0.54.0으로 잠금했으며 실제 프레임워크/실행 argv·설정/lock 해시는 INF 앱 계약에 인계합니다. 실제 AWS 인스턴스 수나 연결 상태를 새로 조회하지 않았습니다.

## 변경 전후와 실제 호출·저장 흐름

변경 전 `run_recommendations`는 rule/Gemini를 구분하지 않고 한 프로세스에서 순서대로 실행했습니다. 기존 PG 선점/30초 lease/heartbeat/결과 token 검사는 있었지만 Gemini의 서버 간 한도·전용 큐·전역 대기 상한·worker 식별/종료 drain·큐 상태 점검은 없었습니다.

변경 후 API는 기존 소유·멱등/Family 트랜잭션 안에서 `dispatch.admit(method)`로 종류별 대기 상한을 확인하고 Job/outbox를 저장합니다. `--queue rule` 워커 두 개가 `SKIP LOCKED`로 서로 다른 작업을 점유합니다. `--queue gemini`는 같은 PG의 `DispatchControl` 짧은 행 잠금으로 동시 점유를 제한합니다. `begin_provider`가 lease/token을 다시 확인한 뒤 최소 시작 간격·provider 예약을 저장하고 DB 잠금을 해제한 다음 외부 호출을 수행합니다. 기본 추천 작업자가 Gemini 응답을 기다리지 않습니다.

정상 외부 응답은 예약을 해제합니다. 불확실한 실패는 timeout+lease 유예까지 예약을 유지하고 자동 재호출하지 않습니다. 정상 결과/실패 갱신은 현재 lease/token/generation에만 적용합니다. 결과·이벤트·Job 성공은 기존 원자 트랜잭션과 Playlist.job 1:1을 유지합니다. 종료 신호는 신규 claim을 멈추고 현재 작업을 drain하며 강제 중단은 lease 기반 회수로 처리합니다. heartbeat 갱신은 한 점유의 job timeout을 넘기지 않습니다. 이 timeout은 진행 중 CPU 함수를 즉시 죽이는 기능이 아닙니다.

## API·인증·송수신 계약

- 기본/재설정의 요청 본문·소유/익명 쿠키·멱등키·202 응답·poll URL·결과/승인·부모 보존은 동일합니다. queue/worker/provider 예약 필드는 서버 내부 필드입니다.
- 추가 오류는 접수 시 HTTP503 `RECOMMENDATION_QUEUE_FULL` / “추천 요청이 많아요. 잠시 후 다시 시도해 주세요.”입니다. details는 queue/retry_after_seconds만 포함하며 나중에 같은 멱등키로 재시도할 수 있습니다. 실패 접수는 성공 멱등 응답이나 outbox 이벤트를 남기지 않습니다.
- 워커 사망 후 외부 호출 여부가 불명확하면 자동 Gemini 재호출 없이 기존 `PROVIDER_OUTCOME_UNKNOWN`을 사용합니다. 기본 후보 부족·탐색 미완료·NO_MEANINGFUL_CHANGE 의미를 바꾸지 않습니다.
- A/B API → PG 업무 Job/outbox → 종류별 워커 → PG Playlist/Job. Gemini만 외부 제공자를 호출하며 제한은 같은 PG를 사용하는 앱 범위입니다. Kafka/Spark는 기존 데이터 파이프라인이며 이 추천 Job 큐로 바꾸지 않습니다.
- 주고받을 값은 공유 DB/TLS·같은 코드/카탈로그·worker ID·queue/한도·private bind·실행 경로/lock·종료 예산입니다. 키/비밀번호/DSN 값은 이 문서나 Git에 기록하지 않습니다.
