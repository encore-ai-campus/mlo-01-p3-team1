- 작성일: 2026-10-15
- 수정일: 2026-10-15
- 브랜치: `feature/ad-logic`
- 구현 범위: 공개 API·광고 선정·배달 재확인·이미지 조회·측정 판정과 MongoDB 원자 저장입니다.

## 2026-10-15 광고 로그 MongoDB 독립 관리

최신 사용자 결정으로 광고 관리·측정·소진 로그는 광고 MongoDB에 저장합니다. PostgreSQL 전달과 공통 로그 테이블 규격은 사용하지 않습니다. 새 `log_record`와 기존 기록 보존·점검/스키마 적용은 [광고 로그 저장 계약](MongoDB_광고_로그_저장_계약.md)을 따릅니다. 관리3+공개5+정책2 구조와 공유 ADMIN/guest 인증 경계는 유지합니다.

### 1.1. 공개 HTTP 연결

| 경로 | 입력 | 동작 |
|---|---|---|
| `GET /api/ads` | 필수 placement, 선택 delivery_id; 재확인은 `X-Ad-Delivery-Token`, 신규 재전송은 선택 `Idempotency-Key` | 새 배달 또는 같은 배달의 현재 자격 재확인 |
| `POST /api/ad-events` | event_id·delivery_id·event_type·occurred_at; 필수 `X-Ad-Delivery-Token` | 최초 판정 응답과 원자 저장; 같은 요청 재전송은 저장 응답 |
| `GET /api/ad-deliveries/{delivery_id}/image` | delivery_token query | 배달 proof·현재 게시 자격을 확인한 이미지 원본 |

응답은 `no-store`, `Referrer-Policy: no-referrer`를 사용합니다. 이미지 URL의 proof는 광고 이미지 읽기 자료이며
공유 계정/guest 쿠키가 아닙니다. 이미지 읽기는 guest를 새로 발급하지 않습니다. 측정 POST는 JSON 해석 전에
Origin/CSRF를 확인합니다. 공개 응답과 로그에 원본 guest 쿠키·서명키·내부 이미지 바이트를 넣지 않습니다.

### 1.2. 운영 연결 전 필수 설정

| 설정 | 서버 계약 |
|---|---|
| `ADS_GUEST_CONTEXT_PROVIDER` | `(django_request, bootstrap=bool)` → `api.ads_public_auth.PublicGuestContext`; 검증한 owner_guest_id 또는 null·측정 가능 bool·선택 response_finalizer |
| `ADS_PUBLIC_POLICY_PROVIDER` | 인자 없는 callable → `AdsPublicPolicy(version, delivery_ttl_seconds, budget_eligible, open_delivery_eligible, occurrence_eligible, split_deadlines=False, cap_at_midnight=False, check_budget_history=False)` |
| `ADS_DELIVERY_SIGNING_KEY` | 서버 전용 배달 HMAC 서명키; 실제 값은 추적하지 않는 환경 설정 |
| `ADS_PUBLIC_BASE_URL` | 배달 이미지 주소를 만들 실제 절대 HTTPS 공개 주소 |

공개 조회·측정의 guest provider가 없거나 실패하면 `GUEST_UNAVAILABLE`/503입니다. 정책·서명·주소가 미설정이거나
자격 callback이 bool을 반환하지 않으면 `ADS_POLICY_UNAVAILABLE`/503으로 차단합니다. DB 장애도 503이며
미확인 자격을 허용으로 바꾸지 않습니다. 이미지 조회는 guest provider 없이 proof와 정책을 확인합니다.

정책 callback은 `budget_eligible(repository, ad, now)`, `open_delivery_eligible(delivery, current_ad, now)`,
`occurrence_eligible(delivery, historical_ad, occurred_at)`입니다. MongoDB 트랜잭션 안에서 재실행될 수 있으므로
외부 API·PostgreSQL·파일·네트워크 I/O를 수행하지 않고 순수 계산 또는 같은 광고 저장소 읽기로 판정합니다.
guest 확인은 업무 트랜잭션 밖에서 수행하며 광고 로그는 MongoDB 업무 트랜잭션에 함께 저장합니다.

### 1.3. 사용자 확정 정책과 기존 기록 호환성

현재 [정책 결정 가이드](./광고_미정_정책_결정_가이드.md#2026-10-15-사용자-답변-반영)는 배달30분·표시/보고 분리·소재 수정 처리·통계/예산 검증 모두5분·수동 paused 유지로 확정했습니다. 캠페인 자동 종료는 소진 또는 게시 기간 끝이며 배달 만료는 재발급 기준입니다.

`domains.ads.runtime_policy.get_public_policy`를 ADS_PUBLIC_POLICY_PROVIDER에 명시 연결합니다. `.env.example`에는 이 선택 경로를 기록했고 실제 `.env`/공유 guest·서명키·HTTPS 주소 연결은 운영 담당 인계입니다. provider는1800초·split_deadlines=True·check_budget_history=True·cap_at_midnight=False를 반환합니다. 단순 `AdsPublicPolicy`의 False 기본은 legacy fixture 호환용이지 현재 운영 정책이 아닙니다.

`delivery_policy.delivery_deadlines`가 광고 종료에 맞춘 표시 마감과 추가300초 보고 마감을 계산합니다. 신규 delivery의 display_expires_at은 표시 마감, event_expires_at은 보고 마감입니다. 서명·이미지/재확인·occurred_at 검사에 이를 사용합니다. 자정 단축은 기본 False이며 기존 발생일 KST 정렬을 별도 경계값 승인으로 해석하지 않습니다. 제목/이미지/링크가 바뀌면 옛 소재 새 표시/변경 이후 발생을 차단하고 변경 전 당시 유효 발생은300초 내 검사합니다.

과거 단일 마감 delivery는 기존 수명/서명으로 읽으며30분으로 늘리지 않습니다. 신규 운영 배달에는 선택 budget_policy_version과 서명을 추가하고 marker 없는 기존 배달에 예산 이력 정책을 소급하지 않습니다. 같은 event_id 원응답도 보존합니다.

5분 원장 검증에서 spent>=일일 또는 전체 예산이면 budget_version별 최초 cutoff를 고정합니다. 이 시각부터 신규/재확인/이미지를 막고 occurred_at < cutoff 유효 발생만300초 지연 내 초과 인정합니다. 경계 이상은 제외합니다. 잔여23/20 최소 조건·예약은 없으므로 다음 검사 전 초과할 수 있습니다. 상태 누락은 부적격,300초 초과 stale/future/형식 오류는503이며 캠페인 종료가 아닙니다.

관리 입력은 daily_budget_tokens/total_budget_tokens 양의 int64 선택 쌍이며 null은 거부합니다. 미설정 광고는 운영 부적격이고 금액 기본값은 없습니다. 실제 값 변경에만 새 budget_version UUID를 만들며 새 검증 후 재제공합니다. paused는 예산/일정 편집이나 다음날에도 자동 해제하지 않습니다. 제목/priority 상세·미사용asset7일·재개API/권한·장기보관은 별도입니다.

## 2. 선정과 표시 상한

`AdCandidate`는 서버의 광고·소재·예산 판정을 담습니다. ID·위치·int64 priority·명시 bool·
시간대/밀리초·기간을 검사합니다. `budget_eligible`은 필수 bool이며 None을 허용으로 바꾸지 않습니다.
예산 금액이나 운영 지연 정책은 이 DTO가 결정하지 않습니다.

`select_ad`는 다음 순서로 결정합니다.

1. 같은 placement·서버 환경, `starts_at <= now < ends_at`, 중단 아님, 소재/예산 적격인 후보를 남깁니다.
2. 가장 높은 priority만 남기고 ad_id를 Unicode 코드 포인트 순으로 정렬합니다.
3. 해당 위치의 마지막 ID보다 큰 첫 후보를 고르며, 없으면 첫 ID로 순환합니다.
4. 광고가 없으면 기존 커서를 유지합니다. 순수 계산에서 `advance_cursor=False`이면 커서를 유지합니다.

`RotationCursor`는 top/bottom을 구분합니다. 기존 delivery 재확인은 해당 배달의 snapshot을
검사합니다. public_service의 재확인은 같은 배달·proof를 검증하고 현재 광고와 정책을 읽습니다.
신규 요청의 동일 소유/위치/환경·멱등키 재전송은 저장된 최초 응답을 반환하며 커서를 진행하지 않습니다.

`cursor_changed`는 마지막 ID 값의 변경만 나타냅니다. 단일 후보를 다시 고르면 False여도
새 delivery를 발급하는 트랜잭션의 커서/version 경합 검사를 생략하면 안 됩니다.

`display_valid_until`은 `min(evaluated_at + 3초, ends_at, 전달한 배달 표시 마감)`을 계산합니다.
종료/만료이면 None입니다. 서비스는 새 분리 형식에서 display_expires_at, 기존 형식에서는 event_expires_at을
그 상한으로 전달합니다. 30분 배달 수명이 매 응답의 3초 표시 lease나 캠페인 게시 기간을 대신하지 않습니다.
재확인에는 배달 당시 종료와 현재 광고 종료 중 이른 값을 사용하므로 관리자가 종료를 앞당겨도 표시 기한에
반영됩니다. 서버의 현재 primary 조회·실제 광고 문서 잠금은 연결했으며, 1초 재확인·브라우저 왕복시간 차감과
통신 실패/기한 만료 숨김은 공개 화면 담당자의 연결·실제 브라우저 검증이 필요합니다.

## 3. 측정 입력과 서버 문맥

`validate_event_input`의 현재 도메인 본문은 event_id·delivery_id·event_type·occurred_at입니다.
event_type은 VIEWABLE_IMPRESSION/CLICK입니다. owner/ad/소재/위치/count/token/is_test·태그는
클라이언트 입력으로 허용하지 않습니다. 배달 검증 자료는 `X-Ad-Delivery-Token` 헤더로 별도 전달합니다.

`DeliveryContext`에는 서버가 검증한 guest/ad/creative/placement·issued_at·당시 기간/중단시각·
is_test와 선택 display_expires_at이 들어갑니다. 현재 편집값으로 과거 유효 구간을 덮지 않습니다.
`judge_event`의 다음 입력도 반드시 서버에서 얻어야 합니다.

| 입력 | 의미 |
|---|---|
| owner_guest_id | 공유 서비스에서 검증한 요청자 내부 ID 또는 쿠키 불가 시 null. 광고 계정/쿠키 원본을 생성하지 않음 |
| delivery_valid | 최종 수명·서명/배달 유효성 검사 결과. 3초/300초/90일로 TTL을 대체하지 않음 |
| occurrence_eligible | 당시 소재/게시 자격의 추가 이력 검사. 현재 provider가 소재 이력을 검사하며 공유 환경 활성화는 별도 |
| measurement_available | 측정 문맥·운영 보고 이용 가능 여부. 미리보기/예시 등 제외 조건도 이 경계에서 확인 |
| delivery_type_consumed | 이 delivery/type의 최초 유효 처리가 이미 소비됐는지 |
| last_accepted_at | `repeat_key(delivery, event_type)`에 속한 마지막 서버 인정 시각 또는 None |
| recorded_event | 요청자 소유의 같은 event_id 최초 요청/판정. 없으면 None |

bool은 필수 명시값이며 숫자/None을 받지 않습니다. 유효 배달/당시 자격을 모르는 상태를
True로 넘겨 성공 제공하는 운영 어댑터를 만들면 안 됩니다.
실제 50%·연속 1초·이미지 로딩·활성 탭과 사용자 클릭은 브라우저 연결에서 검증합니다.

## 4. 최초 판정과 재전송

- 같은 event_id/정규 본문은 최초 decision을 반환합니다. 수신/처리/인정 시각과 단가를 재산출하지 않습니다.
- 다른 본문이면409, 다른 guest/배달이면404입니다. 입력 형태/금지 필드는422입니다.
- 새 보고의 미래 시각·수신 지연300초 초과는 제외합니다. 정확히300초는 검사합니다.
- issued_at 이전, 당시 기간 밖, 중단시각 이후, delivery/당시 자격 실패는 DELIVERY_INVALID입니다.
- 분리 형식의 표시 마감 이후 발생은 보고 유예 중이어도 제외합니다. 표시 마감 전 발생한 보고는 수신 지연300초와 보고 마감을 함께 검사합니다.
- 이미 소비된 delivery/type은 DELIVERY_DUPLICATE입니다.
- 같은 guest/ad/placement/type의 서버 accepted_at부터 노출60초·클릭300초 미만은 REPEAT_SUPPRESSED입니다.
- 정확한 반복 경계부터 COUNTED이며 새 accepted_at은 최초 처리의 서버 processed_at입니다.
- COUNTED와 REPEAT_SUPPRESSED만 delivery/type을 소비합니다. 억제/중복/재전송은 반복 창을 연장하지 않습니다.

`MeasurementOutcome`은 최초 응답 decision과 **이번 처리의 상태 변경 지시**를 분리합니다.
재전송은 같은 decision이어도 consume_delivery_type=False/new_accepted_at=None이므로
과거 claim/창을 다시 적용하지 않습니다. 원본 판정·claim·반복 창·인정 시 예상 항목·MongoDB 내장 로그는
public_service와 MongoDB 트랜잭션으로 함께 저장합니다. 고유키 또는 CAS 경합은 새 snapshot에서
최초 기록을 다시 확인하고, 부분 저장에는 성공 응답을 반환하지 않습니다.

테스트 delivery 또는 측정 불가 보고는 MEASUREMENT_UNAVAILABLE·운영 예상량0입니다.
발생일은 occurred_at의 KST 날짜입니다. KST로 표현할 수 없는 극단 미래 날짜는 제외 응답을
유지하고 metric_date_kst=None으로 둡니다. 정상 인정 항목은 표현 가능한 집계일이 필요합니다.

## 5. 공개 상태 컬렉션과 원자 저장

인정 노출은 top8/bottom5, 인정 클릭은15입니다. 조기 클릭15, 노출 후 클릭 top23/bottom20이며
클릭이 노출을 자동 추가하지 않습니다. 미인정은0입니다. 실제 잔액 차감은 없습니다.
인정 항목만 `ad_estimated_usage_ledger`에 불변 예상값으로 저장합니다.5분 주기 집계/검증을 연결했으며 실시간 대시보드·실제 잔액 차감은 추가하지 않습니다.

| 추가 컬렉션 | 저장 역할 |
|---|---|
| `ad_rotation_state` | top/bottom·환경별 마지막 선정 ID와 revision CAS |
| `ad_deliveries` | 불변 광고 snapshot·명시 이벤트 만료·proof hash·원응답·내장 유형별 claims·마지막 사용/신규 수신 |
| `ad_events` | event_id 최초 판정·정규 요청/원응답·발생/수신/처리·KST 집계일·내장 log_record |
| `ad_repeat_windows` | guest/ad/placement/type/환경별 마지막 인정 시각과 revision CAS |
| `ad_estimated_usage_ledger` | 인정 event_id 고유 예상 항목·당시 단가/정책·`ESTIMATED` 상태 |
| `ad_budget_states` | budget_version별 검증/최초 cutoff·소진 내장 log_record |
| `ad_daily_metrics` | KST일/광고별 원장 재계산 교체·집계 기준시각 |

공개 데이터의 기술 스키마 버전은 `phase3-ads-public-20261015.2`입니다. 관리 데이터 버전·단가 정책 버전·
연결되는 운영 정책 버전을 별도로 유지합니다. 실제 BSON 타입과 required 필드는 public_manifest가 기준입니다.
`claims`는 delivery 내부이고 측정 내장 로그 저장는 event 내부입니다. 별도 claim/outbox/ad_versions 컬렉션은 없습니다.
과거 자격은 `ad_admin_changes.after_snapshot`에서 발생시각 이하의 최신 시각/version을 찾아 판정합니다.

새 배달은 광고 문서의 version 잠금·순환 revision·배달 저장을 한 번에 커밋합니다. 동일 문서 잠금도 실제 쓰기와
복원을 하여 관리자 수정/중단과 직렬화하며 최종 업무 version은 불필요하게 증가시키지 않습니다. 관리자 수정/중단의
적용 시각은 잠금 이후 트랜잭션 안에서 정하여 요청 대기 시각을 과거 중단 이력으로 소급하지 않습니다.
이는 업무 효력 시각이며 MongoDB의 물리적인 commit timestamp를 기록한 값은 아닙니다.
유효 판정은 claim·반복 창·event·예상 항목·MongoDB 내장 로그를 같은 트랜잭션으로 확정합니다.
이벤트 재전송은 원래 수신/처리/단가·응답을 보존하고 마지막 수신 시각도 연장하지 않습니다.

광고 관리·측정·최초 소진 로그는 각 MongoDB 업무 문서의 log_record에 원자 저장합니다. 공통 SQL 로그 테이블과 외부 전달 hook은 사용하지 않습니다. check_ads_logs는 기존 기록을 변경하지 않고 건수/제한 표본의 hash를 점검합니다.
측정 원본은 received_at부터 90일, 예상 원장은 processed_at부터 365일인 기존 보관 기준을 유지합니다.
감사/보관·배달/이미지 참조 보호를 포함한 정리 작업은 미구현이므로 삭제 예정 시각을 계산하지 않고
`retention_due_at=null`로 둡니다. 자동 TTL 삭제도 설정하지 않습니다.

정책 스키마 `phase3-ads-policy-20261015.2`은 policy_manifest에 정의하며 apply_ads_policy_schema 기본은 dry-run, --apply는 loopback `_dev`/primary에 제한합니다. refresh_ads_policy 기본1회, --watch는300초 시작 간격입니다. 통계는 범위 재계산 교체이며 summary는 오늘, 목록 행 measurement는 보존 범위 누적입니다. as_of·aggregation_status·coverage·coverage_from/coverage_through·is_stale로 미연결/PENDING·지연·실제0을 구분합니다.

남은 연결은 실제 watch 상시 실행·공유 guest/서명/주소·브라우저 가시성/3초 숨김·AWS/복구입니다.
AD-02/04/05/06의 기존 직접 선행과 완료 조건을 변경하지 않습니다.

## 6. 재현과 검증 범위

후속 [남은 작업·연결 계획](./광고_남은_작업과_연결_계획.md)의 `run_ads_workers`는 기존
예산/통계를 반복/재시도하고 `check_ads_runtime`은 설정·스키마·MongoDB 로그를
읽기만 합니다. 단일 예산 명령도 유지하며 이번 운영 보완이 공유 인증의 실연결이나
정식 화면·운영 배포 완료를 뜻하지 않습니다.

ad-server/backend에서 실행합니다.

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe manage.py apply_ads_public_schema
.\.venv\Scripts\python.exe manage.py apply_ads_policy_schema
.\.venv\Scripts\python.exe manage.py test tests --verbosity 1
```

규칙·서비스·HTTP·저장 어댑터 검증과 선택 실행형 실제 replica set 시험을 분리합니다. 실행 결과와 미실행은
[검증 기록](../../acceptance/광고_개발_준비_검증.md), AST 코드별 문서는
[라우팅 색인](../../backend-routing/README.md)을 따릅니다. 실제 운영 API/DB/브라우저 완료 근거와 구분합니다.
