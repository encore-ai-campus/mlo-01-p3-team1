## 2026-10-16 로컬 광고 프레젠테이션

최신 사용자 요청으로 저장소 시안을 참고한 로컬 광고 제어 화면을 구성하고
HTML·CSS·문구·브라우저 동작을 분리했습니다. 개발 총괄의 수정 위치와 이식 경계는
[프레젠테이션 수정 가이드](./광고_로컬_화면과_프레젠테이션_수정_가이드.md)를
따릅니다. 이번 예외는 기존 sandbox·시험 DB 범위이며 정식 관리자·공유 인증·운영 연결의
완료와 구분합니다. 광고 정책·태스크 ID/직접 선행 관계는 유지합니다.

## 2026-10-15 광고 로그 MongoDB 독립 관리

최신 사용자 결정으로 광고 관리·측정·소진 로그는 광고 MongoDB에 저장합니다. PostgreSQL 전달과 공통 로그 테이블 규격은 사용하지 않습니다. 새 `log_record`와 기존 기록 보존·점검/스키마 적용은 [광고 로그 저장 계약](MongoDB_광고_로그_저장_계약.md)을 따릅니다. 관리3+공개5+정책2 구조와 공유 ADMIN/guest 인증 경계는 유지합니다.

## 1. 사용할 범위

이 도구는 광고 서버의 기존 관리 API를 확인하는 로컬 개발 화면입니다. 정식 React 관리자 `/admin/ads`·공통 로그인·공유 ADMIN/guest·MongoDB 광고 로그 저장의 완료를 뜻하지 않습니다. 음악 관리·피드백 화면이나 팀 공통 프론트엔드 라우팅을 변경하지 않습니다.

사용자 요청에 따라 기존 ‘관리자 화면 제외’ 범위에 이 로컬 확인 도구만 예외로 추가합니다. [공통 개발 계약](../../product/3차_공통_개발_계약과_검증_기준.md)의 정식 React 관리자 기준과 [ADS 인계](../../handoff/ads/README.md)의 운영 경계는 유지합니다.

| 확인할 기능 | 연결과 제한 |
|---|---|
| 광고 목록·필터·요약 | 기존 관리 API의 위치/상태·오늘 요약·광고별 보존 범위 누적을 표시 |
| 이미지·광고 등록/수정 | 기존 이미지 검사·단일 위치·기간·우선순위·선택 예산 쌍·version/멱등 계약을 사용 |
| 게시 중단·미리보기 | 중단 후 단순 수정은 STOPPED 유지, PC/모바일 미리보기는 운영 측정에서 제외 |
| 예산 검증·통계 | 5분 반복 작업과 명시 수동 갱신으로 기존 원장 재계산·최초 소진 cutoff를 확인 |
| 공개 배달·측정 요청 | 별도 개발 문맥으로 요청/응답과 차단 상태를 확인. is_test=true 보고는 MEASUREMENT_UNAVAILABLE·운영 카운트0 |
| 로그 상태 | MongoDB log_record 원자 저장. 기존 log_relay 기록은 보존 |

예산은 사용자가 직접 입력하는 양의 int64 두 값이며 실제 운영 기본값을 만들지 않습니다. 예산 변경 후 새 budget_version을 검증해야 공개 자격이 생기며 수동 paused는 풀리지 않습니다. 재개/삭제·실제 구매/차감/환불·업종/태그 매칭은 추가하지 않습니다. 제목100자·priority100·미사용asset7일 같은 미승인 수치도 적용하지 않습니다.

임시 도구의 `is_test=true` 배달/이벤트는 기존 측정 제외 정책을 그대로 적용합니다. 클릭·노출 요청을 시험해도 운영 카운트/예상 토큰은0이며, 예산 검증을 반복해도 이 요청으로 한도가 소진되지는 않습니다. 운영 flag를 우회하거나 가짜 원장을 주입하지 않습니다. 소진/cutoff·확인 전 초과 인정의 검증 근거는 [기존 MongoDB 통합 시험](../../acceptance/광고_개발_준비_검증.md)과 구분합니다.

## 2. 분리 실행과 접속

저장소 루트의 PowerShell에서 사용하는 진입점입니다. 아래 명령의 실제 실행 결과와 실행 가능 여부는 검증 기록을 함께 확인합니다.

```powershell
.\ad-server\backend\.venv\Scripts\python.exe .\ad-server\backend\sandbox.py --start-mongo
```

`--start-mongo`는 로컬 `.tools/mongodb-test/mongod.exe`가 있을 때 전용 loopback MongoDB 프로세스를 시작하는 선택 기능입니다. 일반 공유 MongoDB·AWS에 접속하기 위한 옵션이 아닙니다. 전용 replica set과 광고 스키마를 준비하는 절차의 오류가 있으면 화면을 성공 상태로 꾸미지 않습니다. 이미 준비된 개발 DB를 사용하는 연결 방식은 실제 구현/검증된 설정만 따릅니다.

1. 도구는 `config.sandbox_settings`와 `config.sandbox_urls`를 사용하며 기존 `backend/.env`를 읽지 않습니다.
2. API와 화면은 `127.0.0.1:8001`에서 실행합니다. Edge 또는 Chrome의 주소창에 `http://127.0.0.1:8001/dev/ads/`를 직접 입력해 엽니다.
3. 매 실행의 무작위 접근 코드는 Git에서 제외한 `.local/ads-sandbox/access.txt`에서 확인합니다. 코드 파일이나 화면의 인증 자료를 저장소/공유 문서에 복사하지 않습니다.
4. 별도 `ads_sandbox_dev` DB·서버의 `is_test=true`를 사용합니다. 로컬 접근 확인과 개발 guest는 공유 계정/세션·PostgreSQL 검증이 아닙니다.
5. 종료는 실행 터미널의 Ctrl+C입니다. 도구가 직접 시작한 MongoDB 프로세스만 종료하고, 기존에 실행 중인 다른 DB는 종료하지 않습니다.

로컬 HTTP는 이 확인 도구의 실행 범위입니다. 본 서비스의 HTTPS·Origin/CSRF·공유 인증 규정을 대체하지 않습니다. 개발 전용 guard와 로그인·상태/갱신 경로는 `/dev/ads/` 아래에만 연결하며 일반 서버 URLconf에는 추가하지 않습니다.

2026-10-16 로그인403의 원인을 정정했습니다. 기존 `no-referrer` HTTP 헤더/HTML meta가
일반 로그인 폼의 Origin을 null로 만들던 충돌을 로컬 `same-origin` 설정으로 수정했습니다.
내장 브라우저에서 실제 로그인·편집 불러오기·미리보기·수동 예산 검증까지 확인했습니다.
CSRF/Origin·loopback 검사는 유지하며 null/외부 Origin을 허용하지 않습니다.
오류 화면에서는 `/dev/ads/`로 다시 진입하고 재시작된 서버의 access.txt 코드를 사용합니다.
자세한 수정/검증 경계는 [프레젠테이션 가이드](./광고_로컬_화면과_프레젠테이션_수정_가이드.md)를 따릅니다.

## 3. 확인 순서

1. 접근 코드를 사용해 로컬 도구를 연 뒤 개발 DB/테스트 모드·배치 상태를 확인합니다.
2. 정적 WebP/JPEG/PNG 이미지를 업로드하고 제목·절대 HTTPS 링크·top/bottom 하나·KST 시작/종료·우선순위를 입력해 광고를 저장합니다. 두 위치는 별도 광고 기록으로 만듭니다.
3. 운영 후보 자격까지 확인하려면 일일/전체 예산을 함께 입력합니다. 미설정 광고는 저장할 수 있지만 공개 부적격이며 가짜 예산을 자동으로 넣지 않습니다.
4. 수동 예산 검증/통계 갱신 또는 5분 작업 후 상태와 집계 시각·coverage를 확인합니다. 미집계/PENDING과 실제0을 구분합니다.
5. 수정 시 최신 version을 사용하고 저장 충돌·이미지/기간/URL 오류를 확인합니다. 예산 실변경 후에는 새 검증을 수행합니다.
6. 공개 배달과 이벤트 요청은 개발 시험으로 확인합니다. is_test=true의 MEASUREMENT_UNAVAILABLE·counted=false와 운영 카운트0이 정상이며, 임시 도구에서 소진을 만들기 위해 성공값/원장을 주입하지 않습니다. 실제 운영 소진·반복/배달 중복·cutoff는 별도 통합 시험의 근거로 확인합니다.
7. 게시 중단 후 수정해도 STOPPED가 유지되는지 확인합니다. 미리보기·새로고침·로그아웃만으로 운영 노출·클릭이나 재게시를 만들지 않습니다.

서버 정책은 표시30분/보고+300초·통계/예산5분·소진 확인 전 유효 발생의300초 내 초과 인정입니다. 자동 종료는 소진/게시 기간이며 수동 중단은 별도입니다. 수동 갱신은 개발 확인 동작이며 본 서비스의 5분 규정을 바꾸지 않습니다.

## 4. 코드 연결과 남은 작업

| 경로 | 역할 |
|---|---|
| `ad-server/backend/sandbox.py` | 기존 `.env`와 분리한 실행 진입점 |
| `config/sandbox_settings.py`, `config/sandbox_urls.py` | 개발 설정·전용 URL 등록 |
| `api/ads_sandbox.py` | 개발 guard·접근 확인·guest·상태/수동 갱신 |
| `ad-server/backend/domains/ads/sandbox_runtime.py` | 개발 guard·5분 작업·수동 갱신과 현재 프로세스 상태 |
| `ad-server/backend/domains/ads/management/commands/run_ads_sandbox.py` | 전용 MongoDB/HTTP 프로세스·스키마와 작업의 시작/종료 |

정확한 파일/함수 연결은 [라우팅 색인](../../backend-routing/README.md)을 따릅니다. 코드 경로 표는 개발 도구 연결을 설명하며 실행 검증 통과 표가 아닙니다.

로컬 도구로는 정식 프론트엔드의 50%/연속1초 가시성·배경 탭·하단 스크롤·중단3초를 실제 서비스와 통합했다고 판단하지 않습니다. 공유 ADMIN/guest·AWS 라우팅/TLS·운영 상시 프로세스·보관/복구와 정식 관리자 화면은 담당자 연결과 별도 검증이 남습니다. 로그 PENDING을 임의 SENT로 바꾸거나 운영 자료를 삭제해 정상으로 보이게 하지 않습니다.

기존 광고 서버 구현은 `cffbb2c`에 커밋·푸시한 뒤 이 도구 작업을 시작했습니다. 도구와 후속 문서는 같은 `feature/ad-logic`의 별도 커밋으로 관리하며, 원격 반영은 실제 푸시 성공을 기준으로 확인합니다.
