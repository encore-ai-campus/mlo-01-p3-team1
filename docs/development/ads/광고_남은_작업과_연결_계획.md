# 광고 로직 — 남은 작업과 연결 순서

- 작성일: 2026-10-15
- 수정일: 2026-10-16
- 브랜치: `feature/ad-logic`
- 최신 결정: 광고 로그까지 MongoDB에서 관리하며 PostgreSQL 연결·공통 로그 테이블 규격은 사용하지 않습니다.


## 2026-10-16 로컬 광고 프레젠테이션

최신 사용자 요청으로 저장소 시안을 참고한 로컬 광고 제어 화면을 구성하고
HTML·CSS·문구·브라우저 동작을 분리했습니다. 개발 총괄의 수정 위치와 이식 경계는
[프레젠테이션 수정 가이드](./광고_로컬_화면과_프레젠테이션_수정_가이드.md)를
따릅니다. 이번 예외는 기존 sandbox·시험 DB 범위이며 정식 관리자·공유 인증·운영 연결의
완료와 구분합니다. 광고 정책·태스크 ID/직접 선행 관계는 유지합니다.

## 1. 구현한 범위

관리 API·이미지 Binary·등록/수정/수동 중단·version/멱등/감사, 공개 선정·배달·이미지,
노출/클릭 최초 판정·중복/반복 제한·원자 저장,5분 통계/예산·최초 cutoff를 구현했습니다.
30분 배달·300초 보고·검증 이전 유효 초과 인정·수동 중단 유지 정책을 적용합니다.
임시 관리 도구는 로컬 시험용이며 정식 화면·공유 인증과 운영 완료를 뜻하지 않습니다.

이번 후속은 MongoDB 내장 `log_record`, 이전 기록 보존, 읽기 점검과 정책 작업 재시도를
추가했습니다. 로그 컬렉션은 늘리지 않았으며 [광고 로그 저장 계약](./MongoDB_광고_로그_저장_계약.md)을 따릅니다.

|---|---|---|

PostgreSQL 광고 로그 sink·공통 로그 테이블 연동은 남은 작업에서 제외합니다.
공유 사용자 DB와 인증 어댑터는 유지하며 광고 MongoDB에 사용자 정보를 복제하지 않습니다.
4차 업종/태그·실제 구매/차감/환불·CTR/고급 조회는 추가하지 않습니다.

## 3. 실행과 점검

`ad-server/backend`에서 실행합니다. 기존 DB는 새 쓰기 전에 manifest 적용이 필요하며
공유/운영 DB 변경을 자동 실행하지 않습니다.

```powershell
# 설정만 점검: DB 미확인이므로 INCOMPLETE/종료코드1
.\.venv\Scripts\python.exe manage.py check_ads_runtime
# primary·10컬렉션 validator/인덱스·광고 로그 읽기 점검
.\.venv\Scripts\python.exe manage.py check_ads_runtime --database
# 신규/기존/누락 건수와 컬렉션별 최대20문서의 hash 점검
.\.venv\Scripts\python.exe manage.py check_ads_logs --limit 20
# 기존 보관 기산점·기간 도래/참조를 제한 표본으로 읽기 점검. 삭제 없음
.\.venv\Scripts\python.exe manage.py check_ads_retention --limit 100
# 정책 작업1회. 실패 시 상태 출력과 종료코드1
.\.venv\Scripts\python.exe manage.py run_ads_workers
# 명시 반복: 예산/통계300초, 오류 후 다음 주기 재시도
.\.venv\Scripts\python.exe manage.py run_ads_workers --watch
```

기존 `refresh_ads_policy` 단발/반복 명령도 유지합니다. 두 정책 프로세스를 일부러 중복 실행할
필요는 없습니다. 새 실행기는 안전한 오류 종류/코드만 출력하고 지난 주기를 연속 재생하지 않습니다.
Ctrl+C·메인 스레드 SIGTERM은 새 반복을 중단하고 최대10초 종료를 기다립니다. 운영 서비스 등록은 별도입니다.
보관 점검·종료/재시작의 상세와 실제 검증 범위는 [실행 인계](../../runbook/광고_보관_점검과_배치_종료.md)를 따릅니다.

로그는 저장 시 이미 MongoDB에 있으므로 전송 대기/ACK 작업이 없습니다. 이전 PENDING/SENT는
과거 기록으로 보존합니다. `CHECKS_PASSED`는 제한된 설정/MongoDB 점검의 통과만 의미하며
`shared_authentication_verified=false`를 유지합니다. 표본 검사를 전수 무결성·운영 복구로 해석하지 않습니다.
