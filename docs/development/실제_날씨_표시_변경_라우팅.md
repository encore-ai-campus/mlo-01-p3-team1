- 작성자/담당: Codex, 현재 실행 앱의 날씨 연결
- 작성일/수정일: 2026-10-16
- 브랜치/기준 커밋: `feature/integration@34711757b1b1c70e4716f8117a65a69251dc733a`
- 범위: W-02/W-06의 실제 기상청 자료 수집·공개 표시·추천 입력 연결. 운영 인프라 전체 구축·검증은 별개입니다.
- 사용자 요청: 목포가 실제로 흐린데 시험 자료를 보여주고 있다는 지적에 따라 현재 실행 앱을 실제 자료로 전환합니다. 수령 원문과 기존 DB/음악·평가 이력은 보존합니다. 커밋·푸시·배포는 수행하지 않습니다.

## 기준 → 변경 전/후

기준은 [현재 날씨 수령 원문](../handoff/weather/received/20261014/05_날씨분류와_계절기준.md), [서비스 통합 라우팅](./서비스_통합_구현_변경_라우팅.md), [구현 설계도](../product/카페_음악_서비스_구현_설계도.md)의 실제 발표/대상/수신 시각·결측·만료·현재 정시 SKY·HTTP 요청마다 외부 API 호출 금지입니다. 해당 문서 자체는 수정하지 않습니다.

변경 전 현재 앱은 `C_LOCAL_DEMO`와 빈 `WEATHER_PROVIDER` 조합으로 목포를 포함한 모든 선택 지역에 기온22℃·6시간 맑음 고정 자료를 반환했습니다. `is_test=true`, `bundle_version=demo-weather-v1`였고 관측 시각도 요청 시각으로 생성했습니다. 지역 목록이 실제 매핑이라는 사실만으로 날씨도 실제라고 볼 수 없었습니다.

변경 후 로컬 앱은 실제 KMA API허브 전국 격자의 관측 PTY/T1H와 예보 PTY/SKY/T1H를 공유 수집합니다. 현재 하늘 상태는 현재 KST 정시를 대상으로 한 SKY이며 실제 관측 구름값이라고 표시하지 않습니다. 실제 원값·단위·상태·발표/대상/수신 시각과 응답 해시를 유지합니다. API 키·인증 URL·원문 바이트는 캐시나 로그에 저장하지 않습니다.

## 실제 코드·설정·호출/저장 흐름

1. [live_cache.py](../../pipeline/weather/live_cache.py)의 `plan/fetch/refresh/main`: 기존 [키 로더](../../pipeline/weather/collect.py)의 비공개 키로 공식 API허브를 조회합니다. 지역별로 API를 호출하지 않고 전국149×253 격자 응답을 공유합니다. 관측은10분 회차, 예보는1시간 회차이며 제공 지연을 고려해 관측10분/예보15분 여유를 둡니다. 동일 회차는 재수집하지 않고1분마다 새 회차를 확인합니다. 인증/요청 한도 오류에는10분 대기합니다.
2. `.local/weather-live/latest.json`: Git 제외된 로컬 **실제 최신 수치 캐시**입니다. 정제된 격자별 항목 값과 출처 메타만 보관하며 원문 파일·장기 이력 저장소가 아닙니다. 원자적 교체로 API/작업자에 같은 자료를 제공합니다. 수신 시각은 실제 응답을 받은 때이고, 단순 캐시 확인을 새 관측으로 표시하지 않습니다.
3. [live.py](../../backend/weather/live.py)의 `document/display/obtain`: 공식 지역 매핑의 nx/ny로 캐시 값을 선택합니다. 기존 정규화·UTC 구간 어댑터·유효성 검사를 사용합니다. `display`는 실제 현재 값과 누락/만료 상태를, `obtain`은 추천 가능한 자료만 반환합니다. HTTP 처리 경로에 KMA 호출은 없습니다. 캐시 부재/누락/만료를 고정 맑음/22℃로 대체하지 않습니다.
4. [settings.py](../../backend/cafe/settings.py): 로컬 비통합 실행의 기본 provider는 `backend.weather.live.obtain`입니다. `KMA_LOCAL_CACHE_PATH`로 캐시를 선택합니다. 통합 운영의 기존 PG/ES provider는 유지합니다. 시험의 고정 자료는 테스트가 `WEATHER_PROVIDER=''`를 명시한 경우에만 사용합니다. 로컬 CSV/평가 DB가 시험 실행이라는 사실과 실제 날씨 출처는 분리합니다.
5. [Weather API](../../backend/recommendation/api.py): 동일 `GET /api/weather?region_id=...`에서 실제 자료의 부분 표시/추천 가능 여부를 제공합니다. 응답은 `is_test=false`, `source=KMA_API_HUB`, 실제 관측·예보 시각과 불변 묶음 버전을 포함합니다. 지역 계층 API도 날씨 provider 여부에 맞춰 시험 여부를 표시합니다.
6. [공개 화면](../../frontend/src/features/recommendation/PublicPage.tsx)·[날씨 패널](../../frontend/src/features/region-weather/WeatherPanel.tsx)·[헤더](../../frontend/src/components/Header.tsx): 로컬 실행에서도30초 주기로 같은 캐시를 조회하고 관측·예보 시각과 기상청 출처를 표시합니다. 실패하면 이전 패널 값을 지우며 만료 현재값을 정상 날씨로 표시하지 않습니다. 실제 자료에는 `날씨 샘플` 문구를 쓰지 않습니다.

## 실행/재시작과 환경 경계

프로젝트 가상환경에서 최초 수집은 `python -m pipeline.weather.live_cache --once`, 지속 갱신은 `python -m pipeline.weather.live_cache`입니다. 기상청 키는 기존 비공개 `pipeline/weather/.env` 또는 프로세스 환경을 사용합니다. 키를 브라우저에 전달하지 않습니다.

현재 실행 API/작업자는 `C_LOCAL_DEMO=1`, `INTEGRATION_ENABLED=0`, `WEATHER_PROVIDER=backend.weather.live.obtain`과 기존 `artifacts/local-demo-edfcd850/demo.sqlite3`를 사용합니다. API19001/화면19073 주소와 기존 CSV 카탈로그·평가 이력을 유지했습니다. 수집기도 백그라운드에서 동작하며, 현재 PID는 Git 제외된 같은 실행 폴더의 runtime.json에서 확인합니다. 기상청 표시 연결에 필요하지 않은 AWS/PG/ES/Kafka 자원을 생성하거나 변경하지 않았습니다.

이 경로는 현재 PC의 실제 날씨 표시를 위한 독립 수집 경로입니다. 정식 Kafka→Spark→ES 운영 연결이 완료됐다는 뜻은 아닙니다. 운영 시에는 기존 `backend.weather.adapter.obtain`과 실제 매핑/ES·수집 환경을 연결해야 하며, 현재 캐시를 장기 운영 저장소나 복구 이력으로 취급하지 않습니다. KIM/SNO 보완은 이 경로에서 수집하지 않으며 해당 값은 생성하지 않습니다.

## 검증·실행 근거

- 실제 API허브 조회: 최초20개 항목·대상 요청 모두 성공, 이후 새 실황 회차2개 성공. 비밀값/인증 URL/원문 미출력입니다.
- 실제 앱 HTTP: 목포 용당1동은23.0℃/SKY3, 하당동은23.5℃/SKY4, 서울 성수1가제1동은22.9℃/SKY1을 반환했습니다. 모두 `is_test=false`, `source=KMA_API_HUB`, 관측16:20·예보발표15:30(2026-10-16 KST)이며 고정 자료 버전이 아닙니다. 관측/예보는 이후 자동 갱신되므로 이 숫자를 고정 기대값으로 사용하지 않습니다.
- 실제 브라우저 [weather-live-smoke.cjs](../../frontend/scripts/weather-live-smoke.cjs): 현재 앱에서 목포 하당동을 선택하고 `흐림 · 23.5°C`, `관측16:20 · 예보15:30 · 기상청`, 실제 출처·추천 가능 판정을 확인했습니다. 근거는 Git 제외 경로 `artifacts/local-demo-edfcd850/live-weather-browser.json`과 `live-weather-mokpo.png`입니다. 추천 생성이나 외부 계정 변경을 수행하지 않았습니다.
- [단위 검사](../../backend/weather/tests.py): 원값/시각 유지·결측/만료·캐시 부재 시 시험 자료 우회 금지·현재 정시 SKY·부분 예보 시 현재 표시/추천 차단을 검사합니다. 고정 자료는 이 격리 검사에서만 사용합니다. Django 검사 파일은 기존 일반 unittest 경로와 분리했습니다.
- 초기 시험 실행의 Django 클래스/초기화 오류를 정상 Django test runner로 수정해 검증했습니다. API/공통 회귀 포함43개와 프론트 TypeScript 검사가 통과했고, 이후 부분 예보 검사를 추가했습니다. 최종 검사 결과는 아래에 기록합니다.

남은 연결은 정식 수집·저장 환경과 해당 환경의 재시작/복구 검증입니다. 현재 실제 날씨 표시 성공을 전체 운영 파이프라인 완료로 보고하지 않습니다.
