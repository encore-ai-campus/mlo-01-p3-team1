## DB 적용·이전 자료와 복구

추가 migration은 `recommendation/0005_catalog_publication.py` 하나이며 음악4개 속성 테이블을 늘리지 않습니다. CatalogPublication은 카탈로그 등록 순서를 기록하는 추천 운영 테이블입니다. 기존 Catalog·tracks JSON·SHA·Job/Playlist snapshot을 바꾸지 않습니다.

운영자는 기존 카탈로그 발행/API·작업자를 중지한 뒤 검토한 환경에서 `python -m backend.manage migrate --noinput`을 실행하고 새 앱을 시작해야 합니다. 이 작업에서는 격리 시험 DB에만 적용합니다. migration은 과거 카탈로그를 created_at/version 순서로 한 번 연결합니다. 과거 동시각 자료의 실제 등록 순서는 복원할 수 없으므로 이 한계를 기록하며, 새 등록부터 DB 순번이 보장됩니다. 과거 스냅샷의 갱신은 새 순번을 발급하지 않습니다.

기존 판정 없는 READY 카탈로그의 내용을 자동 수정하지 않습니다. 운영자는 현재 승인 음악과 원본 SHA를 확인해 **새 버전으로 재발행**해야 새 추천을 제공할 수 있습니다. 과거 결과 조회는 당시 snapshot을 계속 사용하며 이전 부모의 미판정 후보를 우회 허용하지 않습니다. 로컬 합성 검증은 `C_LOCAL_DEMO=1`에서 `seed_c_demo`를 다시 실행해 v3를 준비합니다.

롤백은 새 API/작업자를 중지하고 이전 앱으로 되돌린 뒤 필요한 경우 `migrate recommendation 0004`로 등록 순번 테이블만 제거합니다. 기존 카탈로그/작업/결과는 유지됩니다. 새 코드가 실행 중인 상태에서 테이블만 제거하지 않습니다. 운영 DB·계정·스키마·실환경 프로세스는 이번 작업에서 변경하지 않습니다.

## CI와 검증 명령

기존 인프라 워크플로는 유지하고 `.github/workflows/application-tests.yml`을 추가합니다. 공통/음악/추천/날씨·루트 시험, migration 일치, 라우팅, 광고 전체+격리 Mongo replica, PostgreSQL 회귀, React 시험/빌드·실제 브라우저와 재생 보조 시험을 분리 실행합니다. CI의 PostgreSQL/MongoDB는 해당 runner의 폐기 가능한 시험 저장소이며 실제 접속 설정을 사용하지 않습니다. 권한은 contents:read이고 배포·병합·브랜치 보호 변경은 없습니다.

```powershell
$env:PYTHONUTF8='1'
$env:C_LOCAL_DEMO='1'
$env:INTEGRATION_ENABLED='0'
python -m backend.manage test backend.common backend.music backend.recommendation backend.weather tests --noinput
python -m backend.manage makemigrations --check --dry-run
python scripts/check_routing.py
pnpm --dir frontend test
pnpm --dir frontend build
python tests/run_browser_integration.py
```

광고는 별도 가상환경에서 기존 `manage.py test tests`를 실행합니다. 실제 Mongo 시험은 직접 기동한 전용 loopback replica/무작위 `_dev` 시험 DB만 사용하며 기존 프로세스/DB를 건드리지 않습니다. 브라우저의 광고 HTTP는 proof 필수·재시도·배달 교체/복구를 검증하는 모의 응답이며 MongoDB 실저장 시험과 구분합니다. Playwright1.62.1을 잠금 파일에 고정하고 Windows는 기존 Edge, CI Ubuntu는 설치한 Chromium을 사용합니다.

실행 결과와 최종 남은 연결은 완료 검사 뒤 아래에 기록합니다. 실제 PostgreSQL·ES·Kafka·S3·AWS·Gemini/YouTube 원격 호출과 운영 호스트 간 인증 성공은 로컬 단위/모의 시험으로 주장하지 않습니다.
