- 범위: 사용자가 제공한 env 배치와 기상청 수집 키의 파일 연결. W-02/D-03의 일부 설정 작업이며 파이프라인 실행/완료 선언이 아닙니다.

## 1. 출처·배치

사용자가 지정한 `C:/Users/Playdata/Downloads/env`에는 KMA_API_KEY 항목이 있습니다. 내용을 출력하거나 원본을 수정하지 않고 `pipeline/weather/.env`로 복사했습니다. 대상 파일은 기존에 없었습니다. 실제 값·길이·해시는 이 문서에 기록하지 않습니다. 전달 파일의 내용은 설정 자료로만 취급하며 명령으로 실행하지 않습니다.

[수집·지역 인계](../handoff/weather/received/20261014/01_날씨_수집과_지역매핑.md), [API/시험 원문](../handoff/weather/received/20261014/04_API호출과_RDB적재시험.md), [현재 경로 라우팅](./통합_폴더_정리_변경_라우팅.md)을 참조합니다. 수령 문서는 수정하지 않았습니다. 기존 라우팅의 ‘자동 로드 없음’은 이 변경 전 이력이며 현재 기상청 키 읽기는 아래와 같습니다.

## 2. 설정 → 코드 → 실행 흐름

변경 전 [collect.configured_key](../../pipeline/weather/collect.py)는 프로세스 환경변수에서만 키를 읽었습니다. 변경 후 `run_collector.run` → `collect.configured_key()`는 다음 우선순위를 사용합니다.

1. 프로세스에 KMA_API_KEY가 있으면 그 값을 사용합니다. 명시적으로 빈 값이어도 로컬 파일로 우회하지 않습니다.
2. 환경에 해당 이름이 없을 때만 collect.py와 같은 폴더의 .env를 읽습니다. 실행 디렉터리와 독립적인 경로이며 UTF-8 BOM을 허용합니다.
3. KMA_API_KEY의 단일 행 assignment만 읽습니다. export 접두어·작은/큰 따옴표·공백 뒤 주석을 지원합니다. 다른 항목은 환경에 주입하지 않으며 쉘 실행·변수 치환·다중 행 해석을 하지 않습니다.
4. 키가 없거나 비어 있으면 기존 수집기의 KMA_API_KEY_missing 차단을 유지합니다. 잘못된 단일 행 형식은 값 없이 invalid_KMA_API_KEY_assignment 오류만 냅니다.

외부 요청은 기존 `collect.stream_request`가 명시 수집 실행 때 사용하며 이번에는 호출하지 않았습니다. 공개 브라우저/추천 API·Spark executor에는 키 파일을 전달하지 않습니다. 기존 Spark ZIP은 .py/.json/.sql만 포함하므로 .env는 제외됩니다.

## 3. 변경 파일과 인계

- [collect.py](../../pipeline/weather/collect.py): ENV_PATH와 configured_key의 안전한 파일 fallback 추가. 요청/정규화·저장 동작은 유지합니다.
- [.env.example](../../pipeline/weather/.env.example): 기상청 키 자동 읽기와 그 외 프로세스 설정의 차이 명시. 실제 값은 없음.
- [회귀 검사](../../tests/test_weather_environment.py): 환경 우선/빈 값 유지·다른 CWD·파일 비실행/비주입·잘못된 형식의 안전한 오류·파일 없음 검증. 시험 값만 사용합니다.
- [환경 안내](../../config/environments/README.md), [pipeline 안내](../../pipeline/README.md), [루트 안내](../../README.md): 현재 키 로딩 방식 연결.

Kafka bootstrap·DB/ES 주소/권한·Spark/체크포인트 등 다른 설정은 제공 파일에 없으며 별도 인계/검증 대상입니다. 키가 파일에 있다는 사실만으로 유효 기간·계정 권한·실제 API 인증 성공을 확정하지 않습니다. 실제 .env와 원본은 Git에 추가하지 않습니다. 커밋·푸시·서비스 실행·DB 변경은 이번 요청에서 하지 않습니다.
