# 4차 광고 업종 매칭 확장 — 3차 제외

- 작성일: 2026-10-14
- 수정일: 2026-10-14
- 사용자 결정: 3차는 카페 전용이며 업종별 광고 매칭/순환은4차로 분리합니다.
- 상태: 후속 인계입니다. 3차 코드/API/DB/화면의 선행 조건이 아닙니다. 실제4차 구현·정책 채택은 해당 작업 요청 후 진행합니다.

## 1. 보존하는 확장 내용

[수령 원문](./04_광고_관리_간소화_인수인계서.md)의 관리자 ALL/TAGGED·복수 업종 태그·사용자 업종/공유 문맥·OR 매칭과 fallback을4차 자료로 보존합니다. 카페·술집·학원/독서실·기타매장 표시명과 CAFE/BAR/ACADEMY_STUDY_ROOM/OTHER_STORE 코드 제안은 이 범위에서 검토합니다. 3차에는 업종 사전/API·targeting_mode·target_tag_codes·tag_catalog_version·targeting_policy_version을 필수 저장/요청 필드로 만들지 않습니다.

## 2. 4차 연결 전에 정할 사항

- 실제 사용자 업종 입력 위치·공유 코드/사전 버전·단일/복수 매장·비로그인/로그인 문맥·전달 API와 권한.
- 관리자 태그 입력·필터·미리보기·태그 사전 읽기 API. 원문의 GET /api/admin/ad-target-tags는4차 제안입니다.
- 일치 TAGGED 우선/ALL fallback을 채택할지와 전체 광고 priority의 관계. 원문의 일치 TAGGED priority1이 ALL100보다 먼저인 예시는 후속 검토 기준입니다.
- 후보군별 round-robin 상태 키·캐시 분리·동시성. 위치만 공유하는3차 커서를 업종별 후보에 그대로 확장해 공정 순환이 보장된다고 가정하지 않습니다.
- 당시 업종·광고 대상 태그·사전/매칭 정책 버전의 delivery 스냅샷·보관과 소재 수정 전 delivery 처리.

업종 미입력/조회 실패를 OTHER_STORE로 바꾸지 않습니다. 사용자 원본/인증 자료는 광고 DB에 복제하지 않습니다. 4차 채택 시 API·데이터 버전·화면/수용 기준을 함께 갱신하고3차 카페 광고/과거 로그를 소급 변경하지 않습니다.
