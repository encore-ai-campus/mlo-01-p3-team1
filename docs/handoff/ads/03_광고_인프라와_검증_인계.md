## 2026-10-14 광고 관리 간소화 적용

사용자가 제공한 [간소화 원문](./04_광고_관리_간소화_인수인계서.md)과 [통합·추가 인계](./05_광고_간소화_통합과_추가_인계.md)를 현행 광고 기준으로 적용합니다. 첫 관리 단계는 ads/ad_assets/ad_admin_changes 세 컬렉션·MongoDB 이미지 Binary·관리 감사/멱등 응답 통합입니다. 3차는 카페 전용이며 관리자/사용자 업종 선택·태그 입력·업종별 매칭은 제공하지 않습니다. 해당 확장은4차로 분리합니다. 공개 제공/측정과 토큰/주기 통계/예산은 다음 구현 단계이며 전체3차 필수 범위와 기존 태스크 ID/직접 선행은 유지합니다. 이하 기존 확장 저장 표는 후속 검토 자료이며 지금 일괄 생성하지 않습니다.

3차는 카페 광고만 운영하고 위치·일정·paused·소재·예산 자격을 충족한 후보에서 높은 priority·위치별 동률 순환을 적용합니다. 업종/태그가 제공·측정의 전제가 아니며 최초 guest 발급·추천 미요청 집계·단가8/5/클릭추가15·중복/지연/보관은 유지합니다. 미연결 지표는 연동 대기, 실제 통계는 주기 집계하며 예산 제공 제어와 구분합니다. 첫 관리 로그는 ad_admin_changes 내부 log_relay로 전달합니다. 업종별 입력/태그/매칭/순환은4차 인계에서 정하고3차 API/DB/화면/검증의 선행 조건으로 넣지 않습니다.

## 1. INF ↔ B/C 접속·설정 인계

[로컬 가이드](../infra/local%20infra%20guide.md)는9VM의 core/SSH 구조, [AWS 원문](../infra/AWS_인프라_구축_계획서.md)은계정5의 advertising/MongoDB와 계정1의 Control/PostgreSQL 배치를 설명합니다. 원문은 보존하며 실제 주소·DB/앱 버전·replica set·광고 설치/접속 완료로 간주하지 않습니다.

| 설정/인계 | 필요한 실제 근거 | 담당 |
|---|---|---|
| ADS_MONGODB_URI·ADS_MONGODB_DATABASE·replica set 이름 | 실제 primary/transaction 가능·TLS/auth·광고 DB 최소권한·날씨 DB 접근 분리 | INF/B |
| DATABASE_URL·광고 로그 namespace | 공통 인증/guest 조회와 로그 쓰기 계정·연결 풀/한도·멱등 인덱스 | INF/B |
| MongoDB/드라이버 | 정확한 호환 버전·session/transaction·read/write concern·재시도 설정 | INF/B |
| 광고 API 실행 | 로컬 프로세스 위치·Django 모듈, AWS 별도광고EC2 분리 시 라우팅/인증 경계·기동 명령/systemd·health | INF/B/C |
| 웹→광고/공통인증 | 동일 서비스 origin 또는 proxy·쿠키/CSRF·신뢰된 내부 문맥 전달·401/403/503 | B/C/INF |
| AWS 통신 | Control계정1↔광고계정5·광고↔MongoDB계정5·광고로그relay↔PostgreSQL계정1의 실제 허용/반환·포트/TLS | INF/B |
| 이미지 저장·제공 | MongoDB ad_assets.image_bytes·Binary/BSON 크기·정적2MB 검사·공개/미리보기 조회URL/권한·원본명 식별키 금지·공유asset 보호 | INF/B/C |

URI/계정 비밀값은 공유 문서에 넣지 않습니다. AWS계정5에는2~4 직접 peering이 없으므로 광고를 이유로 Kafka/Spark 직접 연결을 가정하지 않습니다. MongoDB 선택만으로 EC2를 추가하거나 기존 예산을 변경하지 않습니다. 원문의 한 MongoDB EC2가 개발 replica set이 되는지는 실제 설치로 확인하며 HA 필요 규모는 별도 결정입니다.

## 4. 완료와 다른 담당자의 재현

B는 MongoDB validator/인덱스/트랜잭션·API모델·로그relay·고정fixture·정상/충돌/실패 결과를 인계하고, C는 PC/모바일/키보드·가시성/중단3초·안내격리의 브라우저 근거를 제공합니다. INF는 실제주소의 보안 전달·기동/종료·권한·백업/재시작/로그복구를 확인하고 PL은 확정/미정·문구/시연을 취합합니다.

AD-01~AD-06의 기존 직접 선행 조건은 유지합니다. 실제 실행 절차/명령은 구현 후 docs/runbook, 검증 입력/기대/실제/실패는 docs/acceptance에 기록하며 현재 없는 실행 명령을 만들지 않습니다. 문서만 완성한 상태에서 광고 구현·운영·과금 완료로 표시하지 않습니다.
