## 1. 요청과 공통 적격

사용자는 동 단위 지역을 입력하고 날씨 반영 ON/OFF를 직접 선택합니다. 기본값은 ON이며 취향 유무가 모드를 자동 변경하지 않습니다. 보컬·빠르기·테마·장르는 선택 입력입니다. 테마·장르의 0개 선택과 전부 선택은 해당 그룹의 ANY로 정규화합니다. 요청 시 country/language 조건은 받지 않습니다.

두 모드 모두 승인/발행된 적격 카탈로그·양수 duration_ms·중복 없는 track_id·보컬 옵션·저장된 제외 목록을 적용합니다. 명시된 사용자 조건을 시간이나 점수로 상쇄하지 않습니다. 표출용 18개 필드와 검수 보조값은 [컬럼·변환](./음악_분류_컬럼_정의_및_변환_규칙.md), [테이블 구조](./테이블_구조_설계.md)를 따릅니다. 원본 정밀도 energy/acousticness/valence 및 mode의 불변 참조가 ON 점수에 필요하며, 표시용 floor 변환값으로 재구성하지 않습니다.

## 2. 날씨 반영 ON

유효한 지역 날씨 분류를 받아 맑음·구름많음·흐림·비·눈의 다섯 종류로 정규화합니다. 각 날씨에는 PRIMARY/SUPPORT 두 패턴을 적용합니다. 원본 정밀도 값의 E/A 핵심 합격(각 20 이상)과 W≥75를 만족한 곡만 ON 후보입니다. PTY2/6은 비·눈 양쪽 풀의 교집합을 사용합니다. PTY4/5는 비, PTY7은 눈으로 연결합니다. 실제 PTY/SKY와 유효 시각을 보존하며 180분 전체 날씨 가중평균이나 옛 W=50:45:5를 적용하지 않습니다.

ON 후보 중 확정된 genre/speed 허용 집합을 적용하고, 활성 빠르기·테마·장르의 100/0 평균 P_legacy를 만듭니다. 활성 그룹이 있으면 S_ON=.75W+.25P_legacy, 없으면 S_ON=W입니다. 날씨 자료가 없으면 추천을 보류하며 OFF로 자동 전환하지 않습니다. 날씨가 바뀌면 기존 결과를 덮어쓰지 않고 새 버전을 생성합니다.

## 3. 날씨 반영 OFF

OFF 후보 자격·점수·시간 조합은 날씨 조회·예보 만료·acousticness/valence에 의존하지 않습니다. 테마 9개 표의 energy·genre·mode·speed 각 원소 점수를 40:40:5:15로 결합하고 원소별 최고값으로 정규화해 P_OFF를 계산합니다. 선택 테마가 여럿이면 각각 완성된 P의 최댓값을 사용합니다. 테마 미일치는 약한 관련성 점수이지 무조건 탈락이 아닙니다. 무선호 요청은 P_OFF=NULL로 두고 재현 가능한 시드 순서를 사용합니다.

장르를 선택했다면 해당 장르 곡 100%로 176~184분을 만들 수 있는지 전체 해당 후보에서 먼저 확인합니다. 구성 불가능할 때만 다른 장르를 실제 재생시간의 최대 20%까지 허용합니다. 선택한 각 장르는 서로 다른 곡으로 대표되어야 합니다. 선택 장르가 0개 또는 전부이면 장르 필터는 ANY입니다. ON의 비·눈 speed 제한을 OFF에 복사하지 않습니다.

## 4. 시간·품질·재설정

두 모드 모두 정수 duration_ms의 합이 10,560,000~11,040,000ms이어야 하며 목표는 10,800,000ms입니다. 정확히 목표→가까운 초과→가까운 부족, 같은 시간에서 재생시간 가중 품질을 비교합니다. OFF의 장르 100% 단계가 80% 완화 단계보다 우선합니다. 200곡 창에서 400→800→1,600→전체 적격까지 확장하고, 제한 창의 실패나 UNKNOWN을 후보 부족으로 단정하지 않습니다. 176분 미만 자동 단축은 두 모드 모두 없습니다.

Gemini 3.8 Flash는 사용자의 명시 재설정에서만 해당 모드의 적격 후보를 제안합니다. 서버가 모드별 필터·시간·등록 ID·중복·보컬·제외·부모 고유 곡 수의 20% 내림(최소 1곡) 신규 곡 조건을 재검증합니다. 실패하면 부모 결과·제외 초안·승인/평가를 보존합니다. 각 결과에 모드·입력·정책/카탈로그 버전·곡/점수/필터 근거를 불변으로 남깁니다.
