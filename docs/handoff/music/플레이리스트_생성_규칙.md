# 플레이리스트 생성 규칙
- 수정일: 2026-10-14
- 점수 정책 버전: WEATHER_MUSIC_V4_CYCLE_FIXED
- 문서 범위: 서비스의 선곡·점수·사이클 기준. 테마 세부 정렬 기준은 별도 확정한다.

추천·표시용 음악 18개 컬럼과 날씨 PTY·SKY를 사용하여 곡별 점수와 플레이리스트 점수를 계산한다. 검수 관리 보조 컬럼 instrumental_review_value는 최종 instrumental 결정·보존에 사용하고 별도 가점을 주지 않는다. 사용자 화면의 보컬·빠르기·테마·장르 선택을 반영한다.

날씨 75%·사용자 취향 25% 구조는 기존 프로젝트 기준을 유지한다. 날씨 내부 비율과 날씨별 우선 범위는 이번에 채택한 초기 운영 기준이며, 청취·추천 결과 검증을 마친 최적값은 아니다. 날씨가 특정 음악 취향을 결정한다는 과학적 사실로 해석하지 않는다.

음악 값의 의미·변환은 [음악 분류 컬럼 정의](./음악_분류_컬럼_정의_및_변환_규칙.md)와 [컬럼 변환 규칙](./음악_분류_컬럼_정의_및_변환_규칙.md), 날씨 코드는 날씨 데이터 규격과 정제 문서의 PTY·SKY 기준을 함께 확인한다.

## 0. 입력값과 적용 순서

### 0-1. 음악 입력값

| 컬럼 | 이 점수 정책의 입력 기준 | 사용 |
| --- | --- | --- |
| energy | 원본 0~1에 10을 곱한 뒤 소수점 이하를 버린 정수 0~10 | 날씨 적합도 |
| acousticness | 원본 0~1에 100을 곱한 뒤 소수점 이하를 버린 정수 0~100 | 날씨 적합도 |
| mode | False=단조, True=장조. 원본 숫자 0/1을 명시적으로 변환 | 날씨 보조 적합도 |
| speed | slow / medium / fast / fastest | 날씨 기본·사용자 선택으로 허용 범위 결정 후 사이클 필터·빠르기 취향 |
| mood | 세미콜론으로 구분한 분위기 라벨 | 테마 취향 |
| genre | 세미콜론으로 구분한 곡 장르 라벨 | 사이클 허용 범위 필터·장르 취향 |
| instrumental | instrumental_review_value 우선 적용 후의 최종 False / True / NULL | 보컬 필수 필터 |
| duration_ms | 양의 정수 밀리초 | 시간 조합·가중평균 |

- acousticness는 정수 척도를 유지하며 이 정책에서 True/False로 다시 변환하지 않는다. 현재 CSV의 실제 변환 범위는 0~99이지만, 추후 원본 1.0을 수용할 수 있도록 유효 범위와 일부 우선 범위의 상한은 100으로 둔다.
- energy와 acousticness의 값 자체가 곡 점수는 아니다. 각 날씨의 우선 범위와 비교한 적합도를 계산한다.
- mode는 장조·단조 구분이며 밝음·어두움의 확정 판정값이 아니다. 날씨별 선호 mode는 초기 가설이며 5%의 보조 비중만 부여한다.

### 0-2. 처리 순서

1. 기본 메타데이터·양의 duration_ms·분류값의 타입과 범위를 확인한다.
2. 사용자가 제외한 곡·중복 track_id·보컬 필수 조건과, 이미 지정된 사이클의 장르·speed 허용 범위를 적용한다.
3. 유효한 앞으로 180분 예보에서 날씨 프로필과 시간 비중을 정한다. 최초 생성의 빠르기 허용 범위는 2-0절을 적용하며, 혼합 예보의 빠르기 기준은 별도 확정한다.
4. 후보 곡의 날씨 점수와 선택된 취향 점수를 계산한다.
5. 중복 없는 곡으로 176~184분의 선곡표를 조합한다. 최초 생성이라면 4-4절에 따라 장르·speed 허용 범위를 확정한다.
6. 실제 곡 ID·보컬/사이클 필터·시간·예보 유효성을 다시 확인하고 결과와 고정 범위를 함께 보존한다.

### 0-3. PTY·SKY와 프로필 선택

| PTY | 의미 | 이 정책의 프로필 |
| --- | --- | --- |
| 0 | 강수 없음 | SKY=1 맑음 / SKY=3 구름 많음 / SKY=4 흐림 |
| 1 | 비 | 비 |
| 2 | 비·눈 | 비·눈 |
| 3 | 눈 | 눈 |
| 4 | 소나기 | 비와 같은 초기 점수 범위 |
| 5 | 빗방울 | 비와 같은 초기 점수 범위 |
| 6 | 빗방울·눈날림 | 비·눈과 같은 초기 점수 범위 |
| 7 | 눈날림 | 눈과 같은 초기 점수 범위 |

- PTY=0만으로 맑음이라고 판단하지 않는다. SKY가 없거나 1·3·4 이외이면 해당 구간의 하늘 상태를 확정할 수 없다.
- PTY가 1~7이면 해당 강수 프로필을 우선하며 SKY의 맑음·흐림 점수를 추가로 중복 반영하지 않는다.
- 미확인·허용되지 않은 날씨 코드와 결측을 임의로 0·맑음으로 치환하지 않는다. 채택한 날씨 API의 실황·예보별 허용 코드도 별도로 검사한다.
- PTY=6·7의 연결은 이번 초기안에서 명시적으로 정한 서비스 규칙이다. 기존 문서에 남은 미정 혼합 비율이나 별도 눈+구름 합산식을 함께 적용하지 않는다.

### 1-2. 전체 비율

| 상태 | 날씨 | 사용자 취향 |
| --- | --- | --- |
| 빠르기·테마·장르 중 하나 이상 선택 | 75% | 선택한 그룹의 평균 25% |

| 날씨 컬럼 | 날씨 내부 비율 | 취향 선택이 있을 때 전체 점수의 비율 |
| --- | --- | --- |
| energy | 50% | 37.50% |
| acousticness | 45% | 33.75% |
| mode | 5% | 3.75% |

날씨 가중치는 모든 날씨에 동일하게 적용하고 우선 범위·값만 바꾼다. genre·mood·speed는 날씨 점수에 중복 가산하지 않고 취향 영역에서 계산한다. 비·눈의 기본 speed 제한은 2-0절의 후보 필터이며 별도 날씨 가점이 아니다.

### 1-3. 보컬 필터

| 사용자 선택 | 통과 조건 | 점수 |
| --- | --- | --- |
| 제한 없음 | 보컬 조건으로 곡을 제외하지 않음 | 별도 가점 없음 |
| 연주곡만 | 확정 검수 결과를 우선 적용. 검수 결과가 없으면 instrumental=True인 곡 | 별도 가점 없음 |

- '연주곡만' 선택 시 검수에서 보컬 없음이 확인되면 기존 instrumental=False·NULL이어도 허용한다.
- '연주곡만' 선택 시 검수에서 보컬 있음이 확인되면 기존 instrumental=True여도 제외한다.
- '연주곡만' 선택 시 검수 결과가 없으면 기존 자동 판정을 사용한다. 이때 False·NULL은 제외하고 True만 허용한다.
- '제한 없음' 선택 시 보컬 여부만으로 곡을 제외하지 않는다.
- instrumental_review_value가 True·False이면 이를 최종 instrumental로 사용하고 NULL일 때만 자동 판정을 사용한다. 일반 갱신에 새 원본 수치가 없으면 기존 최종값을 보존하며, 신규 곡의 미확인은 NULL이다. 재처리에서도 DB의 검수값과 원본 instrumentalness를 보존한다.

## 2. 날씨별 점수 반영 규칙

- 아래 우선 범위는 양 끝을 포함한다. 예를 들어 energy 2~4에는 2·3·4가 포함된다.
- 날씨 표의 energy·acousticness 우선 범위와 mode 우선값은 점수용이다. 범위 밖이거나 mode가 달라도 해당 이유만으로 곡을 제외하지 않는다. 보컬·사이클 장르/speed 등 다른 필수 조건은 별도로 충족해야 한다.
- genre·mood의 날씨 우선값 NULL은 날씨 기준을 두지 않는다는 뜻이다. speed의 기본 허용 범위는 2-0절에서 결정하며, 사용자 선택이 있으면 그 범위를 우선한다. 취향 점수는 3절에서 별도로 계산한다.
- 정책의 우선값 NULL과 곡 데이터의 NULL은 구분한다. 결측 처리는 5절을 따른다.
- 아래 수치는 현재 채택한 초기 범위이며 청취·결과 검증 후 정책 버전과 함께 조정한다.

### 2-0. 최초 선곡 시 비·눈의 빠르기 허용 범위

| 최초 선곡의 빠르기 기준 날씨 | 사용자 선택 | 초기 허용 speed |
| --- | --- | --- |
| 비(PTY=1) 또는 눈(PTY=3) | 선택 없음 / 날씨에 맡기기 | slow·medium |
| 비(PTY=1) 또는 눈(PTY=3) | 느린 곡 우선 | slow |
| 비(PTY=1) 또는 눈(PTY=3) | 빠른 곡 우선 | fast |

- 최초 선곡의 기준 날씨가 비·눈이고 빠른 곡 우선이면 날씨 기본 slow·medium과 교집합을 구하지 않고 fast를 적용한다. 이 초기 범위에서는 fastest를 허용하지 않는다.
- 다른 날씨의 빠른 곡 우선은 기존 fast·fastest를 유지한다. 비·눈 혼합·소나기·빗방울·눈날림에 이 개정안을 확대 적용할지는 별도 확정한다.
- 3시간 중 날씨가 바뀌는 혼합 예보에서 어떤 날씨로 빠르기 범위를 정할지도 별도 확정한다. 점수의 시간 가중평균으로 필수 허용 범위를 임의 결정하지 않는다.
- 최초 확정 범위는 4-4절에 따라 같은 사이클에서 유지한다. 이후 비·눈으로 바뀌거나 강수가 끝나도 기존 범위를 다시 제한하거나 확대하지 않는다.
- 예: 맑음·빠른 곡 우선으로 fast/fastest를 허용한 사이클은 비로 바뀌어도 두 값을 유지한다. 비·빠른 곡 우선으로 fast만 허용한 사이클은 맑아져도 fast만 유지한다.

### 2-9. 날씨 적합도 계산

energy·acousticness는 우선 범위 안이면 100점이다. 범위 밖이면 가장 가까운 경계와의 거리 d를 계산한다.

```text
d(x, L, U) = max(L - x, 0, x - U)

energy 적합도 E = max(0, 100 - 10 × d(energy, energy 하한, energy 상한))
acousticness 적합도 A = max(0, 100 - d(acousticness, acousticness 하한, acousticness 상한))
mode 적합도 M = 우선 mode와 일치하면 100, 불일치하면 0

단일 날씨 점수 W_k = 0.50 × E + 0.45 × A + 0.05 × M
```

- energy는 범위에서 1 멀어질 때마다 10점, acousticness는 1 멀어질 때마다 1점 감점한다. mode가 다르다는 이유로 곡을 제외하지 않는다.
- 날씨별 mode 선호를 추후 해제하는 경우 정책 우선값을 NULL로 지정한다. 그 프로필에서 mode 비중을 0으로 하고 energy 50/95, acousticness 45/95로 재배분한다. 같은 프로필의 모든 곡에 같은 비율을 쓴다. 곡의 mode가 없다는 이유로 곡별 재배분하지 않는다.
- 현재 2절의 10개 프로필은 모두 mode 우선값이 지정되어 있으므로 기본 50:45:5를 그대로 사용한다.

### 2-9-1. '범위 밖 거리 감점'의 구체적인 의미

거리는 곡의 값과 우선 범위의 가장 가까운 경계 사이의 차이이다. 하한보다 작으면 하한에서 곡의 값을 빼고, 상한보다 크면 곡의 값에서 상한을 뺀다. 범위 안이면 거리는 0이다.

맑음의 energy 우선 범위가 5~8일 때 계산은 다음과 같다.

| 곡 energy | 가장 가까운 경계와의 차이 | energy 적합도 E | 날씨 점수 기여분 E×50% |
| --- | --- | --- | --- |
| 0 | 5보다 5 낮음 | 50점 | 25점 |
| 3 | 5보다 2 낮음 | 80점 | 40점 |
| 4 | 5보다 1 낮음 | 90점 | 45점 |
| 5~8 | 범위 안이므로 0 | 100점 | 50점 |
| 9 | 8보다 1 높음 | 90점 | 45점 |
| 10 | 8보다 2 높음 | 80점 | 40점 |

energy=4인 곡은 5~8인 곡보다 날씨 점수에서 5점을 덜 받지만 후보에 남는다. 다른 항목 점수가 높으면 최종 점수에서 앞설 수 있다. 현행 감점 강도에서는 energy=0도 적합도 50점·날씨 기여분 25점을 받는다. 따라서 이 규칙은 'energy 5~8인 곡만 사용'하는 필터가 아니다.

acousticness는 같은 거리 계산을 쓰되 1 차이당 1점 감점한다. 맑음의 우선 범위 0~60에서 acousticness=70이면 거리는 10, 적합도는 90점, 날씨 점수 기여분은 90×45%=40.5점이다.

표의 적합도 100점과 가중치 적용 후 기여 점수는 다르다. energy의 날씨 기여분은 최대 50점, acousticness는 최대 45점이다. 취향 선택이 있으면 합산한 날씨 점수에 다시 75%를 적용한다. 예를 들어 energy 적합도 90점의 최종 점수 기여분은 90×50%×75%=33.75점이다.

### 2-9-2. mode 불일치 시 후보를 유지한다는 의미

맑음의 우선 mode=True일 때 다음과 같이 처리한다.

| 곡 mode | mode 적합도 M | 날씨 점수 기여분 M×5% | mode만으로 후보 제외 여부 |
| --- | --- | --- | --- |
| True — 장조 | 100점 | 5점 | 제외하지 않음 |
| False — 단조 | 0점 | 0점 | 제외하지 않음 |

단조 곡은 mode 가점을 받지 않을 뿐, energy·acousticness·사용자 취향을 계산한 최종 점수로 다른 곡과 비교한다. mode가 불일치해도 필수 조건을 모두 충족하고 다른 항목 점수가 높으면 선곡될 수 있다. mode=NULL은 단조라는 뜻이 아니며 5-1절에 따라 미확인으로 구분한다.

반면 보컬 필터와 4-4절의 사이클 장르·speed 범위는 필수 조건이다. 이 조건을 벗어난 곡은 점수가 높아도 선곡하지 않는다.

### 2-10. 앞으로 3시간 예보 결합

```text
구간 비중 r_k = 해당 날씨 구간과 앞으로 180분이 겹치는 분량 / 180분
최종 날씨 점수 W = Σ(r_k × W_k)
Σ(r_k) = 1
```

예를 들어 앞으로 1시간 흐림·2시간 비이면 W=(흐림 점수×1/3)+(비 점수×2/3)이다. 예보 구간은 중복 없이 전체 180분을 덮어야 하며 임의 시간 보간이나 결측 구간 제외 후 재배분은 하지 않는다.

유효 예보로 전체 구간을 확인할 수 없으면 추천을 보류하고 날씨 확인 불가를 안내한다. 날씨 미확인을 W=0으로 저장하거나 취향 100%로 대체하지 않는다. 곡 점수는 요청의 동일한 180분 전망으로 계산하며, 실제 결과가 180분을 초과하면 최대 184분의 실제 종료 시각까지 예보 유효성도 추가 확인한다. 초과분은 이 버전의 180분 점수 가중치에는 더하지 않는다.

## 3. 사용자 취향 점수

### 3-1. 그룹별 일치 판정

| 취향 그룹 | 사용자 선택 | 100점 조건 | 그 외 |
| --- | --- | --- | --- |
| 빠르기 | 날씨에 맡기기 | 이 그룹 미사용 | 분모에서 제외 |
| 빠르기 | 느린 곡 우선 | speed=slow | 허용 speed 밖이면 사이클 필터에서 제외 |
| 빠르기 | 빠른 곡 우선 | speed가 최초 확정한 빠른 곡 허용 집합에 포함됨. 기준 날씨가 비·눈이면 fast, 그 외는 fast/fastest | 허용 speed 밖이면 사이클 필터에서 제외 |
| 테마 | 잔잔한·몽환스러운 등 | 선택 테마 중 하나 이상과 승인된 mood→테마 매핑이 일치 | 0점 |
| 장르 | 재즈·클래식 등 | 선택 장르 중 하나 이상과 승인된 genre→장르 매핑이 일치 | 허용 장르와 일치하지 않으면 사이클 필터에서 제외 |

- 느린 곡 우선은 slow로 고정한다. 빠른 곡 우선은 최초 기준 날씨가 비·눈이면 fast, 그 외 날씨이면 fast·fastest로 고정한다. 같은 사이클에서는 현재 날씨로 이 집합을 다시 계산하지 않는다. medium은 두 사용자 선택의 범위 밖이다. 미선택·날씨에 맡기기는 2-0절의 기본 범위와 4-4절의 사이클 규칙을 따른다.
- 테마와 장르는 각 그룹 안에서 OR로 판정한다. 같은 그룹에서 두 개 이상 일치해도 100점을 넘기지 않는다.
- 테마 우선 기준은 [테마·장르 정의](./테마_장르_정의.md) 4-1·4-2절을 따른다. 판단 요소를 장르 매핑보다 먼저 고려하되, 범위 밖 곡을 자동 제외하거나 mood를 자동 생성하지 않는다. 부분 일치·최종 정렬 기준은 별도 확정한다.
- 세미콜론 복수 값은 분리·공백 및 빈 항목 제거 후 개별 라벨로 비교한다. 단순 부분 문자열 포함으로 일치시키지 않는다.
- 장르 비교는 대분류 코드로 통일한다. 화면 '재즈'는 JAZZ, 곡의 세부 태그 jazz는 승인된 사전으로 JAZZ에 연결한 뒤 비교한다. '클래식'은 CLASSICAL이며 원본 classical·승인된 별칭 classic을 매핑한다. 태그 ID·세부 라벨·표시 이름을 대분류 코드와 직접 비교하지 않는다.
- '잔잔한'을 energy·acousticness로 자동 생성하거나 '감성적인'과 임의로 동일시하지 않는다. '몽환스러운'과 '몽환적인' 같은 표현도 승인 매핑을 거친다. 매핑되지 않은 값은 미확인으로 남기고 일치로 계산하지 않는다.
- 미선택 취향 그룹은 가점 계산에 사용하지 않는다. 선택한 테마의 곡 값이 NULL·미확인이면 해당 그룹 점수는 0이다. genre·speed는 고정 범위 준수 여부를 확인해야 하므로 미확인 곡을 후보 보류하고 원본 NULL은 보존한다.
- 장르·빠르기는 가점 계산보다 사이클 범위 필터를 먼저 적용한다. 사용자가 이 그룹을 선택했다면 필터를 통과한 곡은 해당 그룹에서 모두 100점이므로, 그 가점은 같은 사이클 안에서 공통값이 된다. 75:25 구조와 그룹 균등 배분은 유지하며 남은 차이는 날씨·선택 테마 등에서 발생한다.
- 시스템이 자동 확정한 사이클 범위는 사용자 취향 선택으로 세지 않는다. 사용자가 빠르기·테마·장르를 모두 미선택했다면 범위를 고정한 뒤에도 날씨 100%를 유지한다.

### 3-2. 선택 그룹 수에 따른 비율

| 선택한 그룹 | 날씨 | 빠르기 | 테마 | 장르 |
| --- | --- | --- | --- | --- |
| 없음 | 100% | 0% | 0% | 0% |
| 빠르기 | 75% | 25% | 0% | 0% |
| 테마 | 75% | 0% | 25% | 0% |
| 장르 | 75% | 0% | 0% | 25% |
| 빠르기·테마 | 75% | 12.5% | 12.5% | 0% |
| 빠르기·장르 | 75% | 12.5% | 0% | 12.5% |
| 테마·장르 | 75% | 0% | 12.5% | 12.5% |
| 빠르기·테마·장르 | 75% | 25/3% | 25/3% | 25/3% |

세 그룹을 모두 선택하면 각각 약 8.33%이며 계산에는 정확한 1/3을 사용한다. 테마 칩 두 개와 장르 칩 한 개를 골라도 선택 그룹은 테마·장르 두 개이므로 각 12.5%이다.

```text
n = 사용자가 선택한 빠르기·테마·장르 그룹 수
n > 0: 취향 점수 P = 활성 그룹 일치 점수의 합 / n
n = 0: P는 미사용
```

## 4. 곡 점수와 플레이리스트 조합

### 4-1. 최종 곡 점수

날씨·취향·최종 점수는 모두 0~100 범위이다.

```text
n > 0: 최종 곡 점수 S = 0.75 × W + 0.25 × P
n = 0: 최종 곡 점수 S = W
```

중간 계산은 반올림하지 않고 표시할 때만 소수점 둘째 자리까지 반올림한다. 화면 표시를 반올림한 값으로 곡 순위를 다시 계산하지 않는다.

### 4-2. 계산 예시 — 앞으로 3시간 모두 비

아래 곡은 계산 구조를 설명하기 위한 가상의 값이며 실제 CSV 곡의 조회 결과가 아니다.

| 항목 | 예시 값 | 적합도·일치 점수 |
| --- | --- | --- |
| energy | 6 | 우선 상한 4에서 거리 2 → 80점 |
| acousticness | 70 | 우선 범위 60~100 안 → 100점 |
| mode | False | 비의 우선값 False와 일치 → 100점 |
| 사용자 빠르기 | 느린 곡 우선, 곡 speed=slow | 허용 범위 안·100점 |
| 사용자 테마 | 몽환스러운, 승인된 곡 테마와 불일치 | 0점 |
| 사용자 장르 | 재즈, 승인된 곡 장르와 일치 | 허용 범위 안·100점 |

```text
W = 80 × 0.50 + 100 × 0.45 + 100 × 0.05 = 90
P = (100 + 0 + 100) / 3 = 66.666...
S = 90 × 0.75 + 66.666... × 0.25 = 84.166... → 표시 84.17점
```

빠르기만 선택한 동일 곡은 slow 조건에 일치하여 P=100이므로 S=92.50점이며, 취향을 모두 미선택하면 S=W=90점이다. 조건 변경은 새 사이클로 처리하므로 서로 다른 요청의 점수를 같은 사이클의 순위로 비교하지 않는다. 느린 곡을 선택한 사이클에서 speed=fast인 곡은 낮은 점수로 남기는 것이 아니라 점수 계산 전에 제외한다.

### 4-3. 플레이리스트 조건과 전체 점수

- 목표 시간은 180분, 허용 범위는 176~184분이다. duration_ms의 원본 정수 합으로 판단하고 표시용 분:초를 다시 합산하지 않는다.
- 허용 범위는 10,560,000~11,040,000ms, 목표는 10,800,000ms이다.
- 동일 track_id를 중복 사용하지 않는다. 서로 다른 ID의 동일 녹음 판별은 별도 데이터 검수 대상이며 제목만으로 임의 병합하지 않는다.
- 보컬·사이클 장르/speed 필터·등록/검수 적격성·예보 유효성을 먼저 충족한 조합만 사용한다. 기존 시간 우선순위를 유지하여 정확히 180분 → 180분 초과~184분 → 176분~180분 미만 순으로 확인하고, 같은 구간에서는 목표 시간과의 거리가 가까운 조합을 우선한다. 같은 시간 조건에서는 아래 전체 점수가 높은 조합을 우선한다.

```text
플레이리스트 전체 점수 = Σ(S_i × duration_ms_i) / Σ(duration_ms_i)
```

곡 수가 많다는 이유로 유리해지지 않도록 재생시간 가중평균을 사용한다. 곡별 상위 점수를 차례로 담는 것만으로 시간 조건과 최적 조합이 보장되지는 않으므로 최종 곡 조합을 별도로 검증한다.

유효 후보로 시간 범위를 채울 수 없으면 생성 불가·후보 부족을 안내한다. 별도 시간 단축 정책이 확정되기 전에는 176분 미만 결과를 정상 3시간 선곡표로 제공하지 않는다. 시간 부족 때문에 보컬 필터를 해제하거나 고정한 장르·speed 범위를 자동으로 넓히지 않는다.

### 4-4. 한 사이클의 장르·speed 범위 고정

**한 사이클의 플레이리스트에서는 최초 지정된 장르와 speed 범위를 벗어나지 않도록 한다.** 이 규칙은 가점이 아니라 필수 조건이며, 날씨 우선 범위에 대한 감점 규칙과 구분한다.

#### 사이클의 시작과 유지

- 한 사이클은 같은 시작 조건으로 최초 선곡표를 만들고, 그 선곡표를 바탕으로 곡 제외·재설정·승인을 진행하는 범위이다. 처음 제공한 선곡표의 허용 장르 집합과 허용 speed 집합을 고정하여 기록한다.
- 같은 사이클의 모든 곡과 이후 [다른 선곡표 요청]으로 생성한 결과는 동일한 두 집합을 따른다. 규칙 추천과 Gemini 재설정에도 같은 필터를 적용한다.
- 곡 제외·순서 변경·날씨 갱신·재설정만으로 고정 범위를 바꾸지 않는다. 날씨가 바뀌면 날씨 점수는 재계산할 수 있지만 장르·speed 필수 조건과 빠르기 취향의 일치 기준은 최초 확정값을 유지한다.
- 사용자가 장르·빠르기 등 시작 조건을 바꾸고 새 선곡을 요청하면 새 사이클로 시작한다. 이전 사이클의 범위를 조용히 덮어쓰지 않는다.

#### 최초 범위를 정하는 방법

| 항목 | 사용자가 선택한 경우 | 사용자가 선택하지 않은 경우 |
| --- | --- | --- |
| 장르 | 선택한 장르의 승인된 대분류 코드 집합을 처음부터 허용 범위로 사용한다. 복수 선택은 OR이며 한 장르로 임의 축소하지 않는다. | 최초 선곡표에 실제 포함된 곡의 승인된 대분류 코드 합집합을 초기 범위로 기록하고, 이후 같은 사이클에서 유지한다. |
| speed | 느린 곡 우선은 slow. 빠른 곡 우선은 최초 기준 날씨가 비·눈이면 fast, 그 외이면 fast/fastest를 초기 범위로 지정한다. | 최초 기준 날씨가 비·눈이면 2-0절의 slow·medium을 지정한다. 그 외에는 최초 선곡표에 실제 포함된 speed 집합을 기록한다. 같은 사이클에서는 날씨가 바뀌어도 최초 범위를 유지한다. |

사용자 미선택 시에도 최초 기준 날씨가 비·눈이면 speed를 최초 조합 전에 slow·medium으로 제한한다. 그 외 자동 범위는 최초 선곡표에서 확정하여 기록한 뒤 제공한다. 이후 결과는 동일한 범위를 상속한다. 최초 제공 전에도 genre·speed가 확인되지 않은 곡은 범위를 검증할 수 없으므로 후보 보류한다. 시스템 자동 범위가 정해졌다는 이유만으로 사용자 취향 가점을 활성화하지 않는다.

#### 곡의 통과 조건

```text
장르 통과 = 승인 매핑으로 계산한 곡 대분류 코드 집합과 사이클 허용 대분류 코드 집합의 교집합이 비어 있지 않음
speed 통과 = 곡 speed가 사이클 허용 speed 집합에 포함됨
최종 후보 = 장르 통과 AND speed 통과 AND 그 밖의 필수 조건 통과
```

복수 장르 곡은 승인 매핑 후의 대분류 중 하나 이상이 허용 범위와 일치하면 장르 조건을 통과한다. 곡에 다른 장르 라벨도 함께 있다는 이유만으로 제외하지 않는다. 이 규칙에서 '범위 유지'는 곡마다 허용 대분류가 하나 이상 연결되어 있음을 뜻하며, 모든 곡이 하나의 동일 장르여야 한다는 뜻은 아니다. 원본 세부 라벨은 보존한다.

| 최초 고정 범위 | 통과 예시 | 제외 예시 |
| --- | --- | --- |
| 대분류 JAZZ / speed slow | 세부 태그 jazz·slow, jazz;soul·slow | pop·slow는 대분류 불일치. jazz·medium은 speed 불일치 |
| 비·눈에서 대분류 JAZZ·CLASSICAL / 빠른 곡 우선 speed fast | 세부 태그 jazz·fast, classical·fast | rock·fast는 대분류 불일치. jazz·slow와 jazz·fastest는 speed 불일치 |
| 대분류 ROCK / speed fast | 세부 태그 alt-rock·fast, j-rock·fast | jazz·fast는 대분류 불일치 |

범위 안의 후보가 부족해도 다른 장르·speed를 자동으로 추가하지 않는다. 현재 사이클에서는 생성 불가를 안내하고 기존 결과가 있으면 보존한다. 사용자가 범위 변경을 선택한 경우에만 새 사이클로 다시 시작한다. 재설정 결과를 제공하기 직전에도 모든 곡의 범위 준수를 다시 검사한다.

## 5. NULL·오류·검수와 변경 관리

### 5-1. 결측 처리

| 위치·상태 | 처리 |
| --- | --- |
| 곡 energy 또는 acousticness가 NULL·유효 범위 밖 | 날씨 핵심 입력 미확인으로 후보 보류. 임의값으로 채우지 않음 |
| 우선 mode가 활성인데 곡 mode가 NULL | mode 일치 점수 0. 미확인 상태를 별도 기록하고 원본 NULL 유지 |
| 선택한 테마의 곡 mood가 NULL·매핑 미확인 | 테마 점수 0. 활성 그룹 분모 유지 |
| 곡 genre·speed가 NULL·매핑 미확인 | 사이클 범위 확인 불가로 후보 보류. 원본 NULL 유지 |
| 곡이 사이클 허용 장르·speed 범위 밖 | 점수와 관계없이 후보 제외 |
| 사용자가 취향 그룹을 미선택 | 해당 그룹을 분모에서 제외 |
| 정책의 mode 우선값이 NULL | 해당 날씨의 모든 곡에 공통으로 mode 비중 제거 후 50:45 재배분 |
| 정책 energy·acousticness 우선 범위 누락·역전 | 정책 오류로 계산 보류. 임의 0점 또는 만점 처리 금지 |
| 날씨 구간 결측·무효 코드·예보 유효성 미충족 | 날씨 점수와 추천 생성 보류 |
| duration_ms가 NULL·0 이하·정수가 아님 | 시간 조합 후보에서 제외하고 입력 오류 기록 |

정책 NULL은 기준 미사용, 데이터 NULL은 미확인이다. 실제 energy=0·acousticness=0·mode=False는 정상값이며 결측으로 취급하지 않는다. 곡마다 결측 항목을 빼고 가중치를 재배분하여 미확인 곡이 유리해지게 하지 않는다.

### 5-2. 적용·검증 기준

- 현재 규칙은 음악 18개와 변환 후 energy 0~10·acousticness 0~100을 전제로 한다. 기존 프로젝트의 음악 16개·수동 energy/speed·acousticness 미사용 규칙과 동시에 적용하지 않으며, 실제 구현 시 관련 기준 문서를 이 정책에 맞춰 동기화해야 한다.
- 원본 음향값을 새 값으로 덮어쓰지 않는다. 변환 결과 행은 한 번만 초기화하고 energy·acousticness 등 각 결과를 누적한다. 재처리 때는 다시 원본 값을 입력으로 사용한다.
- 날씨·취향의 비율, 우선 범위, mode 선호, 테마/장르 매핑을 바꾸면 정책·매핑 버전을 갱신한다. 이미 생성한 결과 점수를 새 규칙으로 덮어쓰지 않도록 당시 사용값과 버전을 별도 운영 자료에 보존한다.
- 사용자 평가인 좋아요·싫어요·선곡표 별점은 이 점수에 자동 가산하지 않는다. 평가와 추천 조건 변경은 별도 정책으로 관리한다.
- 검증 시 각 우선 범위의 경계 안팎, energy 0/10, acousticness 0/100, mode False/True/NULL, 취향 그룹 0/1/2/3개, 보컬 필터, 사이클 범위 고정/상속·범위 밖 차단·사용자 미선택 자동 범위·조건 변경 시 새 사이클, 결측·무효 날씨, 176/180/184분 경계를 확인한다.
- 날씨별 추천 곡의 청취 평가와 취향 일치율을 기록하여 초기 범위·가중치를 조정한다. 코드와 계산이 맞다는 사실만으로 날씨별 음악 적합성이 검증됐다고 표현하지 않는다.
