# 음악 분류 컬럼 정의 및 변환 규칙

*음악 컬럼의 의미·자료형·입력 출처와 변환 규칙을 정의한 문서이다.*

## 1. 음악 테이블 컬럼
- 수정일: 2026-10-16

### 1-1. 원본 데이터 컬럼

**원본 데이터에서는 아래의 20개의 컬럼을 사용한다.**

```
track_id, artists, album_name, track_name, popularity, duration_ms, explicit, danceability, energy, key, loudness, mode, speechiness, acousticness, instrumentalness, liveness, valence, tempo, time_signature, track_genre
```

*tempo는 원본 BPM의 소수값이며, time_signature는 원본 박자 값이다. 두 컬럼은 speed 변환의 입력값으로 사용하고 원본 값을 보존한다.*

---
### 1-2. 사용 데이터 컬럼
**추천·표시에 사용하는 음악 정보는 기존 18개 컬럼이며, 검수 관리 보조 컬럼 instrumental_review_value를 추가하여 논리 컬럼 목록은 총 19개로 관리한다. 기본 추천 입력에는 최종 instrumental을 전달하고 검수값은 별도로 보존한다.**

```
track_id, track_name, artists_id, artists_name, album_id, album_name, album_release_date, duration_ms, explicit, genre, energy, mode, acousticness, mood, speed, main_inst, instrumental, play_url, instrumental_review_value
```

#### **판단 기준 및 설명**

**상세 규칙**
- NULL 허용 : NULL과 NOT NULL로 구분한다. NOT NULL에는 값이 필수로 입력되어야 한다.
- 복수 입력 : 여러 개의 값을 입력할 수 있는지에 대한 여부이다. 구분은 세미콜론(;)을 기준으로 한다.
- API 제공 여부 : Spotify에서 공식적으로 제공받을 수 있는 정보를 나타낸다.

| --- | --- | --- | --- | --- | --- |
| track_id | str | NOT NULL | X | O | 트랙의 고유id이다. |

| artists_id | str | NULL | O | O | 아티스트 고유 id이다. |

### 1-3. 판단 보류 컬럼
**현 시점에서 판단 요소로 삼지 않을 컬럼이다. 수치화 또는 명확한 구분이 가능하며, 추후에 정확한 정보를 확인해야할 때 사용 가능성을 염두에 둔다.**

- key : 곡의 조성을 나타내며, 총 12개로 구분한다.
- gender : 가창자의 성별을 표기한다.
- country : 발표곡의 국가 정보를 표기한다.


## 2. 컬럼별 입력 출처 및 대입 규칙

- '원본 컬럼명'은 해당 값을 생성하거나 변환할 때 사용하는 CSV 입력 컬럼을 표기한다. 신규 컬럼명과 같지 않을 수도 있다. CSV 입력 컬럼을 사용하지 않고 API 또는 수기로 확보하는 경우에는 X로 표기한다.

| --- | --- | --- |

## 3. 변환 규칙 상세

각 원본 행에 대해 결과 행을 한 번만 초기화하고, 아래 변환 결과를 같은 결과 행에 누적한다.

### 3-1. duration_ms : 밀리초를 '분:초'로 변환

정수로 변환할 수 있는 duration_ms 입력을 1,000으로 나누고 소수 부분을 버린다. 전체 초를 분과 남은 초로 나누어 분:초 형식으로 표시한다. 초는 두 자리로 표시하며, 이 변환 코드에서는 NULL·음수 등 입력값을 검사하거나 예외 처리하지 않는다.

이는 화면에 표시할 때의 변환 규칙이며, 입력값은 밀리초를 유지한다.

### 3-2. speed : 원본 tempo와 time_signature를 이용하여 4개의 분류로 변환

- time_signature 값이 3이면 원본 tempo를 1.5로 나누고, 그 외에는 보정하지 않는다.
- 보정값을 ROUND_HALF_UP 방식으로 정수 반올림한다.
- 반올림값이 80 미만이면 slow, 80 이상 110 미만이면 medium, 110 이상 150 미만이면 fast, 150 이상이면 fastest로 대입한다.
- 원본 tempo와 time_signature 값은 변경하지 않는다.
- tempo가 없으면 NULL, time_signature가 없으면 보정 없이 분류한다.

### 3-3. energy : 원본 컬럼에서 10을 곱한 정수로 변환

원본 CSV 파일과 입력 행의 energy 값은 그대로 유지한다. 입력 행을 복사한 별도 결과 행(normalized_row)에 변환값을 저장한다. 재처리할 때도 원본 energy를 입력으로 사용하고, 서비스 적재에는 결과 행을 사용한다.

### 3-4. acousticness 소수를 정수로 변환

- 원본의 1 이하 소수에 100을 곱하여 정수로 변환한다.
- 변환된 정수값에 따라 어쿠스틱함 정도를 측정한다.
- 전체 114,000개 행의 비율은 다음과 같다.

| 원본 acousticness 범위 | 행 수 | 비율 |
| --- | --- | --- |
|0 ≤ x < 0.2 | 60,101 | 52.72% |
|0.2 ≤ x < 0.8 | 38,061 | 33.39% |
|0.8 ≤ x ≤ 1 | 15,838 | 13.89% |

### 3-5. instrumental 소수를 불리언으로 변환

원본 데이터는 연주곡 여부를 1.0 이하의 소수로 나타내고 있다. 숫자가 높을 수록 연주곡일 확률이 높다.

아래 구간은 자동 판정 기준이다. 재처리에서는 DB의 instrumental_review_value를 track_id로 먼저 읽어 보존한다. 검수값이 True·False이면 그 값을 최종 instrumental로 사용하며, NULL일 때만 자동 판정을 사용한다. False도 확정 결과이므로 값의 참·거짓이 아니라 NULL 여부로 우선 적용을 결정한다. 새 원본 수치가 없는 일반 API 갱신에서는 기존 최종값을 보존하고, 신규 곡은 NULL로 둔다. 원본 instrumentalness는 보존한다.

| 조건 | 변환값 | 전체 행 수 |
| --- | --- | --- |
| x < 0.2 | False | 90,703 |
| 0.2 ≤ x < 0.8 | NULL — 검토 대기 | 10,421 |
| x ≥ 0.8 | True | 12,876 |

적재 전에 track_id로 DB의 기존 곡 정보를 조회한다. 각 곡의 instrumental_review_value는 불리언 또는 NULL로 읽는다. 신규 곡은 기존 정보가 없으므로 검수값을 NULL로 둔다. 검수 입력은 자동 변환과 별도 작업으로 저장한다.

검수 저장 시에는 instrumental_review_value와 최종 instrumental을 함께 갱신한다. 재적재의 일반 upsert 대상에서 검수 컬럼을 제외한다. 확정 검수를 명시적으로 해제하는 경우에만 검수값을 NULL로 바꾸고, 원본 수치가 있으면 자동 판정을 다시 반영한다. 원본이 없으면 최종 instrumental도 NULL로 둔다.

### 3-6. play_url : 원본 track_id로 Spotify 곡 페이지 URL 생성

원본 track_id를 사용하여 URL을 생성하고, 별도 결과 행에 저장한다. 변환 결과를 SQL에 저장한다.

## 2026-10-16 추천 점수용 원본 정밀도 계약

위 18개 추천·표시 필드와 검수 보조 1개는 유지합니다. [ON/OFF 후보 산출 가이드](../../product/카페_음악_추천_서비스_3차_컬럼_기반_추천_로직_가이드.md)의 ON 점수는 **원본 0~1 정밀도의 energy·acousticness·valence 및 mode**를 별도 점수 입력으로 사용합니다. 정수 표시 필드 energy=floor(raw_energy×10), acousticness=floor(raw_acousticness×100)에서 원본을 역산하면 경계가 달라지므로 금지합니다. raw_valence는 원본 CSV에 있지만 위 18개 표시 필드에는 없으므로 불변 원본 행/버전/해시에서 읽거나 별도 점수 특성 스냅샷으로 발행해야 합니다. OFF의 테마 energy 점수는 표시용 0~10 정수 규칙을 사용하며 날씨용 acousticness/valence는 OFF 적격의 필수값이 아닙니다.

중복 track_id의 ON 필수 원본 값이 충돌하면 대표 행을 임의 선택하지 않고 보류합니다. source_schema_version·원본 참조·catalog_version·score_policy_version을 함께 기록하고, 0/NULL·범위 오류·소수 경계와 재처리 동일성을 검증합니다. 물리 컬럼/DDL 및 원본 보관 연결은 실제 DB 선택 후 확정합니다.
