## 2026-10-14 저장소 결정과 광고 인계

음악 메타데이터·CSV·검수된 불변 카탈로그는 **S3**, 로그·피드백 원본/정제/집계와 공통 업무 상태는 **PostgreSQL**, 광고 업무 데이터는 **MongoDB**를 사용합니다. 3차에는 음원 파일 자체를 저장하거나 직접 재생하지 않습니다. 기존 음악 RDB·피드백 Delta·광고 PostgreSQL 제안은 이 결정으로 대체합니다. 날씨 MongoDB/Elasticsearch·원문 로컬/S3 경로는 유지합니다. 보관 당시 저장 계약 참조 `docs/product/3차_저장소_경계와_발행_계약.md`과 보관 당시 ADS 참조 `docs/handoff/ads/README.md`를 적용하며 실제 설치·접속·운영 검증 완료와 구분합니다.


## 0. 3차 적용·저장·검수 계약

**추가 자료 대기:** 수동 날씨 점수 목표/함수·CSV→16개 필수/수동값 보강·수동 곡 특성의 스냅샷 필수 목록/형식은 담당자 문서 수령까지 보류합니다. 여기의 필드 정의가 실제 값 확보나 해당 정책 확정을 의미하지 않습니다. 날씨75%/활성 빠르기·테마·장르 평균25% 결합, Gemini 명시 재설정과 부모 곡 수20% 내림 신규 곡 추가 기준은 현행 추천 가이드를 따릅니다.

음악 업무 레코드는 아래16개를 기준으로 합니다. `track_id`는 안정적인 곡 ID/논리 키이며 아티스트·앨범 정보는 이 레코드에 함께 관리합니다. 이전 `music_album`/`music_artist` 테이블을 필수로 가정하지 않습니다. S3 객체 형식·manifest·복수 값 직렬화은 인프라 계약에서 정하되 필드의 의미·척도를 바꾸지 않습니다.

- energy는 **수동 청취 정수0~10**이며 원본 CSV의 음향 energy0~1을 그대로 적재하거나 10배/10으로 나눠 자동 환산하지 않습니다. mood·speed·main_inst·genre·instrumental도 수동 입력/검수와 근거를 보존합니다. 이전 energy/danceability/acousticness 수식·충족률0.75·W하한0.55는 현행 규칙에서 제외하며 새 날씨 목표/하한은 R-01에서 확정합니다.
- speed는 slow/medium/fast/fastest 라벨이며 BPM에서 자동 변환하지 않습니다. instrumental=true/false/null은 입력값과 검수 상태를 구분합니다. 엄격 무보컬은 검수 근거가 있는 true 곡만 허용합니다.
- 복수 입력(artists_id/artists_name/genre/mood/main_inst)은 원문 세미콜론 형식과 정규 집합을 대응시킵니다. 아티스트 ID/이름은 제공된 대응만 검증하며 이름만으로 ID를 확정하지 않습니다. 원문 컬럼의 필수/NULL 규칙과 부분 발매일을 유지합니다.
- 보컬 확인 상태/근거·mood→테마 코드·검수 이력/카탈로그 버전은 별도 운영 검수 자료입니다. 국가·언어 설정/검수/필터/가점/관리 입력/피드백 필드는3차에서 모두 제외하며 원본에 관련 값이 있더라도 현행16개/별도 검수/프롬프트로 채택하지 않습니다.
- 커버는 별도 선택적 표시 자산으로 연결할 수 있으며 없는 경우 공통 기본 이미지를 사용합니다. 이미지·결과/평가·추천 정책 등 운영 저장을 모두 음악16개에 억지로 넣지 않습니다.
- play_url은 원문에서 재생용으로 기술됐지만 예시의 Spotify URL은 곡 페이지입니다. URL만으로 직접 음원 재생/권한을 확정하지 않습니다. 3차는 보유 CSV+수동 검수이며 아래 Spotify 수집 절차는 선택적 후속 경로입니다.

### 1-3. 필드값 입력 예시


**- 컬럼 내에 입력된 필드값을 기재하였다. API가 제공되는 컬럼은 제외하였으며 'genre', 'energy', 'mood', 'speed', 'main_inst'에 대한 필드값을 나타낸다.**

### 1-4. 판단 보류 컬럼
**현 시점에서 판단 요소로 삼지 않을 컬럼이다. 수치화 또는 명확한 구분이 가능하며, 추후에 정확한 정보를 확인해야할 때 사용 가능성을 염두에 둔다.**

- key : 곡의 조성을 나타내며, 총 12개로 구분한다.
- mode : 장/단조 구분이며, 총 2개로 구분한다.
- tempo : 곡의 속도(BPM)을 나타내며, 정수로 구분한다.
- time_signature : 곡의 박자를 나타내며, 구분 기준을 즉시 정의하지 않는다.
- gender : 가창자의 성별을 표기한다.

- 아래는 실제 API 조회 결과가 아니라, 응답 구조를 설명하기 위해 필요한 필드만 정리한 예시이다. 실제 조회 시 각 설명 위치에 문자열·숫자·불리언 값이 반환된다.

```
  "previous": 이전 페이지 주소 또는 null,
  "total": 조회 가능한 전체 수록곡 수,
  "items": [
    {
      "artists": [
        {
          "external_urls": {
            "spotify": 해당 아티스트의 Spotify 페이지 주소
          },
          "id": 해당 아티스트의 ID,
          "name": 해당 아티스트의 이름
        }
      ],
      "duration_ms": 해당 곡의 재생시간,
      "explicit": true 또는 false,
      "external_urls": {
        "spotify": 해당 곡의 Spotify 페이지 주소
      },
      "id": 해당 곡의 ID,
      "name": 해당 곡의 이름
    }
  ]
}
```

**결과의 어디를 읽어 컬럼에 넣는가?**

- 먼저 "items": []를 찾는다. 그 안에 들어 있는 곡 정보 객체 하나를 기준으로 아래 값을 읽는다.

| 저장할 컬럼 | 결과에서 찾을 부분 | 읽는 방법
| --- | --- | --- |
| track_id	| 곡 정보 객체의 "id"	| 곡 ID를 그대로 저장 |
| track_name	| 같은 곡 정보 객체의 "name" | 곡명을 그대로 저장 |
| artists_id	| "artists" 안의 각 아티스트 객체에 있는 "id" | 전부 읽어 ;로 연결 |
| artists_name	| 같은 아티스트 객체들에 있는 "name" | ID와 같은 순서로 읽어 ;로 연결 |
| duration_ms	| 곡 정보 객체의 "duration_ms" | 숫자를 정수로 저장 |
| explicit	| 곡 정보 객체의 "explicit" | true/false를 저장 |
| play_url	| 곡 정보 객체의 "external_urls" 안에 있는 "spotify" | 곡 페이지 주소를 저장 |

- id, name, external_urls가 여러 번 나오는 이유는 아티스트와 곡이 각각 자기 정보를 가지고 있기 때문이다.
  - 'artists' 안의 id·name·URL → 아티스트 정보
  - 'artists' 밖이면서 같은 곡 객체 안의 id·name·URL → 곡 정보
  - 조회에 사용한 앨범의 'album_id', 'album_name', 'album_release_date'를 해당 앨범에서 반환된 각 곡의 정보에 함께 저장한다.
