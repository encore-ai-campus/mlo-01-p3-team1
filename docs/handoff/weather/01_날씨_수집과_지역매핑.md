# 01. 날씨 수집과 지역 매핑

- 수정일: 2026-10-13
- 프로젝트 적용 결정: 같은 네트워크의 로컬 Kafka/Spark 클러스터에서 새 날씨 파이프라인을 구현하고 최종 AWS로 이전합니다. 원문은 로컬과 S3에 함께 보관합니다. S3 실패 재시도·해시/사본 상태·보관/재처리 상세는 [최신 구현 가이드](../../product/3차_구현_결정과_익명문맥_원문보관_가이드.md)를 따릅니다.
- 화면은 날씨 패널만 유지하며 별도 강수 카드/X/닫기 상태는 제거합니다. 소나기·빗방울은 비, 기본 눈날림은 눈+구름많음 적합도 결합이며 비율/PTY6은 미정입니다. Gemini 재설정도 서버의 같은 적격 기준을 따릅니다. 원본 PTY 표현은 보존합니다.
- 아래 기존 로컬 시험 코드/경로/수치 설명은 인계 출처의 이력입니다. 현재 저장소에 코드가 구현됐거나 AWS/S3 업로드가 완료됐다는 뜻은 아닙니다.

재석 담당: 날씨 수집·JSON 변환·정제·저장 코드. 인건님 담당: 운영 서버·클러스터 환경.
음악 추천은 음악 담당자 구현. 우리 쪽은 추천에 사용할 날씨 제공.
3차 목표: 서비스 조회와 추후 ML 학습에 사용할 날씨 이력 확보.

## 읍면동 → nx·ny

기상청 공식 매핑표의 지역코드·이름·격자 사용. 지역코드 직접 생성 없음.
시도 / 시군구 / 읍면동 함께 저장. 같은 동 이름도 상위 지역으로 구분.

1. 공식 매핑표에서 읍면동 이름이 있는 행 선택 → 3,564행.
2. 지역 3,564행은 유지하고 nx·ny 쌍만 중복 제거 → 1,625쌍.
3. 실황·초단기·SNO 전국 응답에서 이 1,625쌍에 해당하는 값 선택.

숫자는 2026년 7월 기상청 매핑표 기준. 현재 파일은 `pipeline/mapping.json`.
A동·B동이 모두 (58,125)이면 지역 두 개 유지, 날씨 격자 하나 공유. 설명용 예시.
시·도·시군구 272개도 같은 공식표의 대표 좌표 사용. 기존 목록 밖 6격자 추가 선택 → 조회용 총 1,631격자.
읍면동 1,625격자 기준은 유지. 상위 지역 날씨는 지역 전체의 평균이 아닌 공식 대표 지점 날씨.

기본 API 응답은 149×253=37,697개 값. 3,564개 지역과는 다른 개수.
0부터 세는 배열 위치: `(ny-1) × 149 + (nx-1)`. nx가 먼저 증가.
바다를 제외해 1,625개를 만드는 것이 아니라 공식 대표 격자 목록으로 선택.

## KIM 구름량 연결

KIM은 별도 모델 격자. KIM의 ix·iy와 서비스 nx·ny는 다른 좌표.
우리 1,625격자의 대표 위경도를 포함하는 영역을 CSV로 수집.
같은 nx·ny에 여러 읍면동이 있으면 읍면동 대표점들의 평균 위치에 가장 가까운 한 점 사용.
Spark가 그 지점에 가장 가까운 KIM 모델 격자를 선택하고 우리 nx·ny에 연결.
선택한 모델 ix·iy·위경도·대표점과의 거리도 보관. 좌표 선택 규칙은 `nearest_kim_grid_v1`.

## 정기 수집 흐름

`기상청 API 허브 → Collector → Kafka weather.v1 → Spark → MongoDB / Elasticsearch`

| 자료 | 수집 기준 | 사용 내용 |
|---|---|---|
| 실황 | 10분 간격 | 현재 실황 8항목 |
| 초단기예보 | 1시간 간격 | 미래 6시간 × 11항목 |
| SNO | 3시간 발표 기준 | 가까운 9개 대상 시각의 1시간 신적설 |
| KIM tcld | 초단기 대상 범위와 연결 | 3시간 간격 대상 시각의 예측 구름량 |

Collector에서 원문 gzip 보관·JSON 이벤트 생성. Spark에서 격자 선택·단위·품질 정리.
MongoDB에 이력, Elasticsearch에 최신 조회 묶음 저장.
로컬 run_local.py에서 새 회차 자동 수집·Kafka 전송. 같은 요청 회차는 재호출 제외.
실황은 해당 10분 관측 시각부터 요청, 미제공·실패 항목은 1분 뒤 재확인. 성공 항목은 재호출 제외.
초단기는 xx:30 발표 뒤 15분 여유 후 요청. 새 실황 미도착 동안 기존 자료 유지.

## 사용자 조회 흐름

`읍면동 선택 → 지역 매핑에서 nx·ny 확인 → ES 최신 날씨 조회 → 음악 추천 로직 → 플레이리스트`

사용자 요청마다 기상청을 다시 호출하지 않고 이미 저장된 날씨 조회.
지역코드는 지역 식별, nx·ny는 날씨 선택 기준. 역할 구분.
서비스 입력 안내는 읍·면·동 기준. 검색은 상위 시·도 → 시군구 → 읍면동 → 리 순서.
서울 입력 시 서울특별시 우선. 태안 남면·구로동처럼 글자 순서와 중간 생략 허용.
리 15,203개는 공식 법정리 자료의 상위 읍면으로 연결. 주소 검색 목록은 dashboard/regions.json.
도로명주소 → 공식 주소 DB의 행정동 코드 → 기존 nx·ny → ES 조회. 별도 주소 API 키 불필요.
행정안전부 도로명주소 한글 2026년 9월 전체분: 6,424,765주소 중 6,381,746주소 연결.
미연결 43,019주소는 임의 좌표 대체 없이 읍면동 입력 안내. 행정동 코드가 참고용임에 유의.
도로명·건물번호로 검색, 동·호수는 입력 대상 제외. 주소 DB 갱신 자동화는 미연결.
[공식 주소 자료·스키마](https://business.juso.go.kr/jst/jstAddressDownload) 기준, 로컬 SQLite 조회.
