# 03. 날씨 저장·조회 구조

수정일: 2026-10-14. 저장 방향 확정, 운영 연결은 후속 작업.
날씨 원천 응답 파일 미보관. 날씨 경로에서 MongoDB 제외, 신규 그림의 MongoDB는 광고용.

## 어디에 저장하나

| 데이터 | 저장·조회 |
|---|---|
| 읍면동·도로명 → nx·ny | PostgreSQL. 현재 JSON·SQLite에서 이관 예정 |
| 최신 실황·예보·보완값·공통 특징 | Elasticsearch. 음악·화면 담당의 서비스 서버에서 조회 |
| ML용 정제 날씨 이력 | 개인 로컬. 파일 형식·보관 기간·적재 연결 미정 |
| API 수집 로그 | 현재 로컬 requests.jsonl. 운영은 ES pipeline-logs-v1 → Kibana 연결 방향 |
| 추천에 사용한 날씨 묶음 | 추천 결과와 함께 고정 보관. 추천·백엔드 담당 저장 연결 |
| API 원천 응답 | 메모리 해석 → JSON 발행. 별도 gzip·전체 응답 파일 보관 없음 |

Kafka는 전달·단기 재처리 경로. 보관 기간 이후 원천 재처리 보장 없음.
날씨를 PostgreSQL에도 중복 저장하지 않음. 기존 MongoDB·원문은 과거 시험 자료.

## 수집과 조회

`기상청 → Collector → Kafka → Spark 정제 → ES 최신 자료 갱신`
`사용자 지역 입력 → 서비스 서버 → PostgreSQL 매핑 → nx·ny → ES → 날씨 화면·음악 추천`

ES도 저장소. 스트림은 새 자료를 계속 처리하는 방식이며 조회와 양립.
현재 로컬 인덱스 weather-stream-current-v1-local, 문서 ID nx_ny. 운영 인덱스명은 인계 시 조율.
사용자 조회마다 기상청 호출 없음. 새 자료가 정상 도착하면 갱신, 먼저 기존 자료 삭제 없음.
수집 실패 시 기존 값·시각 유지. 만료 여부는 조회 시 다시 판단.

## 회차·특징·이력

실황은 같은 관측 시각의 8항목 도착 후 전환. 일부 도착은 이전 완성 회차 유지.
도착한 값이 결측이면 NULL. 항목별 과거 정상값으로 메우지 않음.
초단기는 6시각×11항목 완성 회차 우선. 최초 불완전 회차는 부분 상태 표시.
같은 이벤트 중복 처리, 과거 발표가 최신을 덮지 않음. 발표가 다르면 서로 다른 예보.
sky_context는 현재 정시 연결용 최근 SKY·KIM 문맥. 장기 이력 아님.
하늘·체감·눈 강도·주야간 등 공통 계산 결과도 ES 제공 방향.
현재 dashboard/server.py가 조회 시 계산. 특징 ES 적재는 아직 미구현.
시간 경과에 따른 만료·요청 3시간 범위는 조회 때 재검사.
개인 이력에는 격자·출처·항목·발표/대상/수신 시각·값·품질·규칙/매핑 버전 보존 방향.
추천 당시 묶음은 최신 문서 ID만 참조하지 않고 사용값·시각·버전 함께 보관.

## 매핑·로그 인계

PostgreSQL 테이블 후보: region(공식 코드·계층·nx·ny·버전),
road(도로명·행정구역), road_address(주소번호·건물번호·행정동·격자·연결 상태),
metadata(자료 월·버전·행 수). 실제 DDL·월 갱신 미구현.
재석은 매핑 구조·적재 코드 준비, 공통 백엔드와 생성/갱신 담당 조율.
ES는 인덱스·문서 키·필드·단위·시각 형식을 예시 JSON으로 공유.
API 로그는 수신·Kafka 발행·ES 반영 결과 구분. 인증키·원천 본문 제외.
공용 로그 전송·보관 기간은 후속 확정.
