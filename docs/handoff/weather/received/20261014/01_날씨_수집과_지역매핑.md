# 01. 날씨 수집과 지역 매핑

수정일: 2026-10-14. 재석 담당은 수집·정제·전달 코드, 인프라 담당은 실행 환경·클러스터.
확정: 원천 파일 미보관, MongoDB 제외, 검증된 기존 코드 재사용.
지역·도로명 매핑은 PostgreSQL, 최신 날씨는 ES, ML용 정제 이력은 개인 로컬 보관 방향 확정.

## 읍면동 → 격자

1. 기상청 공식표에서 읍면동 행 선택: 현재 자료 3,564행.
2. 지역 행은 유지, nx·ny 중복 제거: 1,625쌍.
3. 전국 배열 149×253=37,697값에서 해당 격자 선택.

배열 위치 `(ny-1)×149+(nx-1)`, 0부터 시작. 바다 제거가 아닌 대표점 선택.
같은 격자의 여러 읍면동은 날씨 공유. 지역코드는 기상청 값, 직접 생성 없음.
상위 지역 272개 대표점은 6격자 추가, 조회용 총 1,631격자. 지역 전체 평균 아님.
pipeline/mapping.json 버전 2026-07-01. 자료 개수는 이 버전 기준.
KIM ix·iy는 별도 모델 격자. 대표 위경도에서 가까운 모델 격자를 nx·ny에 연결.
모델 좌표·거리 보존. 원래 SKY 유지, 같은 대상 시각 KIM으로 서비스 하늘 상태 세분화.

## 정기 수집

`API허브 → 메모리 JSON → Kafka weather.v1 → Spark 정제 → Elasticsearch 최신 갱신`

| 자료 | 기준 |
|---|---|
| 실황 | 10분 관측 회차, 8항목 |
| 초단기 | 1시간 발표 회차, 미래 6시각×11항목 |
| SNO | 3시간 발표 회차, 가까운 9시각 |
| KIM | 현재 정시 + 초단기 대상까지 1시간 간격, 같은 발표·대상 요청 재사용 |

실황은 해당 관측 시각부터 요청, 초단기는 xx:30+15분부터.
최신 요청 우선, 실패한 이전 요청은 별도 큐 유지.
새 경로에서 원천 gzip·전체 이벤트 파일 생성 없음. 요청 결과 메타데이터만 기록.
새 자료를 처리하는 스트림과 결과를 저장·조회하는 ES를 함께 사용. 날씨의 PostgreSQL 중복 적재 제외.
체감·일출/일몰은 기존 기온·습도·풍속·좌표로 계산. 추가 기상 API 요청 없음.

## 사용자 조회

`지역·도로명 입력 → PostgreSQL 매핑 조회 → nx·ny → ES 최신 날씨 → 서비스 서버`
서비스 서버에서 사용자 날씨 화면 표시 + 음악 담당 추천 로직에 전달 → 플레이리스트.

사용자 조회마다 기상청 호출 없음. 실제 음악 연결은 별도 통합.
리 15,203개는 상위 읍면 매핑. dashboard/regions.json 사용.
도로명 → 공식 행정동 코드 → nx·ny. 현재 로컬 SQLite 기준표 사용.
202609 자료 6,424,765주소 중 6,381,746 연결. 43,019 미연결은 읍면동 입력 안내.
운영 매핑은 PostgreSQL로 이관 예정. 현재 JSON·SQLite 조회와 구분.
주소 월 갱신·이관 미구현. 테이블 생성·갱신 실행 담당과 접속 정보는 공통 백엔드·인프라 담당과 조율.
