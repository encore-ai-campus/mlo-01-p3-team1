## 0. 문서만으로 같은 동작을 만드는 기준

같은 **자료·정책/선택 정의·설정 버전과 같은 입력**에서는 동일한 요청 해석, 상태 전이, 필수 검증, 오류 및 저장 결과를 구현합니다. 기본 추천의 동점/순서는 아래 기준으로 고정합니다. 외부 Gemini 응답의 곡 목록 자체가 매번 같다는 보장은 하지 않으며, 동일한 모의 응답을 넣었을 때는 동일하게 합격/거절해야 합니다.

최신 사용자 결정 → 확정된 도메인 정책 → 본 문서의 공통 형식/상태 계약과 구현 설계도의 상세 기능 → 참고 시안/원본 인계 자료 순으로 해석합니다. 본 문서와 설계도에 같은 항목이 다르게 적혀 있으면 임의로 한쪽을 선택하지 말고 충돌을 정정합니다. 보류 항목은 각 개발자가 추측한 값을 넣는 영역이 아닙니다.

| 구현 기준 | 개발자가 선택할 수 없는 부분 |
|---|---|
| 입력 | 생략 기본값·null·상속·빈 배열·제외 전체 집합의 의미 |
| 화면 | 초기 상태·저장/생성 중·충돌/실패·버튼 활성 조건·결과 귀속 |
| API/저장 | 경로·필드/타입·상태/오류·소유·revision·멱등 범위·원자 이벤트 |
| 추천 | 모드별 필수 필터·ON 75:25/OFF P_OFF·시간 우선순위·새 곡20%·기본/Gemini 경계 |
| 미정 사항 | 공통 차단 상태·담당·필요 자료. 구현별 임의 fallback 금지 |

아래 계약과 가상 예시를 A/B/C의 공통 수용 기준으로 사용합니다. 각 담당이 별도 API 이름·상태값·필터·성공 기준을 만드는 방식으로 구현하지 않습니다.

## 1. 개발 기준 기술

| 영역 | 이번에 정리한 기준 | 실제 적용 단계 |
|---|---|---|
| 공개/관리 화면 | React + TypeScript + Vite | C는 공개/음악/피드백 화면, B는 광고 관리 화면. 공통 라우팅·스타일은 C 조율 |
| 온라인 API | Python FastAPI + Pydantic, 도메인별 APIRouter | 인증/날씨/추천/음악 관리/피드백/광고를 분리. 동일 서비스 origin을 기본으로 개발 |
| 온라인 업무 저장 | PostgreSQL + SQLAlchemy/Alembic | 소유·작업·결과·상태/outbox·광고의 개발 기준. 실제 인스턴스/버전/접속은 INF 자료로 확인 |
| 음악 저장 | 추천·표시18개 및 검수 보조값의 RDB 어댑터 | 원본 정밀도 energy/acousticness/valence의 불변 참조가 별도로 필요. 제품/DDL·실제 CSV 발행은 확인 대기 |
| 기본 추천 | 별도 Python 작업자 + OR-Tools CP-SAT | 정수 ms·필수 필터·시간 우선순위·범위/UNKNOWN 검증. W 정책은 주입 가능하게 분리 |
| 재설정 | 서버의 Google Gen AI Python SDK `google-genai` 어댑터 | 사용자 확정 모델 gemini-3.8-flash. 계정 한도/예산은 확인 대기. 명시 재설정에만 호출하며 기본 규칙과 독립 |
| 비밀번호 | Argon2id 기반 검증된 라이브러리 | `argon2-cffi`를 사용한 해시/검증 어댑터 기준. 최소 m=19MiB,t=2,p=1에서 실제 호스트 비용을 측정하고 저장 파라미터로 검증 |
| 공통 명세 | JSON Schema Draft 2020-12 + FastAPI 모델에서 OpenAPI 생성 | [기계 판독 계약](../contracts/3차_공통_API_이벤트.schema.json)을 코드 모델과 대조. 실제 OpenAPI는 서버 구현 시 생성 |

위 FastAPI/SQLAlchemy는 목표 문서 계약입니다. 현재 수령된 추천/음악 backend와 독립 광고는 Django이며, 이번 로컬 재생을 위해 프레임워크를 전환하지 않습니다. 정본 변경 라우팅에서 실제 구현·어댑터·미이식 부분을 구분합니다.

정확한 패키지 버전은 설치 환경을 대조한 뒤 잠금 파일로 고정합니다. 문서에 확인하지 않은 설치 버전을 기재하지 않습니다. 기존 태스크의 직접 선행 조건을 건너뛰거나 환경 검증을 완료 처리하지 않습니다.

FastAPI의 OpenAPI/JSON Schema 기반 모델 문서화는 [공식 기능 설명](https://fastapi.tiangolo.com/features/), SDK 선택은 [Google 공식 라이브러리](https://ai.google.dev/gemini-api/docs/libraries), 해시 기준은 [OWASP 비밀번호 저장 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), 스키마 형식은 [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)를 참고했습니다. 이 자료들은 추천 품질이나 본 서비스의 실측 결과를 보장하지 않습니다.

## 2. API 공통 형식

- 기존 `/api` 경로·HTTP 메서드·3차/4차 구분은 설계도7절을 유지합니다. 일괄 `data` wrapper를 새로 씌우지 않고 기능별 응답 필드를 사용합니다.
- JSON은 UTF-8·snake_case입니다. ID는 불투명 문자열이며 외부 음악 ID는 원문을 유지합니다. 국가·언어 필드, 임의 owner/role/account ID를 요청에 추가하지 않습니다.
- region_id만 있는 기본 요청은 허용합니다. weather_influence_mode=ON/OFF는 선택 입력이며 생략 시 ON입니다. vocal_option=any/instrumental_only, tempo_preference=auto/slow/fast, theme/genre는 각각 배열입니다. 테마·장르의 0개/전체 선택은 각 그룹에서 같은 ANY로 정규화합니다.
- 빠르기 원본 speed는 slow/medium/fast/fastest입니다. 화면은 auto/slow/fast를 사용합니다. fast 선호에 fast/fastest를 대응시키는 현재 매핑을 유지하고 medium을 새 사용자 선택으로 추가하지 않습니다.
- 취향·제외 **집합**만 중복 제거·정규 정렬합니다. 곡 재생 순서와 아티스트 ID/이름 대응 순서를 바꾸지 않습니다.
- 값 누락과 null은 다릅니다. 평가 취소는 값 필드를 명시적으로 null로 보냅니다. integer를 boolean/숫자 문자열에서 강제 변환하지 않습니다. API 모델은 strict integer를 사용하고 소수 입력도 거부합니다. JSON Schema integer 판정과 실제 API strict 타입 검사를 각각 확인합니다.
- 추천 등록/재설정·제외·평가·승인과 설계도에서 명시한 관리 업무 변경은 Idempotency-Key를 사용합니다. 필수 키 누락/빈 값은 VALIDATION_ERROR/422입니다. 로그인/로그아웃은 인증/CSRF 계약, 광고 행동 수신은 delivery/event_id 중복 계약을 각각 따릅니다. 별점/곡 반응·제외·승인은 서로 다른 revision 범위입니다. HTTP 성공/작업 등록과 비동기 작업의 성공을 구분합니다.
- 서버가 request_id를 만들고 응답의 X-Request-ID로 제공합니다. 오류 본문에도 request_id를 넣으며 개인 접근 토큰/비밀키는 응답·로그에 넣지 않습니다.
- 응답의 X-Contract-Version은 본 계약 버전을 표시합니다. policy_version·catalog_version·option_version·duration_policy_version·prompt/schema_version을 이 값 하나로 대체하지 않습니다.
- 시각은 API/온라인 이벤트에서 UTC ISO 8601의 Z 형식으로 직렬화합니다. 날씨 인계의 +09:00 시각은 같은 순간으로 변환하고 발표/대상/수신을 별도로 보존합니다. 부분 앨범 발매일은 시간으로 바꾸지 않습니다.
- 기간 조회는 from 포함/to 미포함입니다. 관리 화면 입력/표시는 KST, 저장은 UTC입니다. 날짜 단위 범위는 KST 자정으로 해석해 UTC 경계로 변환합니다.
- 관리자 제외 이력은 기존 occurred_at/event_id 내림차순·next_cursor·as_of를 사용합니다. 커서는 필터·기준 시각·마지막 행에 묶은 불투명 값이며 임의 페이지 번호/offset으로 바꾸지 않습니다. 최신 상태는 날짜 필터 밖 이벤트도 포함해 해당 as_of 기준으로 계산합니다.
- 개발용 조회 페이지는 기본20/최대100을 설정값으로 둡니다. 실제 조회 규모를 측정해 조정하며 운영 성능 합격 수치로 주장하지 않습니다.

### 2.1. 요청·응답 정의 연결

| 기계 판독 정의 | 기존 경로/용도 |
|---|---|
| BasicRequest | POST /api/recommendation-jobs; 독립 추천의 제외는 빈 목록 |
| RegenerationRequest | POST /api/playlists/{id}/regenerations; 저장된 exclusion_revision 필수 |
| ExclusionReplaceRequest | PUT /api/playlist-families/{family_id}/exclusions |
| ReactionPutRequest / RatingPutRequest | 곡 반응·선곡표 별점 PUT |
| ApprovalRequest | POST /api/playlists/{id}/approval |
| JobAcceptedResponse | 202 job_id/status/poll_url |
| FeedbackReadResponse / FeedbackPutResponse | GET /api/playlists/{id}/feedback 및 평가 PUT |
| JobStatusResponse | GET /api/recommendation-jobs/{id} |
| ExclusionReadResponse / ExclusionWriteResponse | 제외 GET/PUT |
| ApprovalResponse | 승인 POST |
| ErrorResponse | 공통 오류 본문 |
| WeatherMeasurement | raw/value/unit/status. 전체 날씨 조회 응답은 A 인계 자료로 보완 |
| GeminiProposal | track_ids/summary/track_reasons. 서버 의미 검증 별도 |
| FeedbackEventEnvelope | 확정된 평가 변경/취소 이벤트의 공통 필드. 곡 스냅샷 필수 payload는 담당 자료로 보완 |

반환 곡이 등록 목록에 있는지, ID/이유 대응, 소유/초안 revision·현재 승인 가능 여부, ON의 활성 W 또는 OFF의 P_OFF 정책, 총시간/ON의 유효 예보와 신규 곡 수는 JSON 형태 검사만으로 판정할 수 없습니다. 서버 도메인 검사를 함께 구현합니다. outbox의 snapshot 참조만 Kafka로 보내 현재 곡을 조회하는 구현은 허용하지 않습니다. 발행 payload에는 기존 설계도의 당시 조건/곡 필수값도 포함합니다. 현재 기계 판독 FeedbackEventEnvelope는 **공통 envelope 정의**이며 payload의 완성 스키마가 아닙니다. 이 스키마는 전체 발행 payload에서 정의된 공통 필드를 추출한 객체에 적용합니다. 스냅샷 필드를 additionalProperties 오류라는 이유로 발행에서 버리지 않으며, 완성 payload 스키마는 담당 자료에 맞춰 보완합니다.

### 2.2. 오류 처리 통일

| 상황 | 처리 |
|---|---|
| 국가·언어 관련 입력 | OPTION_NOT_SUPPORTED / 400 |
| 잘못된 선택 코드 | OPTION_INVALID / 400 |
| 별도400 예외에 해당하지 않는 값 필드 누락·타입/범위·알 수 없는 입력 필드 | VALIDATION_ERROR / 422 |
| 같은 범위/멱등 키에 다른 정규 본문 | IDEMPOTENCY_CONFLICT / 409로 통일 |
| 오래된 제외/평가 revision | EXCLUSION_REVISION_CONFLICT / FEEDBACK_REVISION_CONFLICT / 409 |
| 인증/권한/소유/만료 | 설계도7-4의401/403/404/410 구분 유지 |
| 비동기 실패 | 작업 FAILED + error.code. 부모 성공 결과를 실패 결과로 바꾸지 않음 |

IDEMPOTENCY_KEY_CONFLICT는 별도 오류 이름으로 늘리지 않고 IDEMPOTENCY_CONFLICT로 통일했습니다. 멱등 재전송은 소유/유효 보관 검사 후 원래 성공 응답을 revision 재검사보다 먼저 반환합니다. 무변경 요청은 revision/event/집계를 증가시키지 않습니다.

### 2.3. 기존 대시보드의 외부 기본 재생과 분리 검수

최신 사용자 선택은 키 없는 YouTube 외부 재생을 기본, iframe을 접이식 보조로 사용하는 방식입니다. 기본 KEYLESS는 LLM/YouTube Data API를 호출하지 않고 각 경로에 맞는 레지스트리 확인값을 읽습니다. `GET /api/playlists/{id}/youtube-queue`는 본인 결과/원본 곡 범위·native 승인 ID를 결과 상대 순서대로 묶고 준비수/누락·전체/부분 여부와 임시 URL을 제공합니다. 일부만 준비되면 명시 부분 열기로 구분하며 원본176~184분 성공 결과를 수정하지 않습니다.18개·전체GENERAL 후보·평가/제외/승인은 유지합니다. 상세는 [재생 가이드](../development/music/YouTube_로컬_재생_기획과_구현_가이드.md)를 따릅니다.

큐 응답은 playlist_id, tracks[{track_id,video_id,source}], missing[{track_id,track_name,reason}], total_count, ready_count, is_complete, url, queue_kind=TEMPORARY_NATIVE_QUEUE, account_saved=false입니다. 원본 상대 순서·준비/누락을 표시하고 누락이 있는 목록은 명시 부분 열기로 안내합니다. 응답/링크 생성은 실제 전곡 PLAYING이나 계정 저장 완료가 아닙니다.

운영자 검수는 LOCAL_DEMO+실행코드 헤더 `X-Youtube-Review-Code`와 기존 CSRF 경계를 사용하며 운영 모드는503입니다. 상태 안내 외 자료/전역 검색은 운영자 전용이고 playlist_id 조회는 본인 소유도 검사합니다. 신규 URL/CSV는 native/iframe 모두 미확정입니다. `/verify`의 iframe PLAYING 보고/원곡확인/양의 길이와 `/native-verify`의 외부 PLAYING 수동 보고/원곡확인/길이를 구분합니다. 원본 초 d에 대해 길이차≤min(60,max(12,0.12*d))를 검사하되 길이만으로 원곡을 확정하지 않습니다. native 전용 예외는 duration_difference_confirmed=true·메모 필수·절대 길이차60초 이내를 모두 만족해야 하며 VERIFY_NATIVE_DURATION_DIFFERENCE_ACK로 감사를 남깁니다. iframe의 기본 길이 허용차는 변경하지 않고 원본 추천 시간도 유지합니다. `/block`과 `/native-block`은 각각 해당 경로의 영상 대안만 변경하며 다른 검수값을 유지합니다. 공개 오류로 자동 변경하지 않습니다.

native_verified/native_duration_seconds/native_observed_at/native_source/native_reason은 iframe 판정과 별도입니다. 새 native 확인의 출처는 OPERATOR_NATIVE_REPORTED_PLAYING, 과거 원곡/버전·길이·목록 포함/순서 근거 복원은 LEGACY_NATIVE_METADATA_REVIEW로 구분합니다. 과거 근거 복원을 현재47곡 PLAYING·완주/음향·iframe 가능 확정으로 표시하지 않습니다. 브라우저 보고는 서버의 물리 소리·파형/완청 입증이 아닙니다.

expected_revision은 track_id별 버전이며 같은 곡의 모든 영상 대안이 공유합니다. CSV는 UTF-8 BOM·1MiB·최대500행과 헤더 track_id/video_url/expected_revision/note(선택)를 사용합니다. 같은 곡의 다른 대안은 최대10개 허용하되 배치의 해당곡 expected_revision은 같아야 하고 같은(track_id,video_id) 중복은 거절합니다. 모든 행의 형식·존재·중복·revision을 확인한 뒤 원자 저장하며 어느 한 행 실패도 부분 적용하지 않습니다. 오래된 revision은409로 최신값 재조회/편집 보존 후 다시 확인합니다. 음악 카탈로그·피드백/outbox와 별도 저장이며 등록/검수로 추천·평가 이벤트를 만들지 않습니다.

펼친 보조 iframe에서 자동재생 차단이면 현곡/명시 재생을 유지하고 실제 PLAYING 뒤 ENDED를 한 번만 처리합니다.150/101 삽입 제한과153 Referer/client 식별 문제·검색 불가를 분리해 안내하며 우회하지 않습니다. 같은 원곡 대안 소진/건너뛴 곡은 별도 기록하고 전곡 재생 완료로 표시하지 않습니다. 설정/제외 미반영·생성/저장 중에는 재생/요청을 멈추고 해제 후 명시 재개합니다. 실패/재생 사건은 기존 피드백·승인/광고 이벤트 및 오류와 격리합니다.

보조 iframe KEYLESS의 `MAPPING_REQUIRED`는 reason=UNMAPPED/PENDING/BLOCKED·mapping_revision을 전달하고 해당 곡 누락 기록 후 다음 곡을 처리합니다. `SEARCH_UNAVAILABLE`의 운영 레지스트리 미연결/저장소 기술 장애는 현곡 보류이며 전곡 누락으로 바꾸지 않습니다. 등록 후 같은 불변 결과에서 재생 연결을 다시 확인할 수 있고 새 추천/승인으로 가장하지 않습니다.

기본 native 임시 URL은 watch_videos의 영상ID 목록이며 계정에 저장한 영구 재생목록/공식 영구 링크 보장이 아닙니다. iframe150으로 native 이용 불가를 판정하지 않고 native 승인만으로 iframe을 통과시키지 않습니다. 실제 Chrome 로그인/Premium은 브라우저 문맥에 따르며 키 없는 등록/재생·계정 OAuth와 별개입니다. 광고 제거·전곡 완주·음원 배포·운영 Gold·공유 ADMIN/AWS 완료를 이번 예외로 주장하지 않습니다. 선택 편집·제외 미반영·생성/저장 중에는 외부 열기와 보조 iframe을 보류합니다.

## 3. 기본 추천과 재설정의 고정 기준

일반 추천에는 별도 시즌 판정 GENERAL만 허용하고 SEASONAL_EVENT 제외·REVIEW_REQUIRED/UNSCREENED 보류를 공통 적용합니다. 판정 버전·근거는 당시 조건/곡 스냅샷과 연결하며 원본18개·점수·날씨 합격 풀은 보존합니다. 로컬 분석/재생의 실제 연결 범위와 수령 원문 차이는 [정본 변경 라우팅](../development/음악_재생_정본_변경_라우팅.md)에 기록합니다.

1. 공통 카탈로그 등록/검수·보컬·제외·중복·양수 duration_ms와 요청 모드별 후보 자격을 기본/Gemini에 동일하게 적용합니다. ON만 유효 날씨와 W 합격을 요구합니다. OFF는 날씨 자료 부재로 실패하지 않습니다.
2. ON은 5개 날씨×2프로필의 E/A 핵심≥20, W≥75로 후보를 거른 후 활성 취향 P_legacy와 S_ON=.75W+.25P_legacy(미선택이면 W)를 적용합니다. OFF는 별도 P_OFF 40:40:5:15 점수와 선택 장르 100% 우선·불가 입증 후 80% 이상 규칙을 적용합니다. 수식·계수·NULL은 [후보 산출 가이드](./카페_음악_추천_서비스_3차_컬럼_기반_추천_로직_가이드.md)가 기준입니다.
3. 두 모드 모두 STANDARD 목표10,800,000ms, 범위10,560,000~11,040,000ms입니다. 정확히180분→가까운 초과→가까운 부족·같은 시간의 가중 품질 순서입니다. 후보 창은 200→400→800→1,600→전체 적격으로 확장합니다. OFF의 장르 100% 단계가 80% 완화 단계보다 우선합니다.
4. 새 Gemini 결과는 부모 전체 고유 곡 수 N에 대해 max(1,N//5) 이상의 신규 곡을 포함해야 합니다. 모드별 필수 조건과 시간 조건도 모두 통과해야 합니다.
5. ON 정책/필수 날씨가 준비되지 않으면 POLICY_NOT_READY/FORECAST_UNAVAILABLE로 처리하고 OFF로 자동 전환하지 않습니다. OFF에는 이 오류를 후보 산출 차단으로 적용하지 않습니다. 두 모드 모두 176분 미만 자동 단축은 없습니다.
6. RULE_BASED 결과의 모델/프롬프트 필드는 null, GEMINI_RECONFIGURE에만 실제 SDK/모델/프롬프트·시도/목록 해시를 기록합니다.
7. 좋아요/싫어요·별점은 결과 버전에 귀속하며 자동 제외·승인·추천 점수 변경·Gemini 호출을 만들지 않습니다.

## 3.2. 기본 추천의 동점·순서와 외부 응답 판정

- 같은 총시간에서는 Q=sum(duration_ms_i*score_i)/total_ms로 재생시간 가중 품질을 비교합니다(score_i=ON의 S_ON, OFF의 P_OFF). OFF에 선택 선호가 없어 P_OFF=NULL이면 후보 산출 가이드의 안정적 시드 순서를 적용합니다. 비교용 값을 화면 표시 때문에 반올림하지 않습니다.
- 시간 구간·목표 거리·Q까지 같으면 곡 ID 집합을 코드 포인트 오름차순으로 정렬한 배열의 사전순이 작은 조합을 선택합니다. DB의 임의 행 순서·시스템 locale·무작위 값을 동점 기준으로 쓰지 않습니다.
- 기본 결과 재생 순서는 해당 모드의 점수 내림차순, 동점이면 track_id 코드 포인트 오름차순입니다. OFF 점수가 NULL인 무선호 요청은 고정 시드 순서를 사용합니다. Gemini는 검증된 track_ids의 응답 순서를 유지합니다.
- 후보 확장 단계·상한·탐색 예산은 버전 설정으로 고정하며 같은 환경의 공통 설정을 사용합니다. 후보 조회 순서를 명시하고 같은 설정/고정 입력 fixture로 재현합니다. 미확정 탐색 수치를 개인별 기본값으로 운영하지 않습니다.
- solver 시간 초과/UNKNOWN은 SEARCH_INCOMPLETE입니다. 시간/품질 우선순위를 확인하지 못한 결과를 최적 성공으로 표시하지 않습니다. INFEASIBLE은 확인한 탐색 범위를 함께 기록합니다.
- Gemini 이유는 선택한 각 ID당 정확히1개이며 중복/누락/목록 밖 이유는 PROVIDER_RESPONSE_INVALID입니다. 응답에 없는 곡의 이유를 서버가 생성해 채우지 않습니다.
- ON의 POLICY_NOT_READY·FORECAST_UNAVAILABLE 또는 명시 재설정의 RECONFIGURATION_UNAVAILABLE는 접수 전 확인되면 해당 코드/503으로 작업을 만들지 않습니다. 접수 이후 작업자가 발견하면 FAILED+같은 error.code이며 성공 결과를 만들지 않습니다. 대기 중 기준 시각/예보가 만료된 ON 작업은 EXPIRED/JOB_EXPIRED입니다. OFF의 예보 만료는 추천 작업 만료 원인이 아닙니다.

## 3.3. 저장·오류 판정 순서

1. 관리자 인증/CSRF 또는 공개 문맥을 확인하고, 문법 오류 JSON은 VALIDATION_ERROR/422로 처리합니다.
2. 3차 국가·언어 필드는 OPTION_NOT_SUPPORTED/400입니다. 필수 region_id 생략/빈 값은 REGION_REQUIRED/400, 재설정/승인의 exclusion_revision 생략은 EXCLUSION_REVISION_REQUIRED/400으로 예외 매핑합니다. 다른 required/type/range/unknown field 오류는422입니다. 문자열 형식이 맞지만 선택 enum/코드가 없으면 OPTION_INVALID/400입니다.
3. 본인 자료의 존재/소유·유효 보관을 확인합니다. 타 소유/없음은404이며 그 자료의 revision/저장값을 노출하지 않습니다.
4. 같은 범위·멱등 키의 저장 성공 기록을 확인합니다. 정규 요청이 같으면 원래 응답, 다르면 IDEMPOTENCY_CONFLICT/409입니다. 재전송 성공의 request_id/updated_at/event_id도 원래 본문을 유지하고 HTTP X-Request-ID는 이번 요청 ID입니다.
5. 새 요청은 revision/현재 상태·코드 가용성과 버전을 검사합니다. stale option_version은 OPTIONS_CHANGED/409, 알려졌지만 비활성인 선택도 OPTIONS_CHANGED/409입니다.
6. 동기 변경은 원자 상태/event/outbox/멱등 응답 저장 후200, 비동기 등록은 작업 커밋 후202입니다. no-op은 저장값/revision/updated_at 유지·event_id=null입니다. 최초 미평가 no-op은 revision0/updated_at=null입니다.

동시에 여러 오류가 있으면 위 순서에서 먼저 판정한 오류 하나를 반환합니다. 동일 단계의 형태 오류는 필드명을 코드 포인트 정렬해 details.fields에 제공합니다. Pydantic 기본 오류 모양을 별도 공통 오류 본문 없이 그대로 반환하지 않습니다.

## 3.6. 광고 동률 순환과 중단3초 — 2026-10-14 사용자 결정

같은 위치의 유효 최상위 우선순위 광고가 여러 개이면 ad_id 코드 포인트 순서의 서버 round-robin을 사용합니다. top/bottom의 순환 상태는 분리하며 새 delivery 발급마다 원자적으로 한 칸 이동합니다. 기존 delivery의 유효성 재확인·멱등 재전송·미리보기는 순환을 진행하지 않습니다. 신규/중단/종료 광고를 다시 조회해 유효한 다음 광고를 선택합니다.

게시 중단 성공 커밋 시점을 t_stop으로 기록하고 서버는 신규 제공을 즉시 막습니다. 정상 활성 화면은 t_stop+3초 이내에 해당 배너를 숨겨야 합니다. 클라이언트는1초마다 기존 delivery_id로 GET /api/ads?placement=...&delivery_id=...를 재확인합니다. 재확인 응답은 같은 delivery를 유지하며 새 순환/노출/클릭을 만들지 않습니다. 활성 검사에는 업무 DB의 현재 상태를 읽고, 같은 검사 시각 evaluated_at을 기준으로 valid_until<=min(evaluated_at+3초,광고 종료시각)을 발급합니다. 캐시의 과거 활성값으로 새 표시 기한을 연장하지 않습니다. 중단/종료이면 ad=null입니다. 표시 유효기한은 delivery 이벤트 수명/중복 보관과 별개입니다. 클라이언트는 서버 유효기간에서 요청 왕복시간을 보수적으로 차감해 남은 표시 시간을 계산하고 늦은 응답의 수신 시각부터3초를 다시 주지 않습니다. 확인 실패/유효기한 종료에는 배너/노출 타이머를 중단하고 배경 탭 복귀/화면 재개 시 먼저 재확인합니다.

실제 브라우저·서버 지연/실패에서3초 수용 기준을 검증합니다. 반복 인정·이미지/URL·지연 집계/보관 수치는 사용자 채택에 따라3.7절과 광고 규정6-5절을 적용합니다.

- 계산 검증: 활성 선호75:25/미선택100W·176/180/184±1ms·부모49/50/53곡 신규 수·광고23/20/조기클릭15를 검산합니다.
- 필수 기능 수용: 정한 고정 사례에서 필수 필터·시간·소유·revision·원자 상태/outbox·취소/재처리·테스트/운영 구분이 모두 기대값과 일치해야 합니다.
- ON/OFF·기본/Gemini 성능은 따로 측정하고 P50/P95·실행 수·후보/입력 규모·환경·실패 사유를 기록합니다. 문서 예시 숫자를 실측 처리시간으로 쓰지 않습니다.
- 2026-10-16 로컬 CSV 프리뷰의 화면 목표는 [선곡표 받기] 클릭부터 곡 목록 표시까지 P95 2.5초 이하입니다. 현재는 목표이며 달성 판정이 아닙니다. 카탈로그 발행 시 원본 해시·track_id 중복을 검증하고, 작업자는 불변 `catalog_version`/SHA-256별 검증된 스냅샷을 프로세스에서 재사용합니다. 새 버전은 검증 후 교체하고 과거 버전 결과 스냅샷은 보존합니다. 메모리 사용량·시작 직후 첫 요청·버전 교체·동시 요청을 별도로 측정합니다.
- 로컬 프리뷰 조합은 기존 점수/시드 순서의 상위 200곡만 우선 추출합니다. 유효 조합이 없으면 400→800→전체 후보로 확장하고 필수 필터·선택 장르 구성·176~184분·부모 대비 신규 곡 기준을 완화하지 않습니다. 상위 후보 추출 전후의 고정 입력 결과 일치와 후보 부족/탐색 미완료 오류를 회귀 검증합니다. 실제 화면 목표는 작업 등록·대기·계산·저장·조회·렌더링 전체를 브라우저에서 재야 합니다.
- 만족도는 최신 유효 별점의 평균/분포·평가수와 곡 LIKE 비율을 보고합니다. 미평가를0점으로 처리하지 않으며 내부 점수를 사용자 만족도로 환산하지 않습니다.
