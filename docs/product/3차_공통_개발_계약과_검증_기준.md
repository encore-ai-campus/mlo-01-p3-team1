## 0. 문서만으로 같은 동작을 만드는 기준

같은 **자료·정책/선택 정의·설정 버전과 같은 입력**에서는 동일한 요청 해석, 상태 전이, 필수 검증, 오류 및 저장 결과를 구현합니다. 기본 추천의 동점/순서는 아래 기준으로 고정합니다. 외부 Gemini 응답의 곡 목록 자체가 매번 같다는 보장은 하지 않으며, 동일한 모의 응답을 넣었을 때는 동일하게 합격/거절해야 합니다.

최신 사용자 결정 → 확정된 도메인 정책 → 본 문서의 공통 형식/상태 계약과 구현 설계도의 상세 기능 → 참고 시안/원본 인계 자료 순으로 해석합니다. 본 문서와 설계도에 같은 항목이 다르게 적혀 있으면 임의로 한쪽을 선택하지 말고 충돌을 정정합니다. 보류 항목은 각 개발자가 추측한 값을 넣는 영역이 아닙니다.

| 구현 기준 | 개발자가 선택할 수 없는 부분 |
|---|---|
| 입력 | 생략 기본값·null·상속·빈 배열·제외 전체 집합의 의미 |
| 화면 | 초기 상태·저장/생성 중·충돌/실패·버튼 활성 조건·결과 귀속 |
| API/저장 | 경로·필드/타입·상태/오류·소유·revision·멱등 범위·원자 이벤트 |
| 추천 | 필수 필터·75:25·시간 우선순위·새 곡20%·기본/Gemini 경계 |
| 미정 사항 | 공통 차단 상태·담당·필요 자료. 구현별 임의 fallback 금지 |

아래 계약과 가상 예시를 A/B/C의 공통 수용 기준으로 사용합니다. 각 담당이 별도 API 이름·상태값·필터·성공 기준을 만드는 방식으로 구현하지 않습니다.

## 1. 개발 기준 기술

2026-10-14 사용자 결정으로 백엔드를 Django로 통일합니다. API는 Django REST Framework(DRF), 온라인 PostgreSQL은 Django ORM·migrations, OpenAPI는 drf-spectacular를 개발 기준으로 사용합니다. 웹은 Django WSGI + Gunicorn + systemd 실행안을 사용하고 추천 작업자·outbox relay는 별도 프로세스로 유지합니다. 실제 버전/명령·호환성은 INF/B/C가 검증합니다. React 화면을 Django 기본 admin 화면으로 대체하지 않습니다.

기존 API 경로·JSON 필드/타입·UTC·소유·revision·멱등·오류 코드/HTTP 상태는 유지합니다. DRF serializer에서 boolean/문자열의 정수 강제 변환과 알 수 없는 입력 무시를 차단하고 strict integer·unknown field 거부·누락/null 구분을 구현합니다. DRF 기본 serializer/auth 오류 대신 본 계약의401/403/400/409/422 등 판정 순서와 공통 오류 본문을 적용합니다. 서버 저장형 ADMIN 세션·guest 쿠키·Origin/CSRF 검사는 익명 API와 별도 광고 프로세스에서도 유지합니다.

PostgreSQL 상태/event/outbox/멱등 응답은 transaction.atomic과 DB 제약으로 원자 저장하고 큐 claim은 select_for_update(skip_locked=True)로 연결합니다. 외부 Gemini 호출 중 긴 DB 잠금을 유지하지 않습니다. 광고 MongoDB replica set 트랜잭션은 별도 어댑터로 유지하며 Django ORM을 MongoDB에 적용하거나 두 저장소를 단일 원자 트랜잭션으로 취급하지 않습니다. JSON Schema Draft2020-12 계약은 보존하고 DRF·생성 OpenAPI와 대조합니다. 전환은 설치·코드·migration 실행 완료를 뜻하지 않습니다.

| 영역 | 이번에 정리한 기준 | 실제 적용 단계 |
|---|---|---|
| 공개/관리 화면 | React + TypeScript + Vite | C는 공개/음악/피드백 화면, B는 광고 관리 화면. 공통 라우팅·스타일은 C 조율 |
| 온라인 API | Python Django + Django REST Framework(DRF), 도메인별 Django app·URLconf·APIView | 인증/날씨/추천/음악 관리/피드백/광고를 분리. 동일 서비스 origin을 기본으로 개발 |
| 온라인 업무·로그 저장 | PostgreSQL + Django ORM/migrations | 소유·작업·결과·상태/outbox·로그/피드백. 광고 업무는 별도 MongoDB |
| 광고 저장 | MongoDB 광고 전용 DB + replica set 트랜잭션 | 광고·delivery/판정·반복 창/순환·집계/예상 원장·로그 outbox. 실제 구성/버전은 INF/B 검증 |
| 음악 저장 | 음악RDB4개·추천/표시18개+검수 보조1개 | 수령 테이블의FK/UNIQUE/조회, 실제DB제품/물리DDL·접속/발행은 별도 검증 |
| 기본 추천 | 별도 Python 작업자 + OR-Tools CP-SAT | 정수 ms·필수 필터·시간 우선순위·범위/UNKNOWN 검증. W 정책은 주입 가능하게 분리 |
| 재설정 | 서버의 Google Gen AI Python SDK `google-genai` 어댑터 | 사용자 확정 모델 gemini-3.8-flash. 계정 한도/예산은 확인 대기. 명시 재설정에만 호출하며 기본 규칙과 독립 |
| 비밀번호 | Argon2id 기반 검증된 라이브러리 | `argon2-cffi`를 사용한 해시/검증 어댑터 기준. 최소 m=19MiB,t=2,p=1에서 실제 호스트 비용을 측정하고 저장 파라미터로 검증 |
| 공통 명세 | JSON Schema Draft 2020-12 + DRF serializer·drf-spectacular에서 OpenAPI 생성 | [기계 판독 계약](../contracts/3차_공통_API_이벤트.schema.json)을 코드 모델과 대조. 실제 OpenAPI는 서버 구현 시 생성 |

정확한 패키지 버전은 설치 환경을 대조한 뒤 잠금 파일로 고정합니다. 문서에 확인하지 않은 설치 버전을 기재하지 않습니다. 기존 태스크의 직접 선행 조건을 건너뛰거나 환경 검증을 완료 처리하지 않습니다.

DRF의 OpenAPI 문서화는 [공식 문서화 가이드](https://www.django-rest-framework.org/topics/documenting-your-api/), SDK 선택은 [Google 공식 라이브러리](https://ai.google.dev/gemini-api/docs/libraries), 해시 기준은 [OWASP 비밀번호 저장 지침](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), 스키마 형식은 [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)를 참고했습니다. 이 자료들은 추천 품질이나 본 서비스의 실측 결과를 보장하지 않습니다.

## 2. API 공통 형식

- 기존 `/api` 경로·HTTP 메서드·3차/4차 구분은 설계도7절을 유지합니다. 일괄 `data` wrapper를 새로 씌우지 않고 기능별 응답 필드를 사용합니다.
- JSON은 UTF-8·snake_case입니다. ID는 불투명 문자열이며 외부 음악 ID는 원문을 유지합니다. 국가·언어 필드, 임의 owner/role/account ID를 요청에 추가하지 않습니다.
- region_id만 있는 기본 요청은 허용합니다. vocal_option=any/instrumental_only, tempo_preference=auto/slow/fast, theme/genre는 각각 배열입니다.
- 빠르기 원본 speed는 slow/medium/fast/fastest이고 화면은 auto/slow/fast를 사용합니다. 최초 허용 집합과 날씨별 fast/auto 규칙은 [음악 통합 계약 5.1절](./3차_음악_정책_통합_계약.md)을 그대로 따릅니다. 단일 PTY1/3의 fast는 fast만, 그 밖의 단일 프로필은 fast/fastest이며 혼합 최초 예보의 auto/fast 미정값을 임의로 정하지 않습니다. medium 선택을 새로 추가하지 않습니다.
- 취향·제외 **집합**만 중복 제거·정규 정렬합니다. 곡 재생 순서와 아티스트 ID/이름 대응 순서를 바꾸지 않습니다.
- 값 누락과 null은 다릅니다. 평가 취소는 값 필드를 명시적으로 null로 보냅니다. integer를 boolean/숫자 문자열에서 강제 변환하지 않습니다. API 모델은 strict integer를 사용하고 소수 입력도 거부합니다. JSON Schema integer 판정과 실제 API strict 타입 검사를 각각 확인합니다.
- 추천 등록/재설정·제외·평가·승인과 설계도에서 명시한 관리 업무 변경은 Idempotency-Key를 사용합니다. 필수 키 누락/빈 값은 VALIDATION_ERROR/422입니다. 로그인/로그아웃은 인증/CSRF 계약, 광고 행동 수신은 delivery/event_id 중복 계약을 각각 따릅니다. 별점/곡 반응·제외·승인은 서로 다른 revision 범위입니다. HTTP 성공/작업 등록과 비동기 작업의 성공을 구분합니다.
- 서버가 request_id를 만들고 응답의 X-Request-ID로 제공합니다. 오류 본문에도 request_id를 넣으며 개인 접근 토큰/비밀키는 응답·로그에 넣지 않습니다.
- 응답의 X-Contract-Version은 본 계약 버전을 표시합니다. policy_version·catalog_version·option_version·duration_policy_version·prompt/schema_version을 이 값 하나로 대체하지 않습니다.
- 시각은 API/온라인 이벤트에서 UTC ISO 8601의 Z 형식으로 직렬화합니다. 날씨 인계의 +09:00 시각은 같은 순간으로 변환하고 발표/대상/수신을 별도로 보존합니다. 부분 앨범 발매일은 시간으로 바꾸지 않습니다.
- 기간 조회는 from 포함/to 미포함입니다. 관리 화면 입력/표시는 KST, 저장은 UTC입니다. 날짜 단위 범위는 KST 자정으로 해석해 UTC 경계로 변환합니다.
- 관리자 제외 이력은 기존 occurred_at/event_id 내림차순·next_cursor·as_of를 사용합니다. 커서는 필터·기준 시각·마지막 행에 묶은 불투명 값이며 임의 페이지 번호/offset으로 바꾸지 않습니다. 최신 상태는 날짜 필터 밖 이벤트도 포함해 해당 as_of 기준으로 계산합니다.
- 개발용 조회 페이지는 기본20/최대100을 설정값으로 둡니다. 실제 조회 규모를 측정해 조정하며 운영 성능 합격 수치로 주장하지 않습니다.

## 3. 기본 추천과 재설정의 고정 기준

1. 음악18개/검수 보조·RDB READY·사이클 장르/speed·최종보컬·제외·중복·WEATHER_MUSIC_V4_CYCLE_FIXED·유효 예보를 두 경로에 동일 적용합니다.
2. 선택 그룹이 있으면 S=0.75W+0.25P, 없으면 S=W입니다. 같은 요청의 활성 그룹 분모를 곡별로 바꾸지 않습니다.
3. STANDARD는 목표10,800,000ms, 범위10,560,000~11,040,000ms이며 정확히→초과→부족·목표 거리·품질 순입니다.
4. 새 Gemini 결과는 부모 전체 고유 곡 수 N에 대해 max(1,N//5) 이상의 신규 곡을 포함해야 합니다. 추가만으로 변화 기준을 통과할 수 있지만 다른 필수 검사도 통과해야 합니다.
5. W 정책 미준비/최초 혼합auto·fast 기준 미정은 POLICY_NOT_READY입니다. 시간은3.5절의176~184분/STANDARD_ONLY입니다. 모의값은 테스트에만 사용합니다.
6. RULE_BASED 결과의 모델/프롬프트 필드는 해당 없음(null), GEMINI_RECONFIGURE에만 실제 SDK/모델/프롬프트·시도/목록 해시를 기록합니다.
7. 좋아요/싫어요·별점은 결과 버전에 귀속하며 자동 제외·승인·추천 점수 변경·Gemini 호출을 만들지 않습니다.

## 3.2. 기본 추천의 동점·순서와 외부 응답 판정

- 같은 총시간에서는 Q=sum(duration_ms_i*S_i)/total_ms로 재생시간 가중 품질을 비교합니다. 비교용 값을 화면 표시 때문에 반올림하지 않습니다.
- 시간 구간·목표 거리·Q까지 같으면 곡 ID 집합을 코드 포인트 오름차순으로 정렬한 배열의 사전순이 작은 조합을 선택합니다. DB의 임의 행 순서·시스템 locale·무작위 값을 동점 기준으로 쓰지 않습니다.
- 기본 결과 재생 순서는 S 내림차순, 동점이면 track_id 코드 포인트 오름차순입니다. 별도 speed 곡선·아티스트 간격 제약은 3차 확정 규칙에 추가하지 않습니다. Gemini는 검증된 track_ids의 응답 순서를 유지합니다.
- 후보 확장 단계·상한·탐색 예산은 버전 설정으로 고정하며 같은 환경의 공통 설정을 사용합니다. 후보 조회 순서를 명시하고 같은 설정/고정 입력 fixture로 재현합니다. 미확정 탐색 수치를 개인별 기본값으로 운영하지 않습니다.
- solver 시간 초과/UNKNOWN은 SEARCH_INCOMPLETE입니다. 시간/품질 우선순위를 확인하지 못한 결과를 최적 성공으로 표시하지 않습니다. INFEASIBLE은 확인한 탐색 범위를 함께 기록합니다.
- Gemini 이유는 선택한 각 ID당 정확히1개이며 중복/누락/목록 밖 이유는 PROVIDER_RESPONSE_INVALID입니다. 응답에 없는 곡의 이유를 서버가 생성해 채우지 않습니다.
- POLICY_NOT_READY·FORECAST_UNAVAILABLE·RECONFIGURATION_UNAVAILABLE는 접수 전 확인되면 해당 코드/503으로 작업을 만들지 않습니다. 접수 이후 작업자가 발견하면 FAILED+같은 error.code이며 성공 결과를 만들지 않습니다. 대기 중 기준 시각/예보가 만료된 작업은 EXPIRED/JOB_EXPIRED입니다.

## 3.3. 저장·오류 판정 순서

1. 관리자 인증/CSRF 또는 공개 문맥을 확인하고, 문법 오류 JSON은 VALIDATION_ERROR/422로 처리합니다.
2. 3차 국가·언어 필드는 OPTION_NOT_SUPPORTED/400입니다. 필수 region_id 생략/빈 값은 REGION_REQUIRED/400, 재설정/승인의 exclusion_revision 생략은 EXCLUSION_REVISION_REQUIRED/400으로 예외 매핑합니다. 다른 required/type/range/unknown field 오류는422입니다. 문자열 형식이 맞지만 선택 enum/코드가 없으면 OPTION_INVALID/400입니다.
3. 본인 자료의 존재/소유·유효 보관을 확인합니다. 타 소유/없음은404이며 그 자료의 revision/저장값을 노출하지 않습니다.
4. 같은 범위·멱등 키의 저장 성공 기록을 확인합니다. 정규 요청이 같으면 원래 응답, 다르면 IDEMPOTENCY_CONFLICT/409입니다. 재전송 성공의 request_id/updated_at/event_id도 원래 본문을 유지하고 HTTP X-Request-ID는 이번 요청 ID입니다.
5. 새기본요청은revision/현재상태·최신선택가용버전을검사하고stale/비활성은OPTIONS_CHANGED/409입니다. 재설정은생략을부모조건으로정규화한뒤시작선택/option_version 차이를CYCLE_CONDITIONS_CHANGED/409로거절하며 고정사이클의사전/버전으로검증합니다. 최신전역옵션으로부모선택/매핑을덮어쓰지않습니다.
6. 동기 변경은 원자 상태/event/outbox/멱등 응답 저장 후200, 비동기 등록은 작업 커밋 후202입니다. no-op은 저장값/revision/updated_at 유지·event_id=null입니다. 최초 미평가 no-op은 revision0/updated_at=null입니다.

동시에 여러 오류가 있으면 위 순서에서 먼저 판정한 오류 하나를 반환합니다. 동일 단계의 형태 오류는 필드명을 코드 포인트 정렬해 details.fields에 제공합니다. DRF 기본 오류 모양을 별도 공통 오류 본문 없이 그대로 반환하지 않습니다.

## 3.4. 공통 응답의 최소 필드

| 응답 | 고정 필드/상태 |
|---|---|
| 작업 조회 | job_id/status/playlist_id/error. QUEUED/RUNNING은 둘 다null, SUCCEEDED는 playlist_id만 있음, FAILED/EXPIRED는 error만 있음 |
| 평가 PUT | source_playlist_id/target_kind/track_id/value/revision/updated_at/event_id. 별점 track_id=null, 무변경 event_id=null |
| 제외 GET | family_id/excluded_track_ids/revision/items. items는 제외 목록의 track_id/track_name/artists_name이며 이전 결과 곡도 공급 |
| 제외 PUT | family_id/excluded_track_ids/revision. 작업/새 선곡표를 반환하지 않음 |
| 승인 POST | family_id/approved_playlist_id/approval_revision. 같은 승인 no-op은 revision 유지 |

평가 GET의 track_reactions는 원본 결과 순서의 **모든 곡**을 한 번씩 포함하고 미기록 곡은 null/revision0입니다. 실제 저장된 일부 곡만 반환해 클라이언트가 임의 기본값을 만들지 않습니다. 실패 error는 공통 ErrorResponse 모양을 사용합니다. 원본 선곡표의 전체 음악/정책/조건 스냅샷은 설계도와 음악 담당 보완 자료를 함께 적용하며 이 최소 응답표로 누락을 허용하지 않습니다.

## 3.5. 시간176~184분 — 새 음악 문서 우선

시간 정책 phase3-duration-20261014.2/STANDARD_ONLY를 적용합니다. 목표180분·허용176~184분·정수ms·정확히→초과→부족·거리→Q→ID 비교는 유지합니다. 수령 음악 규칙4-3절이 별도 단축 정책 확정 전176분 미만을 성공으로 제공하지 않도록 하므로 자동 SHORTENED·기존25%/135분 단계는 현행에서 제외합니다. [이전 단축 정책](./archive/자동_시간_단축_25퍼센트_정책_보관.md)은 이력입니다.

날씨 점수는 앞180분으로 집계하고 실제 결과가 초과하면 실제 종료까지 유효성을 검사합니다. 새 단축 정책을 채택하려면 음악 문서·통합 계약·화면/API·고정 사례를 함께 갱신해야 합니다.

## 3.6. 광고 동률 순환과 중단3초 — 2026-10-14 사용자 결정

같은 위치의 유효 최상위 우선순위 광고가 여러 개이면 ad_id 코드 포인트 순서의 서버 round-robin을 사용합니다. top/bottom의 순환 상태는 분리하며 새 delivery 발급마다 원자적으로 한 칸 이동합니다. 기존 delivery의 유효성 재확인·멱등 재전송·미리보기는 순환을 진행하지 않습니다. 신규/중단/종료 광고를 다시 조회해 유효한 다음 광고를 선택합니다.

게시 중단 성공 커밋 시점을 t_stop으로 기록하고 서버는 신규 제공을 즉시 막습니다. 정상 활성 화면은 t_stop+3초 이내에 해당 배너를 숨겨야 합니다. 클라이언트는1초마다 기존 delivery_id로 GET /api/ads?placement=...&delivery_id=...를 재확인합니다. 재확인 응답은 같은 delivery를 유지하며 새 순환/노출/클릭을 만들지 않습니다. 활성 검사에는 광고 MongoDB primary의 현재 상태를 읽고, 같은 검사 시각 evaluated_at을 기준으로 valid_until<=min(evaluated_at+3초,광고 종료시각,delivery의 display_expires_at)을 발급합니다. 캐시의 과거 활성값으로 새 표시 기한을 연장하지 않습니다. 중단/종료·소재 변경·검증된 예산 소진이면 ad=null이며 신규/기존 배달 재확인/이미지를 모두 차단합니다. 표시 유효기한은 delivery 이벤트 수명/중복 보관과 별개입니다. 클라이언트는 서버 유효기간에서 요청 왕복시간을 보수적으로 차감해 남은 표시 시간을 계산하고 늦은 응답의 수신 시각부터3초를 다시 주지 않습니다. 확인 실패/유효기한 종료에는 배너/노출 타이머를 중단하고 배경 탭 복귀/화면 재개 시 먼저 재확인합니다.

실제 브라우저·서버 지연/실패에서3초 수용 기준을 검증합니다. 반복 인정·이미지/URL·지연 집계/보관 수치는 사용자 채택에 따라3.7절과 광고 규정6-5절을 적용합니다.

## 3.8. 광고 공개 수명·5분 통계/예산 — 2026-10-15

이 절의30분 수명·소재 변경 전후 처리·관리 통계/예산5분 검증·소진 확인 이전 발생의 초과 인정은 최신 사용자 결정입니다. 광고 이미지·공개 API·MongoDB 원자 저장·관리 API의 예산 입력과 배치를 연결하며 관리자 화면은 이번 구현에서 변경하지 않습니다.

1. delivery의 `display_expires_at=min(issued_at+1800초,광고 ends_at)`, `event_expires_at=display_expires_at+300초`입니다. 새 발생은 표시 마감 전만 유효하며 보고는 발생 후0~300초와 보고 마감을 모두 검사합니다.1초 재확인과 최대3초 `valid_until` 표시 lease는 별도입니다.30분은 한 delivery의 수명이며 광고의 게시기간이나 캠페인 자동 종료 주기가 아닙니다.
2. 제목·asset·link 실제 변경은 새 `creative_version`으로 이전 배달의 새 표시·재확인·이미지를 막습니다. 변경 이전 당시 유효 발생은 허용 지연 안에서 인정하고 변경 시각부터의 이전 소재 발생은 제외합니다. 최초 `event_id` 판정/응답은 재전송에서 그대로 반환하며 현재 상태로 재판정하지 않습니다.
3. 관리 API의 `daily_budget_tokens`와 `total_budget_tokens`는 함께 지정하는 선택 쌍이며 각 값은1~9,223,372,036,854,775,807의 strict integer입니다. bool/소수/문자·한쪽만 입력·null은 거부합니다. 생략은 새 광고 예산 미설정/수정 시 기존값 유지이며 미설정 광고는 공개 부적격입니다. 서버 UUID `budget_version`은 최초 설정 또는 예산 실변경에만 새로 만들고 동일값 저장·일반 소재 수정·멱등 재전송에는 유지합니다. 실제 금액 기본값이나 클라이언트가 지정하는 예산 버전을 만들지 않습니다.
4. 관리 통계는 인정된 예상 원장 합에서5분마다 발생일KST별/광고·위치별로 재계산·교체합니다. 지연 보고는 과거 발생일을 갱신하고 재실행이 중복 합산하지 않게 합니다. 응답의 `as_of`·`coverage`·`aggregation_status`로 집계 범위/누락을 구분하며 미연결·미집계 값을 실제0으로 채우지 않습니다. 실시간 측정의 원자 확정과 관리자 표시 집계는 별개입니다.
5. 예산도5분 배치에서 검증합니다. 인정 예상 원장의 해당 일자 합 또는 광고 전체 합이 각각 한도 이상이면 당시 예산 버전/일자의 최초 `daily_blocked_at` 또는 버전 전체 `total_blocked_at`을 고정합니다. 광고의 `budget_blocked_at`은 현재 적용되는 소진 확인 시각이며 이후 재집계·지연 보고로 최초 시각을 뒤로 미루지 않습니다. 신규 발급·재확인·공개 이미지를 차단하고 이미 열린 화면은 기존 최대3초 lease로 숨깁니다.
6. `occurred_at < 소진 확인 시각`의 당시 유효 이벤트는300초 안의 지연 보고이면 예산 초과분도 인정합니다. 확인 시각과 그 이후 발생은 제외합니다. 링크 이동은 지표 실패/제외로 막지 않습니다. 다음 검증 전 양수 잔여에서 초과할 수 있으며 상단23/하단20토큰 최소 잔여·예약/차감·엄격한 상한 보장은 채택하지 않습니다.
7. 캠페인의 자동 종료 조건은 예산 소진 확인 또는 게시기간 종료이며 수동 `paused` 중단은 별도입니다. 예산 증액은 실제 변경된 새 예산 버전 상태를 재검증한 뒤 제공하고 수동 paused를 자동 해제하지 않습니다. 배달 만료·통계 미집계·검증 장애를 추가 캠페인 종료 조건으로 만들지 않습니다.
8. 공개 요청은 저장된 예산 검증 상태만 확인하며 요청마다 원장을 다시 합산하지 않습니다. 예산 미설정/검증 상태 없음은 후보 부적격입니다. 검증 시각이 미래·무효이거나 현재보다300초 넘게 오래됐으면 `ADS_POLICY_UNAVAILABLE/503` 기술 장애입니다. 광고 실패는 추천을 막지 않습니다. 일일KST 정렬은 기존 발생일 집계에 맞춘 개발 기준이며 별도 사용자 승인값으로 표시하지 않습니다. 자정 delivery 단축은 기본 `cap_at_midnight=False`로 유지합니다.
9. 운영 연결 provider는 `domains.ads.runtime_policy.get_public_policy`이며 `delivery_ttl_seconds=1800`, `split_deadlines=True`, `check_budget_history=True`, `cap_at_midnight=False`를 제공합니다. guest 검증·서명 키·ADMIN 권한·PostgreSQL sink의 실제 환경 연결은 별도입니다. 예산 값과 운영 접속 비밀을 임의 생성하지 않습니다.
10. 관리3·공개5 컬렉션에 `ad_budget_states`/`ad_daily_metrics`2개를 추가합니다. 예산 검증·최초 소진 내부 `log_relay`·광고의 예산 상태 표시·통계 교체는 해당 광고 MongoDB 트랜잭션으로 저장하고 PostgreSQL 로그는 이후 멱등 전달합니다. 별도 outbox 컬렉션이나 두 DB의 원자 동시 쓰기를 추가하지 않습니다.
11. `apply_ads_policy_schema`는 기본 dry-run이며 `--apply`는 명시 로컬 개발 DB 제한을 검사합니다. `refresh_ads_policy`는 단발 실행, `--watch`는 시작 시각 간격300초의 반복 실행입니다. `relay_ads_budget_logs`는 최초 소진 로그를 전달합니다. 운영 watch 상주·공유 PostgreSQL·AWS·브라우저 통합은 미실행이며 실제 검증 수치/명령은 광고 개발/수용 문서에서 관리합니다.

실금액·토큰 원화 가치·실제 구매/차감/환불·원장 조회UI/API·asset 정리 기간 등 승인하지 않은 항목은 미정으로 유지합니다. 업종 선택·태그/업종별 매칭은4차이며 제목100자·priority100·asset7일 정리 같은 미승인 수치를 기본값으로 채택하지 않습니다. 수령 ADS04 원문은 출처로 보존하고 현행 계약은 ADS05 및 본 절로 연결합니다.

## 4. 세션·권한과 개발 초기값

- 기존 서버 저장형 세션을 유지합니다. guest와 ADMIN 인증은 서로 다른 소유/인증 문맥입니다. guest 토큰은 브라우저 쿠키로 전달하고 내부 guest ID/검증용 해시만 서버에 저장합니다.
- 최초 공개 메인 진입의 상단 GET /api/ads?placement=top에서 유효 guest 쿠키를 재사용하거나 새로 발급합니다. 광고가 없어도 발급하며 추천 요청·지역 선택·로그인은 필요하지 않습니다. 최초 상단 응답 완료 후 하단 조회/측정 전송을 시작해 두 초기 요청이 서로 다른 쿠키를 만드는 일을 피합니다. 쿠키 저장 불가이면 광고 표시/링크 이동/기본 이용은 유지하고 식별 불가 측정은 MEASUREMENT_UNAVAILABLE로 제외합니다. 추천도 같은 문맥을 재사용하고 누락/만료 시 새로 발급합니다. 발급/조회 자체는 노출/클릭·추천 작업·피드백이 아닙니다.
- 예측하기 어려운 토큰은 암호학적 난수32바이트 이상으로 발급합니다. HTTPS 쿠키는 Secure·HttpOnly·SameSite=Lax이며 상태 변경에 Origin/CSRF 검사를 적용합니다. 개발 HTTP 설정은 별도 환경으로 관리합니다.
- 관리자 초기화 명령은 최초 발급만 수행하고 재실행으로 기존 비밀번호/권한을 덮지 않습니다. 비활성화+세션 무효화로 회수하고 관리 API에서 매번 활성/권한을 확인합니다.
- 비밀번호 해시 알고리즘 선택은 기술 기준으로 정리했습니다. 실제 관리자 이름/계정·권한 배정·키 전달은 담당자가 수행하며 문서 작업에서 계정을 발급하지 않습니다.
- 개발 초기값: poll=2초, lease=30초, heartbeat=10초, 일시 인프라 오류 재시도 최대3회. 기존 제안을 개발 기본값으로 사용하며 실제 요청 대기·외부 호출 예산과 겹치지 않게 검증합니다.
- guest/ADMIN 세션 만료·결과/초안/피드백/원문 보관·정리 기간은 운영 정책으로 남깁니다. 개발 환경은 별도 테스트 namespace와 명시 초기화 절차를 사용하며 미정 보관을 영구 보관으로 설명하거나 운영 자료를 자동 삭제하지 않습니다.
- Gemini 재설정 모델은 gemini-3.8-flash로 고정합니다. gemini-flash-latest 별칭이나 다른 모델로 자동 전환하지 않습니다. 프로젝트 접근/키/호출 예산이 준비되지 않은 재설정 어댑터는 RECONFIGURATION_UNAVAILABLE로 종료합니다. 기본 규칙 추천은 이 사유로 차단하지 않습니다. 테스트 어댑터의 응답을 실제 Gemini 호출로 기록하지 않습니다.

## 5. 인프라·원문 보관·미정 설정

환경 변수에는 실제 값을 넣지 않고 이름·목적·단위만 기록합니다. 필수 운영 설정 누락은 설정 오류로 처리하며 임의 주소·날씨·곡·예산으로 성공시키지 않습니다.
