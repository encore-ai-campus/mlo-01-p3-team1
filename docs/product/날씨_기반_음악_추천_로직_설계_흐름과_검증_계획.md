## 1. 기준과 만드는 순서

[음악 통합 계약](./3차_음악_정책_통합_계약.md)과[수령 선곡 규칙](../handoff/music/플레이리스트_생성_규칙.md)을 적용합니다. 기본은규칙/정수시간조합, Gemini3.8은명시재설정만입니다. 국가·언어 기능은제외하고 평가/제외/승인을구분합니다.

1. 원본20개+인덱스와 결과18개+검수보조1개를구분하고 source/schema 버전·NULL·ID·raw값을보존합니다.
2. energy/acousticness를각각10/100배후절삭, mode0/1변환, tempo/박자→speed보정·HALF_UP·구간분류를검증합니다. 변환결과를재변환하지않습니다.
3. 검수값우선·자동instrumental 경계와장르/테마매핑을검사하고 음악RDB4개/활성approved·READY를구분합니다.
4. 제외·최종보컬·사이클장르/speed·양의ms·유효예보를필수로검사합니다. genre/speed와점수핵심값미확인은보류합니다.
5. 날씨10프로필·50:45:5·앞180분 W와활성3그룹평균P·75:25를계산합니다. 테마세부정렬/혼합최초speed의미정을개인별초기값으로채우지않습니다.
6. 176~184분·정확히→초과→부족·거리→시간가중품질→ID로조합합니다. 자동시간단축/필수완화는현행미사용입니다.
7. 사이클집합/시작선택/정책·매핑버전을고정하고 조건변경은새기본요청/새family로처리합니다. 동일조건재설정에만Gemini를호출하고 부모전체N의20%내림신규곡을검증합니다.
8. 당시18개/검수보조·날씨/선택/허용집합/버전·점수·raw근거와평가/취소를불변기록으로보존합니다.

## 2. 계산 계약과 경험적 가설

```text
d(x,L,U)=max(L-x,0,x-U)
E=max(0,100-10*d(energy,L_e,U_e))
A=max(0,100-d(acousticness,L_a,U_a))
M=100 if mode==preferred_mode else 0
W_k=.50E+.45A+.05M
W=sum(overlap_ms/10800000 * W_k)
n=선택된빠르기/테마/장르그룹수
n>0: P=sum(활성100/0일치점수)/n; S=.75W+.25P
n=0: S=W
Q=sum(S_i*duration_ms_i)/total_ms
required_new_count=max(1,parent_unique_count//5)
actual_new_count=len(result_ids-parent_ids)
```

W/P/S/Q는0~100입니다. 반올림한표시점수로순위를계산하지않고 표시만소수2자리HALF_UP입니다. 날씨범위밖/불일치mode만으로곡을제외하지않으며 W하한도없습니다. 결측의곡별비중재배분은금지합니다.

50:45:5·우선범위·mode선호는수령자료의채택된초기가설입니다. 계산일치와만족도검증은구분합니다. energy4/acousticness60/modeTrue는맑음/비모두W95이며 모든곡에점수차가생기는모델이아닙니다. 같은선택이면날씨차가없을수있고 장르/speed필터통과곡의해당가점은공통100입니다.

## 4. 데이터가 적을 때의 품질 확인

평가자10명이없어도측정가능한설계가설과코드검증을진행할수있습니다. 확보한청취자료로분류/누락·처짐/곡흐름을먼저살피고 실제곡별mood/악기/검수확보율을보고합니다. 내부팀자료를카페운영자전체로일반화하지않습니다.

같은평가자의비교순서를무작위로하고 음량/장비/구간을맞춥니다. 날씨적합성전용질문과좋아요/싫어요·전체별점을구분합니다. 반복결과/여러곡평가를독립사람수로세지않습니다. 추론가능한자료가있을때평가자별차이/조건과95%신뢰구간을보고하며신뢰구간만으로가중치를정당화하지않습니다.
