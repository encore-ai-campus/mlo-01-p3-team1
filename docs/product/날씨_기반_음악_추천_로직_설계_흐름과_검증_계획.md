## 2026-10-14 공통 구현 기준 정리

문서만 읽어도 같은 입력 해석·화면 상태·검증·오류·저장 결과를 만들도록 [공통 개발 계약](./3차_공통_개발_계약과_검증_기준.md)을 적용합니다. 프레임워크/SDK·공통 형식/동점·상태 처리의 개발 기준을 정리했으며 실제 설치·코드·운영 검증 완료는 아닙니다. 자료/운영 판단이 필요한 부분만 [사용자 확인·담당자 인계 목록](./3차_사용자_확인과_담당자_인계_목록.md)에 남깁니다. 음악 W·입력 보강·수동 스냅샷과 남은 광고 규정의 보류는 유지합니다. 2026-10-14 사용자 결정으로 후보 부족 시 자동 최대25% 시간 단축·광고 동률 순환·중단3초를 반영합니다.

## 1. 기준과 현재 결정

기본 추천은 자체 규칙과 정수 시간 조합으로 생성하고, Gemini는 사용자의 명시적인 선곡표 재설정에만 사용합니다. 음악의 수동 energy 0~10·mood·speed·genre·instrumental과 별도 보컬/테마 검수를 사용합니다. 국가·언어 기능은3차 전체에서 제외합니다. 이전 음향 3개 기반 점수·충족률 0.75·W 하한 0.55·A~E 예시는 보관 이력입니다. 새 날씨 목표·특성 비중·필수 입력/NULL·하한, CSV 보강과 수동 곡 스냅샷 규격은 음악 담당 자료 수령까지 보류합니다. 수령 후 R-01/M-01/A-02/F 계열에 반영합니다. 날씨 75%/활성 세 선호 25%, 필수 조건·시간·20% 내림 신규 추가·평가 수집 방향은 유지합니다.

## 2. 로직을 만드는 순서

1. 음악 16개 필드와 수동값의 척도·라벨·원본·검수 상태를 고정합니다. 원본 CSV 20개와 현행 추천 자료를 구분하고 음향 energy 0~1을 수동 0~10으로 자동 환산하지 않습니다.
2. 무보컬·제외·공개 검수와 유효 예보를 필수 조건으로 둡니다. country·market·제목에서 언어를 추정하지 않습니다.
3. 날씨 유형별 수동 energy 목표와 승인 mood 라벨의 대응·비중·필수 입력/NULL·하한을 가설로 정의합니다. 확정 전 정책은 DRAFT이며 운영 성공을 만들지 않습니다.
4. 승인된 weather_fit이 구간별 0~1을 반환하도록 구현하고 STANDARD 앞 180분의 시간 비율로 W를 구합니다. 날씨의 실제 값·코드·시각을 보존하며 현재 아이콘 하나로 전체 구간을 대표하지 않습니다.
5. speed·테마·genre의 선호를 결합합니다. 같은 그룹의 복수 선택은 OR이며 필수 조건을 점수로 상쇄하지 않습니다.
6. 정수 duration_ms로 표준 176~184분을 구성합니다. 정확히 180분 → 초과 → 부족, 목표 거리, 재생시간 가중 품질 순으로 비교합니다. 한정 후보군의 최적과 UNKNOWN을 구분합니다.
7. 사용자의 재설정 요청에만 Gemini를 호출하고 부모 전체 곡 수의 20% 내림에 해당하는 신규 곡과 등록·필수·시간·예보를 재검증합니다. 새 결과는 별도 승인·미평가이며 실패·변화 미달에는 부모를 보존합니다.
8. 곡별 좋아요·싫어요와 선곡표 1~5점은 당시 결과·날씨·취향·수동 곡 스냅샷에 연결합니다. 자동 점수 변경·제외·재설정 없이 자료를 수집·검증합니다.

## 3. 수식과 미정의 경계

```text
W_k = weather_fit(확정 정책, 날씨 유형, 수동 energy, 승인 mood)
W = sum(예보 구간의180분 겹침비율 * W_k)                 # STANDARD
n = 선택된 빠르기/테마/장르 그룹 수
n > 0: P = 활성선호일치합 / n; S = 100 * (0.75*W + 0.25*P)
n = 0: S = 100 * W
required_new_count = max(1, 부모고유곡수 // 5)
actual_new_count = len(result_ids - parent_ids)
변화 기준 = actual_new_count >= required_new_count  # 기존 곡 제거는 필수 아님
```

75:25·정수 합계·내림·버전 검사는 계산 계약입니다. weather_fit의 목표·내부 비중·하한은 경험적 가설이며 아직 새 수치가 없습니다. 이전 중심값을 10배로 옮겼다고 타당성이 확보되지는 않습니다. 실제 음악 점수는 R-01의 수동 정책 확정 후 새 fixture로 검산합니다.

확인된 후보 부족이면 자동으로 최대25% 단축하며 최소135분을 유지합니다. 목표 단계/오차/집계는 공통 개발 계약3.5절을 따릅니다. 확인된 부족은 후보 수·총길이·필터·탐색 범위로 설명하며 모델의 짧은 응답·UNKNOWN을 부족 증거로 쓰지 않습니다. duration_policy_version·mode·적용 범위를 생성·검증·승인·피드백에 고정합니다.

## 4. 데이터가 적을 때 검증

평가자 10명이 있어야 설계 가설이 되는 것은 아닙니다. 먼저 고정 자료로 음악 16개 파서·NULL·energy 범위·speed 라벨·필수 필터·활성1/2/3그룹75:25·모두 미선택100W·시간 경계·20%·API·원자 저장·재처리를 검증합니다. 모의 자료와 실제 수동 검수·승인 카탈로그를 구분합니다. 출처의 로컬 파이프라인 연결시험은 참고 테스트 이력으로, 운영 통합 완료 근거에서 제외합니다.

확보 가능한 팀원 청취로 질문 이해·극단적인 처짐·곡 흐름을 살핍니다. 같은 평가자의 순서를 무작위로 하고 음량·장비·구간·곡 수를 맞춥니다. 내부 팀 자료를 카페 운영자 전체로 일반화하지 않습니다. 곡 반응과 전체 별점에는 개별 취향·친숙함 등이 섞이므로 날씨 적합성 전용 질문과 구분합니다.
