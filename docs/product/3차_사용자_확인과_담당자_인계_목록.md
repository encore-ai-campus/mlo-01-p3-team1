## 2026-10-14 광고 관리 간소화 적용

사용자가 제공한 [간소화 원문](../handoff/ads/04_광고_관리_간소화_인수인계서.md)과 [통합·추가 인계](../handoff/ads/05_광고_간소화_통합과_추가_인계.md)를 현행 광고 기준으로 적용합니다. 첫 관리 단계는 ads/ad_assets/ad_admin_changes 세 컬렉션·MongoDB 이미지 Binary·관리 감사/멱등 응답 통합입니다. 3차는 카페 전용이며 관리자/사용자 업종 선택·태그 입력·업종별 매칭은 제공하지 않습니다. 해당 확장은4차로 분리합니다. 공개 제공/측정과5분 통계/예산 코드는 관리3+공개5+정책2 구조로 연결했습니다. 전체3차 필수 범위와 기존 태스크 ID/직접 선행은 유지하고 실환경/화면 검증과 구분합니다.

3차는 카페 광고만 운영하고 위치·일정·paused·소재·예산 자격을 충족한 후보에서 높은 priority·위치별 동률 순환을 적용합니다. 업종/태그가 제공·측정의 전제가 아니며 최초 guest 발급·추천 미요청 집계·단가8/5/클릭추가15·중복/지연/보관은 유지합니다. 미연결 지표는 연동 대기, 실제 통계는 주기 집계하며 예산 제공 제어와 구분합니다. 첫 관리 로그는 ad_admin_changes 내부 log_relay로 전달합니다. 업종별 입력/태그/매칭/순환은4차 인계에서 정하고3차 API/DB/화면/검증의 선행 조건으로 넣지 않습니다.

## 2026-10-14 음악 담당 수령 문서 우선 적용

## 5. 광고 회의 규정

추가 인계는 [간소화 통합](../handoff/ads/05_광고_간소화_통합과_추가_인계.md)을 따릅니다. 3차는 카페 전용이며 업종 입력·태그·업종별 매칭은 제외하고 [4차 확장 가이드](../handoff/ads/06_4차_광고_업종매칭_확장_가이드.md)에 보존합니다. 공통 커버 파일·화면/API 코드·실제 OpenAPI·실행/장애/검증 결과 문서는 구현 태스크에서 작성합니다. 현재 문서 정리만으로 이 산출물들을 구현 완료로 표시하지 않습니다.


## 8. 보류 중인 계약 버전 확인

공통 계약 문서 버전은 `phase3-20261014.2`이고, JSON Schema의 `FeedbackEventEnvelope.contract_version`은 `phase3-20261014.1`입니다. 예시 fixture의 최상위 계약 버전도 `.2`입니다. 사용자가 버전 정정을 보류했으므로 관련 JSON 값을 수정하거나 어느 쪽을 정답으로 확정하지 않습니다. 구현/통합 전에 envelope 버전이 별도 스키마 버전인지, 문서/fixture와 함께 올릴 계약 버전인지 담당자가 확인해야 합니다.
