## 1. 음악 담당 자료 — 기존 보류 유지

**연결 담당:** C, PL·B 협력. A는 실제 날씨 유형/구간을 공급합니다.

- 실제 보유 CSV와 원본 버전/헤더/건수·고유 곡 수·NULL/오류 현황
- 음악16개 필수 ID/앨범/발매일/play_url·수동 energy/mood/speed/main_inst/instrumental의 확보·매핑·검수 근거
- 수동 날씨 W의 유형별 목표/함수·mood 대응·내부 비중·필수/NULL·하한·출력 정밀도/반올림·고정 기대값
- 수동 곡 특성의 당시 스냅샷 필수 목록/타입/직접 복사 또는 불변 참조·버전·보관 연결
- explicit의 False/미확인 의미에 대한 사용자 최신 문서
- 실제 검수 적격 곡 수·총길이와 제공 가능한 테마/장르/무보컬 목록

기존 바탕화면의 `3차_음악데이터_담당자_인계요청_날씨점수_입력보강_스냅샷.md`를 사용해 회신할 수 있습니다. 이 요청을 완료하려고 값을 가상 ID/날짜/음향 환산값으로 채우지 않습니다.

## 2. 날씨 담당 자료

**연결 담당:** A, C·INF 협력.

- 실제 지역→대표 nx/ny 매핑과 검색 자료, mapping_version·지원 지역
- 정상/비/눈/혼합/누락/만료의 관측·예보 입력과 기대 조회 결과
- 실제 발표/대상 구간 경계와 항목별 만료·필수성, 앞180분/실제184분·뒤6시간 누락 구분
- PTY2 비·눈과 PTY6 빗방울·눈날림의 추천 연결, PTY7 눈날림의 눈+구름많음 결합 비율을 음악 정책 담당과 합의

코드·단위·+09:00→UTC 변환 형식은 공통 계약으로 정리했습니다. 실제 없는 매핑/원문과 추천용 미정 유형은 자료가 필요합니다.

## 3. 인프라 실제 구성과 인계

**연결 담당:** INF, A/B/C 협력.

[받은 로컬 가이드](../handoff/infra/local%20infra%20guide.md)에 이어 공개용 [AWS 구축 계획](../handoff/infra/AWS_인프라_구축_계획서.md)을 수령했습니다. [인프라 인계 안내](../handoff/infra/README.md)의 5계정/14EC2·SSM/ALB·생성/삭제 계획과 적용 경계를 확인합니다. 원문 안의 주소/식별자는 예시이며 실제 구성·서비스 동작 증빙은 후속 인계까지 보류합니다.

- 추가 확인: 원문의 Django와 현재 FastAPI 기준 정합성, Spark 계정2~4→MongoDB 계정5 통신, 원문/Delta/음악/광고 저장 위치와 보존·삭제 범위, 추천/outbox 배치, Delta/ES connector·DB/앱 호환 버전. 원문 수령만으로 조율 완료나 제품 정책 변경으로 처리하지 않습니다.

- 웹/API·수집기·추천 작업자·outbox 발행기의 실제 배치
- 설치된 OS/런타임/서비스 버전·자원, 서비스 주소/포트·인증·서버 간 라우팅/반환 경로
- 온라인 PostgreSQL·음악 RDB 제품/DDL·MongoDB·Delta의 접속과 실제 저장 위치
- 원문 로컬/S3·광고 이미지·체크포인트·보관/백업·기동/종료·PC1 장애/복구 절차
- 팀원별 접속 자료의 배치·등록·회수·실제 접속 확인

개인키·비밀번호·API 키를 MD/공유 저장소에 넣지 말고 실행 환경에서 전달합니다. 접속 자료를 특정 폴더에서 못 찾았다는 사실을 전체 배포 자료 미제공으로 단정하지 않습니다.

## 4. 시간 단축과 운영 보관 정책

**연결 담당:** PL, C·B·INF 협력.

- 확정: 후보 부족이면 자동 최대25% 단축,180분 기준 실제 최소135분. 단계/범위/집계는 공통 개발 계약3.5절의 기술 기준으로 정리했습니다.
- 단축 정책은 실제 데이터와 solver/외부 응답으로 검증하며 보류 중인 W 함수와 실제 예보 자료는 별도 인계합니다.
- 익명 문맥/ADMIN 세션 만료·최근 결과 복원 범위
- 결과·제외 초안·피드백/조건/곡 스냅샷·원문/로그·백업의 보관/정리 기간
- 실제 관리자 계정/권한 배정과 팀 담당자 이름·일정

STANDARD180분/176~184분과 신규 곡20% 내림 기준은 유지합니다. 활성 제외 초안의 취소에 필요한 이벤트/곡 스냅샷은 초안 유효기간까지 남아야 합니다. 기간 결정 전 영구 보관/자동 운영 삭제를 확정하지 않습니다.

## 5. 광고 회의 규정

**연결 담당:** PL, B·INF·C 협력.

상단8/하단5/클릭추가15토큰·50%/연속1초·동일 delivery 각각1회·최초 예상 계산은 이미 정한 기준입니다. 2026-10-14 제안 수치 적용 지시로6-5절의 반복/소재/지연/보관 기준도 채택했습니다. [AD-M01~AD-M21 목록](./3차_광고_운영_회의_결정사항_목록.md)의 남은 항목만 회신해 주세요.

- 확정: 같은 우선순위는 순환, 게시 중단은 정상 활성 화면에3초 이내 반영. 공통 개발 계약3.6절을 따릅니다. 재개 확인 방식은 미정입니다.
- 채택: 정적WebP/JPEG/PNG·최대2MB·HTTPS/새 탭, PC1536×120/104·2배 소재·모바일390×120/104. 실제 파일 공개/미사용 정리와 수정 전 delivery 처리는 보완 대기입니다.
- 채택: 익명 문맥/광고별 새 delivery 노출60초·클릭300초, 당시 유효 이벤트 지연5분. delivery 자체 수명·재전송 횟수/백오프는 보완 대기입니다.
- 채택: 광고 원본/delivery90일·일별 집계/예상 원장/관리 변경 이력365일. 일일/전체 예산 수치·경계·소진/재개와 원장 조회UI/API 세부는 보완 대기입니다.
- 채택: 검증된 발생일KST 귀속·received_at 별도. 통계 화면 갱신 주기/성과 목표·실제 권한 배정은 보완 대기입니다.

실제 구매/차감/환불 기능을3차에 추가하지 않습니다. 채택한 초기 기준은 광고 규정6-5절로 검증하고 남은 회의 규정은 임의 확정하지 않습니다.

## 6. 실제 시연·품질·외부 호출 목표

**연결 담당:** PL·C·INF, A/B 협력.

- 초기 실제 곡/지역·시연 규모와 대상 사용자/청취 조건
- 허용 가능한 기본/Gemini 지연·동시 요청·복구 목표
- 날씨 적합성/만족도를 어떤 질문과 기준으로 평가할지

기술 계산·형태·필수 필터 검증은 고정 사례로 먼저 진행합니다. 모델 gemini-3.8-flash·SDK·응답 형식은 정리되어 있어 실제 프로젝트/키 준비 전에도 모의 응답으로 개발할 수 있습니다. 평가자10명이나 특정 신뢰구간을 모든 개발의 착수 조건으로 요구하지 않습니다. 실측 전에는 만족도·성능을 검증 완료로 보고하지 않습니다.
