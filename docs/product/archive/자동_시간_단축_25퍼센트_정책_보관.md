# 자동 시간 단축25% 정책 보관

- 보관일: 2026-10-14
- 상태: 수령 음악 문서 우선 채택으로 현행 동작에서 제외한 이력입니다.
- 이전 버전: phase3-duration-20261014.1


**사용자 확정:** 적격 후보 부족이면 자동 단축, 최대 단축률25%입니다. 기준은 STANDARD 목표180분이며 실제 결과 하한은135분=8,100,000ms입니다. 부모 결과의 길이에 다시25%를 적용해 재설정마다 계속 짧아지는 방식은 사용하지 않습니다.

다른 구현에서 같은 경계를 사용하도록 다음 기술 초기값을 정합니다. 이 단계/오차는 사용자 발언의 인용이 아니라 기존 ±4분 정책을 연결한 공통 개발 기준입니다.

1. STANDARD180분/176~184분을 먼저 탐색합니다. 실제 적격 카탈로그/필터/탐색 범위로 부족을 확인한 경우에만 SHORTENED로 전환합니다. 제한 풀의 실패·UNKNOWN/시간 초과·Gemini의 짧은 응답/변화 미달을 부족으로 간주하지 않습니다.
2. 단축 목표는175→170→165→160→155→150→145→140→135분 순으로 검사합니다. 각 단계의 최소는 max(135분,목표-4분), 최대는 min(목표+4분,176분-1ms)입니다. 실제 총시간135분-1ms는 항상 실패입니다.
3. 첫 성공 단계에서 정지합니다. 해당 단계는 정확한 목표→목표 초과→목표 미만, 같은 구간 목표 거리→재생시간 가중 품질→ID 동점 기준을 적용합니다. 상위 단계 탐색이 미완료이면 낮은 단계의 성공으로 숨기지 않고 SEARCH_INCOMPLETE로 처리합니다.
4. SHORTENED의 W 집계 구간은 해당 effective_target_ms입니다: r_k=예보 구간과 목표 구간의 겹침/목표 길이, W=sum(r_k*W_k). 목표가 달라지면 같은 ACTIVE 정책으로 후보 W/S와 필터를 다시 계산합니다. 목표 구간과 실제 결과 끝까지 필수 예보의 유효성을 확인합니다.
5. Gemini에는 서버가 선택한 시간 모드/단계와 적격 후보를 전달합니다. 호출/수정 요청의 전체 예산은 모든 단계를 합해 적용하며 무한 호출하지 않습니다. 응답 실패만으로 단축 단계로 이동하거나 solver로 답을 보정하지 않습니다.
6. duration_policy_version=phase3-duration-20261014.1·duration_mode·effective_target_ms/min_ms/max_ms·shortening_reason·검사 단계/근거를 작업/결과/당시 조건에 고정합니다. 보컬·검수·제외·중복·확정된 날씨 하한과 부모 전체N 기준 신규20%를 완화하지 않습니다.
7. 자동 단축 성공은 SHORTENED로 별도 집계하고 화면에 ‘후보 곡이 부족해 선곡표를 자동으로 단축했어요.’를 표시합니다. 메인의 총시간/곡별 시간 비표시 정책은 유지하고 실제 시간은 API/저장/검증에 보존합니다.135분까지 모든 단계가 확인된 구성 불가이면 CANDIDATE_SHORTAGE와 부모 보존입니다.
