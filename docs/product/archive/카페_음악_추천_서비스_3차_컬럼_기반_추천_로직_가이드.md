## 2026-10-13 구현 결정 반영

초기에는 같은 네트워크의 로컬 클러스터에서 Kafka·Spark를 연결하고 최종 AWS로 이전합니다. 프레임워크는 팀 회의 후 결정합니다. 날씨 파이프라인은 새로 구현하며 3차 음악은 보유 CSV를 사용하고, 상세 음악 규격은 추가 문서로 받습니다. 원문은 로컬과 S3에 함께 보관합니다. 작은 후보군부터 상한까지 확장하는 탐색을 사용하고 실제 크기/시간은 미정입니다.

날씨 패널은 유지하고 별도 강수 카드·X·닫기 기록·재노출 방지는 제거합니다. 6시간 공유 수집/조회와 앞 3시간·실제 초과분 추천 검증은 유지하며, 펭귄 안내의 X/Esc는 별개입니다. 소나기·빗방울은 비, 눈날림은 눈+구름 많음 적합도 결합을 사용합니다. 결합 비율/혼합 코드·만료 숫자는 미정입니다. 관리자 초기화 발급·초기 권한 배정, 회수 시 비활성화/세션 무효화, 익명 쿠키 소유 검사, 로컬·S3 원문 보관의 상세 계약은 아래 연결 가이드를 따릅니다. 광고 규정은 별도 회의 결과 대기입니다. 문서 반영은 실행/설치/배포 완료가 아닙니다.
상세 계약: [3차 구현 결정과 익명 문맥·원문 보관 가이드](.././3차_구현_결정과_익명문맥_원문보관_가이드.md).

## 3. 현재 컬럼을 어떤 역할로 사용하나요?

### 3.1. music_track — 18개 컬럼

| 컬럼 | 용도 | 적용·해석 기준 |
| --- | --- | --- |
| `track_id` | 곡 식별, 동일 ID 중복 방지, 제외곡 대조 | 곡명을 식별자로 사용하지 않습니다. |
| `track_name` | 결과 표시 | 제목이 같다는 이유로 병합하지 않습니다. |
| `artists` | 표시, 같은 이름의 연속 배치 완화 | 세미콜론 문자열이며 아티스트 ID 연결이 아닙니다. |
| `album_name` | 결과 표시, 앨범 정보 일치 확인 | 이름만으로 앨범을 연결하지 않습니다. |
| `duration_ms` | 시간 조합·최종 검증 | 양수인 정수 밀리초를 그대로 사용합니다. |
| `explicit` | 운영 정책에서 정한 경우 후보 제한 | 가사·보컬 유무와 다릅니다. false도 미확인을 포함할 수 있습니다. |
| `album_id` | 앨범 ID 연결·무결성 확인 | `music_album.album_id`와 연결합니다. |
| `album_release_date` | 메타데이터 확인·표시 | 부분 날짜 원문을 유지합니다. 곡 최초 발매일로 간주하지 않습니다. |
| `genres` | 복수 장르 선호 | 검토한 원본 라벨과 선택 그룹의 매핑을 사용합니다. |

| `danceability` | 날씨 적합도 | 리듬·춤추기 적합성이며 BPM 자체가 아닙니다. |
| `energy` | 날씨 적합도 | 지각되는 강도·활동성이며 빠르기·볼륨과 동일하지 않습니다. |
| `musical_key` | 초기 핵심 점수에서는 미사용 | -1은 미검출입니다. 분위기를 단독 판정하지 않습니다. |
| `loudness_db` | 순서 조정 시 큰 차이 완화 | 곡 평균 음량이며 매장 재생 볼륨 설정이 아닙니다. |
| `mode` | 초기 핵심 점수에서는 미사용 | 장조·단조로 밝음·우울함을 확정하지 않습니다. |
| `acousticness` | 날씨 적합도 | 어쿠스틱 성향에 대한 판단 수치입니다. |
| `instrumentalness` | 연주곡 검수 후보 선정 | 보컬 없음의 확정 증거로 사용하지 않습니다. |
| `tempo_bpm` | 빠르기 선호, 순서 조정 | 곡 전체 추정 BPM이며 NULL·0은 미확인으로 처리합니다. |

### 3.2. music_album — 7개 컬럼

`album_id`, `album_name`, `album_release_date`는 곡에 복사된 앨범 정보와 일치하는지 확인합니다. `album_type`, `total_tracks`는 앨범 정보 표시, `spotify_url`, `cover_image_url`은 링크·커버 표시 용도입니다. 초기 날씨 점수에는 사용하지 않습니다. 메인의 기본 대표는 현재 결과 첫 곡이며 `album_id`로 `cover_image_url`을 연결합니다. 커버가 없거나 로딩에 실패하면 중앙·행 썸네일에 공통 기본 이미지를 쓰고, 이미지 확보를 필수 후보 조건·시간 조합·점수로 사용하지 않습니다. 실시간 외부 커버 API 호출을 새 의존성으로 추가하지 않습니다.

### 3.3. music_artist — 5개 컬럼

`artist_id`, `artist_name`, `spotify_url`, `artist_image_url`은 아티스트 정보에 사용하고, `artist_genres`는 아티스트 장르로 보관합니다. 현재 곡 테이블에는 아티스트 ID 목록이 없으므로 이름만으로 확정 조인하거나 아티스트 장르를 모든 곡에 자동 복사하지 않습니다.

### 3.4. 현재 스키마에 없는 정보와 이번 추가 설계

- 현재 v1.3은 곡 18개·앨범 7개·아티스트 5개, 총 30개 컬럼입니다.
- `mood_ids`, `vocal_presence`, `tempo_class`, `artist_ids`, `track_languages`·검수 상태는 현행 음악 테이블에 없습니다.
- 이번 추가안은 **music_track.track_languages** 한 개입니다. STRING/TEXT·NULL 허용, 코드 en·zh·ko·ja·other, 다국어는 `ko;en`처럼 저장합니다. 적용 시 곡 19개·전체 31개가 됩니다. 첨부 원본 스키마는 수정하지 않습니다.
- 테마는 별도 `track_review.theme_codes`, 언어 상태/근거는 `track_review.language_status` 등 운영 검수 자료로 설계합니다. 검수 이력과 카탈로그 버전을 함께 고정합니다.
- 언어 미확인 곡은 track_languages=NULL·UNKNOWN, 검수된 무보컬은 NULL·NOT_APPLICABLE입니다. VERIFIED에는 확인된 코드가 하나 이상 필요합니다. '그 외'나 빈 문자열로 미확인을 숨기지 않습니다.
- 신규 컬럼의 NULL 허용과 추천의 요청별 후보 제한은 다릅니다. 언어/테마 누락만으로 기본 음악 카탈로그 전체를 불합격 처리하지 않습니다.
- 빠르기 분류·점수·충족률은 계산값입니다. `valence`, `liveness`, `speechiness`, `time_signature`는 현재 추천 입력에서 제외합니다.
- 선택 코드·장르 라벨 매핑·정책은 버전 있는 운영 설정입니다. 장르 ID·곡-장르 연결 테이블을 필수로 만들지 않습니다.

[음악 분류 컬럼 정의](../../handoff/music/음악_분류_컬럼_정의.md)의 원본 20개·관리 17개는 입력/검수 후보이며 위 30개+신규 언어 1개 계약의 대체안으로 확정되지 않았습니다. 직접 청취한 `energy` 0~10은 현행 곡 `energy` 음향값과 이름만 같고 척도/출처가 다릅니다. 수동 `speed`는 `tempo_bpm`이 아니며, `mood`는 검수 후 `theme_codes`로 매핑하고 `genre`는 `genres`/선택 라벨에 매핑합니다. `instrumental`의 참/거짓/미확인은 보컬 검수의 입력일 뿐 `instrumentalness` 또는 단일 값만으로 엄격 무보컬을 확정하지 않습니다. `country`/Spotify `market`는 노래 언어가 아니고, Spotify 곡 페이지 `play_url`은 음원 재생 URL이 아닙니다. 아티스트 이름은 ID 연결 증거가 아닙니다. 매핑·검수·버전 계약은 M-01/A-02에서 고정합니다.

## 4. 사용자에게 받는 최소 입력

| 항목 | 기본값 | 선택지·영향 | 조건 성격 |
|---|---|---|---|
| 지역 | 최초 설정 필요 | 시·도·시·군·구·동. 서버가 기상청 조회 정보로 연결 | 필수 |
| 보컬 | 제한 없음 | 연주곡만 | 선택하면 필수 제한 |
| 빠르기 | 날씨에 맡기기 | 느린/빠른 곡 우선 | 선호 |
| 테마·장르 | 선택 없음 | 한 영역에서 잔잔한·몽환스러운·재즈·클래식 등 복수 선택 | 선호 |
| 언어 설정 | 5개 모두 기본·목록 접힘 | 영어·중국어·한국어·일본어·그 외의 선호/비선호 두 버튼. 재클릭 해제·반대 버튼 전환·별도 펼치기/접기 | 선호 보너스·비선호 필터 |
| 이번 곡 제외 | 없음 | 서버 제외 초안에 저장한 track_id 전체 목록 | 저장 후 재생성의 필수 제한 |
| 길이 | 180분 | 추가 입력 없음 | 고정 정책 |

지역만으로 요청할 수 있습니다. 테마 칩 선택은 제공하되 분위기 자유 입력·매장 타입·상세 위치·BPM·점수 가중치를 사용자에게 요구하지 않습니다.

이번 선택 집합과 제외 곡은 재생성에 유지합니다. 독립적인 새 추천은 기본값으로 시작하고 기존 결과를 조회하면 그 버전의 조건을 보여줍니다. 계정 기본 설정의 영구 저장은 별도 확장입니다.

### 4.1. ‘연주곡만’과 가사 O/X의 차이

`explicit`는 가사 유무가 아니며 `instrumentalness`는 추정치입니다. 허밍·스캣 등을 고려해 높은 값만으로 엄격한 무보컬 조건을 보장하지 않습니다. [Spotify Audio Features 설명](https://developer.spotify.com/documentation/web-api/reference/get-audio-features)

예를 들어 instrumentalness >= 0.95를 검수 후보 선정 기준으로 검토할 수 있지만 최종 '연주곡만'은 검수된 무보컬 track_id로 제한합니다. 미확인 곡은 포함하지 않습니다. 목록이 미준비면 선택을 비활성화하며 임의로 '연주곡 우선'으로 바꾸지 않습니다.

### 4.2. 테마·장르 복수 선택의 연결

화면의 한 칩 영역을 요청의 두 집합으로 변환합니다.

```json
{
  "selected_theme_codes": ["calm", "dreamy"],
  "selected_genre_codes": ["jazz", "classical"]
}
```

calm·dreamy는 테마, jazz·classical은 장르 선택 코드입니다. 코드는 정책의 type·label·enabled와 연결하며 사용자가 임의 코드/태그를 만들지 않습니다.

- 테마 내 OR: calm 또는 dreamy가 검수 태그와 겹치면 M=1.
- 장르 내 OR: jazz 또는 classical 중 검토된 원본 라벨 매핑과 겹치면 G=1.
- 테마와 장르가 모두 맞으면 두 보너스를 각각 받습니다.
- 네 칩을 동시에 만족해야 후보가 되는 AND 제한으로 해석하지 않습니다.
- 없는/미검수 태그는 선호 일치가 아니며 기본 후보에서 무조건 제외할 이유도 아닙니다.
- 실제 장르 라벨을 확인하기 전 예시 코드를 운영 선택지로 활성화하지 않습니다.

### 4.3. 언어 설정과 노래 언어의 선호·비선호

요청에서는 `preferred_language_codes`와 `blocked_language_codes`를 구분합니다. 화면 제목은 [언어 설정]이며 영어/중국어/한국어/일본어/그 외는 en/zh/ko/ja/other로 연결합니다. 각 언어에 선호·비선호 두 버튼만 표시하고 둘 다 미선택이면 기본(중립)입니다. 기본은 별도 선택 코드가 아닙니다.

| 언어별 UI 상태 | preferred_language_codes | blocked_language_codes |
|---|---|---|
| 기본·두 버튼 미선택 | 해당 코드 없음 | 해당 코드 없음 |
| 선호 선택 | 해당 코드 포함 | 해당 코드 없음 |
| 비선호 선택 | 해당 코드 없음 | 해당 코드 포함 |

초기 요청은 두 목록이 모두 빈 배열입니다. 선택한 버튼을 다시 누르면 해당 코드를 두 목록에서 제거합니다. 반대 버튼을 누르면 이전 목록에서 제거하고 새 목록에 추가합니다. 다른 언어의 값은 유지하며 서버도 두 집합의 교집합을 거부합니다. 이 UI 변경으로 신규 음악 컬럼이나 요청 필드를 추가하지 않습니다.

목록은 최초 접힘이며 별도 [펼치기]/[접기] 버튼으로 제어합니다. 접기·재펼침은 선택 목록과 결과를 유지하고 추천 요청·음악 피드백을 만들지 않습니다. 상태 요약은 모두 중립이면 [기본 적용], 선택이 있으면 [선호 n · 비선호 n]입니다. 선택 해제·전환도 다음 실제 추천 요청에 반영하며 기존 결과의 조건·점수는 다시 계산하지 않습니다. 상세 UI는 서비스 문서 5-1/7-2 및 설계도 3-2를 따릅니다.

| 상태·사례 | 비선호 필터 | 선호 점수 |
|---|---|---|
| VERIFIED + ko;en, en 비선호 | 교집합이 있으므로 제외 | 계산하지 않음 |
| VERIFIED + ko, en 비선호·ko 선호 | 후보 유지 | L=1 |
| VERIFIED + other | 다른 언어로 확인된 자료에만 적용 | other 선호와 일치하면 L=1 |
| UNKNOWN·분류 불완전, 비선호 있음 | 안전한 언어 판정이 없어 제외 | 계산하지 않음 |
| UNKNOWN, 비선호 없음 | 기본 후보 조건을 만족하면 유지 | L=0·미확인 |
| NOT_APPLICABLE + 검수된 무보컬 | 언어 제외 대상 아님 | L=0·해당 없음, 선호 충족 아님 |

다국어는 사용된 언어를 빠짐없이 확인한 상태에서 VERIFIED로 처리합니다. 부분적으로만 확인된 곡은 UNKNOWN입니다. '그 외'는 UNKNOWN의 대체값이 아닙니다.

언어는 아티스트 국적·이름·제목·장르로 추정하지 않습니다. 새 분류 자료는 3차에 수동 입력·검수로 확보합니다. 모든 언어를 비선호로 설정하면 검수된 무보컬 후보만 남을 수 있으며 부족해도 비선호를 자동 해제하지 않습니다.

## 5. 추천 전 데이터 준비·검증

### 5.1. 기존 CSV 컬럼 대응

| 초기 CSV | 현재 컬럼 |
| --- | --- |
| `key` | `musical_key` |
| `loudness` | `loudness_db` |
| `tempo` | `tempo_bpm` |
| `track_genre` | `genres` |

이름 없는 행 번호는 곡 ID로 사용하지 않습니다. 첨부 문서의 114,000개는 CSV 행 수이며, 고유 곡 수나 검수된 추천 후보 수가 아닙니다. 원본 CSV의 실제 전체 값은 이번 가이드 작성에서 직접 검사하지 않았습니다.

초기 CSV에는 `album_id`, `album_release_date` 등이 없으므로 최종 테이블의 N 규칙을 바로 충족한다고 가정하지 않습니다. 미확보·무효 N 값의 행은 정제 준비 영역에 보관하고 최종 적재를 보류합니다. 이런 행을 사용한 알고리즘 실험은 운영용 후보와 구분합니다.

실제 음악 데이터가 없어도 필드·타입/NULL·코드/검수·버전 계약을 먼저 정하면 적격/부적격·언어 UNKNOWN/다국어·경계 시간·후보 부족 사례의 고정 자료로 필터, 점수, 정수 시간 조합, 작업자/API를 구현할 수 있습니다. 이 fixture의 검수/Gold 표시는 테스트 전용이며 실제 카탈로그 발행·후보 규모·성능·날씨/음악 적합성 검증의 완료 근거가 아닙니다. 실데이터 유입 후 원본/키/NULL·검수·176~184분 조합 가능성·탐색/처리시간을 다시 확인합니다. 새 자료의 Spotify 조회 절차는 수집 후보이며 3차 필수 API 연동으로 가정하지 않습니다.

### 5.2. 기본 후보 검사

1. 최종 테이블의 필수값과 곡–앨범 무결성을 확인합니다.
2. 추천에 사용할 수 있도록 검수된 카탈로그에 포함되는지 확인합니다.
3. `duration_ms`가 양수인 정수이고 최대 선곡표 길이보다 길지 않은지 확인합니다.
4. 같은 `track_id`가 여러 행에 있으면 메타데이터 충돌 여부를 확인합니다.
5. 사용자 제외 곡·검수된 연주곡 제한·비선호 언어 필터를 적용합니다. 언어 필터의 UNKNOWN/NOT_APPLICABLE 처리는 4.3절을 따릅니다.
6. 음향 데이터의 존재·범위를 확인합니다.

같은 ID의 장르만 다른 원본 행도 핵심 메타데이터 일치와 장르 병합 기준을 검토한 뒤 처리합니다. 서로 다른 ID가 같은 녹음을 가리키는지는 현재 컬럼만으로 확정할 수 없습니다.

`genres`, `artists`, 신규 `track_languages`는 항목 공백을 제거하고 구분 규칙을 적용합니다. 장르는 정확히 같은 라벨만 중복 제거하며 대소문자·동의어를 임의로 병합하지 않습니다. 이름 자체에 세미콜론이 있는 경우는 예외 처리합니다.

### 5.3. 음향 데이터 충족률

초기안에서는 다음 세 컬럼을 날씨 점수에 사용합니다.

| 컬럼 | 가중치 |
| --- | ---: |
| `energy` | 0.50 |
| `danceability` | 0.25 |
| `acousticness` | 0.25 |

`energy`가 유효하고 다른 두 컬럼 중 하나 이상이 유효한 곡을 후보로 둡니다. 가중치 합 기준 충족률은 최소 0.75입니다.

- 세 값이 있으면 충족률 1.00입니다.
- energy와 다른 한 값이 있으면 충족률 0.75입니다.
- energy만 있으면 충족률 0.50이므로 제외합니다.
- NULL·무효 값은 점수 0으로 채우지 않습니다. 실제 0은 정상값으로 계산합니다.

0~1 컬럼의 범위 밖 값은 유효한 입력으로 사용하지 않고 품질 오류로 남깁니다. `musical_key=-1`, `mode=0`, `explicit=false`, `popularity=0`도 결측과 구분합니다.

테이블의 Y 규칙은 유지합니다. 특정 컬럼이 없는 곡을 이번 추천 후보에서 제외하는 것은 테이블에서 NULL을 금지하는 것과 다릅니다.

## 6. 날씨를 점수 계산에 연결합니다

### 6.1. 앞 3시간과 뒤쪽 조회 구간을 구분합니다

이 가이드의 기본 추천 기준시각은 요청 시각입니다. 해당 시각부터 180분까지를 날씨 점수 계산 구간으로 사용합니다. 시간대는 Asia/Seoul로 명시하고 실제 예보 시간 구간의 의미는 날씨 수집 규격을 따릅니다.

날씨 입력은 [수집·지역매핑](../../handoff/weather/01_날씨_수집과_지역매핑.md)과 [데이터규격·정제](../../handoff/weather/02_날씨_데이터규격과_정제.md)에 따른 공식 지역 코드/격자, `issued_at`·`target_at`·`received_at`, 항목별 `raw`·`value`·`unit`·`status`, 출처/정규화 버전으로 받습니다. [저장구조](../../handoff/weather/03_날씨_저장구조.md)의 최신 조회 모델을 사용하며 조회 시점마다 예보 유효성을 다시 평가합니다. 최신 항목이 누락됐는데 오래된 정상값을 현재 값으로 메우거나 실제 `0`을 누락으로 취급하지 않습니다. API허브 원문과 로컬 [적재시험](../../handoff/weather/04_API호출과_RDB적재시험.md)의 결과는 운영 데이터/성능 검증으로 간주하지 않습니다.

- 추천 기준 3시간의 필수 예보가 누락·만료되면 새 생성을 차단합니다.
- 뒤쪽 조회 구간만 누락된 경우 유효한 앞 3시간의 추천을 차단하지 않습니다.
- 수집 실패와 기존 예보의 유효성·누락을 구분합니다.
- 180분을 넘는 결과는 실제 총시간까지 예보가 유효한지도 확인합니다. 확인되지 않는 초과 길이는 유효한 시간 조합 후보로 취급하지 않습니다.
- 6시간 공유 조회는 유지하고 별도 강수 카드·닫기 상태는 제거합니다. 뒤쪽 예보는 현재 선곡에 미리 반영하지 않습니다.

예약 시작 시각, 실제 재생 시작의 지연, 날씨에 따른 자동 곡 교체는 후속 설계 사항입니다.

### 6.2. 날씨별 목표 중심과 허용 거리 — v3 초기값

2026-10-13 사용자 결정에 따라, 범위 전체에 만점을 주던 v2 대신 목표 중심과의 거리로 점수를 구합니다. 날씨별 수치 구분을 강화하는 변경이며 청취 적합성이 입증됐다는 뜻은 아닙니다.

| 예보 유형 | energy 목표 중심 | danceability 목표 중심 | acousticness 목표 중심 |
| --- | ---: | ---: | ---: |
| 맑음 | 0.55 | 0.55 | 0.35 |
| 구름 많음·흐림 | 0.40 | 0.375 | 0.55 |
| 비 | 0.30 | 0.30 | 0.75 |
| 눈 | 0.25 | 0.275 | 0.80 |

세 특성의 허용 거리 `delta_j`는 각각 0.30으로 시작합니다. 중심값·허용 거리는 버전별 초기 설정이며 실제 데이터 분포와 청취로 검증합니다. 대화에서 나온 비 energy 0~0.4는 범위 비교 아이디어였고, 현행 계산은 비 중심 0.30을 사용합니다. 과거 범위가 새로운 필수 필터로 남지 않도록 합니다.

이는 운영팀이 검토할 선곡 정책이며 날씨와 음악 취향의 검증된 인과관계가 아닙니다. 기상청 원본 코드는 변환 규칙을 검토해 위 유형에 연결하고, 알 수 없는 코드를 맑음으로 기본 처리하지 않습니다.

[날씨분류와 계절기준](../../handoff/weather/05_날씨분류와_계절기준.md)의 PTY/SKY/강수량/풍속/낙뢰 분류는 날씨 표시와 상태 해석의 입력이며 이 표의 음향 목표·가중치를 확정하지 않습니다. POP는 강수 확률이지 비가 내렸다는 판정이 아니고, KIM 보조 구름값으로 기본 SKY를 덮거나 임의 평균하지 않습니다. 계절·체감온도·온습도 등 미정 분류는 임의 점수로 채우지 않습니다. 날씨→음악 연결 로직과 수치는 후속 회의와 R-01 검증 결과로 정합니다.

비·눈 혼합은 별도 유형을 유지합니다. 초기 비교안으로 비 적합도와 눈 적합도를 0.5씩 반영할 수 있으나 이는 실제 강수 비율을 뜻하지 않으며 검토 후 확정합니다.

### 6.3. 한 컬럼의 중심 거리 적합도

값 x와 해당 날씨·특성의 목표 중심 c_j의 적합도 m을 계산합니다. 유효 값은 0~1, 허용 거리는 양수여야 합니다.

```text
distance = abs(x - c_j)
m = max(0, 1 - distance / delta_j)
```

중심에서만 1점이며 멀어질수록 낮아집니다. 중심에서 delta_j 이상 떨어지면 0점입니다. 유효한 실제 0도 정상 계산하며 NULL을 0으로 채우지 않습니다. 예를 들어 energy=0.30이면 비 적합도 1, 맑음 적합도 약 0.1667입니다. 날씨 목표 중심이 달라도 중간에 있는 곡은 같은 점수를 받을 수 있으며 모든 곡의 점수 차이를 보장하지 않습니다.

### 6.4. 날씨별·3시간 종합 적합도

유효한 컬럼만 분자와 분모에 포함합니다.

```text
C = 유효한 컬럼의 가중치 합
W_weather = sum(유효 컬럼의 가중치 × 중심 거리 적합도) / C

r_k = 예보 구간 k와 앞 180분의 겹치는 길이 / 180분
W = sum(r_k × W_weather_k)
```

예를 들어 흐림 2시간과 비 1시간이면 흐림 점수의 2/3와 비 점수의 1/3을 더합니다. 현재 날씨 아이콘 하나만으로 전체 3시간을 판단하지 않습니다. 예보 경계는 겹침·빈 구간 없이 계산해야 합니다.

v3에서도 `W >= 0.55`를 후보 하한으로 유지합니다. 점수 분포가 바뀌므로 날씨별 후보 수·총길이·시간 조합 성공률·미확정률을 다시 측정합니다. 이 하한이 검증됐다는 뜻은 아니며 시간 부족을 이유로 자동 완화하지 않습니다. 후보가 부족하면 정책을 별도 개정하고 새 버전으로 기록합니다.

## 7. 사용자 선호 점수 — 정책 v3 초기안

2026-10-13 사용자 결정에 따라 **날씨 0.75·빠르기/테마/장르/선호 언어 각 0.0625**를 사용합니다. 중심 거리 계산과 비중 변경을 정책 v3로 구분하고 이전 결과는 재계산하지 않습니다. 네 그룹 모두 활성화하면 75:25, 미선택 그룹은 활성 분모로 재정규화합니다. 효과 검증은 R-01에서 진행합니다.

### 7.1. 빠르기 T

초기 분류는 느림 0 < BPM < 90, 중간 90 <= BPM <= 120, 빠름 BPM > 120입니다. 실제 분포·청취 후 경계를 조정합니다.

선택한 분류와 일치하면 T=1, 아니면 T=0입니다. NULL·0·무효 BPM은 미확인이며 선호 충족으로 집계하지 않습니다. 빠르기 미일치 곡도 필수/날씨 조건을 만족하면 후보입니다.

### 7.2. 테마 M·장르 G

- M=1: 검수된 theme_codes와 선택한 테마 집합에 교집합이 있음.
- G=1: 정규화된 genres가 선택 장르 코드의 검토된 원본 라벨 집합 중 하나와 정확히 일치.
- 나머지는 0이며 미확인·미연결을 구분해 기록합니다.
- 여러 선택에 일치해도 같은 그룹 보너스를 중복 합산하지 않습니다. 많은 칩 선택만으로 점수가 계속 높아지지 않습니다.
- pop을 한국어·국내 음악으로 자동 분류하지 않습니다. 장르와 언어는 별도 자료입니다.

### 7.3. 선호 언어 L

필터를 통과한 VERIFIED 곡의 언어와 preferred_language_codes가 하나 이상 겹치면 L=1, 아니면 0입니다. 비선호는 이 계산 전에 제외합니다.

UNKNOWN·NOT_APPLICABLE은 L=0입니다. 무보컬은 언어 비선호에서 제외되지 않지만 특정 언어 선호를 충족한 것으로 표시하지 않습니다. 언어 선호가 켜진 요청에서는 이 곡도 공통 분모를 사용하며 언어 가중치를 곡마다 제거해 점수를 올리지 않습니다.

### 7.4. 최종 점수

```text
a_t = tempo_preference가 auto가 아니면 1
a_m = selected_theme_codes가 비어 있지 않으면 1
a_g = selected_genre_codes가 비어 있지 않으면 1
a_l = preferred_language_codes가 비어 있지 않으면 1

S = 100 × (0.75×W + 0.0625×a_t×T + 0.0625×a_m×M
                 + 0.0625×a_g×G + 0.0625×a_l×L)
        / (0.75 + 0.0625×a_t + 0.0625×a_m + 0.0625×a_g + 0.0625×a_l)
```

선택하지 않은 그룹은 분모에서도 제외합니다. 선택한 그룹의 값이 미확인·미일치·해당 없음이면 해당 보너스는 0입니다. 같은 요청에서는 모든 곡에 같은 활성 그룹과 분모를 적용합니다.

연주곡 제한·비선호 언어·제외 곡은 가감점이 아닙니다. 높은 S로 제한을 위반한 곡을 되살리지 않습니다. 사용자 입력은 점수 가중치가 아닌 검증된 선택 코드만 받습니다.

### 7.5. 가상 곡 계산 예시

비 날씨·느린 곡 우선·클래식 장르 선택, 테마/선호 언어는 선택 없음입니다. v3 분모는 0.875입니다. 실제 CSV 행이 아닌 계산 확인용 값이며 필수 정보·일반 검수를 통과했다고 가정합니다. 보컬은 제한 없음입니다.

|---|---:|---:|---:|---:|---|---:|---:|---|
| A | 0.35 | 0.30 | 0.80 | 80 | classical;new-age | 0.8750 | 1.00 | 89.29점 |

### 7.6. 맑음과 비의 수치 구분 확인

3시간 내내 해당 날씨이고 취향 미선택이면 S=100×W입니다. 아래는 계산용 가상 곡이며 하한 미달 점수는 진단용으로만 표시하고 공개 성공 후보로 사용하지 않습니다.

| 곡 특성 energy/danceability/acousticness | 비 점수 | 맑음 점수 | 비−맑음 | 후보 상태 |
|---|---:|---:|---:|---|

첫 곡의 구 v2 범위 방식 점수는 비 100·맑음 75로 차이 25점이었습니다. 중심 거리 방식에서는 차이 약 66.67점입니다. 두 방식 모두 최종 비중을 75:25로 맞추고 네 선호 항목의 동일한 일치를 가정하면, 하한 적용 전 진단용 최종 점수 차이는 18.75점에서 50점으로 커집니다. 실제로는 맑음 후보에서 제외되므로 두 최종 점수를 승인 가능한 후보의 비교로 해석하지 않습니다.

검증은 점수 차이뿐 아니라 동일 카탈로그·취향·제외 조건에서 상위/최종 곡의 공통 비율, 결과의 음향 특성 평균, 태그 반영률, 후보 수와 조합 성공률을 함께 기록합니다. 공통 곡 비율은 공통 track_id 수 / 두 목록 중 적은 곡 수이며 한 목록이 비었으면 비교 불가로 기록합니다. 날씨만 달라졌다고 강제로 다른 곡을 넣지 않습니다.

## 8. 3시간 선곡표 조합

### 8.1. 시간과 품질의 비교 순서

| 순위 | 유효한 총시간 | 구간 내부 비교 |
| --- | --- | --- |
| 1 | 정확히 180분 | 품질 높은 조합 우선 |
| 2 | 180분 초과~184분 이하 | 180분과의 거리 최소, 같은 시간이면 품질 비교 |
| 3 | 176분 이상~180분 미만 | 180분과의 거리 최소, 같은 시간이면 품질 비교 |

179분 59초보다 180분 30초를 우선합니다. 범위 밖 조합은 점수가 높아도 정상 선곡표로 확정하지 않습니다. 검수·날씨·보컬·비선호 언어·제외 곡·예보 유효성도 만족하는 결과끼리 비교합니다.

```text
MIN_MS    = 10_560_000
TARGET_MS = 10_800_000
MAX_MS    = 11_040_000
total_ms  = sum(선택한 곡의 duration_ms)
```

실제 밀리초 합으로 판정합니다. 곡마다 초 단위로 반올림한 합을 최종 시간으로 사용하지 않습니다. 이 총시간은 곡 길이의 합이며, 정지·외부 재생 지연 등 실제 재생 환경까지 포함한 시간은 아닙니다.

### 8.2. 조합 구현 후보

정수 제약 최적화인 CP-SAT를 구현 후보로 권합니다. 각 곡의 선택 여부를 0/1로 두고 시간 조건을 만족하는 조합을 찾습니다. 제약식은 정수로 표현하며 점수 목적함수는 정수 배율로 변환합니다. [OR-Tools CP-SAT 공식 문서](https://developers.google.com/optimization/cp/cp_solver)

```text
x_i ∈ {0, 1}
T = sum(duration_ms_i × x_i)
MIN_MS <= T <= MAX_MS
동일 track_id는 최대 1회
```

처음에는 정확히 180분인 조합을 검색합니다. 같은 후보군에서 해당 조합이 없다고 확인되면 초과 구간, 그다음 부족 구간을 검색합니다. 각 구간의 목표 거리 최소화 후 총시간을 고정하고 품질을 비교합니다.

품질은 다음과 같이 재생시간으로 가중한 평균을 사용합니다.

```text
playlist_quality = sum(S_i × duration_ms_i × x_i) / T
```

T를 고정한 뒤에는 분자만 최대화할 수 있습니다. 예를 들어 S를 100배 후 반올림해 정수 점수로 변환할 수 있으며, 변환 기준과 정수 범위를 확인합니다. 시간은 그대로 밀리초를 유지합니다. 단순 점수 합만 최대화하면 짧은 곡을 많이 넣는 조합이 유리해질 수 있습니다.

### 8.3. 후보군·검색 시간 관리

114,000개 원본 행 전체를 밀리초 단위 DP에 바로 넣는 방식을 기본으로 삼지 않습니다. 먼저 유효한 고유 곡을 만들고 점수 상위 후보와 선호·음향 특성이 다른 후보를 포함한 제한된 후보군에서 검색합니다.

조합을 찾지 못하면 후보군을 확장하되 필수 제한·날씨 하한·허용 시간은 유지합니다. 후보군 크기, 검색 제한시간, 검색 방식은 실제 데이터의 처리시간을 측정해 확정합니다.

| 검색 결과 | 해석 |
| --- | --- |
| OPTIMAL | 해당 후보군·문제에서 최적 결과가 확인됐습니다. |
| FEASIBLE | 조건을 만족하는 결과를 찾았지만 최적성은 미확인입니다. |
| INFEASIBLE | 해당 후보군·문제에 유효한 조합이 없다고 확인됐습니다. |
| UNKNOWN | 제한시간 등의 이유로 결과·불가능 여부를 확정하지 못했습니다. |
| MODEL_INVALID | 문제 정의 오류로 처리하며 사용자 조건 부족으로 안내하지 않습니다. |

상태의 의미는 [공식 설명](https://developers.google.com/optimization/cp/cp_solver)을 따릅니다. UNKNOWN을 INFEASIBLE로 바꾸지 않습니다. 상위 시간 구간의 검색이 미완료인데 하위 구간 결과를 반환한다면 시간 우선순위가 최적으로 확인됐다고 표시하지 않습니다. 제한된 후보군의 최적 결과도 전체 카탈로그의 최적 결과를 보장하지 않습니다.

유효 결과가 없으면 검색 미완료와 확인된 구성 불가를 구분해 안내합니다. 조건을 자동 해제하거나 중복 곡·미검수 곡으로 시간을 채우지 않습니다.

## 9. 재생 순서와 재생성

시간 조합 이후 다음 기준을 약한 순서 조정 조건으로 사용합니다.

1. 같은 아티스트 이름이 연속되지 않도록 가능한 범위에서 배치합니다.
2. 유효한 BPM이 있는 곡끼리 급격한 빠르기 변화를 완화합니다.
3. 유효한 평균 음량이 있는 곡끼리 큰 차이를 완화합니다.
4. 미확인 값을 0으로 채워 변화량을 비교하지 않습니다.
5. 단순 순서 변경 후에도 중복·시간·필수 조건을 최종 확인합니다.

아티스트 이름은 연속 배치의 참고값이며 동일 인물의 확정 ID로 취급하지 않습니다. BPM·음량 변화의 허용 수치와 다양성 강도는 검수 후 결정합니다.

곡 제외 재생성에서는 보컬·빠르기·복수 테마/장르·선호/비선호 언어·이번 제외 곡 목록을 유지하고 전체 추천을 새 결과 버전으로 검증합니다. 재조회된 날씨를 사용하면 새 근거를 기록합니다. 같은 요청에 항상 다른 곡을 제공하는 정책은 별도 결정하며, 다양성을 추가할 경우 동점 선택의 seed도 기록해 재현 가능하게 합니다.

[제외] 클릭은 회색 곡 정보·‘제외됨’·파란 테두리 [제외 취소]를 즉시 표시하고 현재 전체 제외 집합을 서버 초안에 저장합니다. 행은 남기며 자동 추천 계산은 실행하지 않습니다. ‘이번 제외 곡 n개 [보기 ▾]’ 목록은 접힌 상태로 제공하고 새 결과에 없는 제외도 취소할 수 있습니다. 취소는 목록에서 해당 ID를 제거해 저장하며 해당 곡의 포함을 보장하지 않습니다.

초안 GET/PUT은 `/api/playlist-families/{family_id}/exclusions`를 사용합니다. PUT은 source_playlist_id·expected_revision·전체 excluded_track_ids·Idempotency-Key로 소유/곡·멱등·수정 버전을 확인하고 전체 집합을 교체합니다. 같은 요청 재전송과 변경 없는 저장은 제외/취소 이벤트를 중복 생성하지 않습니다. 저장 중/실패/미저장 변경에는 재생성과 승인을 차단하고 화면의 편집값을 보존해 다시 저장합니다.

[다른 선곡표 요청]은 필수 exclusion_revision과 현재 선택을 보내며 서버가 최신 저장 초안과 일치하는지 확인합니다. 재생성 API에서 제외 목록을 직접 받거나 부모 목록에 추가 제외를 합치지 않습니다. 작업 등록 시 서버 초안의 최종 excluded_track_ids·exclusion_revision을 작업 입력에 고정해 후보 필터와 최종 검증에 사용하고 새 결과에 기록합니다. 작업자에서 실시간 초안을 다시 읽지 않습니다. A 제외 저장 후 다음 결과에는 A가 없어야 하고 이어 B를 저장하면 A/B 모두 없어야 합니다. A 취소 저장 후에는 B만 제외하며 부모의 이전 목록에서 A가 다시 차단되지 않아야 합니다.

재생성 실패·요청 오류·시간 조합 불가에도 선택과 서버 초안을 유지하고 재시도에 반영합니다. 완료/실패 처리에서 초안을 지우거나 작업 입력으로 되돌리지 않습니다. 새 결과에서도 제외는 명시 취소 전까지 유지하며 독립 새 추천은 새 계열의 빈 초안으로 시작합니다. 수정 버전 충돌에는 최신 목록 확인 후 다시 저장/요청하고 같은 유효 소유 문맥에서만 복원합니다. 미저장 변경·미반영 변경·생성 중·실패 결과는 승인하지 않습니다. 서버 승인에도 현재 exclusion_revision과 결과 제외 집합=현재 초안 검사를 적용하며 필수 조건·시간·예보·중복을 검증한 새 버전은 별도 승인합니다. 이전 결과 버전은 변경하지 않습니다.

### 10.2. 추천 결과에 남길 정보

다음은 추천 응답·이력의 논리 항목이며 현재 music_track에 추가된 컬럼 목록이 아닙니다.

- 추천 결과 ID·버전·부모 버전, 생성/요청 기준시각, 지역.
- 익명 소유 문맥·접근 검증 범위, 선택한 결과 버전·선택 시각. 4차 계정 소유 연결은 별도 항목으로 설계합니다.
- vocal_option·tempo_preference·selected_theme_codes·selected_genre_codes·preferred_language_codes·blocked_language_codes·excluded_track_ids.
- 재생성에 사용한 exclusion_revision과 불변 제외 스냅샷. 현재 서버 초안·편집 중인 화면 값은 결과 조건과 별도이며 music_track의 신규 컬럼이 아닙니다.
- 사용한 예보 묶음과 실제 시간 구간, 누락·유효성 판정 근거.
- 카탈로그·검수 자료·추천 규칙 버전.
- 순서가 정해진 track_id 목록, 곡별 점수·데이터 충족률·선택 일치 여부. 표시용 items의 album_id·nullable cover_image_url은 첫 곡 대표/행별 썸네일에 사용합니다.
- 실제 total_ms, 적용된 시간 구간, 재생시간 가중 평균 점수.
- 그룹별/선택 코드별 반영 곡 수·전체 곡 수·미확인·해당 없음 수. 비선호 언어 제외·미확인 언어 제외 수는 운영 진단으로 기록합니다.
- 검색 상태·후보군 범위·한도, 최적성 확인 여부.

선호 반영률의 기본 분모는 최종 전체 곡 수입니다. 미확인 곡을 분모에서 몰래 제외해 충족률을 높이지 않습니다. 재생시간 기준 반영률을 추가하면 곡 수 기준과 구분해 표시합니다.

메인에는 첫 곡 대표 이미지·곡 수/목록·날씨 기준·선호 반영·미확인 또는 부족 안내를 보여주고 총시간·곡별 재생시간은 표시하지 않습니다. duration_ms·total_ms의 정수 계산/응답/저장·당시 피드백 기록과 180분 목표·176~184분·정확히 목표 → 초과 → 부족·초과 구간 날씨 검증은 유지합니다. 규칙 수치와 검색기 내부 상태는 관리자 기록에 남깁니다. [이 선곡표 승인]은 현재 이용할 버전을 지정하며 실제 재생·장기 계정 저장을 의미하지 않습니다.

### 10.3. 관리자 전용 곡 제외 피드백 이력 — 3차 P0

제외/취소를 피드백 계열의 원본 행동으로 보존하고 ADMIN + 피드백 조회 권한의 `/admin/feedback/exclusions`에서 검색·조회합니다. 일반 사용자의 ‘이번 제외 곡’ 초안 목록·4차 계정 이력과 구분하며 관리자 조회는 추천 점수·후보·초안·승인 상태를 변경하지 않습니다. 최소 목록/상세 화면과 API는 F-07/Q-04 P0이며 Q-07 통합 대시보드는 P1입니다.

- feedback_context_snapshot에는 실제 source_playlist에 사용한 selected_theme_codes·selected_genre_codes와 당시 명칭, vocal_option·tempo_preference·선호/비선호 언어, 지역·추천 기준시각·예보 묶음/발표 시각/적용 구간·날씨 요약·정책/카탈로그/선택 정의 버전을 결과당 한 번 고정합니다. 아직 재생성하지 않은 화면 선택은 원본 생성 조건으로 기록하지 않습니다.
- feedback_event의 제외/취소에는 event_id·event_type·occurred_at·owner 내부 식별자·family_id·source_playlist_id·track_id·context_id·exclusion_revision·request_id·is_test와 당시 곡 스냅샷을 필수 기록합니다. 곡 스냅샷은 track_name·artists·duration_ms·theme_codes/당시 명칭·genres 라벨·track_languages·검수/확인 상태·곡의 카탈로그/검수 버전을 포함합니다.
- 사용자가 선택한 테마/장르와 곡 자체의 테마/장르를 별도 항목/필터로 둡니다. 선택 없음 []와 곡 NULL/미확인, 검수 무보컬의 언어 NOT_APPLICABLE을 보존하고 없는 정보를 추정하지 않습니다. 서버가 원본 결과/불변 카탈로그에서 가져오며 현재 음악 값이나 클라이언트의 곡명/태그를 대신 신뢰하지 않습니다.
- 취소는 원래 제외 이벤트를 삭제하지 않고 related_exclusion_event_id로 연결합니다. 취소의 곡 스냅샷은 원래 제외 기록 기준이고 취소 당시 조건은 현재 표시된 source_playlist 기준으로 구분합니다. 재제외는 새 이벤트입니다. 초안 변경·필수 기록·outbox를 원자적으로 저장하고 실패/변경 없음/멱등 재시도는 실제 행동으로 중복 집계하지 않습니다.
- 발행 payload·Bronze·Silver에는 당시 조건/곡의 필수값을 보존합니다. feedback_exclusion_history 뷰/정제 테이블에서 기간·곡·선택 태그/곡 태그·행동/최신 기록 상태를 검색하고 목록/상세·페이지·as_of·취소 연결·원본 만료를 제공합니다. 최신 상태는 검색 기간 밖의 후속 취소도 반영합니다.
- 이벤트·스냅샷·연결 기록의 보관/삭제는 D-02/D-03에서 함께 정합니다. 새 추천/초안 초기화만으로 보관 이력을 지우지 않고 원본 결과 만료 뒤에는 당시 스냅샷과 만료 상태를 표시합니다. 문맥 만료는 마지막 기록 상태와 현재 작업 효력을 구분합니다. 누락 정보는 ‘미기록’이며 현재 값으로 과거 정보를 채우지 않습니다.

피드백 스키마의 세부 필수 항목·관리자 GET API·권한·상태/취소 처리·폴더는 [구현 설계도](.././카페_음악_서비스_구현_설계도.md) 5-1/6-8/7-2/11-1을 따릅니다. music_track의 컬럼 추가·사용자 추가 입력·3차 AI 도입을 요구하지 않습니다.

익명 결과 조회·재생성·선택은 해당 문맥의 제어 권한을 검증합니다. 임의 결과 ID로 타 문맥의 기록을 공개하거나 변경하지 않습니다. 보관 기간·브라우저 복원 한도는 D-02·D-03에서 정합니다. 3차 운영 기록은 후속 사용자 장기 이력 화면과 구분하며, 계정 편입을 도입할 때 기존 문맥/보관 상태를 검증합니다.

## 12. 구현 순서와 의사코드

권장 순서는 현행/신규 데이터 계약 → 테마·장르·언어 검수 → 선택지 가용성 → 필수 필터 → 날씨/선호 점수 → 시간 조합 → 순서·최종 검증 → 결과 승인/행동입니다.

다음은 설계 의사코드이며 실제 구현이 아닙니다. 요청·결과 저장·비동기 작업은 [구현 설계도](.././카페_음악_서비스_구현_설계도.md)에 연결합니다.

```text
generate_playlist(job):
    context = load_verified_request_context(job)
    request = job.normalized_request
    validate_owned_parent_result_if_present(context, request)
    validate_option_codes_and_disjoint_language_sets(request)
    forecast = load_pinned_forecast_bundle(job.forecast_bundle_id)
    require_valid_weather(forecast, job.requested_at, 180_minutes)
    weather_segments = overlap_with_first_180_minutes(forecast, job.requested_at)

    tracks = load_published_catalog_snapshot(job.catalog_version)
    tracks = validate_required_metadata_and_unique_track_ids(tracks)
    tracks = remove_excluded_track_ids(tracks, request.excluded_track_ids)

    if request.vocal_option == "instrumental_only":
        tracks = keep_verified_no_vocal_track_ids(tracks)

    if request.blocked_language_codes is not empty:
        tracks = keep_verified_no_vocal_or_fully_verified_unblocked_languages(
            tracks, request.blocked_language_codes
        )

    candidates = []
    for track in tracks:
        if not valid_energy_and_minimum_feature_coverage(track):
            continue
        W = duration_weighted_weather_fit(track, weather_segments)
        if W < policy.min_weather_fit:
            continue
        S, status = score_v3_with_active_preference_groups(track, W, request)
        candidates.append(track, W, S, status)

    if candidates is empty:
        return no_eligible_candidates_with_filter_diagnostics

    allowed_time = valid_playlist_time_limit(forecast, job.requested_at, 184_minutes)
    result = optimize_time_then_quality_with_pool_expansion(
        candidates, allowed_time, policy.search_limits
    )
    if result has no valid_solution:
        return distinguish_search_incomplete_and_scoped_infeasible(result)

    ordered = arrange_tracks_with_soft_transition_rules(result.tracks)
    validate_final_time_ids_vocal_languages_exclusions_and_weather(
        ordered, request, forecast, job.requested_at
    )
    output = versioned_result_with_reasons_and_search_scope(ordered, result)
    persist_result_only_with_current_worker_lease(context, job, output)
    return output
```

작업의 기준 시각·예보·카탈로그·정책 버전을 고정하고 큐 지연/만료도 재검사합니다. 재생성은 새 시각·예보·버전을 기록하면서 요청 조건·제외 곡을 유지합니다.

공개 요청의 익명/계정 소유·이용 한도와 작업 등록은 API에서 먼저 검증합니다. 관리자 로그인을 기본 추천 조건으로 넣지 않습니다. 광고 오류·안내 위젯 닫기는 추천 입력을 바꾸지 않습니다. 3차 구현은 R-01~R-05·U-01~U-02이며 계정 이력·결제는 4차입니다.

### 14.1. 펭귄 안내와 추천 계산의 경계

- 지역 선택·날씨 패널 → 음악 취향 → 선곡표 확인·승인의 세 안내 단계는 프론트엔드 설명 기능입니다. 별도 4번 날씨 안내와 강수 카드는 제거하고 날씨 패널을 유지합니다. 메인을 먼저 표시하고 [안내 보기]/[사용 안내]로 시작하며 1/3~3/3·3번 종료로 guideVersion을 갱신합니다. 공통 자산은 사용자가 확정한 [penguin-guide-first.png](../../assets/penguin/penguin-guide-first.png) 한 장으로 프로젝트 자산 폴더에 확보됐고, 프론트엔드 배치·실제 화면 검증은 남았습니다. guideVersion은 추천 규칙/카탈로그/예보 버전과 별도로 관리합니다.
- 안내 이동/종료/다시 보기·완료 기록을 사용자 음악 취향·추천 요청·곡 제외·실제 승인·명시적 평가로 해석하지 않습니다. 추천 가중치·필수 필터·시간 우선순위는 바꾸지 않습니다.
- 결과/날씨 자료가 없으면 예시 선곡표/예시 날씨 패널을 사용합니다. 예시값을 실제 추천·저장·피드백으로 처리하지 않습니다.
- 안내 중 실제 화면 조작을 차단하고 종료 후 원래 선택·결과·승인·날씨 패널 상태를 유지합니다. 저장/PNG/대상 실패가 기본 추천 이용을 막지 않도록 합니다.
- 추가 음악 컬럼·언어 입력·계정·서버 이벤트를 요구하지 않습니다. 자산/흐름은 서비스 문서 7-13 및 설계도 3-5, 구현/검증은 U-03~U-05를 따릅니다.

### 14.2. GitHub 변경·검증·버전 인계

- 추천 기준/기대값은 기획 PL이 취합하고 C가 추천·음악/카탈로그를, B가 날씨/피드백·공통 저장을 구현/검증합니다. A는 화면, INF는 실행 환경을 맡습니다. 개발 3명·인프라 1명·기획 1명 기준이며 기획 확인을 기술 검증으로 대체하지 않습니다.
- 상세 협업은 [GitHub 협업 및 운영 방침](../../../CONTRIBUTING.md), 담당/폴더는 AGENTS.md, 설정/실행은 설계도 11-4·D-05/D-06을 따릅니다.
- 추천 정책·필수 필터·시간 조합·데이터/검수 계약 변경은 타인 검토 2명과 고정 입력/기대/실제 결과를 연결합니다. 기존 네 제품 문서를 확인하고 영향받는 부분을 맞춥니다.
- PR에는 태스크/실제 이슈, 바뀐 동작, policy_version·카탈로그/검수·예보 기준, 필요한 검사·미실행·구버전/복구 영향을 적습니다.
- 브랜치/PR/안내 버전은 추천 policy_version을 대신하지 않습니다. main 병합이 추천 정책·카탈로그 발행/실제 배포 완료를 뜻하지 않습니다.
