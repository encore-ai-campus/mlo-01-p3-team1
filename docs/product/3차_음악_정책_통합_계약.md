## 2. 입력·저장·변환

추천·표시 필드18개는 다음 순서입니다. instrumental_review_value는 검수 관리용이며 점수 항목이 아닙니다.

```text
track_id, track_name, artists_id, artists_name, album_id, album_name,
album_release_date, duration_ms, explicit, genre, energy, mode,
acousticness, mood, speed, main_inst, instrumental, play_url
```

- track_id/track_name/artists_name/album_name/play_url은 필수 문자열, duration_ms는 정수, explicit은 필수 bool입니다. artists_id/album_id/album_release_date와 분류값은 문서의 NULL 허용을 따릅니다. 추천 duration_ms는 양수만 허용합니다. 저장 가능한 0은 추천 적격과 구분합니다.
- 원본 CSV의20개 + 이름 없는 행 인덱스 열을 분리합니다. 인덱스를 곡 키로 사용하지 않습니다. track_id별 한 곡을 만들고 모든 원본 genre 연결을 합집합으로 보존합니다. 같은 ID의 추천 필수값 충돌은 staging 오류이며 임의 평균/마지막 행 덮어쓰기를 하지 않습니다.
- energy=floor(원본 energy×10), acousticness=floor(원본 acousticness×100). 입력 범위는0~1, 결과는 각각0~10/0~100입니다. 원본을 보존하고 재처리는 원본에서 수행합니다. 결과19개 입력과 원본21열 입력은 source_schema_version으로 구분하여 이중 변환을 막습니다.
- mode는 원본0→False,1→True입니다. 다른 값은 오류입니다. False를 결측으로 해석하지 않습니다.
- time_signature=3이면 tempo/1.5, 그 밖에는 그대로 사용하고 ROUND_HALF_UP 정수 반올림 후 <80 slow / <110 medium / <150 fast / 나머지 fastest입니다. tempo 누락은 speed=NULL, time_signature 누락은 보정 없이 분류합니다. mood/main_inst는 실제 청취 자료가 필요합니다.
- artists_id는 이름 순서에 대응하고 일부 ID 누락의 빈 위치를 보존합니다. 이름A;B;C / ID idA;;idC는 정상입니다. 이름·ID에 장르용 빈 토큰 삭제를 적용하지 않습니다.
- 실제 앨범 ID는 NULL 가능하며 내부 album_key와 구분합니다. 같은 이름만으로 앨범을 병합하지 않습니다.
- play_url은 https://open.spotify.com/track/{track_id}입니다. 직접 재생 주소가 아니며 3차에 음원 파일/직접 재생/API 필수 연동을 추가하지 않습니다. duration_ms의 분:초 변환은 표시 자료용이며 메인 시간 비표시 UX는 유지합니다.
- explicit은 원본 bool을 그대로 보존합니다. 새 문서의 False 설명에는 미확인이 포함되므로 실제 False와 미확인을 완전히 구분할 수 있다고 주장하지 않습니다. 원본에서 값이 누락된 행은 필수 오류로 분리하며 누락을 False로 생성하지 않습니다. 추가 출처의 미확인 세부 표현은 후속 인계 사항입니다.

음악 기본4개 테이블·FK/UNIQUE·태그 활성/approved 연결은 수령 테이블 설계를 적용합니다. DB 제품/문자열 길이/키 생성/물리 DDL은 D-03/M-01에서 확정합니다. catalog/review 이력·작업·결과·스냅샷 등 서비스 운영 테이블은 이 음악4개에 포함한 것으로 세지 않습니다.

## 3. 보컬과 공개 적격

```text
review_value가 True/False → 최종 instrumental = review_value
review_value가 NULL:
  원본 x < .2 → False
  .2 <= x < .8 → NULL
  x >= .8 → True
```

일반 upsert는 DB 검수값을 보존하며 확정 False도 우선합니다. 검수 저장은 review_value와 최종값을 함께 갱신합니다. 명시 검수 해제만 review_value=NULL로 바꿀 수 있습니다. 해제 후 원본 수치가 없으면 최종값도 NULL입니다. 새 원본 수치가 없는 일반 API 갱신은 기존 최종값을 보존하며 신규 곡은 NULL입니다.

instrumental_only는 최종 True만 통과합니다. REVIEW True 또는 AUTO True를 허용하고 False/NULL은 제외합니다. 기존 '미검수 True도 금지' 규칙은 폐기합니다. 자동 True는 실제 무보컬 청취 확정이 아니므로 source=REVIEW/AUTO/PRESERVED/UNKNOWN과 검수 근거·버전을 별도 운영 자료로 기록합니다. 원본 자동값을 정상 입력으로 승인해 카탈로그를 발행할 수 있으며 자동값 존재 자체가 READY 발행 완료는 아닙니다.

genre/mood/instrument는 is_active=True AND 연결 review_status=approved만 추천 조회에 사용합니다. 원본 장르 확인 적재 연결은 approved로 등록할 수 있고 mood/main_inst는 청취 확인 후 승인합니다. 곡별 추천 적격·카탈로그 READY는 연결 승인과 구분합니다.

## 4. 날씨 점수·취향 점수

| 프로필 | 원본 조건 | energy 범위 | acousticness 범위 | 우선 mode |
|---|---|---|---|---|
| 맑음 | PTY0/SKY1 | 5~8 | 0~60 | True |
| 구름많음 | PTY0/SKY3 | 3~6 | 20~80 | False |
| 흐림 | PTY0/SKY4 | 2~5 | 40~100 | False |
| 비 | PTY1 | 2~4 | 60~100 | False |
| 비·눈 | PTY2 | 2~4 | 50~100 | False |
| 눈 | PTY3 | 1~4 | 60~100 | True |
| 소나기 | PTY4 | 2~4 | 60~100 | False |
| 빗방울 | PTY5 | 2~4 | 60~100 | False |
| 빗방울·눈날림 | PTY6 | 2~4 | 50~100 | False |
| 눈날림 | PTY7 | 1~4 | 60~100 | True |

```text
d(x,L,U)=max(L-x,0,x-U)
E=max(0,100-10*d(energy,L_e,U_e))
A=max(0,100-d(acousticness,L_a,U_a))
M=100 if mode==preferred_mode else 0
W_k=.50*E+.45*A+.05*M
W=sum(overlap_ms_k/10800000 * W_k)
P=sum(사용자가 선택한 그룹의 100/0 일치 점수)/활성 그룹 수
S=.75*W+.25*P  # 활성 그룹이 하나라도 있음
S=W           # 세 그룹 모두 미선택
Q=sum(S_i*duration_ms_i)/sum(duration_ms_i)
```

W/P/S/Q는0~100입니다. 기존0~1 값을 같은 이름으로 혼용하거나 최종100을 다시 곱하지 않습니다. 중간 계산은 반올림하지 않습니다. 구현 비교는 정확한 유리수 또는 그와 동등한 정확한 연산으로 수행하고 화면 점수만 소수2자리 ROUND_HALF_UP을 쓰는 공통 기술 기준입니다. 메인 시간 비표시와 별개입니다.

energy/acousticness 결측·범위 오류는 후보 보류, mode=NULL은0점/NULL 보존, 선택 mood 미확인은0점/활성 분모 유지입니다. 곡별 결측으로 가중치를 재배분하지 않습니다. 우선 mode를 정책 NULL로 해제한 프로필만 E=50/95,A=45/95로 공통 재배분합니다. 현행10개 프로필은 mode 우선값이 모두 있습니다.

날씨 범위 밖·mode 불일치만으로 제외하지 않고 별도 W 하한도 적용하지 않습니다. 이전0.55 하한·음향3개 충족률·danceability 수식을 복원하지 않습니다. 예보 결측/무효 코드는 FORECAST_UNAVAILABLE, 미완성 정책은 POLICY_NOT_READY이며 임의 맑음/W0/취향100%로 대체하지 않습니다. 180분 전체를 겹침/빈 구간 없이 덮고 실제 결과가 초과하면 종료까지 유효성을 확인합니다. 초과분을180분 점수 분모에 더하지 않습니다.

수령 문서의 내부50:45:5·우선 범위·mode 선호는 채택한 초기 가설입니다. 계산 일치가 날씨별 적합성/만족도 검증을 뜻하지 않습니다. energy4/acousticness60/modeTrue는 맑음과 비 모두W95이므로 모든 곡의 날씨 점수 차이를 보장하지 않습니다.

## 5. 장르·테마와 사이클 필터

대분류18개/테마9개는 수령 매핑을 그대로 사용합니다. API 선택 코드는 CALM/DREAMY 등 테마 코드, JAZZ/CLASSICAL 등 대분류 코드이며 raw jazz/classical/tag_id/표시 이름을 직접 비교하지 않습니다. j-rock은 ROCK/J-POP에 연결하되 곡·점수를 중복하지 않습니다. ambient는 원본 보존/비활성이며 다른 유효 장르가 없는 곡은 서비스 장르 후보에서 제외합니다. 별도36개 라벨은 승인 대분류 매핑 없이 임의 편입하지 않습니다. K-POP/J-POP은 장르 묶음이며 국가/언어 기능을 활성화하지 않습니다.

사용자 장르 복수는 OR, 테마 복수도 OR입니다. 장르는 허용 대분류와 하나 이상 일치해야 하는 필수 필터, 테마는 승인 mood 연결에 따른100/0 가점입니다. 테마의 energy/speed/mode 우선 판단은 팀 협의 전 기준입니다. 추가 가점·부분 일치·장르 후보 확대·최종 정렬 관계를 임의 구현하지 않고 별도 정책 확정까지 남깁니다.

### 5.1. 최초 허용 집합

- 선택 장르가 있으면 선택 대분류 집합을 허용합니다. 없으면 첫 결과의 대분류 합집합을 고정합니다. 첫 결과 전에도 genre/speed 미확인은 후보 보류합니다.
- 느린 곡 우선은 항상 slow입니다. 단일 최초 기준 PTY1 또는3에서 auto는 slow/medium, fast는 fast만 허용합니다. 그 밖의 단일 프로필에서 fast는 fast/fastest, auto는 첫 결과의 실제 speed 집합을 고정합니다.
- 점수 프로필이 비와 같더라도 PTY4/5에 PTY1의 speed 제한을 확대하지 않습니다. PTY2/4/5/6/7에 비·눈 특별 제한을 확대할지는 미정이며 현행은 특별 제한 미적용입니다.
- 혼합 예보에서 auto/fast의 최초 기준 날씨 선택은 미정입니다. 최초 사이클은 POLICY_NOT_READY와 안내로 보류하고 임의 우세/현재/평균 날씨를 선택하지 않습니다. slow는 모든 날씨에 동일한 명시 집합이므로 해당 미정에 의존하지 않습니다. 이미 집합이 고정된 사이클의 혼합 예보는 유효성 확인 후 W 시간 가중평균을 계산할 수 있습니다.

### 5.2. 같은 사이클과 조건 변경

family_id를 음악 문서의 사이클에 대응시키는 공통 기술 기준입니다. 최초 결과의 allowed_genre_group_codes/allowed_speed_codes·시작 선택·policy_version·mapping_version·option_version을 family와 작업/결과에 불변 고정합니다. 같은 사이클에서 제외/날씨 갱신/Gemini 재설정은 두 허용 집합을 변경하지 않습니다. 새 버전 정책은 새 사이클에 적용하며 과거 결과 점수를 덮어쓰지 않습니다. 작업별 READY catalog_version·당시 값은 별도로 고정하고 다른 카탈로그를 사용해도 원래 사이클 매핑/집합 준수를 검증합니다.

재설정 API의 선택 필드 생략은 부모 상속, 명시값이 부모와 같으면 동일 조건으로 허용합니다. 보컬/빠르기/테마/장르/option_version을 바꾼 명시 요청은 CYCLE_CONDITIONS_CHANGED/409와 새 기본 요청 안내로 거절하며 새 작업/Gemini 호출을 만들지 않습니다. 조건 변경은 POST /api/recommendation-jobs으로 새 family를 만들고 빈 제외 초안·미평가로 시작합니다. 이전 family의 결과/제외/평가를 지우거나 자동 상속하지 않습니다. 선택만 편집하면 기존 결과는 변경 전 표시로 유지하고 화면의 생성 동작은 새 사이클 요청으로 연결합니다. 재설정 버튼은 동일 시작 조건에서만 가능합니다.

선택한 장르·빠르기 필터를 통과한 곡은 해당 취향 그룹100점입니다. 이 공통 가점이 후보 간 순위를 구분하지 않아도75:25/활성 그룹 균등 배분을 바꾸지 않습니다. 사용자 미선택 자동 집합은 취향 그룹을 활성화하지 않습니다.

## 6. 시간·Gemini·결과·스냅샷

STANDARD 목표10,800,000ms/범위10,560,000~11,040,000ms입니다. 정확히180분 → 초과~184분 →176분 이상 부족 순이며 같은 구간은 거리→Q→ID 동점 기준입니다. 기본 재생 순서는S 내림차순/ID 오름차순, Gemini는 검증된 응답 순서입니다.

수령 규칙4-3절을 우선해 자동 SHORTENED는 사용하지 않습니다. 176분 미만은 성공/승인 금지이고 확인된 전체 적격 후보 부족은 CANDIDATE_SHORTAGE입니다. UNKNOWN/제한 풀/모델의 짧은 응답은 후보 부족 증명이 아닙니다. 기존25%/135분·단계 정책은 이력으로만 보존하며 새 단축 정책을 채택하기 전 운영하지 않습니다.

Gemini 3.8 Flash는 명시 재설정에만 같은 RDB 적격 조회 목록을 제공합니다. 사이클 필터·날씨·등록/카탈로그·보컬·제외·중복·176~184분·실제 예보·max(1,parent_unique_count//5) 신규 곡을 서버가 사전/사후 검증합니다. 실패/변화 미달은 부모/평가/제외/승인 보존이며 자동 규칙 대체나 solver 보정은 하지 않습니다.

다음 스냅샷 형식은 수령 데이터와 기존 불변 기록을 연결한 기술 계약이며 실제 곡값 확보 완료가 아닙니다.

- 조건: family_id/source_playlist_id·시작 선택 코드/당시 명칭·허용 장르/speed 집합·지역·기준/발표/대상/수신 시각·180분 예보 구간/값/상태·catalog/source/schema/review/option/mapping/policy/time 버전·총ms·검증 결과.
- 곡: 당시18개 전부 + instrumental_review_value·instrumental_source·genre_group_codes/theme_codes 및 당시 명칭·검수 참조/버전·W/P/S. 원본 변환 근거는 당시 raw 값 또는 읽기 가능한 불변 source 참조/해시를 보존합니다.
- 필수 필드는 키를 생략하지 않고 허용 결측만NULL/미확인으로 기록합니다. 당시RDB/카탈로그에서 서버가 복사하고 현재 테이블 값으로 과거를 복원하지 않습니다. 제거/취소는 원래 이벤트/곡 자료를 연결합니다. outbox는 공통 envelope와 실제 당시 payload를 함께 발행합니다.
- 결과/제외/평가/스냅샷/outbox의 PostgreSQL 원자 저장과 보관 참조를 유지합니다. 음악RDB와 업무DB가 다르면 두 DB의 원자 동시쓰기를 가정하지 않고 검증된 불변 카탈로그를 먼저 고정합니다. 보관 기간은 미정이며 광고90/365일을 적용하지 않습니다.
