## 2. 입력·저장·변환

추천·표시 필드18개는 다음 순서입니다. instrumental_review_value는 검수 관리용이며 점수 항목이 아닙니다.

```text
track_id, track_name, artists_id, artists_name, album_id, album_name,
album_release_date, duration_ms, explicit, genre, energy, mode,
acousticness, mood, speed, main_inst, instrumental, play_url
```

- track_id/track_name/artists_name/album_name/play_url은 필수 문자열, duration_ms는 정수, explicit은 필수 bool입니다. artists_id/album_id/album_release_date와 분류값은 문서의 NULL 허용을 따릅니다. 추천 duration_ms는 양수만 허용합니다. 저장 가능한 0은 추천 적격과 구분합니다.
- 원본 CSV의20개 + 이름 없는 행 인덱스 열을 분리합니다. 인덱스를 곡 키로 사용하지 않습니다. track_id별 한 곡을 만들고 모든 원본 genre 연결을 합집합으로 보존합니다. 같은 ID의 추천 필수값 충돌은 staging 오류이며 임의 평균/마지막 행 덮어쓰기를 하지 않습니다.
- energy=floor(원본 energy×10), acousticness=floor(원본 acousticness×100)는 표시·관리 변환값입니다. ON/OFF 산정에는 원본 정밀도의 energy·acousticness·valence가 필요하며 변환값에서 역산하지 않습니다. 입력 범위는0~1이고 결측·범위 오류는 모드별 필요 필드 기준으로 보류합니다. 원본을 보존하고 재처리는 원본에서 수행합니다. 결과19개 입력과 원본21열 입력은 source_schema_version으로 구분하여 이중 변환을 막습니다.
- mode는 원본0→False,1→True입니다. 다른 값은 오류입니다. False를 결측으로 해석하지 않습니다.
- time_signature=3이면 tempo/1.5, 그 밖에는 그대로 사용하고 ROUND_HALF_UP 정수 반올림 후 <80 slow / <110 medium / <150 fast / 나머지 fastest입니다. tempo 누락은 speed=NULL, time_signature 누락은 보정 없이 분류합니다. mood/main_inst는 실제 청취 자료가 필요합니다.
- artists_id는 이름 순서에 대응하고 일부 ID 누락의 빈 위치를 보존합니다. 이름A;B;C / ID idA;;idC는 정상입니다. 이름·ID에 장르용 빈 토큰 삭제를 적용하지 않습니다.
- 실제 앨범 ID는 NULL 가능하며 내부 album_key와 구분합니다. 같은 이름만으로 앨범을 병합하지 않습니다.
- play_url은 https://open.spotify.com/track/{track_id}입니다. 직접 재생 주소가 아니며 3차에 음원 파일/직접 재생/API 필수 연동을 추가하지 않습니다. duration_ms의 분:초 변환은 표시 자료용이며 메인 시간 비표시 UX는 유지합니다.
- explicit은 원본 bool을 그대로 보존합니다. 새 문서의 False 설명에는 미확인이 포함되므로 실제 False와 미확인을 완전히 구분할 수 있다고 주장하지 않습니다. 원본에서 값이 누락된 행은 필수 오류로 분리하며 누락을 False로 생성하지 않습니다. 추가 출처의 미확인 세부 표현은 후속 인계 사항입니다.

음악 기본4개 테이블·FK/UNIQUE·태그 활성/approved 연결은 수령 테이블 설계를 적용합니다. DB 제품/문자열 길이/키 생성/물리 DDL은 D-03/M-01에서 확정합니다. catalog/review 이력·작업·결과·스냅샷 등 서비스 운영 테이블은 이 음악4개에 포함한 것으로 세지 않습니다.

## 3. 보컬과 공개 적격

```text
review_value가 True/False → 최종 instrumental = review_value
review_value가 NULL:
  원본 x < .2 → False
  .2 <= x < .8 → NULL
  x >= .8 → True
```

일반 upsert는 DB 검수값을 보존하며 확정 False도 우선합니다. 검수 저장은 review_value와 최종값을 함께 갱신합니다. 명시 검수 해제만 review_value=NULL로 바꿀 수 있습니다. 해제 후 원본 수치가 없으면 최종값도 NULL입니다. 새 원본 수치가 없는 일반 API 갱신은 기존 최종값을 보존하며 신규 곡은 NULL입니다.

instrumental_only는 최종 True만 통과합니다. REVIEW True 또는 AUTO True를 허용하고 False/NULL은 제외합니다. 기존 '미검수 True도 금지' 규칙은 폐기합니다. 자동 True는 실제 무보컬 청취 확정이 아니므로 source=REVIEW/AUTO/PRESERVED/UNKNOWN과 검수 근거·버전을 별도 운영 자료로 기록합니다. 원본 자동값을 정상 입력으로 승인해 카탈로그를 발행할 수 있으며 자동값 존재 자체가 READY 발행 완료는 아닙니다.

genre/mood/instrument는 is_active=True AND 연결 review_status=approved만 추천 조회에 사용합니다. 원본 장르 확인 적재 연결은 approved로 등록할 수 있고 mood/main_inst는 청취 확인 후 승인합니다. 곡별 추천 적격·카탈로그 READY는 연결 승인과 구분합니다.

## 4. 모드별 점수와 후보 자격

[후보 산출 가이드 2~6절](./카페_음악_추천_서비스_3차_컬럼_기반_추천_로직_가이드.md)의 표·계수·정규화·분류·필터 순서를 그대로 적용합니다. 이 문서는 수식을 재정의하지 않습니다. 요청의 `weather_influence_mode`는 `ON|OFF`이고 최초 생략은 ON입니다. 테마·장르 0개 선택과 전부 선택은 각 그룹의 필터가 없는 ANY 상태입니다. 두 모드의 후보 자격과 점수를 섞지 않습니다.

- ON: 실제 PTY/SKY 분류가 유효해야 하며, 5개 날씨별 PRIMARY/SUPPORT 프로필의 원본 정밀도 energy/acousticness/valence·mode로 E/A/W를 계산합니다. 핵심 E/A≥20과 W≥75를 통과한 곡만 남깁니다. PTY2/6은 비·눈 양쪽 적격의 교집합입니다. 그 후 사용자가 활성화한 빠르기·테마·장르의 100/0 평균 P_legacy를 구하고 S_ON=.75W+.25P_legacy, 활성 그룹이 없으면 S_ON=W로 정렬합니다. 날씨별 평균이나 예전 50:45:5 수식은 적용하지 않습니다.
- OFF: 날씨 조회·유효성·W가 후보와 순위에 영향을 주지 않습니다. 선택 테마는 9개 매핑, 장르·energy·mode·speed는 40:40:5:15 원소 점수의 정규화로 P_OFF를 산정합니다. 테마 불일치는 제외가 아닌 약한 점수이며 선택 테마 복수는 완성된 P 중 최대값을 취합니다. 취향 선택이 전혀 없으면 P_OFF=NULL로 남기고 안정적 시드 순서를 사용합니다. 선택 장르로만 176~184분 구성이 가능하면 100% 그 장르 곡으로 만듭니다. 전체 해당 후보에서도 불가능함을 입증할 때만 다른 장르를 시간 기준 최대20% 허용하고, 선택한 각 장르는 서로 다른 곡으로 대표합니다.
- 공통: 승인 카탈로그·양수 duration_ms·중복 ID·보컬·제외·사용자 조건을 먼저 검사합니다. ON에 필요한 원본 세 값은 표시용 정수 energy/acousticness로 대체하지 않습니다. OFF는 유효 예보나 ON 전용 acousticness/valence를 요구하지 않습니다. 정수 duration_ms로 총시간을 합산하고 결과·당시 조건에 모드/정책/카탈로그 버전을 보존합니다.

이전 10개 독립 날씨 프로필, 180분 날씨 구간 가중평균, W 무하한, 자동 모드 전환은 현행 추천 계약에서 제외합니다. ON의 날씨 자료가 없으면 오류로 보류하며 OFF로 묵시 전환하지 않습니다. 화면 날씨 패널은 OFF에서도 독립적으로 표시할 수 있습니다.

## 5. 장르·테마와 사이클

18개 장르/9개 테마의 **현행 점수용 매핑**은 후보 산출 가이드 표를 사용합니다. raw 장르·표시 이름을 API 대분류 코드와 직접 비교하지 않습니다. j-rock 중복 연결은 곡을 두 번 세지 않습니다. 국가·언어 기능은 3차에서 제외합니다. 테마·장르 0개/전부 선택은 같은 ANY 의미로 정규화합니다.

ON은 [후보 산출 가이드 3절](./카페_음악_추천_서비스_3차_컬럼_기반_추천_로직_가이드.md)의 확정 장르/speed 허용 집합을 family에 고정합니다. OFF는 장르 100% 우선/80% 하한과 대표 곡 조건을 결과마다 검사합니다. OFF에 ON의 비·눈 speed 제한이나 ON의 100/0 테마 점수를 적용하지 않습니다. `family_id`의 시작 모드·선택·정규화한 필터·정책/매핑 버전을 불변으로 보존합니다. 같은 family의 제외/날씨 갱신/명시 Gemini 재설정은 시작 조건을 바꾸지 않습니다.

재설정 API의 선택 필드 생략은 부모 상속, 명시값이 부모와 같으면 동일 조건으로 허용합니다. weather_influence_mode를 포함해 보컬/빠르기/테마/장르/option_version을 바꾸면 CYCLE_CONDITIONS_CHANGED/409와 새 기본 요청 안내로 거절합니다. 조건 변경은 POST /api/recommendation-jobs로 새 family를 만들고 빈 제외 초안·미평가로 시작합니다. 이전 family의 결과·제외·평가를 자동 상속하지 않습니다.

## 6. 시간·Gemini·결과·스냅샷

STANDARD 목표10,800,000ms/범위10,560,000~11,040,000ms입니다. 두 모드 모두 정확히180분 → 가까운 초과 → 가까운 부족 순이며 같은 시간에서는 재생시간 가중 Q를 최대화합니다. OFF는 이 시간·품질 순위를 장르 100% 가능 집합 안에서 먼저 적용하고, 그 집합이 불가능할 때만 80% 이상 완화 집합을 탐색합니다. 최초 200곡 창에서 400→800→1,600→전체 적격 후보까지 확장합니다. 제한 창 실패나 solver UNKNOWN은 전체 후보 부족 증명이 아닙니다.

수령 규칙4-3절을 우선해 자동 SHORTENED는 사용하지 않습니다. 176분 미만은 성공/승인 금지이고 확인된 전체 적격 후보 부족은 CANDIDATE_SHORTAGE입니다. UNKNOWN/제한 풀/모델의 짧은 응답은 후보 부족 증명이 아닙니다. 기존25%/135분·단계 정책은 이력으로만 보존하며 새 단축 정책을 채택하기 전 운영하지 않습니다.

Gemini 3.8 Flash는 명시 재설정에만 해당 모드의 같은 RDB 적격 조회 목록을 제공합니다. ON에만 유효 날씨/날씨 풀·실제 재생 구간 예보를 요구하며 OFF에는 요구하지 않습니다. 두 모드 모두 등록/카탈로그·보컬·제외·중복·176~184분·각 모드의 장르 조건·max(1,parent_unique_count//5) 신규 곡을 서버가 사전/사후 검증합니다. 실패/변화 미달은 부모/평가/제외/승인 보존이며 자동 규칙 대체나 solver 보정은 하지 않습니다.

다음 스냅샷 형식은 수령 데이터와 기존 불변 기록을 연결한 기술 계약이며 실제 곡값 확보 완료가 아닙니다.

- 조건: family_id/source_playlist_id·weather_influence_mode·시작 선택 코드/당시 명칭·ON의 허용 장르/speed 집합 또는 OFF의 선택 장르 대표/비율·지역·ON에 사용한 날씨 기준/발표/대상/수신 시각과 유효 구간·catalog/source/schema/review/option/mapping/score/duration 버전·총ms·검증 결과. OFF의 날씨 패널 정보는 추천 입력과 분리합니다.
- 곡: 당시18개 전부 + instrumental_review_value·instrumental_source·genre_group_codes/theme_codes 및 당시 명칭·검수 참조/버전·모드별 W/P/S 또는 P_OFF·후보 적격/탈락 근거. 원본 정밀도 energy/acousticness/valence와 mode 또는 읽기 가능한 불변 source 참조/해시를 보존합니다.
- 필수 필드는 키를 생략하지 않고 허용 결측만NULL/미확인으로 기록합니다. 당시RDB/카탈로그에서 서버가 복사하고 현재 테이블 값으로 과거를 복원하지 않습니다. 제거/취소는 원래 이벤트/곡 자료를 연결합니다. outbox는 공통 envelope와 실제 당시 payload를 함께 발행합니다.
- 결과/제외/평가/스냅샷/outbox의 PostgreSQL 원자 저장과 보관 참조를 유지합니다. 음악RDB와 업무DB가 다르면 두 DB의 원자 동시쓰기를 가정하지 않고 검증된 불변 카탈로그를 먼저 고정합니다. 보관 기간은 미정이며 광고90/365일을 적용하지 않습니다.
