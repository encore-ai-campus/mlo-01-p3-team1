- 작성일: 2026-10-15
- 수정일: 2026-10-15
- 상태: 사용자 결정과 CSV 분석을 반영한 **새 정책 제안**. 현행 계약·코드·DB·화면은 이 문서 작성만으로 변경되지 않습니다.

- 목적: 선택 조건에 대한 곡별 밀접도로 추천 대상의 우선순위를 만들고, ON에서만 날씨를 결합해 3시간 선곡표를 구성합니다.

## 1. 분석 대상과 재현 기준

입력은 [spotify_dataset.csv 인계 정보](../handoff/music/README.md)입니다. 크기 20,118,244바이트, SHA-256은 b202fa49909b2d5cef71a04b1d21243cfeb36414535f2ca9272aa646721177bd입니다. 원본 114,000행, 고유 track_id 89,741개, 같은 track_id의 추가 행 24,259개입니다. 원본 track_genre는 114종이고 각 라벨이 1,000행씩 들어 있으므로 이 CSV의 장르 빈도를 실제 서비스 수요·음악 시장 비율로 해석할 수 없습니다.

원본 헤더는 이름 없는 행 인덱스 1개와 음악 열 20개입니다. 행 인덱스는 곡 ID가 아닙니다.

## 2. 컬럼 사이 상관성: 무엇을 알 수 있고 없는가

고유 track_id 89,741개를 한 곡당 한 행으로 놓고 계산한 Pearson 상관계수입니다. energy·acousticness 등 원본 0~1 수치를 사용했고, 결측이 있는 쌍은 해당 쌍에서 제외했습니다. 비교용 Spearman energy–acousticness는 -0.712입니다.

| 두 원본 컬럼 | Pearson r | 후보 목록에 주는 의미 |
|---|---:|---|
| energy ↔ acousticness | -0.733 | 높은 에너지 곡이 낮은 어쿠스틱 성향을 갖는 경향이 강함. 두 열을 독립 증거처럼 과신하면 편향이 커질 수 있음 |
| energy ↔ loudness | +0.759 | 음량 특성은 에너지와 많이 겹침. 이번 식에 loudness를 별도 가점으로 추가하지 않음 |
| danceability ↔ valence | +0.493 | 움직임·긍정 정서가 함께 높아지는 중간 수준의 경향. 곡별 테마 판정의 대체 근거는 아님 |
| energy ↔ valence | +0.256 | 밝은 감정과 에너지가 같은 개념은 아님 |
| energy ↔ tempo | +0.259 | 빠르기를 에너지로 추정하지 않고 tempo에서 별도 계산해야 함 |
| energy ↔ instrumentalness | -0.181 | 에너지로 무보컬 여부를 판단할 수 없음 |
| popularity ↔ energy | +0.014 | 인기도를 날씨 적합도의 대리값으로 쓰기 어려움 |

이 수치는 **곡의 컬럼 사이 연관성**입니다. 실제 날씨에서 손님이 그 곡을 선호했다는 관측치나 인과관계가 아닙니다. 장르별 상관도 달라지므로 전체 r 하나로 테마를 자동 부여하지 않습니다. 재즈면‘재즈면 잔잔한’, ‘메탈이면 강렬한’ 식의 일괄 연결은 금지합니다. 테마를 선택한 요청에는 곡별 승인 mood가 필요합니다.

## 3. 날씨와 결합했을 때의 분포

현행 음악 매핑을 적용하고 필수 메타데이터·양의 길이·energy/acousticness/mode·tempo 구조만 확인하면 **61,934 고유곡, 총 4,054.3시간**입니다. 이 중 실제 READY·태그 승인·사용자 제외·예보 유효성은 확인되지 않았습니다. 다음 표는 **날씨 ON의 분석 자료**로, 예보 180분이 한 날씨 프로필로 유지된다고 가정하고 현행 날씨 식을 계산한 내부 W입니다. OFF 결과의 점수·품질 근거로 사용하지 않습니다.

같은 곡들에 대해 계산한 W 벡터의 Pearson 상관은 맑음–비 -0.539, 맑음–눈 -0.512, 비–눈 +0.964, 비–비·눈 +0.997입니다. 이는 **정의된 점수식으로 만든 값들 사이의 상관**이며 실제 날씨별 청취 성공률이 아닙니다. “비가 100점이면 맑음은 반드시 낮다”도 성립하지 않습니다. 변환 후 energy=4, acousticness=60, mode=True인 곡은 맑음 W=95, 비 W=95입니다.

장르와 날씨가 충돌할 수 있는지도 확인했습니다. 비가 180분 지속되고 현행 auto 빠르기가 slow/medium인 경우의 **원본 구조상 후보**입니다. 보컬·READY·테마·제외는 적용하지 않았습니다.

같은 조건의 비 W≥80 곡 길이는 JAZZ 24.71시간, METAL 3.51시간입니다. 원본만 보면 3시간을 넘지만 READY·무보컬·테마 밀접도·제외를 적용하면 달라질 수 있습니다. **ON에도 고정 W 하한은 두지 않습니다.** 날씨와 선택 장르가 충돌해도 선택 장르의 필수 조건을 몰래 풀지 않고 그 안에서 순위를 매깁니다. OFF의 선택 장르 80% 규칙은 4~6절에서 별도로 정의합니다.

### 3.1. CALM+METAL의 범위 확인

같은 원본 구조 검사를 통과한 곡 중 METAL은 5,624곡입니다. 이 가운데 CALM의 우선 판단 요소인 energy 0~4와 speed slow/medium을 모두 만족하는 곡은 **76곡, 합계 약 394.55분**입니다. 76곡은 엄격한 두 요소 동시 일치의 분석 사례이지 CALM mood 승인곡 수나 최종 후보 수가 아닙니다. 조건에서 조금 벗어난 METAL도 4.3절의 밀접도에 따라 다음 순위의 후보가 됩니다. READY·무보컬·제외·사용자 빠르기·예보를 적용한 뒤의 3시간 조합 가능성은 따로 검사합니다.

## 4. 사용자 선택과 추천 대상 집합

### 4.1. 입력·중립 상태

새 입력 weather_influence_mode는 ON/OFF입니다. ON을 초기값으로 **제안**하되, 서비스 기본값의 최종 채택은 별도 결정 사항입니다. ON/OFF는 작업·family·결과·피드백 당시 조건에 저장하고 같은 family의 재설정에서는 바꾸지 않습니다. 지역은 현행 공개 화면의 필수 입력으로 유지하는 제안입니다. OFF일 때 날씨 패널 조회는 유지할 수 있지만, 예보 누락·만료가 추천 생성 자체를 막거나 곡 선택에 영향을 주어서는 안 됩니다.

전체 테마 코드 U_T는 9개, 전체 장르 코드 U_G는 18개입니다. 사용자가 누른 집합 T/G를 그룹별로 정규화합니다.

~~~text
T_eff = ANY  if |T|=0 또는 T=U_T;  그 밖에는 T
G_eff = ANY  if |G|=0 또는 G=U_G;  그 밖에는 G
~~~

따라서 한 그룹에서 아무 버튼도 누르지 않은 상태와 그 그룹의 전부를 누른 상태는 **같은 추천 조건**입니다. 화면의 원래 선택 상태는 보존하고 서버는 원래 집합과 T_eff/G_eff를 모두 기록합니다. 장르 전부 선택을 18개 장르 각각의 강제 포함으로 바꾸지 않습니다.

입력 화면은 테마·장르를 별도 펼침 영역으로 나누고, 긴 목록을 내부 세로 스크롤로 탐색시키지 않습니다. 테마 버튼은 옅은 초록 파스텔, 장르 버튼은 옅은 갈색으로 표시하며 누른 버튼은 해당 색을 진하게 합니다. 별도 체크표시는 사용하지 않습니다. 이 표시 방식은 위의 0개/전체 선택 정규화와 후보·순위식을 바꾸지 않습니다.

### 4.2. 공통 자격과 ON/OFF 후보

B는 READY 카탈로그에서 track_id가 고유하고 필수 메타데이터·양의 duration_ms·승인 서비스 장르가 있으며, 보컬·빠르기·제외 조건을 통과한 곡입니다. 원본 track_genre는 승인된 서비스 장르 18개로 매핑하며 복수 대분류에 연결돼도 곡은 한 번만 사용합니다. 부분 테마 선택은 B에서 곡을 즉시 제외하는 필터가 아니라 4.3절의 밀접도를 활성화합니다. 승인 mood가 미확인이어도 곡별 근거와 미확인 상태를 구분해 점수를 계산하며 기존 mood를 자동 수정하지 않습니다. 복수 테마는 선택 목록 중 가장 가까운 테마를 사용하고, 선택한 모든 테마별 곡을 강제하지 않습니다.

빠르기를 날씨에 맡기는 auto는 ON일 때 현행 단일 현상별 허용 속도를 따릅니다. OFF에서는 날씨가 빠르기를 통해 우회 반영되지 않도록 auto=slow/medium/fast/fastest 전체 허용, 명시 slow=slow, 명시 fast=fast/fastest를 제안합니다. OFF에서도 곡의 speed 값 자체는 유효해야 합니다. 혼합 예보의 ON 최초 auto/fast 기준이 미정인 현행 항목은 이 문서가 임의 확정하지 않습니다.

~~~text
match_G(i) = (G_eff≠ANY 그리고 approved_genre_i ∩ G_eff ≠ ∅)

ON:
  STANDARD에서는 유효한 180분 예보를 먼저 확인; SHORTENED에서는 effective_target_ms 구간의 예보를 확인
  C_ON = B                              if G_eff=ANY
       = {i ∈ B : match_G(i)}           if G_eff≠ANY

OFF:
  추천 생성에 예보/W를 요구하지 않음
  C_OFF = B
  C_selected = {i ∈ C_OFF : match_G(i)}  if G_eff≠ANY
  C_other = C_OFF - C_selected
~~~

ON의 부분 장르 선택은 선택 장르가 결과의 100%를 차지하는 **초기 제안 필터**입니다. OFF의 부분 장르 선택은 다른 장르도 후보에 포함하되 최종 선곡표의 재생시간 80% 이상을 선택 장르로 채우는 **초기 제안 비율**입니다. 두 모드 모두 선택한 각 장르는 서로 다른 결과 곡으로 최소 한 번 등장합니다. 테마가 선택됐다면 OFF의 다른 장르 보완곡도 테마 밀접도로 우선순위를 매기며, 테마를 엄격하게 일치시키지 않습니다. 장르가 ANY일 때는 장르 대표·비율 조건이 없습니다. 승인 서비스 장르가 없는 곡은 ANY에서도 B에 포함하지 않습니다.

### 4.3. 테마·장르 밀접도와 모드별 순위

이 절의 수치는 **구현·청취 검증을 위한 초기 가설**이며 CSV 상관계수에서 학습한 최적 계수가 아닙니다. [테마·장르 정의](../handoff/music/테마_장르_정의.md) 4-1절의 9개 테마별 energy 범위·speed 집합·mode 값·매핑 장르를 그대로 읽습니다. 판단 요소가 없는 새 필드는 임의 생성하지 않습니다. energy는 원본 0~1에 10을 곱한 값의 내림으로 0~10 정수를 만들고, speed는 1절의 원본 변환 결과를 사용합니다.

~~~text
d(x,L,U) = max(L-x, 0, x-U)
E_t(i) = 1 - d(energy_i,L_t,U_t) / max(L_t,10-U_t)       # energy 범위가 있는 테마; 0~1
V_t(i) = 1 - min_{s∈allowed_speed_t}|index(speed_i)-index(s)| / 3
         index(slow,medium,fast,fastest) = (0,1,2,3)
M_t(i) = 1 if mode_i = preferred_mode_t, else 0
F_t(i) = (2*E_t(i)+V_t(i))/3    if energy와 speed 둘 다 기준
       = E_t(i), V_t(i), M_t(i) if 해당 판단 요소 하나만 기준
J_t(i) = 1 if approved_genre_i가 테마 t의 확정 매핑 장르와 겹침, else 0
proxy_t(i) = 0.90*F_t(i) + 0.10*J_t(i)
theme_t(i) = 1 if 승인 mood에 t가 명시되어 있음, else proxy_t(i)
T_i = max_{t∈T_eff} theme_t(i)  # T_eff≠ANY; 복수 테마 중 최고 밀접도
G_i = 1 if match_G(i), else 0    # G_eff≠ANY

U_i = 0.55*T_i + 0.45*G_i       if T_eff≠ANY and G_eff≠ANY
    = T_i                       if T_eff≠ANY and G_eff=ANY
    = G_i                       if T_eff=ANY and G_eff≠ANY
    = 미사용                    if T_eff=ANY and G_eff=ANY
~~~

E_t의 분모가 0인 전체 energy 구간은 E_t=1로 정의합니다. 범위 밖 값의 거리가 클수록 밀접도가 연속적으로 낮아집니다. speed 역시 허용 집합에서 한 단계 멀어질 때마다 1/3씩 낮아집니다. 해당 테마의 필요 특성이 NULL이면 그 성분을 0으로 기록하고 다른 성분에 가중치를 몰아주지 않습니다. 승인 mood의 미일치는 그 테마를 자동 불합격으로 만들지 않지만, 미확인/미일치와 추정 근거를 별도 보존합니다. 매핑 장르는 테마 자체를 확정하지 않도록 10%의 작은 보조 근거만 줍니다.

예를 들어 CALM+METAL에서 energy=4, speed=slow인 METAL 곡은 J=0이어도 T=0.90, U=0.945입니다. energy=5, speed=slow인 METAL 곡은 E=5/6, T=0.80, U=0.89로 바로 탈락하지 않고 뒤를 잇습니다. 같은 특성의 JAZZ만 승인된 곡은 T=1, G=0, U=0.55이므로 OFF의 보완 후보가 될 수 있지만 최종 선택 장르 재생시간 80% 규칙을 넘어설 수 없습니다. 76곡은 앞의 강한 일치군에 해당하며 이 수식의 전체 후보 수가 아닙니다.

ON은 선곡 단계별 W_i를 별도로 계산하고, 선호가 활성화되면 내부 순위 H_i=0.45*(W_i/100)+0.55*U_i를 사용합니다. 테마·장르가 모두 ANY이면 H_i=W_i/100입니다. OFF는 예보와 W를 계산하지 않고, 선호가 활성화되면 H_i=U_i, 모두 ANY이면 저장된 seed로 후보 순서를 정합니다. 선택을 활성화하지 않은 그룹은 0점으로 평균에 넣지 않습니다. ON의 45:55 결합은 사용자 선택을 살리기 위한 초기 제안이며, 5절의 W 내부 50:45:5와 서로 다른 계수입니다. H/U/T/G는 0~1의 **내부 순위값**으로 화면 표시점수가 아닙니다.

## 5. ON에서만 사용하는 내부 날씨 적합도 W

ON은 STANDARD에서 유효한 180분 예보를 빈 구간·겹침 없이 고정합니다. 적격 후보 부족이 입증되어 SHORTENED로 옮기면 해당 단계의 effective_target_ms 구간으로 W를 다시 계산합니다. 어느 단계든 실제 결과가 목표보다 길면 결과 종료 시각까지 예보 유효성을 추가 검사합니다. 결측·만료 예보를 맑음이나 W=0으로 대체하지 않습니다. energy=floor(원본 energy×10), acousticness=floor(원본 acousticness×100)으로 변환합니다. ON의 energy/acousticness 결측·범위 오류는 후보 보류입니다. OFF는 W를 계산하지 않지만 READY 카탈로그와 원본/필수값 검증을 면제하지는 않습니다.

| 프로필 | PTY/SKY | energy 목표 | acousticness 목표 | 선호 mode |
|---|---|---:|---:|---|
| 맑음 CLEAR | PTY0/SKY1 | 5~8 | 0~60 | True |
| 구름많음 CLOUDY | PTY0/SKY3 | 3~6 | 20~80 | False |
| 흐림 OVERCAST | PTY0/SKY4 | 2~5 | 40~100 | False |
| 비 RAIN | PTY1/4/5 | 2~4 | 60~100 | False |
| 비·눈 MIXED | PTY2/6 | 2~4 | 50~100 | False |
| 눈 SNOW | PTY3/7 | 1~4 | 60~100 | True |

~~~text
d(x,L,U) = max(L-x, 0, x-U)
E_ik = max(0, 100 - 10*d(energy_i, energy_lower_k, energy_upper_k))
A_ik = max(0, 100 -    d(acousticness_i, acoustic_lower_k, acoustic_upper_k))
M_ik = 100 if mode_i = preferred_mode_k, else 0
W_ik = 0.50*E_ik + 0.45*A_ik + 0.05*M_ik

W_i = Σ_k [ overlap_ms_k / effective_target_ms × W_ik ]  # STANDARD=10,800,000ms
~~~

mode=NULL은 날씨 M=0이며 가중치를 재배분하지 않습니다. 중간 계산을 반올림하지 않습니다. W에 합격 하한은 없습니다. 위 50:45:5는 현행 음악 계약의 초기 가설을 ON의 내부 순위에 가져온 것이지 CSV 상관계수에서 추정한 최적값이 아닙니다. OFF에는 W·기존 P(취향 가점)·S=0.75W+0.25P·화면 표시점수·popularity·loudness 가점이 없습니다. OFF도 테마 선택이 있으면 energy/speed/mode를 **음악 테마의 밀접도**에 사용하지만 예보나 날씨 목표는 참조하지 않습니다. ON은 W와 새 U를 4.3절의 H로 결합합니다.

## 6. 목표시간별 장르 보장·80% 비율·시간 조건

부분 장르 선택(1~17개)에서는 **각 선택 장르가 결과에 서로 다른 곡으로 최소 1번** 등장해야 합니다. j-rock처럼 두 장르를 가진 곡 하나를 두 장르의 최소 1곡으로 중복 계산하지 않습니다. 다음 y_ig는 선곡한 곡 i를 선택 장르 g의 대표로 배정한 값입니다.

~~~text
x_i ∈ {0,1}                       # 곡 i의 선곡 여부
y_ig ∈ {0,1}                      # 곡 i가 선택 장르 g의 대표인지
y_ig = 0                          if g ∉ approved_genre_i
y_ig ≤ x_i
Σ_g y_ig ≤ 1                      # 한 곡은 대표 장르 하나만 담당
Σ_i y_ig ≥ 1                      for every g ∈ G_eff, if G_eff≠ANY

D(R) = Σ_i duration_ms_i*x_i
effective_min_ms ≤ D(R) ≤ effective_max_ms
STANDARD: target=10,800,000; min=10,560,000; max=11,040,000
SHORTENED: target_ms ∈ {175,170,165,160,155,150,145,140,135} × 60,000
           min=max(8,100,000, target_ms-240,000); max=min(target_ms+240,000, 10,560,000-1)
~~~

곡에는 여러 승인 장르가 남아도 되지만 결과에는 같은 track_id가 한 번만 나옵니다. 선택 장르 전체의 재생시간은 복수 장르곡을 **한 번만** 더합니다.

~~~text
D_G(R) = Σ_i duration_ms_i*x_i*1[approved_genre_i ∩ G_eff ≠ ∅]

ON, G_eff≠ANY:  R ⊆ C_ON 이므로 D_G(R)=D(R)
OFF, G_eff≠ANY: 5*D_G(R) ≥ 4*D(R)     # 선택 장르 ≥80%, 나머지 ≤20%
G_eff=ANY:      장르 대표·비율 제약 없음
~~~

STANDARD에서 정확히 180분이면 OFF의 선택 장르는 최소 144분, 다른 장르는 최대 36분입니다. SHORTENED에도 같은 80%와 장르 대표 조건을 적용합니다. **80%는 결과의 재생시간 기준**이며 200곡 후보 창의 곡 수만 맞춰 통과시키지 않습니다. 이는 장르당 80%나 균등 배분을 뜻하지 않습니다. JAZZ+ROCK이면 서로 다른 두 곡이 각각 장르를 대표해야 하지만, 나머지 선택 장르 시간의 비율은 이 문서에서 강제하지 않습니다. 80%는 사용자 의도를 수치화한 **초기 제안값**이며 READY 카탈로그와 청취 평가로 검증해야 합니다.

시간 선택은 두 날씨 모드 모두 STANDARD 180분을 먼저 검사합니다. 전체 적격 후보에서 표준 구성이 불가능하다고 확인된 때만 현행 공통 계약 3.5절의 SHORTENED 단계(175→170→…→135분)로 옮기고 첫 성공 단계에서 멈춥니다. 각 단계는 정확한 목표 → 목표 초과 중 가까운 시간 → 목표 미만 중 가까운 시간 순입니다. 같은 총시간 D에서는 재생시간 가중 내부 밀접도 Q를 최대화하고, 동점은 저장된 seed와 결과 track_id 집합으로 결정합니다. ON의 SHORTENED 단계마다 해당 목표의 W와 H를 다시 산정합니다. OFF의 Q에는 날씨가 들어가지 않습니다. 무작위로 처음 찾은 조합을 그대로 성공으로 확정하지 않습니다. duration_policy_version·duration_mode·effective_target/min/max·shortening_reason과 단계별 근거를 작업·결과·당시 조건에 고정합니다.

~~~text
선호 활성화 ON: Q(R) = Σ[i∈R] duration_ms_i*H_i / D(R)
선호 미선택 ON: Q(R) = Σ[i∈R] duration_ms_i*(W_i/100) / D(R)
선호 활성화 OFF: Q(R) = Σ[i∈R] duration_ms_i*U_i / D(R)
선호 미선택 OFF: Q 미사용; seed와 결과 track_id로 재현 가능한 동점 처리
~~~

Gemini 3.8 Flash는 사용자가 명시 재설정을 요청한 경우에만 같은 모드의 후보·장르 대표·80%/100%·시간·제외 조건을 적용합니다. 부모 전체 고유 곡 수의 20% 내림, 최소 1곡 이상 새 track_id를 포함해야 합니다. 실패하면 부모 결과와 제외·평가·승인을 보존합니다.

## 7. 200곡 시작 창과 단계별 확장

각 시간 단계의 전체 C_ON 또는 C_OFF가 추천 대상의 논리적 범위이고, 200곡은 계산을 시작하는 **탐색 창**입니다. 원본 구조상 평균 곡 길이 3.928분으로 180분은 약 46곡, 200곡은 약 4.4배입니다. 사용자 결정인 약 200곡에서의 무작위 탐색을 저장된 seed로 재현 가능하게 구현하되, 200을 고정 상한으로 삼지 않습니다. 실제 READY/승인곡과 선택 조합의 길이·성공률은 아직 확인되지 않았습니다.

- 선호가 있으면 H 내림차순의 0.05 점수 구간을 높은 순서로 취하고 같은 구간 안에서는 저장된 seed로 섞습니다. 0.05 구간은 탐색 다양성을 위한 초기 제안값이며 최종 Q 비교에는 반올림 전 H를 사용합니다. 선호가 없는 OFF는 전체 C_OFF를 seed로 섞고, 선호가 없는 ON은 W 순위와 seed를 사용합니다.
- ON, G_eff≠ANY: C_ON에서 선택한 각 장르의 서로 다른 대표 후보를 먼저 확보하고, 나머지를 H 구간·seed 순으로 200곡까지 채웁니다. 같은 장르의 길이·밀접도 대안도 포함해 3시간 조합을 탐색합니다.
- OFF, G_eff≠ANY: C_selected와 C_other를 각자의 H 구간·seed 순으로 뽑습니다. 첫 K곡 창에서 선택 장르 후보 ceil(0.8K)개를 우선 확보하고 나머지를 보완곡으로 채우는 **탐색용 시작 배분**을 제안합니다(K=200이면 최대 160/40곡). 한쪽 후보가 부족하면 남는 자리를 다른 쪽으로 채웁니다. 각 선택 장르의 서로 다른 대표 후보도 창 안에 확보합니다. 이 곡 수 배분은 최종 재생시간 80% 판정이 아닙니다.
- OFF, G_eff=ANY: C_OFF를 H 구간·seed 순으로 200곡까지 채웁니다. 선택 장르 비율과 장르 대표 조건은 없습니다.

창 안에서는 기록된 seed로 순서·조합 시작점을 바꾸어 여러 조합을 탐색합니다. 모든 결과에 READY·보컬·빠르기·제외·정수 시간·중복 검증을 적용하고, 부분 장르 선택 시 장르 대표·ON 100%/OFF 80%도 검증하며, 활성 테마의 곡별 T 및 결과의 재생시간 가중 평균을 기록합니다. 테마 밀접도는 필수 일치 필터가 아니므로 작은 창의 저득점 결과를 곧바로 확정하지 않고 같은 시간 우선순위에서 Q를 비교합니다. seed·시도 수·탐색 시간·창 크기·solver 상태·관련도/날씨 정책 버전·선택/비선택 장르 재생시간을 저장합니다. 무작위 시도만으로 시간 우선순위나 최적성을 증명할 수 없으므로 해당 탐색 창의 solver가 필요한 입증을 해야 합니다. 입증하지 못한 휴리스틱 성공은 별도 결과 상태·수용 계약이 필요합니다.

200곡에서 유효한 조합 또는 필요한 입증을 얻지 못하면 남은 예산 안에서 400→800→1,600→…으로 창을 넓혀 전체 C까지 살핍니다. 장르 대표가 없거나 OFF의 80%가 창에서 불가능해도 **전체 C에서 증명하기 전에는** 부족으로 단정하지 않습니다. 전체 C에서 해당 목표 단계의 서로 다른 장르 대표 배정·80%·유효 시간을 만족할 수 없다고 증명되거나 총 적격 길이가 부족한 경우에만 다음 단축 단계를 검사합니다. 135분까지 모든 단계를 확인한 뒤에도 불가능하면 CANDIDATE_SHORTAGE로 안내하고 부족한 장르와 원인을 함께 기록합니다. 제한 창 실패·무작위 시도 실패·solver UNKNOWN/시간 초과는 SEARCH_INCOMPLETE이며 단축 근거가 아닙니다. 단축해도 135분 하한·장르 대표/비율·보컬·제외·예보 유효성은 완화하지 않습니다. 테마 관련도는 완화할 필수 문턱값이 아니라 순위와 품질 검증값입니다. 실제 실행시간·창 크기·난수 시도 횟수는 아직 실측되지 않았습니다.
## 8. 사용자 자율성·화면·기존 계약과의 차이

부분 테마 선택은 두 모드 모두 밀접도 T/U로 반영합니다. 부분 장르 선택은 ON에서 선택 장르 100%, OFF에서 전체 재생시간의 선택 장르 80% 이상이라는 **검증 전 초기 수치**와 각 장르의 서로 다른 대표 곡으로 보장합니다. OFF의 나머지 최대 20%는 테마에 가까운 다른 장르를 허용하며 반드시 채우지는 않습니다. CALM+METAL의 76곡은 우선 사례이지 후보 상한이 아닙니다. 이렇게 하면 엄격한 테마·장르 동시 일치가 빈 목록을 만들지 않으면서 가까운 곡을 우선합니다. 선택이 충돌하거나 READY가 적을 때 실제 결과의 평균 테마 밀접도가 얼마나 낮아지는지는 별도로 측정하며, 임의의 합격 하한은 아직 확정하지 않습니다.

ON에서만 선택 장르와 날씨 적합도의 간극을 비차단 안내로 표시할 수 있습니다. 동일 조건의 태그 중립 결과 Q 차이 10점은 기존 검증 전 실험값이므로 새 0~1 Q에 그대로 적용하지 않습니다. OFF는 날씨 패널을 볼 수 있어도 추천 후보·속도·순위·성공 여부에 예보가 스며들지 않아야 합니다. OFF의 지역 필수 유지/패널 오류 분리는 현재 공개 흐름을 보존하는 제안이며, 날씨 선택 버튼의 문구·초기 ON 값은 UX 수용 전에 확인해야 합니다.

## 9. 적용 전 검증 기준

1. **입력·집합:** 같은 모드·카탈로그·seed에서 테마 0/9개와 장르 0/18개가 각각 같은 유효 조건·순위를 만듭니다. 부분 테마는 선택 목록 중 최고 밀접도를 사용하고 모두 동시 충족을 요구하지 않습니다. 선택하지 않은 그룹을 0점으로 계산하지 않습니다. 승인 genre가 없는 곡, 승인 mood가 없는 곡, 중복 track_id의 처리를 구분합니다.
2. **밀접도 고정 사례:** CALM+METAL에서 energy=4/slow/METAL은 T=0.90·U=0.945, energy=5/slow/METAL은 T=0.80·U=0.89입니다. 후자는 후보에서 바로 사라지지 않습니다. CALM에 매핑된 JAZZ의 energy=4/slow는 T=1이며, OFF의 비선택 장르 보완곡으로만 들어갈 수 있습니다. 76곡은 엄격한 원본 특성 일치 수이고 READY·mood 승인곡 수가 아님을 검증합니다. E/V/M 결측은 해당 성분 0, 승인 mood 일치는 1, 매핑 장르만 맞는 경우는 약한 근거임을 확인합니다.
3. **날씨 분리:** ON은 예보 180분 연속·유효성, W 내부 50:45:5, energy=4/acousticness=60/mode=True의 맑음/비 W=95를 확인합니다. 선호 활성화 시 H=0.45W/100+0.55U, 미선택 시 H=W/100입니다. OFF는 예보 누락·만료에도 추천 가능하고 W가 계산·저장·정렬에 사용되지 않으며 auto speed가 날씨를 참조하지 않습니다. OFF의 테마 energy/mode 사용은 날씨 사용으로 간주하지 않습니다. 날씨 패널 오류가 OFF 추천을 막지 않습니다.
4. **장르 대표·비율:** JAZZ+ROCK 결과에는 각각을 대표하는 서로 다른 곡이 있어야 합니다. ROCK/J-POP 복수 태그 한 곡으로 두 장르를 충족시키지 않습니다. OFF의 부분 장르에서 5*D_G≥4*D를 정수 ms로 검사합니다. 정확히 180분 결과의 선택 장르 144분은 통과, 144분-1ms는 실패입니다. 복수 장르곡의 D_G는 한 번만 셉니다. ON의 부분 장르 결과에는 선택 외 장르만 가진 곡이 없어야 합니다. 테마 미일치는 단독 탈락 사유가 아닙니다.
5. **시간·탐색:** STANDARD의 176/180/184분은 허용하고 범위 밖은 거부합니다. 전체 적격 후보로 표준 부족을 확인한 후에만 단축 단계를 적용하며, 135분-1ms는 거부하고 단축 결과에도 장르 비율·대표를 재검사합니다. 같은 seed·작업·catalog/policy 버전에서 0.05 점수 구간/창/결과를 재현합니다. 200곡 창에 장르 대표 또는 유효 시간 조합이 없으면 확장하고, 제한 창 실패·UNKNOWN을 전체 후보 부족으로 표시하지 않습니다. 창 안의 결과를 전체 최적해라고 주장하지 않습니다.
6. **재설정·상태:** Gemini 결과도 모드·장르 대표·80%/100%·시간·신규곡 조건을 서버에서 검사하고 테마 밀접도·출처를 같은 방식으로 기록합니다. OFF에서 날씨만 갱신해도 기존 추천 결과의 곡·선택·평가는 자동 변경되지 않아야 합니다. 선택 모드 변경은 새 family이며 이전 결과/제외/평가 스냅샷을 보존합니다.
7. **실측:** 실제 READY·approved 카탈로그에서 6개 날씨 프로필과 OFF, 장르 선택 개수/희소 조합, 테마·보컬·빠르기별 후보 수·D_G 비율·대표 충족률·테마 밀접도 분포/재생시간 가중 평균·176~184분 성공률·200/400/800창 성공률·지연 p50/p95를 기록합니다. CALM+METAL처럼 매핑 밖이지만 특성은 가까운 조합과 특성도 먼 조합을 별도로 청취 평가합니다. PL의 청취 검수·곡 반응·별점으로 OFF 80%/ON 100%, U의 55:45와 H의 55:45, 테마/매핑 90:10, 0.05 구간의 초기값을 검토합니다. 원본 CSV 상관계수만으로 추천 품질이나 계수 타당성을 주장하지 않습니다.

필요한 인계는 C의 실제 READY 카탈로그·곡별 특성/승인 테마/장르·관련도 정책 버전, A의 ON용 유효 예보, B의 모드/비율/장르 대표·밀접도 근거를 담는 공통 결과·소유·불변 피드백 계약, PL의 ON/OFF 문구·초기값·비율/밀접도 수용 기준입니다. 구현 후보 위치는 backend/recommendation/inputs.py, policy.py, solver.py, service.py, worker.py 및 frontend/src/PublicPage.tsx입니다. **이 문서 수정 시점에는 해당 프로젝트 파일을 변경하지 않았습니다.**
