사용자가 제공한 [간소화 원문](../handoff/ads/04_광고_관리_간소화_인수인계서.md)과 [통합·추가 인계](../handoff/ads/05_광고_간소화_통합과_추가_인계.md)를 현행 광고 기준으로 적용합니다. 첫 관리 단계는 ads/ad_assets/ad_admin_changes 세 컬렉션·MongoDB 이미지 Binary·관리 감사/멱등 응답 통합입니다. 3차는 카페 전용이며 관리자/사용자 업종 선택·태그 입력·업종별 매칭은 제공하지 않습니다. 해당 확장은4차로 분리합니다. 공개 제공/측정과 토큰/주기 통계/예산은 다음 구현 단계이며 전체3차 필수 범위와 기존 태스크 ID/직접 선행은 유지합니다. 이하 기존 확장 저장 표는 후속 검토 자료이며 지금 일괄 생성하지 않습니다.

3차는 카페 광고만 운영하고 위치·일정·paused·소재·예산 자격을 충족한 후보에서 높은 priority·위치별 동률 순환을 적용합니다. 업종/태그가 제공·측정의 전제가 아니며 최초 guest 발급·추천 미요청 집계·단가8/5/클릭추가15·중복/지연/보관은 유지합니다. 미연결 지표는 연동 대기, 실제 통계는 주기 집계하며 예산 제공 제어와 구분합니다. 첫 관리 로그는 ad_admin_changes 내부 log_relay로 전달합니다. 업종별 입력/태그/매칭/순환은4차 인계에서 정하고3차 API/DB/화면/검증의 선행 조건으로 넣지 않습니다.

## 1. 기존 기준에서 유지할 사항

광고 업무 저장소는 2026-10-14 사용자 결정의 MongoDB입니다. 자료·delivery·최초 판정·반복 창·집계/예상 원장·관리 변경과 로그 outbox를 광고 전용 DB에 저장하며 PostgreSQL에는 로그 사본/진단을 멱등 발행합니다. [ADS 인계](../handoff/ads/README.md)의 컬렉션/트랜잭션·환경/검증 계약을 적용합니다. 광고 이미지는 MongoDB `ad_assets.image_bytes`에 Binary로 저장합니다. delivery 자체 수명·예산/재개 등 미정은 유지합니다.

| 항목 | 기존 기준 |
|---|---|
| 배치 | 상단과 하단. 광고 한 기록은 한 위치이며 두 위치에 게시하려면 두 기록을 사용합니다. |
| 입력 | 제목·이미지·링크·기간·우선순위. 저장으로 예약/게시 상태를 판정합니다. |
| 중단 | 단순 편집으로 중단을 해제하지 않으며 관리자 로그아웃은 광고를 중단시키지 않습니다. |
| 미리보기 | PC/모바일 미리보기는 운영 노출·클릭 집계에서 제외합니다. |
| 기본 추천 | 광고 없음·지연·실패가 기본 추천을 막지 않습니다. |

### 6-2. 예산과 첫 검증 범위

- 광고별 일일·전체 예산을 둡니다. 잔액 또는 예산 소진 시 신규 제공을 중단합니다. 상·하단 같은 소재도 별도 광고 기록의 예산과 지표로 처리합니다.
- 최초에는 실제 잔액 차감 없이 예상 사용량·예산 소진을 계산합니다. 예산 수치와 일일 초기화 시각, 예산 변경·재개 계약은 후속 결정합니다.
- 초기 방향은 예산 부족 시 추가 차감 없이 클릭 이동을 허용하는 것입니다. 실제 차감의 동시성·예산 상한 보장은 구현 전 검증하며 예약 방식·초과 이벤트 처리를 임의 확정하지 않습니다.
- 관리자 중단은 신규 제공·과금을 중단합니다. 중단 전 유효 이벤트는5분 이내 수신 시 검사하며 중단 후 발생은 제외합니다. 화면 반영3초는 AD-M04, 별도 delivery 수명은 AD-M15를 따릅니다.
- 새 delivery 간 노출60초/클릭300초와 기존 익명 문맥을 사용합니다. 억제/중복은 예상 사용량을 추가하지 않고 클릭 이동은 유지합니다.

### 6-3. 통계와 사용량 원장

노출/클릭 통계와 토큰 사용량 원장을 분리합니다. 원장은 광고·위치·소재 버전·delivery_id·event_id·유형·발생/처리 시각·정책 버전·적용 단가·계산 사용량·처리 상태·취소 사유를 기록합니다. 첫 검증 기록은 예상 계산으로 표시하며 실제 차감 내역과 섞지 않습니다. 향후 실제 차감 시 차감 시각·금액을 기록하고 중복 전송·동시 요청에도 한 이벤트를 한 번만 반영해야 합니다. 취소/정정은 원래 기록과 연결하고 원본을 덮어쓰지 않습니다. 가격 변경은 과거 기록에 소급하지 않습니다.

예: 상단 노출 100회 × 8 + 하단 노출 100회 × 5 + 인정 클릭 10회 × 15 = 예상 1,450토큰. 광고 집계·원장은 음악 추천 점수/피드백 및 4차 USER 결제와 별개입니다. 원장 보관은365일로 채택했고 조회 UI·API 세부는 후속 계약이며 현재 시안을 구현 완료로 해석하지 않습니다.

### 6-5. 반복·소재·지연·보관 수치 — 2026-10-14 사용자 채택

사용자가 앞서 브리핑한 제안 수치를 문서에 적용하도록 지시했으므로 다음을 **3차 초기 구현 기준**으로 채택합니다. 광고 정책 버전은 `phase3-ads-20261014.1`입니다. 숫자 채택과 실제 코드/브라우저/집계/정리 검증 완료는 구분합니다.

#### 새 delivery 간 반복 제한

- 기존 delivery별 노출/클릭 각각1회 제한을 유지합니다. 같은 event_id/본문 재전송은 최초 저장 응답을 반환하며 원본/집계/원장에 새 성공 이벤트를 만들지 않습니다.
- 서버의 익명 문맥을 식별 기준으로 사용합니다. 첫 공개 메인 진입의 상단 광고 조회에서 쿠키를 발급/재사용하고 광고 없음에도 발급합니다. 최초 상단 응답 이후 하단 조회/측정 전송을 시작하며 추천 요청·지역 선택·로그인은 집계 조건이 아닙니다. 동일 브라우저의 새로고침/새 탭은 같은 유효 guest 쿠키 문맥을 공유합니다. 범위는 `(owner_guest_id, ad_id, placement, event_type)`이며 소재 버전 변경만으로 반복 제한을 초기화하지 않습니다. 쿠키가 저장되지 않거나 새 문맥이면 같은 사람이라고 추정해 합치지 않습니다. 발급 자체는 광고 지표가 아닙니다.
- 새 delivery라도 같은 문맥/광고의 유효 노출은 서버의 마지막 인정 시각 accepted_at부터 **60초**, 클릭은 **300초(5분)** 동안 추가 인정하지 않습니다. 경계는 `[accepted_at, accepted_at+window)`이며 정확히60/300초부터 다시 인정할 수 있습니다. 노출과 클릭의 창은 별개이고 중복/억제 보고는 accepted_at을 연장하지 않습니다.
- 노출은 기존 이미지 로딩 완료·활성 탭·면적50%/연속1초를 먼저 충족해야 합니다. 유효 보고를 delivery 단위로 최초 처리한 뒤 COUNTED 또는 REPEAT_SUPPRESSED를 기록하며, 억제된 같은 delivery를 기다렸다가 새 event_id로 다시 보내 집계하지 않습니다.
- delivery/event 중복·반복 억제는 통계와 예상 토큰을 추가하지 않습니다. 클릭 이동은 허용합니다. 서로 다른 광고 기록은 각각 판정하며 같은 소재의 top/bottom 두 기록도 분리합니다.
- 유효 guest 문맥이 없는 측정 보고는 MEASUREMENT_UNAVAILABLE로 집계/예상 원장에서 제외하고 진단 상태를 남깁니다. 광고 표시와 링크 이동을 로그인/쿠키 저장 성공의 필수 조건으로 만들지 않습니다.
- B는 동일 범위의 검사/인정 상태·delivery 처리·원본 판정·통계/예상 원장을 원자적으로 저장합니다. 동시 탭 요청이 모두 제한을 통과하지 않도록 DB 잠금 또는 원자 조건 변경을 사용하고 취소/재처리는 최초 판정/accepted_at을 보존합니다.

#### 이미지·링크와 화면 크기

| 위치 | 1536px PC 기준 표시 | PC용 권장2배 이미지 | 390px 모바일 기준 표시 | 모바일용 권장2배 이미지 |
|---|---:|---:|---:|---:|
| top | 1536×120px | 3072×240px | 390×120px | 780×240px |
| bottom | 1536×104px | 3072×208px | 390×104px | 780×208px |

- 최신 메인 시안의 측정 근사치를 표시 초기값으로 채택합니다. 실제 배너 폭은 사용 가능한 폭의100%, 최대1536px이며 가운데 정렬합니다. 높이는 top120px/bottom104px를 유지하고 좁은 화면에서도 단순 비율 축소로30px/26px 높이가 되지 않게 합니다.
- 사진은 컨테이너에 cover로 배치하고 제목·기본 이동 버튼은 HTML로 표시합니다. 광고 제목의 기존 title·대체 텍스트를 재사용하며 이미지에 넣은 글씨가 잘리는 것을 필수 안내 방식으로 삼지 않습니다. 모바일은 줄바꿈/재배치로 버튼을 유지합니다.
- PC/모바일 권장 파일 크기는 제작 기준이며,3차에 별도 모바일 업로드 입력/필수 이미지 컬럼을 추가하지 않습니다. 기존 단일 이미지로 PC/모바일을 표시할 수 있고 모바일 전용 소재는 후속 확장입니다.
- 정적 WebP/JPEG/PNG를 허용하고 파일당 **최대2,000,000bytes(2MB)**입니다. 정확히2MB는 허용하고1byte 초과는 거부합니다. 확장자만으로 판단하지 않고 실제 형식/디코딩/정적 여부를 확인합니다. 권장 해상도와 다르다는 이유만으로 유효 파일을 거부하지 않으며 PC/모바일 미리보기로 잘림·가독성을 검증합니다.
- 광고 이동 링크는 호스트가 있는 **절대 HTTPS URL**만 허용합니다. 클릭은 새 탭으로 열고 `rel="noopener noreferrer"`를 적용합니다. 이미지 저장 경로와 이동 링크를 구분하며 파일 공개 경로/미사용 파일 정리는 INF/AD-M10~11의 별도 계약입니다.

#### 지연 이벤트·날짜·판정 기록

- API는 delivery_id·event_id·event_type과 UTC Z 형식 occurred_at을 받으며 서버가 received_at/판정/정책 버전/적용 단가를 기록합니다. owner/인정 여부/토큰을 클라이언트가 확정하지 않습니다.
- 발생 시각이 수신 시각보다 미래이거나 당시 광고/delivery가 유효하지 않으면 집계하지 않습니다. 정상 이벤트는 `0 <= received_at-occurred_at <= 300초`일 때만 신규 인정 검사를 진행합니다. 정확히5분은 허용하고 초과는 LATE_EVENT로 제외합니다.
- 중단/종료 전에 유효하게 발생한 보고는5분 이내 도착하면 중복/반복 검사를 거쳐 인정할 수 있습니다. 중단/종료 이후 발생한 보고는 표시가 늦게 사라졌더라도 인정하지 않습니다. 이를 위해 당시 광고/소재/정책·기간·중단 시각을 보존합니다.
- 집계 날짜와 예상 원장의 일자는 **검증된 occurred_at을 Asia/Seoul로 변환한 날짜**입니다.23:59:59에 발생하고 다음날00:00:03에 수신한 이벤트는 전날 집계에 반영하며 수신/처리 시각은 별도로 보존합니다.
- 처리 순서는 저장된 동일 event_id/본문의 최초 응답 재반환 → 대상/시각/당시 유효성 → delivery 최초 처리 →60/300초 반복 제한 → 원자 저장입니다. COUNTED/DELIVERY_DUPLICATE/REPEAT_SUPPRESSED/LATE_EVENT/DELIVERY_INVALID/MEASUREMENT_UNAVAILABLE 등 결과와 counted 여부를 기록합니다. 이미 처리된 이벤트 재전송은 현재 시각으로 다시 과금 판정하지 않습니다.
- 최초 판정은 입력/발생/수신/accepted_at·정책 버전과 함께 보존합니다. 재처리에서 현재 광고/단가/현재 시각으로 원본을 다시 판정하지 않습니다. 지연 허용5분과 최대3초 표시 유효기한, delivery 자체 수명을 같은 설정으로 혼용하지 않습니다.

| 자료 | 채택 기간 | 기준 시각 |
|---|---|---|

보관 기간을 UTC 기준 경과 시간으로 계산하고 만료 경계부터 정리 대상으로 삼습니다. 원장/집계는 원본이90일 후 만료되어도 날짜·광고/소재/정책 버전·단가·사용량·판정/원본 식별자를 자체적으로 보존하며 원본 상세 만료를 구분합니다. 단순 재전송으로 보관 기산점을 연장하지 않습니다. 유효 delivery·미완료 발행/재처리·유지할 원장/집계에 필요한 참조를 끊는 정리는 하지 않습니다.

이 기간은 **광고 자료에만 적용**합니다. 음악/날씨/추천/평가 로그·세션/최근 결과 복원·광고 이미지 파일/백업의 보관 정책은 별도입니다. 실제 정리 작업은 운영 환경에서 검증하며 이번 문서 변경으로 파일/DB를 삭제하지 않습니다.
