## 1. 제품 정의

날씨 기반 선곡표 추천 서비스는 카페·음식점 등 매장 운영자가 지역 날씨와 음악 취향에 맞는 선곡표를 고르고 조정하는 서비스다. 곡을 하나씩 찾아 목록을 구성하는 수고를 줄이는 것을 목표로 한다.

## 2. 사용자 필요

| ID | 사용자 필요 |
|---|---|
| UN-STORE-001 | 매장 운영자는 적은 시간과 수고로 날씨·매장 분위기·취향에 맞는 선곡표를 준비하고, 사용할 결과를 결정하고 싶다. |
| UN-STORE-003 | 매장 운영자는 마음에 들지 않는 곡을 빼거나 지역·음악 취향을 바꾸어 원하는 선곡표로 조정하고 싶다. |
| UN-STORE-006 | 매장 운영자는 곡과 선곡표에 대한 만족·불만족을 전달하고, 평가를 바꾸거나 취소하고 싶다. |
| UN-STORE-007 | 처음 이용하는 운영자는 추천과 조정 방법을 익히고, 필요할 때 안내를 다시 보고 싶다. |
| UN-MUSIC-001 | 음악 관리자는 추천에 쓸 음악을 등록하고, 분류와 검수 상태를 확인하고 싶다. |
| UN-FEEDBACK-001 | 피드백 관리자는 사용자의 곡 반응·선곡표 평가를 파악하고, 어떤 조건에서 곡을 제외했는지 확인하고 싶다. |
| UN-ADS-001 | 광고 관리자는 광고의 내용·위치·기간과 게시 상태를 관리하고, 게시 모습과 노출·클릭 등 운영 결과를 확인하고 싶다. |

상태의 `active`는 현행 적용 요구사항을 뜻하며, 구현 완료 여부는 나타내지 않는다.

### 3-2. 데이터·공통 운영

검수된 음악을 확보하고 피드백의 당시 맥락을 확인해 추천 운영을 뒷받침한다(UN-MUSIC-001·UN-FEEDBACK-001).

| ID | 우선순위 | 요구사항 | 상태 |
|---|---|---|---|
| FR-WEATHER-DATA-001 | Must | 지역을 기상 격자에 연결해 날씨를 수집·정제·저장하고 6시간 범위로 조회한다. | active |
| FR-AUTH-001 | Must | 서버가 ADMIN 역할과 업무별 관리 권한을 확인하고 공통 로그인 후 광고 관리로 이동시킨다. | active |
| FR-OWNERSHIP-001 | Must | 익명 이용자는 본인 결과만 조작하도록 제한한다. | active |
| FR-MUSIC-IMPORT-001 | Must | 음악 CSV를 현행 규격으로 정제·등록하고 중복 곡과 행별 오류를 구분한다. | active |
| FR-MUSIC-REVIEW-001 | Must | 분류·보컬의 근거와 검수 상태를 관리해 승인·보류하고 적격 음악을 버전이 고정된 카탈로그로 발행한다. | active |
| FR-FEEDBACK-001 | Must | 평가·제외·취소·재설정·승인의 당시 조건과 결과 버전을 중복 없이 기록·정제·집계하며 평가로 추천·제외·승인·점수 변경·Gemini 호출을 자동 실행하지 않는다. | active |
| FR-FEEDBACK-ADMIN-001 | Must | 권한이 있는 관리자가 사용자 초안을 변경하지 않고 제외·취소 이력과 당시 곡·조건·날씨를 검색·조회할 수 있도록 한다. | active |
| FR-OPS-001 | Must | 허용된 담당자가 음악 준비·날씨 수집 및 조회·추천 작업·피드백 처리·광고의 상태와 오류를 확인하도록 한다. | active |
| FR-OPS-VIEW-001 | Should | 필수 개별 조회와 별도로 운영 조회·로그를 모아 보는 통합 편의 화면을 선택 기능으로 제공한다. | active |

피드백의 필수 관리자 화면은 제외 이력 조회이며, 평가 통합 화면은 FR-OPS-VIEW-001의 선택 범위에서 구체화한다.

### 3-3. 광고 운영

관리자가 광고를 게시·중단하고 실제 운영 결과를 확인하도록 한다(UN-ADS-001).

| ID | 우선순위 | 요구사항 | 상태 |
|---|---|---|---|
| FR-ADS-MANAGE-001 | Must | 관리자가 광고 내용·위치·기간·우선순위·게시·예약을 관리하도록 하며 게시 중단은 정상 활성 화면에 3초 이내 반영한다. | active |
| FR-ADS-PREVIEW-001 | Must | PC·모바일 광고 미리보기를 제공하고 미리보기의 노출·클릭은 운영 통계에서 제외한다. | active |
| FR-ADS-DELIVERY-001 | Must | 위치·일정·게시 상태·소재·예산 자격과 우선순위·동률 순환 규칙에 따라 상하단 카페 광고를 제공한다. | active |
| FR-ADS-MEASURE-001 | Must | 유효 노출과 실제 클릭을 광고 제공 건별로 각각 1회 인정하고 반복·재전송 제한을 적용한다. | active |
| FR-ADS-STATS-001 | Must | 오늘 요약과 광고별 누적 통계를 집계 기준시각과 함께 표시하고 연동 대기와 실제 0건을 구분한다. | active |
| FR-ADS-BUDGET-001 | Must | 유효 광고 이벤트의 예상 토큰 사용량을 원장에 중복 없이 기록하고 광고별 일일·전체 예산 소진 시 신규 제공을 중단하며 실제 잔액을 차감하지 않는다. | active |

- 3차 제외 범위는 [BRD 5절](./BRD.md#5-범위-제외-항목)을 따른다.
- 추천·재설정의 세부 입력·표시·검증 기준은 [공통 개발 계약](./product/3차_공통_개발_계약과_검증_기준.md)과 [추천 로직 가이드](./product/카페_음악_추천_서비스_3차_컬럼_기반_추천_로직_가이드.md), 광고는 [광고 인계 자료](./handoff/ads/README.md)를 기준으로 한다.
- 광고 단가·예상 사용량·예산 판정은 [광고 운영 정책 6절](./product/3차_광고_운영_회의_결정사항_목록.md#6-토큰-단가예산원장--합의한-초기-정책)을 따른다.
- 미정인 운영 수치와 추가 결정은 [확인·인계 목록](./product/3차_사용자_확인과_담당자_인계_목록.md)에서 관리한다.

## 5. 성공 지표·검증 방법

### 5-1. 사용자 효과 지표

| ID | 지표 | 검증 방법 |
|---|---|---|
| MET-01 | 선곡 준비·조정 부담 | 같은 참여자가 동일 과제를 기존 방식과 서비스로 수행한 시간과 체감 부담을 비교한다. |
| MET-02 | 선곡표 만족도 | 취소·미평가를 제외한 최신 별점의 평균·분포·평가 수를 확인한다. |
| MET-03 | 날씨·매장 분위기 적합성 | 전체 별점과 별도의 사용자 조사로 날씨·매장 분위기·취향에 어울리는지 평가한다. |
| MET-04 | 재설정의 조정 효과 | 같은 조건에서 재설정 전후의 만족도와 원하는 결과를 얻기까지의 시간·수고를 비교한다. |

### 5-2. 품질·운영 지표

| ID | 지표 | 검증 방법 |
|---|---|---|
| MET-05 | 선곡표 생성 성공률 | 사전에 정한 유효 입력에서 검증된 결과를 만든 비율을 기본 추천·Gemini별로 측정하고 실패 원인을 구분한다. |
| MET-06 | 추천 조건 준수 | 생성 결과의 검수·보컬·장르·빠르기·제외·중복·날씨·시간 조건 위반 여부를 검사한다. |
| MET-07 | 응답 시간 | 합의한 자료 규모·동시 요청 조건에서 기본 추천·Gemini별 P50·P95를 측정하고 환경·실행 수·실패 사유를 기록한다. |
| MET-08 | 광고 집계·예상 사용량 정확성 | 같은 집계 범위와 기준시각에서 기대한 노출·클릭·예상 토큰 사용량을 실제 집계·원장과 대조하고 중복·운영 제외 사례를 확인한다. |

- MET-03은 현재 제품의 효과를 확인하는 사용자 조사이며, 9절의 전용 평가 기능·후속 버전 간 품질 비교와 구분한다.
- 시간·만족도·성공률·성능의 목표값과 평가 대상·규모·기간은 평가 전에 합의한다.
- 미완료·실패·미응답 건수를 함께 보고하고, 목표 미정 상태에서는 달성 여부를 판정하지 않는다.
- 승인·제외·재설정 횟수를 만족도나 실제 청취로 간주하지 않으며, 광고 지표를 실제 매출과 구분한다.

## 6. 실패·예외 처리

재설정 실패 시 기존 결과·승인·평가·제외 초안을 보존하고 규칙 추천으로 자동 대체하지 않는다. 아래 표는 상황별 안내와 사용자의 다음 행동을 정한다.

### 6-1. 입력·데이터 문제
