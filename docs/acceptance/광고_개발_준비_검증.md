## 재현과 증거

`ad-server/backend`에서 기본 검사를 실행합니다.

```powershell
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test tests --verbosity 1
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe manage.py spectacular --file '../../.cache/ads-openapi.yaml' --validate
```

기본 실행에서는 실제 DB 클래스 하나를 명시적으로 건너뜁니다(69개 실행·DB 11사례 skip).
그 DB 시험을 별도로 활성화하여 실제 11개를 확인했습니다. loopback ads-rs primary 준비 후 실행합니다.
테스트는 무작위 ads_integration_UUID_dev DB만 생성·검사·정리하고 공유/운영 DB는 사용하지 않습니다.

```powershell
$env:ADS_RUN_MONGO_TESTS='1'
$env:ADS_TEST_MONGODB_URI='mongodb://127.0.0.1:27019/?replicaSet=ads-rs&directConnection=true'
.\.venv\Scripts\python.exe manage.py test tests.test_ads_mongo_integration --verbosity 2
Remove-Item Env:ADS_RUN_MONGO_TESTS
Remove-Item Env:ADS_TEST_MONGODB_URI
```

[MongoDB 공식 배포본](https://www.mongodb.com/try/download/community-edition/releases)의 Windows 8.0.34
실행 파일을 워크스페이스 .tools/에 두고, loopback 27019의 임시 시험 프로세스로 검증했습니다.
시험 뒤 해당 프로세스를 종료했고 시스템 서비스/공유 DB는 변경하지 않았습니다.
.cache/check_ads_mongo.py는 이번 검증의 로컬 도우미이며 공유 설치 명령이 아닙니다.
시험 데이터·바이너리·로그·OpenAPI 출력은 Git 추적 대상이 아닙니다.

## 유지한 경계와 남은 인계

계정·세션·guest 원본은 공통 환경입니다. AUTHORIZER/SINK 함수 계약과 차단 동작을 구현했지만
실제 공유 ADMIN·PostgreSQL 로그 연결, 공통 응답 버전 확정은 인계 대기입니다.
공개 delivery/노출·클릭/토큰·예산·업종 태그·재개·자동 삭제·관리자 UI를 추가하지 않았습니다.
관리 이미지 조회 경로와 목록/요약 응답, creative_version 내부 식별 조건은 코드 연결을 위한 개발 선택이며
미정 공개 이미지/열린 delivery 운영 정책을 확정한 것은 아닙니다.
기존 기획 문서·타인의 브랜치·AWS 자원은 변경하지 않았습니다.
사용자가 요청한 GitHub 게시 범위는 feature/ad-logic의 이번 코드·문서입니다.

## 2026-10-15 광고 폴더 재배치 검증

사용자 요청으로 광고 코드와 환경 설정을 `ad-server/backend/`, `ad-server/config/`로 옮겼습니다.
가상환경은 새 위치에서 동일 uv.lock으로 재구성했고, 기존 환경 파일과 실행 데이터는 보존했습니다.

- 기능 코드·환경·잠금 파일 38개는 원본과 바이트 단위로 동일합니다. 설정 오류 안내의 경로만 갱신했습니다.
- 새 경로에서 Django 점검·Ruff/실행 스크립트·기본 테스트69개·OpenAPI 생성·스키마 dry-run이 통과했습니다.
- Compose 설정·초기화 JS 문법과 문서 링크를 확인했습니다. 이번 이동에서는 실제 MongoDB 시험을 다시 실행하지 않았습니다.
- 라우팅 Python33파일·248심볼의 누락0을 확인했습니다. 검사 보고서는 `.cache/routing-after-ad-server-move.json`입니다.

이동 직후 실제 Git index는 이전 경로를 추적합니다. 검사기의 경로 부분 문자열 판정이 새 경로를
삭제된 옛 경로로 오인하지 않도록, `.cache/`의 별도 index에 이동 매핑만 적용해 검사했습니다.
검사기는 새 위치의 실제 소스·문서를 읽었으며 실제 Git index·커밋·원격 브랜치는 변경하지 않았습니다.

## 2026-10-15 공개 API·MongoDB 원자 저장 연결 검증

사용자 요청에 따라 `feature/ad-logic`의 광고 로직만 이어서 구현했습니다.
사용자 답변대로 delivery 수명·소재 수정 후 기존 delivery 처리·예산 금액/일일 경계/허용 초과는
미정으로 유지했습니다. 운영 정책 provider 없이 공개 API를 성공시키는 기본값은 없습니다.
연결 계약은 [공개 선정·측정 인계](../development/ads/공개_선정과_측정_로직_인계.md)와
[라우팅 색인](../backend-routing/README.md)을 따릅니다.

| 검사 | 실제 결과 | 적용 경계 |
|---|---|---|
| 공개 HTTP | `GET /api/ads`, `POST /api/ad-events`, delivery별 이미지 GET 연결 | 실제 브라우저 배너/가시성 구현은 별도 담당 |
| 전체 단위/API 회귀 | 207개 실행·통과, 실제 DB 클래스 2개는 기본 실행에서 명시 skip | `Found 233`, `Ran 207`, `OK (skipped=2)`; 실제 DB 26개는 별도 실행 |
| 실제 MongoDB | 8.0.34·로컬 단일 멤버 ads-rs에서 관리 11개+공개 15개=26개 통과 | 무작위 `_dev` 시험 DB, 공유/AWS/고가용성 환경 아님 |

| 과거 자격/중단 | 중단 전 발생 후 지연 수신 집계, 중단이 먼저 커밋된 선정 재시도 검증 | 중단 효력 시각은 잠금 후 업무 시각이며 DB commit timestamp가 아님 |

| 측정 로그 relay | 새 `relay_ads_event_logs`의 실패/ACK 재시도·불변 payload/응답 검증 | 실제 DB에서도 PENDING→SENT와 원장/claim 불변 확인, sink는 시험용 |

공개 추가 상태는 `ad_rotation_state`, `ad_deliveries`, `ad_events`, `ad_repeat_windows`,
`ad_estimated_usage_ledger`입니다. 유형별 소비는 delivery 안에, 로그 전달 상태는 event 안에
내장합니다. 원시 이벤트와 원장에 자동 TTL을 설정하지 않았고 삭제/보관 집행은 별도 인계입니다.
8/5/15는 예상 토큰 계산이며 실제 청구/잔액 차감은 구현하지 않았습니다.

전체 기본 검사와 명세 생성은 `ad-server/backend`에서 실행했습니다.

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONIOENCODING='utf-8'
.\.venv\Scripts\python.exe manage.py test tests --verbosity 1
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py spectacular --file '../../.cache/ads-public-openapi.yaml' --validate
.\.venv\Scripts\python.exe manage.py apply_ads_public_schema
```

OpenAPI의 이벤트 요청은 정확히4필드와 `additionalProperties=false`, 판정 응답은9필드,
공개 광고는8필드·전체 조회 응답은4필드임을 대조했습니다. guest/운영정책 필수 표식과

## 2026-10-15 확정 정책·5분 예산 검증 연결

사용자 후속 답변으로 예산 검증도 **5분 주기**로 확정했고, 자동 종료는 토큰 소진·게시 기간 종료,
관리자 수동 중단은 별도로 유지했습니다. 앞 단계의 답변 대기·provider 미연결·통계 미구현 표현은

그 시각부터 신규 배달·재확인·이미지를 차단합니다. `occurred_at < cutoff`인 당시 유효 이벤트는
발생 후300초 이내 수신 조건을 만족하면 한도 초과분도 인정하고, `occurred_at >= cutoff`는 제외합니다.

차단하되 변경 전 유효 발생은 지연 검사합니다. 신규 배달에는 서명에 포함되는 정책 버전을 저장하고,
